## 10.2 对象之间的关系

面向对象设计中，常见关系包括：

```
依赖
关联
聚合
组合
继承
实现
```

本章重点讨论普通对象关系，继承与实现后续展开。

**10.2.1 依赖关系**

一个类的方法临时使用另一个类：

```java
public class OrderService {
    public void create(Order order) {
    }
}
```

OrderService 依赖 Order 。

依赖可能通过：

- 方法参数
- 局部变量
- 返回值
- 静态方法调用

产生。

**10.2.2 关联关系**

一个对象长期持有另一个对象引用：

```java
public class Order {
    private Customer customer;
}
```

Order 与 Customer 存在关联。

**10.2.3 聚合关系**

聚合表示较弱的整体与部分关系，部分可以脱离整体独立存在。
例如：

```java
public class Team {
    private List<Employee> members;
}
```

Employee 可以离开 Team 后继续存在。

**10.2.4 组合关系**

组合表示较强的整体与部分关系，部分生命周期通常由整体管理。
例如：

```java
public class Order {
    private final List<OrderItem> items = new ArrayList<>();
}
```

OrderItem 通常属于某个具体 Order，不应脱离订单独立存在。
代码层面聚合与组合都可能表现为字段引用，它们的区别主要来自业务语义和生命周期。

## 10.3 组合优于直接暴露数据

假设订单包含商品项。
不推荐：

```java
public class Order {
    public List<OrderItem> items = new ArrayList<>();
}
```

外部可以随意：

```
order.items.clear();
order.items.add(null);
```

更合理：

```java
public class Order {
    private final List<OrderItem> items = new ArrayList<>();
    public void addItem(OrderItem item) {
        Objects.requireNonNull(item, "item");
        boolean duplicate = items.stream()
        .anyMatch(existing -> existing.sameSku(item));
        if (duplicate) {
            throw new IllegalArgumentException("商品重复");
        }
        items.add(item);
    }
    public List<OrderItem> getItems() {
        return List.copyOf(items);
    }
}
```

这样 Order 自己管理内部组成。

## 10.4 对象不变量

对象不变量是：
对象在对外可观察的有效状态中必须始终满足的规则。
例如库存对象：

```
availableStock >= 0
lockedStock >= 0
totalStock = availableStock + lockedStock
```

订单对象：

```
订单号不能为空
订单项不能为空
已取消订单不能完成
已完成订单不能重新创建
总金额不能为负数
```

**10.4.1 构造时保证初始合法**

不推荐：

```
Order order = new Order();
order.setOrderNo(orderNo);
order.setStatus(OrderStatus.CREATED);
order.setItems(items);
```

在多个 Setter 调用之间，对象处于半初始化状态。
更合理：

```
Order order = new Order(orderNo, items);
```

构造方法内部完成校验：

```java
public Order(String orderNo, List<OrderItem> items) {
    if (orderNo == null || orderNo.isBlank()) {
        throw new IllegalArgumentException("订单号不能为空");
    }
    if (items == null || items.isEmpty()) {
        throw new IllegalArgumentException("订单项不能为空");
    }
    this.orderNo = orderNo;
    this.items = new ArrayList<>(items);
    this.status = OrderStatus.CREATED;
}
```

对象一旦创建完成，就处于合法状态。

**10.4.2 每次行为执行后仍然合法**

```java
public void deduct(int quantity) {
    if (quantity <= 0) {
        throw new IllegalArgumentException("数量必须大于 0");
    }
    if (availableStock < quantity) {
        throw new IllegalStateException("库存不足");
    }
    availableStock -= quantity;
}
```

执行后仍保证：

```
availableStock >= 0
```

## 10.5 构造方法中调用可重写方法的风险

下面的代码存在风险：

```java
public class Parent {
    public Parent() {
        initialize();
    }
    protected void initialize() {
    }
}
```

子类重写：

```java
public class Child extends Parent {
    private String name = "Java";
    @Override
    protected void initialize() {
        System.out.println(name.length());
    }
}
```

创建：

```
new Child();
```

父类构造方法执行时，子类字段可能尚未完成初始化。
但动态调用可能进入子类重写方法，导致读取未初始化字段，甚至产生 NPE。
因此：
构造方法中不要调用可能被子类重写的方法。

构造期间更适合调用：

- private 方法
- final 方法
- 静态方法
- 明确不会被重写的内部逻辑

继承初始化顺序下一章进一步展开。

## 10.6 不可变对象设计

不可变对象创建后状态不能再改变。
简单示例：

```java
public final class Money {
    private final BigDecimal amount;
    private final Currency currency;
    public Money(BigDecimal amount, Currency currency) {
        this.amount = Objects.requireNonNull(amount);
        this.currency = Objects.requireNonNull(currency);
    }
    public BigDecimal getAmount() {
        return amount;
    }
    public Currency getCurrency() {
        return currency;
    }
}
```

**10.6.1 常见设计原则**

不可变对象通常遵循：

- 1.类不允许被随意继承。
- 2.字段使用 private final 。
- 3.构造时完成全部初始化。
- 4.不提供修改状态的方法。
- 5.不暴露内部可变对象。
- 6.修改操作返回新对象。
- 7.构造时对可变入参防御性复制。

**10.6.2 final 字段不等于深度不可变**

```java
private final List<String> items;
```

只表示 items 引用不能重新赋值。
如果内部引用的是可变 ArrayList：

```
items.add("A");
```

仍然可以修改列表。
因此不可变对象需要：

```
this.items = List.copyOf(items);
```

并避免暴露可变元素。

**10.6.3 不可变对象的优势**

- 天然更容易线程安全
- 状态简单
- 便于缓存
- 便于作为 Map Key
- 更容易测试
- 没有中间非法状态
- 更适合函数式编程

代价：

- 修改时需要创建新对象
- 大对象复制可能有成本
- 复杂对象构建可能需要 Builder

## 10.7 贫血模型与充血模型

**10.7.1 贫血模型**

对象主要包含字段和 Getter/Setter：

```java
public class Order {
    private String orderNo;
    private OrderStatus status;
    public OrderStatus getStatus() {
        return status;
    }
    public void setStatus(OrderStatus status) {
        this.status = status;
    }
}
```

业务逻辑全部放在 Service：

```java
public void cancel(Order order) {
    if (order.getStatus() == OrderStatus.COMPLETED) {
        throw new IllegalStateException();
    }
    order.setStatus(OrderStatus.CANCELED);
}
```

特点：

- 数据与行为分离
- DTO、DO 常见
- 对简单 CRUD 友好
- 复杂业务下规则容易散落

**10.7.2 充血模型**

对象同时包含状态和领域行为：

```java
public class Order {
    private OrderStatus status;
    public void cancel() {
        if (status == OrderStatus.COMPLETED) {
            throw new IllegalStateException("已完成订单不能取消");
        }
        status = OrderStatus.CANCELED;
    }
}
```

特点：

- 业务规则集中
- 对象维护自身不变量
- 更贴近领域模型
- 复杂业务更易演进

**10.7.3 不必极端二选一**

实际项目可以按对象职责区分：

- 对象 推荐风格
- Request/Response DTO 数据承载为主
- MyBatis DO 数据映射为主
- 配置类 数据承载为主
- 核心领域对象 行为与状态结合
- 值对象 尽量不可变
- 复杂聚合根 维护业务不变量
- 核心不是追求形式，而是：

业务规则应该放在最能够保证一致性的位置。

## 10.8 静态工厂方法

除了直接调用构造方法，也可以使用静态工厂方法创建对象：

```java
public class Order {
    private final String orderNo;
    private OrderStatus status;
    private Order(String orderNo, OrderStatus status) {
        this.orderNo = orderNo;
        this.status = status;
    }
    public static Order create(String orderNo) {
        return new Order(orderNo, OrderStatus.CREATED);
    }
}
```

调用：

```
Order order = Order.create(orderNo);
```

**10.8.1 静态工厂方法的优势**

相较构造方法：

```
new Order(orderNo, OrderStatus.CREATED);
```

静态工厂方法可以：

- 使用有业务含义的名称
- 返回子类型
- 返回缓存对象
- 控制是否创建新对象
- 隐藏复杂构造过程
- 区分多个相同参数类型的创建方式
- 例如：

```
Order.create(orderNo);
Order.restore(orderNo, status);
Order.copyOf(source);
```

比多个相同类型参数的构造方法更清晰。

**10.8.2 静态工厂方法不是工厂模式本身**

- 方法名叫 create() 或 of() ，不代表使用了完整的工厂设计模式。
- 它首先是一种对象创建 API 设计方式。

## 10.9 Builder 模式的适用场景

当构造参数很多时：

```
new Order(
orderNo,
customerCode,
warehouseCode,
address,
phone,
priority,
urgent,
splitAllowed
);
```

可读性很差。
可以使用 Builder：

```
Order order = Order.builder()
.orderNo(orderNo)
.customerCode(customerCode)
.warehouseCode(warehouseCode)
.priority(Priority.HIGH)
.urgent(true)
.build();
```

适合：

- 参数较多
- 大量可选参数
- 需要分步骤构造
- 希望构造结果不可变
- 参数类型重复较多

不适合所有简单对象。
只有两个必填参数的对象使用复杂 Builder，可能反而增加代码量。

## 10.11 常见设计问题

**10.11.1 对象创建后处于非法状态**

```
Order order = new Order();
```

此时：

```
orderNo = null
status = null
items = null
```

需要依赖调用方按顺序设置字段，风险较高。

解决：

- 构造方法保证必填字段
- 静态工厂方法
- Builder
- 参数校验

**10.11.2 Setter 暴露全部状态**

```
setAvailableStock(-100);
setStatus(null);
setOrderNo("");
```

解决：

- 只暴露业务行为
- 限制 Setter 可见性
- 在构造时完成初始化
- 使用不可变值对象
- 方法内部维护状态转换规则

**10.11.3 返回内部集合**

```
public List<Item> getItems() {
return items;
}
```

解决：

```
return List.copyOf(items);
```

或者提供只读操作与受控修改方法。

**10.11.4 构造方法承担过多业务逻辑**

不推荐在构造方法中执行：

- 数据库查询
- 网络调用
- MQ 发送
- 文件读取
- 长时间计算
- 构造方法应主要完成：
- 参数校验
- 状态赋值
- 维护对象不变量
- 复杂创建流程可以放在：
- 静态工厂
- Factory
- Builder
- 应用服务

**10.11.5 方法名无法表达副作用**

不清晰：

```
order.process();
```

更明确：

```
order.allocateStock();
order.cancel();
order.complete();
```

对象行为应使用领域语言命名。

## 10.12 建议实验

实验一：构造器调用可重写方法的风险

```java
public class ConstructorOverrideDemo {
    public static void main(String[] args) {
        new Child();
    }
    static class Parent {
        Parent() {
            print();
        }
        void print() {
            System.out.println("Parent");
        }
    }
    static class Child extends Parent {
        private String name = "Java";
        @Override
        void print() {
            System.out.println(name);
        }
    }
}
```

可能输出：

```
null
```

用于说明父类构造期间，子类字段尚未完成初始化。

实验二：静态工厂返回缓存对象

```java
public final class Status {
    private static final Status ENABLED = new Status("ENABLED");
    private final String value;
    private Status(String value) { this.value = value; }
    public static Status enabled() { return ENABLED; }
}
```

验证：`Status.enabled() == Status.enabled()` 为 `true`，说明静态工厂不保证每次创建新对象。

实验三：Builder 的最终校验

```java
Order order = Order.builder()
    .orderNo(orderNo)
    .warehouseCode(warehouseCode)
    .build();
```

Builder 可以分步收集参数，但必须在 `build()` 中验证必填字段和业务约束。

实验四：final List 仍可修改

```java
import java.util.ArrayList;
import java.util.List;

public class Order {

    private final List<String> items = new ArrayList<>();

    public void addItem(String item) {
        items.add(item);
    }

    public static void main(String[] args) {
        Order order = new Order();
        order.addItem("A");
        System.out.println(order.items);
    }
}
```

`final` 只限制 `items` 引用不能重新赋值，不限制 `ArrayList` 自身内容发生变化。

`final` 只限制引用重新赋值，不限制修改对象内容。

实验五：构造器防御性复制

```java
public Order(List<String> items) {
    this.items = new ArrayList<>(items);
}
```

外部修改原集合后，对象内部状态不应变化。

实验六：Getter 防御性返回

```java
// 不可修改视图：仍可能观察到原集合后续变化
return Collections.unmodifiableList(items);

// 独立的不可修改快照
return List.copyOf(items);
```

`unmodifiableList` 返回视图，原集合修改仍可见；`List.copyOf` 创建独立快照。两者都不保证元素对象本身深度不可变。

实验七：不可变对象修改时返回新对象

```java
public Money add(Money other) {
    return new Money(this.amount.add(other.amount), this.currency);
}
```

不可变对象不修改自身状态，而是返回新对象。

## 10.14 易错点

**误区一：`final` 引用意味着对象深度不可变**

**错误。**

`final` 只限制引用不能重新赋值，内部对象仍可能可变。

**误区二：没有 Setter 的类一定不可变**

**错误。**

内部可变集合仍可能通过 Getter 泄露，实例方法也可能修改状态。

**误区三：静态工厂一定创建新对象**

**错误。**

它可以返回缓存、单例、子类型或已有实例。

**误区四：Builder 自动保证对象合法**

**错误。**

Builder 只是收集参数，必须在 `build()` 中执行最终校验。

**误区五：`Collections.unmodifiableList` 与原集合完全隔离**

**错误。**

它通常是不可修改视图，原集合改变仍可被观察。

**误区六：`List.copyOf` 保证元素对象深度不可变**

**错误。**

它只创建不可修改的列表快照，元素本身仍可能可变。

**误区七：聚合和组合完全等价**

**错误。**

二者代码形式可能相似，但生命周期和业务语义不同。

**误区八：所有业务逻辑都应该放在 Service**

**错误。**

与对象状态和不变量强相关的行为通常适合由领域对象维护。

**误区九：构造器逻辑越复杂越好**

**错误。**

构造器应主要完成参数校验、必要赋值和不变量建立，不应执行数据库、网络或长耗时操作。

## 10.15 工程实践建议

**10.15.1 对象创建完成后应立即可用**

避免：

```
Order order = new Order();
order.setOrderNo(orderNo);
order.setStatus(status);
order.setItems(items);
```

优先：

```
Order order = Order.create(orderNo, items);
```

**10.15.2 必填字段通过构造方法保证**

```
public Order(String orderNo, CustomerId customerId) {
this.orderNo = Objects.requireNonNull(orderNo);
this.customerId = Objects.requireNonNull(customerId);
}
```

可选字段再考虑 Builder 或明确行为。

**10.15.3 不要暴露无约束 Setter**

不推荐：

```
setStock(int stock);
setStatus(OrderStatus status);
```

推荐：

```
increaseStock(quantity);
deductStock(quantity);
cancel();
complete();
```

**10.15.4 返回集合时保护内部状态**

```
public List<OrderItem> getItems() {
return List.copyOf(items);
}
```

修改应通过对象方法完成：

```
order.addItem(item);
order.removeItem(itemId);
```

**10.15.5 默认使用最小访问权限**

优先顺序：

```
private
↓ 确有包内协作需求
package-private
↓ 确有继承扩展需求
protected
↓ 确有外部 API 需求
public
```

**10.15.6 DTO 与领域对象分开考虑**

不要机械要求所有对象都使用同一种风格：

```
DTO
→ 负责数据传输
DO
→ 负责数据库映射
领域对象
→ 负责业务状态和规则
VO
→ 表达无身份的业务值
```

对象设计应服务于其职责。

面试口述版：

- 对象之间的关系包括依赖、关联、聚合和组合，组合表示强生命周期绑定。对象不变量要求构造完成后对象立即处于合法状态，每次方法调用后仍保持合法。构造器中不应调用可重写方法，因为子类尚未完成初始化。贫血模型只有字段和 Getter/Setter，充血模型让对象自身维护业务规则。静态工厂方法可以隐藏创建细节、返回缓存对象或子类型。Builder 适合参数较多且可选参数多的场景，`build()` 必须执行最终校验。不可变对象通过 `final` 字段和防御性复制实现，修改时返回新对象而非改变自身状态。
