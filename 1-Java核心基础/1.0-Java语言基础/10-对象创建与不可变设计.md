# 第5章：对象创建与不可变设计

## 5.21 对象之间的关系

面向对象设计中，常见关系包括：
1 依赖
2 关联
3 聚合
4 组合
5 继承
6 实现
7
本章重点讨论普通对象关系，继承与实现后续展开。
### 5.21.1 依赖关系
一个类的方法临时使用另一个类：
1 public class OrderService {
2
3 public void create(Order order) {
4 }
5 }
6
OrderService 依赖 Order 。
依赖可能通过：
方法参数

局部变量
返回值
静态方法调用
产生。
### 5.21.2 关联关系
一个对象长期持有另一个对象引用：
1 public class Order {
2
3 private Customer customer;
4 }
5
Order 与 Customer 存在关联。
### 5.21.3 聚合关系
聚合表示较弱的整体与部分关系，部分可以脱离整体独立存在。
例如：
1 public class Team {
2
3 private List<Employee> members;
4 }
5
Employee 可以离开 Team 后继续存在。
### 5.21.4 组合关系
组合表示较强的整体与部分关系，部分生命周期通常由整体管理。
例如：
1 public class Order {
2
3 private final List<OrderItem> items = new ArrayList<>();
4 }
5
OrderItem 通常属于某个具体 Order，不应脱离订单独立存在。
代码层面聚合与组合都可能表现为字段引用，它们的区别主要来自业务语义和生命周期。

## 5.22 组合优于直接暴露数据

假设订单包含商品项。
不推荐：
1 public class Order {
2
3 public List<OrderItem> items = new ArrayList<>();
4 }

5
外部可以随意：
1 order.items.clear();
2 order.items.add(null);
3
更合理：
1 public class Order {
2
3 private final List<OrderItem> items = new ArrayList<>();
4
5 public void addItem(OrderItem item) {
6 Objects.requireNonNull(item, "item");
7
8 boolean duplicate = items.stream()
9 .anyMatch(existing -> existing.sameSku(item));
10
11 if (duplicate) {
12 throw new IllegalArgumentException("商品重复");
13 }
14
15 items.add(item);
16 }
17
18 public List<OrderItem> getItems() {
19 return List.copyOf(items);
20 }
21 }
22
这样 Order 自己管理内部组成。

## 5.23 对象不变量

对象不变量是：
对象在对外可观察的有效状态中必须始终满足的规则。
例如库存对象：
1 availableStock >= 0
2 lockedStock >= 0
3 totalStock = availableStock + lockedStock
4
订单对象：
1 订单号不能为空
2 订单项不能为空
3 已取消订单不能完成
4 已完成订单不能重新创建
5 总金额不能为负数

6
### 5.23.1 构造时保证初始合法
不推荐：
1 Order order = new Order();
2 order.setOrderNo(orderNo);
3 order.setStatus(OrderStatus.CREATED);
4 order.setItems(items);
5
在多个 Setter 调用之间，对象处于半初始化状态。
更合理：
1 Order order = new Order(orderNo, items);
2
构造方法内部完成校验：
1 public Order(String orderNo, List<OrderItem> items) {
2 if (orderNo == null || orderNo.isBlank()) {
3 throw new IllegalArgumentException("订单号不能为空");
4 }
5
6 if (items == null || items.isEmpty()) {
7 throw new IllegalArgumentException("订单项不能为空");
8 }
9
10 this.orderNo = orderNo;
11 this.items = new ArrayList<>(items);
12 this.status = OrderStatus.CREATED;
13 }
14
对象一旦创建完成，就处于合法状态。
### 5.23.2 每次行为执行后仍然合法
1 public void deduct(int quantity) {
2 if (quantity <= 0) {
3 throw new IllegalArgumentException("数量必须大于 0");
4 }
5
6 if (availableStock < quantity) {
7 throw new IllegalStateException("库存不足");
8 }
9
10 availableStock -= quantity;
11 }
12

执行后仍保证：
1 availableStock >= 0
2

## 5.24 构造方法中调用可重写方法的风险

下面的代码存在风险：
1 public class Parent {
2
3 public Parent() {
4 initialize();
5 }
6
7 protected void initialize() {
8 }
9 }
10
子类重写：
1 public class Child extends Parent {
2
3 private String name = "Java";
4
5 @Override
6 protected void initialize() {
7 System.out.println(name.length());
8 }
9 }
10
创建：
1 new Child();
2
父类构造方法执行时，子类字段可能尚未完成初始化。
但动态调用可能进入子类重写方法，导致读取未初始化字段，甚至产生 NPE。
因此：
构造方法中不要调用可能被子类重写的方法。
构造期间更适合调用：
private 方法
final 方法
静态方法
明确不会被重写的内部逻辑
继承初始化顺序下一章进一步展开。

## 5.25 不可变对象设计

不可变对象创建后状态不能再改变。

简单示例：
1 public final class Money {
2
3 private final BigDecimal amount;
4 private final Currency currency;
5
6 public Money(BigDecimal amount, Currency currency) {
7 this.amount = Objects.requireNonNull(amount);
8 this.currency = Objects.requireNonNull(currency);
9 }
10
11 public BigDecimal getAmount() {
12 return amount;
13 }
14
15 public Currency getCurrency() {
16 return currency;
17 }
18 }
19
### 5.25.1 常见设计原则
不可变对象通常遵循：
1.类不允许被随意继承。
2.字段使用 private final 。
3.构造时完成全部初始化。
4.不提供修改状态的方法。
5.不暴露内部可变对象。
6.修改操作返回新对象。
7.构造时对可变入参防御性复制。
### 5.25.2 final 字段不等于深度不可变
1 private final List<String> items;
2
只表示 items 引用不能重新赋值。
如果内部引用的是可变 ArrayList：
1 items.add("A");
2
仍然可以修改列表。
因此不可变对象需要：
1 this.items = List.copyOf(items);
2
并避免暴露可变元素。

### 5.25.3 不可变对象的优势
天然更容易线程安全
状态简单
便于缓存
便于作为 Map Key
更容易测试
没有中间非法状态
更适合函数式编程
代价：
修改时需要创建新对象
大对象复制可能有成本
复杂对象构建可能需要 Builder

## 5.26 贫血模型与充血模型

### 5.26.1 贫血模型
对象主要包含字段和 Getter/Setter：
1 public class Order {
2
3 private String orderNo;
4 private OrderStatus status;
5
6 public OrderStatus getStatus() {
7 return status;
8 }
9
10 public void setStatus(OrderStatus status) {
11 this.status = status;
12 }
13 }
14
业务逻辑全部放在 Service：
1 public void cancel(Order order) {
2 if (order.getStatus() == OrderStatus.COMPLETED) {
3 throw new IllegalStateException();
4 }
5
6 order.setStatus(OrderStatus.CANCELED);
7 }
8
特点：
数据与行为分离
DTO、DO 常见
对简单 CRUD 友好
复杂业务下规则容易散落
### 5.26.2 充血模型

对象同时包含状态和领域行为：
1 public class Order {
2
3 private OrderStatus status;
4
5 public void cancel() {
6 if (status == OrderStatus.COMPLETED) {
7 throw new IllegalStateException("已完成订单不能取消");
8 }
9
10 status = OrderStatus.CANCELED;
11 }
12 }
13
特点：
业务规则集中
对象维护自身不变量
更贴近领域模型
复杂业务更易演进
### 5.26.3 不必极端二选一
实际项目可以按对象职责区分：
对象 推荐风格
Request/Response DTO 数据承载为主
MyBatis DO 数据映射为主
配置类 数据承载为主
核心领域对象 行为与状态结合
值对象 尽量不可变
复杂聚合根 维护业务不变量
核心不是追求形式，而是：
业务规则应该放在最能够保证一致性的位置。

## 5.27 静态工厂方法

除了直接调用构造方法，也可以使用静态工厂方法创建对象：
1 public class Order {
2
3 private final String orderNo;
4 private OrderStatus status;
5
6 private Order(String orderNo, OrderStatus status) {
7 this.orderNo = orderNo;
8 this.status = status;
9 }
10
11 public static Order create(String orderNo) {
12 return new Order(orderNo, OrderStatus.CREATED);
13 }

14 }
15
调用：
1 Order order = Order.create(orderNo);
2
### 5.27.1 静态工厂方法的优势
相较构造方法：
1 new Order(orderNo, OrderStatus.CREATED);
2
静态工厂方法可以：
使用有业务含义的名称
返回子类型
返回缓存对象
控制是否创建新对象
隐藏复杂构造过程
区分多个相同参数类型的创建方式
例如：
1 Order.create(orderNo);
2 Order.restore(orderNo, status);
3 Order.copyOf(source);
4
比多个相同类型参数的构造方法更清晰。
### 5.27.2 静态工厂方法不是工厂模式本身
方法名叫 create() 或 of() ，不代表使用了完整的工厂设计模式。
它首先是一种对象创建 API 设计方式。

## 5.28 Builder 模式的适用场景

当构造参数很多时：
1 new Order(
2 orderNo,
3 customerCode,
4 warehouseCode,
5 address,
6 phone,
7 priority,
8 urgent,
9 splitAllowed
10 );

11
可读性很差。
可以使用 Builder：
1 Order order = Order.builder()
2 .orderNo(orderNo)
3 .customerCode(customerCode)
4 .warehouseCode(warehouseCode)
5 .priority(Priority.HIGH)

8

不适合所有简单对象。
只有两个必填参数的对象使用复杂 Builder，可能反而增加代码量。

## 5.30 常见设计问题

### 5.30.1 对象创建后处于非法状态
1 Order order = new Order();
2
此时：

1 orderNo = null
2 status = null
3 items = null
4
需要依赖调用方按顺序设置字段，风险较高。
解决：
构造方法保证必填字段
静态工厂方法
Builder
参数校验
### 5.30.2 Setter 暴露全部状态
1 setAvailableStock(-100);
2 setStatus(null);
3 setOrderNo("");
4
解决：
只暴露业务行为
限制 Setter 可见性
在构造时完成初始化
使用不可变值对象
方法内部维护状态转换规则
### 5.30.3 返回内部集合
1 public List<Item> getItems() {
2 return items;
3 }
4
解决：
1 return List.copyOf(items);
2
或者提供只读操作与受控修改方法。
### 5.30.4 构造方法承担过多业务逻辑
不推荐在构造方法中执行：
数据库查询
网络调用
MQ 发送
文件读取
长时间计算
构造方法应主要完成：

参数校验
状态赋值
维护对象不变量
复杂创建流程可以放在：
静态工厂
Factory
Builder
应用服务
### 5.30.5 方法名无法表达副作用
不清晰：
1 order.process();
2
更明确：
1 order.allocateStock();
2 order.cancel();
3 order.complete();
4
对象行为应使用领域语言命名。

## 5.33 易错点

误区一：类就是对象
错误。
类是类型定义，对象是运行时实例。
误区二：引用变量中保存整个对象
错误。
引用变量保存引用值，对象是独立的运行时实体。
误区三：每个类只能创建一个对象
错误。
普通类可以创建任意多个实例。
误区四：字段和局部变量都有默认值
错误。
实例字段和静态字段有默认值，局部变量必须满足确定赋值规则。
误区五：构造方法有 void 返回类型
错误。
写了 void 就是普通方法，不是构造方法。
误区六：编译器永远会生成无参构造方法

错误。
只有类没有显式声明任何构造方法时，才会生成默认构造方法。
误区七：默认构造方法一定是 public
错误。
其访问权限通常与类的访问权限一致。
误区八：封装就是字段私有化并生成 Getter/Setter
不完整。
真正的封装还包括：
控制状态修改
隐藏实现
维护对象不变量
限制可见性
防止内部可变对象泄漏
误区九：private 字段不能被其他对象访问
不准确。
同一个类内部可以访问另一个同类对象的 private 字段。
误区十：protected 对所有子类对象都等同于 public
错误。
跨包子类访问 protected 成员受到继承关系和引用类型限制。
误区十一：final 引用字段代表对象完全不可变
错误。
final 只限制引用不能重新赋值，内部对象仍可能可变。
误区十二：静态工厂方法一定会创建新对象
错误。
静态工厂方法可以：
创建新对象
返回缓存对象
返回单例
返回子类型
返回已有对象
误区十三：构造方法越复杂越好
错误。
构造方法应主要完成必要初始化和不变量校验，不宜执行外部 IO 或复杂业务流程。
误区十四：所有业务逻辑都应该放在 Service
不一定。
与对象状态和不变量强相关的业务行为，通常更适合放在领域对象中。

## 5.34 工程实践建议

### 5.34.1 对象创建完成后应立即可用

避免：
1 Order order = new Order();
2 order.setOrderNo(orderNo);
3 order.setStatus(status);
4 order.setItems(items);
5
优先：
1 Order order = Order.create(orderNo, items);
2
### 5.34.2 必填字段通过构造方法保证
1 public Order(String orderNo, CustomerId customerId) {
2 this.orderNo = Objects.requireNonNull(orderNo);
3 this.customerId = Objects.requireNonNull(customerId);
4 }
5
可选字段再考虑 Builder 或明确行为。
### 5.34.3 不要暴露无约束 Setter
不推荐：
1 setStock(int stock);
2 setStatus(OrderStatus status);
3
推荐：
1 increaseStock(quantity);
2 deductStock(quantity);
3 cancel();
4 complete();
5
### 5.34.4 返回集合时保护内部状态
1 public List<OrderItem> getItems() {
2 return List.copyOf(items);
3 }
4
修改应通过对象方法完成：

1 order.addItem(item);
2 order.removeItem(itemId);
3
### 5.34.5 默认使用最小访问权限
优先顺序：
1 private
2 ↓ 确有包内协作需求
3 package-private
4 ↓ 确有继承扩展需求
5 protected
6 ↓ 确有外部 API 需求
7 public
8
### 5.34.6 DTO 与领域对象分开考虑
不要机械要求所有对象都使用同一种风格：
1 DTO
2 → 负责数据传输
3
4 DO
5 → 负责数据库映射
6
7 领域对象
8 → 负责业务状态和规则
9
10 VO
11 → 表达无身份的业务值
12
对象设计应服务于其职责。

面试口述版：
类是对一类事物状态和行为的抽象，对象是类在运行时创建出的实例。引用变量保存的是对象引用值，而不是对象本身。对象创建时，实例字段会先获得默认值，然后
按源码顺序执行字段初始化表达式和实例代码块，最后执行构造方法。构造方法用于建立对象的初始合法状态，如果类没有显式声明任何构造方法，编译器才会生成默
认无参构造方法。封装不只是字段私有化和生成 Getter、Setter，更重要的是隐藏内部实现、限制状态修改入口并维护对象不变量。复杂业务对象应优先暴露 cancel、
deduct、complete 这类业务行为，而不是让外部通过 Setter 任意修改状态。
