# 多态与动态绑定

## 12.1 本章定位

本章覆盖方法重写规则、多态和动态绑定，解决以下问题：

- 方法重写需要满足哪些规则？
- @Override 注解的作用是什么？
- 重载和重写有什么本质区别？
- 编译时类型和运行时类型分别是什么？
- 动态绑定是如何工作的？
- 字段是否具有多态性？
- 静态方法能否被重写？
- 向上转型和向下转型分别是什么？
- instanceof 模式匹配解决了什么问题？
- 里氏替换原则是什么？
- 多态在工程中有什么价值？

## 12.2 方法重写

方法重写是指：
子类对父类已经存在的可继承实例方法提供新的实现。
父类：

```java
public class Animal {
    public void speak() {
        System.out.println("Animal sound");
    }
}
```

子类：

```java
public class Dog extends Animal {
    @Override
    public void speak() {
        System.out.println("Dog bark");
    }
}
```

调用：

```
Dog dog = new Dog();
dog.speak();
```

输出：

```
Dog bark
```

## 12.3 @Override 注解

建议所有重写方法都添加：

```java
@Override
```

例如：

```java
@Override
public void speak() {
}
```

作用：

- 编译器检查是否真的重写了父类方法
- 防止参数写错
- 防止方法名写错
- 明确表达设计意图
- 提高代码可读性
- 错误示例：

```java
public class Child extends Parent {
    @Override
    public void excute() {
    }
}
```

如果父类方法叫：

```
execute()
```

编译器会直接报错。
如果不写 @Override ，可能意外定义成一个全新方法。

## 12.4 重写规则

方法重写需要满足若干规则。

**12.4.1 方法名和参数列表必须相同**

父类：

```java
public void execute(String value) {
}
```

子类：

```java
@Override
public void execute(String value) {
}
```

参数类型、数量、顺序必须一致。
如果写成：

```java
public void execute(Object value) {
}
```

这不是重写，而是新增了一个重载方法。

**12.4.2 返回类型必须兼容**

父类：

```
public Animal create() {
return new Animal();
}
```

子类可以返回更具体的类型：

```java
@Override
public Dog create() {
    return new Dog();
}
```

这称为协变返回类型。
允许：

```
父类返回 Animal
子类返回 Dog
```

因为 Dog 是 Animal 的子类。
不允许返回无关类型：

```java
@Override
public String create() {
}
```

**12.4.3 访问权限不能缩小**

父类：

```java
protected void execute() {
}
```

子类可以扩大为：

```java
@Override
public void execute() {
}
```

但不能缩小为：

```java
@Override
private void execute() {
}
```

访问权限关系：

```
private
<
默认
<
protected
<
public
```

重写时权限只能保持或扩大，不能缩小。
原因：
子类对象必须能够替代父类对象，不能让父类原本可访问的方法在子类中变得不可访问。

**12.4.4 受检异常不能扩大**

父类：

```java
public void execute() throws IOException {
}
```

子类可以：

```java
@Override
public void execute() {
}
```

也可以：

```java
@Override
public void execute() throws FileNotFoundException {
}
```

因为 FileNotFoundException 是 IOException 的子类。
但不能：

```java
@Override
public void execute() throws Exception {
}
```

因为 Exception 范围更宽。

规则：

- 子类重写方法不能声明比父类更宽的受检异常。
- 但非受检异常 RuntimeException 不受该限制。

**12.4.5 final 方法不能重写**

父类：

```java
public final void execute() {
}
```

子类不能：

```java
@Override
public void execute() {
}
```

因为 final 表示该行为不允许子类改变。

**12.4.6 private 方法不能被重写**

父类：

```java
private void execute() {
}
```

子类即使定义同名方法：

```java
public void execute() {
}
```

也不是重写。
因为父类 private 方法对子类不可见。
这两个方法是彼此独立的方法。

**12.4.7 static 方法不是重写**

父类：

```java
public static void execute() {
    System.out.println("Parent");
}
```

子类：

```java
public static void execute() {
    System.out.println("Child");
}
```

这种情况称为：

```
静态方法隐藏
```

而不是实例方法重写。
静态方法根据引用的编译时类型决定调用哪个方法，不具有运行时多态。

## 12.5 重载与重写

重载与重写容易混淆，但本质完全不同。

| 维度 | 重载 | 重写 |
|---|---|---|
| 英文 | Overload | Override |
| 发生位置 | 同一类或继承体系 | 父子类 |
| 方法名 | 相同 | 相同 |
| 参数列表 | 必须不同 | 必须相同 |
| 返回类型 | 不能单独区分 | 可协变 |
| 访问权限 | 无特殊要求 | 不能缩小 |
| 异常 | 独立声明 | 受检异常不能扩大 |
| 绑定阶段 | 编译期 | 运行期 |
| 本质 | 同名不同参数 | 子类替换父类行为 |

**12.5.1 重载是编译期选择**

```java
public void print(Animal animal) {
    System.out.println("Animal");
}
public void print(Dog dog) {
    System.out.println("Dog");
}
```

调用：

```
Animal animal = new Dog();
print(animal);
```

输出：

```
Animal
```

因为重载根据变量的编译时类型选择。
animal 的编译时类型是 Animal 。

**12.5.2 重写是运行期选择**

父类：

```java
public class Animal {
    public void speak() {
        System.out.println("Animal");
    }
}
```

子类：

```java
public class Dog extends Animal {
    @Override
    public void speak() {
        System.out.println("Dog");
    }
}
```

调用：

```
Animal animal = new Dog();
animal.speak();
```

输出：

```
Dog
```

因为重写方法根据实际对象类型选择。

## 12.6 多态

多态表示：
同一个父类型引用，在指向不同子类对象时，可以表现出不同的运行时行为。
例如：

```
Animal animal1 = new Dog();
Animal animal2 = new Cat();
animal1.speak();
animal2.speak();
```

输出：

```
Dog bark
Cat meow
```

调用形式相同：

```
animal.speak();
```

但实际行为由运行时对象决定。

**12.6.1 多态成立的条件**

通常需要：

- 1.存在继承或接口实现关系
- 2.父类或接口引用指向子类对象
- 3.子类重写父类实例方法
- 4.通过父类型引用调用重写方法
- 例如：

```
Animal animal = new Dog();
animal.speak();
```

**12.6.2 编译时类型与运行时类型**

```
Animal animal = new Dog();
```

这里存在两种类型：

```
编译时类型：Animal
运行时类型：Dog
```

编译时类型决定：

- 能访问哪些成员
- 方法调用是否通过编译
- 重载方法如何选择
- 字段访问绑定到哪个声明
- 运行时类型决定：
- 实际执行哪个重写实例方法
- 核心口诀：

能调用什么，看编译时类型；实际执行哪个重写方法，看运行时类型。

## 12.7 父类引用指向子类对象

```
Animal animal = new Dog();
```

这是合法的，因为：

```
Dog 是一种 Animal
```

这种转换称为向上转型。

向上转型可以：

- 自动完成
- 不需要强制转换
- 保留对象实际类型
- 隐藏子类特有成员
- 为多态提供基础

**12.7.1 向上转型不会改变对象**

```
Dog dog = new Dog();
Animal animal = dog;
```

并没有创建新的 Animal 对象。
关系是：

```bash
dog ─────┐
├────→ 同一个 Dog 对象
animal ─────┘
```

只是增加了一个父类型引用。

**12.7.2 父类引用不能直接访问子类特有方法**

```java
public class Dog extends Animal {
    public void fetch() {
    }
}
```

调用：

```
Animal animal = new Dog();
animal.fetch();
```

编译失败。
因为 animal 的编译时类型是 Animal ，而 Animal 没有声明 fetch() 。
即使运行时对象确实是 Dog，编译器也只根据静态类型检查可访问成员。

## 12.8 动态绑定

动态绑定是多态的核心机制。
对于重写的实例方法：

```
animal.speak();
```

JVM 会根据对象的实际类型决定执行哪个实现。
可以抽象为：

```
编译阶段
↓
确认 Animal 类型存在 speak()
↓
程序运行
↓
发现实际对象是 Dog
↓
执行 Dog.speak()
```

因此重写方法调用又称：
动态绑定
后期绑定
运行时绑定

**12.8.1 哪些成员具有动态绑定**

通常具有动态绑定的是：

```
可重写的实例方法
```

不具有动态绑定的主要包括：

- 字段
- 静态方法
- private 方法
- final 方法
- 构造方法

这些内容要分别理解。

## 12.9 字段没有多态性

父类：

```java
public class Parent {
    public String name = "Parent";
}
```

子类：

```java
public class Child extends Parent {
    public String name = "Child";
}
```

调用：

```java
Parent value = new Child();
System.out.println(value.name);
```

输出：

```
Parent
```

因为字段访问根据引用的编译时类型确定。

**12.9.1 方法与字段对比**

```java
public class Parent {
    public String name = "Parent";
    public String getName() {
        return "Parent";
    }
}
public class Child extends Parent {
    public String name = "Child";
    @Override
    public String getName() {
        return "Child";
    }
}
```

调用：

```java
Parent value = new Child();
System.out.println(value.name);
System.out.println(value.getName());
```

输出：

```
Parent
Child
```

原因：

```
字段访问
→ 看编译时类型 Parent
实例方法调用
→ 看运行时类型 Child
```

**12.9.2 字段隐藏不是重写**

子类定义同名字段：

```
public String name = "Child";
```

不会替换父类字段。
对象中可能同时存在：

```
Parent.name
Child.name
```

这两个字段分别属于父类部分和子类部分。
实际开发中应尽量避免父子类定义同名字段，因为容易引起误解。

## 12.10 静态方法没有运行时多态

父类：

```java
public class Parent {
    public static void print() {
        System.out.println("Parent");
    }
}
```

子类：

```java
public class Child extends Parent {
    public static void print() {
        System.out.println("Child");
    }
}
```

调用：

```
Parent value = new Child();
value.print();
```

输出：

```
Parent
```

因为静态方法根据引用编译时类型绑定。
更推荐写成：

```
Parent.print();
```

而不是通过对象引用调用静态方法。

**12.10.1 静态方法隐藏**

子类声明与父类相同签名的静态方法称为隐藏：

```
Parent.print()
Child.print()
```

它们属于两个类。
不存在运行时根据对象类型动态选择的过程。

## 12.11 private 与 final 方法的调用

**12.11.1 private 方法**

- private 方法对子类不可见，因此不存在重写。
- 父类内部调用 private 方法时，调用目标固定为父类自己的实现。

**12.11.2 final 方法**

- final 方法允许子类继承和调用，但不允许重写。
- 因此调用目标也是确定的。

final 方法可用于：

- 固定核心算法步骤
- 保护不变量
- 防止子类改变关键安全逻辑
- 保证模板流程中的固定部分

但不应为了所谓性能优化而机械添加 final 。
现代 JVM 可以自行进行内联和去虚拟化优化。

## 12.12 向下转型

向上转型后，如果需要重新访问子类特有能力，可以向下转型：

```
Animal animal = new Dog();
Dog dog = (Dog) animal;
dog.fetch();
```

这种转换称为向下转型。

**12.12.1 向下转型需要显式转换**

```
Dog dog = animal;
```

编译失败。
必须写：

```
Dog dog = (Dog) animal;
```

因为父类引用可能指向很多不同子类对象，编译器无法保证它一定是 Dog。

**12.12.2 向下转型不会创建新对象**

```
Animal animal = new Dog();
Dog dog = (Dog) animal;
```

animal 和 dog 指向同一个对象：

```bash
animal ─────┐
├────→ Dog 对象
dog ─────┘
```

转换只是改变引用变量的静态类型视角，不复制对象。

## 12.13 ClassCastException

错误向下转型会抛出：

```
ClassCastException
```

例如：

```
Animal animal = new Cat();
Dog dog = (Dog) animal;
```

编译可以通过，但运行时失败。
因为：

```
animal 实际指向 Cat
不能转换为 Dog
```

**12.13.1 编译通过不代表运行安全**

只要两个类型存在可能的继承关系，编译器可能允许强制转换：

```
Animal animal = getAnimal();
Dog dog = (Dog) animal;
```

但最终是否成功取决于运行时对象。

**12.13.2 完全无关类型通常编译失败**

```
String value = "Java";
Dog dog = (Dog) value;
```

通常编译器会判断二者不可能存在合法转换关系，因此直接拒绝。

## 12.14 instanceof

向下转型前可以使用 instanceof 判断：

```
if (animal instanceof Dog) {
Dog dog = (Dog) animal;
dog.fetch();
}
```

instanceof 判断：
当前引用所指向的对象，是否属于指定类型或其子类型。

**12.14.1 null instanceof**

```java
Animal animal = null;
System.out.println(animal instanceof Dog);
```

输出：

```
false
```

不会抛出异常。

**12.14.2 模式匹配**

现代 Java 支持：

```
if (animal instanceof Dog dog) {
dog.fetch();
}
```

相比传统写法：

```
if (animal instanceof Dog) {
Dog dog = (Dog) animal;
}
```

模式匹配减少了重复强转。

**12.14.3 模式变量作用域**

```java
if (value instanceof String text) {
System.out.println(text.length());
}
```

text 只在编译器能够确定类型判断成立的作用域内可用。
例如：

```java
if (!(value instanceof String text)) {
return;
}
System.out.println(text.length());
```

这里 return 保证后续代码执行时判断一定成立，因此 text 可用。

## 12.15 多态的工程价值

多态的价值不是为了展示语法，而是为了：

- 面向抽象编程
- 降低调用方与具体实现的耦合
- 扩展新实现时减少修改
- 支持策略替换
- 支持框架扩展点
- 支持统一处理不同子类型

**12.15.1 不使用多态**

```java
public void process(String type) {
    if ("ALIPAY".equals(type)) {
        processAlipay();
    } else if ("WECHAT".equals(type)) {
        processWechat();
    } else if ("BANK".equals(type)) {
        processBank();
    }
}
```

随着类型增加，条件分支不断扩大。

**12.15.2 使用多态**

定义父类：

```java
public abstract class PaymentProcessor {
    public abstract void process();
}
```

具体实现：

```java
public class AlipayProcessor extends PaymentProcessor {
    @Override
    public void process() {
        System.out.println("支付宝支付");
    }
}
public class WechatProcessor extends PaymentProcessor {
    @Override
    public void process() {
        System.out.println("微信支付");
    }
}
```

调用方：

```java
public void execute(PaymentProcessor processor) {
    processor.process();
}
```

调用方不关心具体实现。
新增银行卡支付时，只需增加新实现。
接口和抽象类的选择下一章展开。

## 12.16 多态与集合

可以使用父类型集合统一保存不同子类：

```
List<Animal> animals = List.of(
new Dog(),
new Cat(),
new Bird()
);
```

遍历：

```
for (Animal animal : animals) {
animal.speak();
}
```

每个对象执行各自实现。
这体现了多态的统一处理能力。

## 12.17 多态与参数设计

方法参数使用父类型：

```java
public void feed(Animal animal) {
    animal.eat();
}
```

可以接收：

```
feed(new Dog());
feed(new Cat());
feed(new Bird());
```

相比：

```
feedDog(Dog dog);
feedCat(Cat cat);
feedBird(Bird bird);
```

父类型参数具有更好的扩展性。

设计原则：

- 方法参数应尽量依赖调用所需的最小抽象，而不是具体实现。
- 后续接口章节会进一步讨论依赖抽象。

## 12.18 多态与返回值

方法也可以返回父类型：

```
public Animal create(String type) {
return switch (type) {
case "DOG" -> new Dog();
case "CAT" -> new Cat();
default -> throw new IllegalArgumentException();
};
}
```

调用方：

```
Animal animal = create("DOG");
animal.speak();
```

这种方式隐藏了具体对象创建细节。
静态工厂、工厂模式和依赖注入都大量使用这种思想。

## 12.19 建议实验

实验一：重写方法的运行时绑定

```java
public class Animal {
    public void speak() { System.out.println("Animal"); }
}

public class Dog extends Animal {
    @Override
    public void speak() { System.out.println("Dog"); }

    public static void main(String[] args) {
        Animal animal = new Dog();
        animal.speak();
    }
}
```

观察输出是否为 `Dog`，理解运行时类型决定执行实现。

实验二：字段没有多态性

```java
public class Parent {
    public String name = "Parent";
    public String getName() { return "Parent"; }
}

public class Child extends Parent {
    public String name = "Child";
    @Override
    public String getName() { return "Child"; }

    public static void main(String[] args) {
        Parent value = new Child();
        System.out.println(value.name);
        System.out.println(value.getName());
    }
}
```

验证字段访问看编译时类型、方法调用看运行时类型。

实验三：静态方法隐藏

```java
public class Parent {
    public static void print() { System.out.println("Parent"); }
}

public class Child extends Parent {
    public static void print() { System.out.println("Child"); }

    public static void main(String[] args) {
        Parent value = new Child();
        value.print();
        Parent.print();
        Child.print();
    }
}
```

观察静态方法根据引用类型绑定，没有运行时多态。

实验四：向下转型与 ClassCastException

```java
public class Animal {}
public class Dog extends Animal { public void fetch() {} }
public class Cat extends Animal {}

public class Demo {
    public static void main(String[] args) {
        Animal animal = new Cat();
        // Dog dog = (Dog) animal; // 运行时 ClassCastException
        if (animal instanceof Dog dog) {
            dog.fetch();
        }
    }
}
```

观察错误强转抛出的异常，以及 `instanceof` 模式匹配如何安全转型。

实验五：多态与集合

```java
import java.util.List;

public class Demo {
    public static void main(String[] args) {
        List<Animal> animals = List.of(new Dog(), new Cat());
        for (Animal animal : animals) {
            animal.speak();
        }
    }
}
```

验证父类型集合统一处理不同子类对象。

实验六：父类构造中调用重写方法

```java
public class Parent {
    public Parent() { print(); }
    protected void print() { System.out.println("Parent"); }
}

public class Child extends Parent {
    private String name = "Java";
    @Override
    protected void print() { System.out.println(name); }

    public static void main(String[] args) { new Child(); }
}
```

观察是否输出 `null`，理解动态绑定在构造阶段引发的风险。

## 12.21 易错点

**误区一：重写就是方法名相同**

**错误。**

重写要求方法名和参数列表都相同。方法名相同但参数列表不同属于重载，不属于重写。

**误区二：重写时返回类型必须完全相同**

**错误。**

重写允许协变返回类型，子类可以返回父类返回类型的子类型，例如父类返回 `Animal`，子类可以返回 `Dog`。

**误区三：重写时可以抛出任意异常**

**错误。**

受检异常不能比父类更宽。非受检异常（`RuntimeException`）不受此限制。

**误区四：子类定义与父类同签名的 static 方法是重写**

**错误。**

静态方法不存在运行时多态，同签名静态方法属于"隐藏"，调用哪个方法根据引用的编译时类型决定。

**误区五：字段也具有多态性**

**错误。**

字段访问根据引用的编译时类型绑定，没有运行时多态。父子类同名字段是两个独立字段，称为字段隐藏。

**误区六：向上转型会创建新的父类对象**

**错误。**

向上转型只是改变引用的静态类型视角，对象本身不变，仍指向原对象。

**误区七：向下转型总是安全**

**错误。**

只有当引用指向的对象确实是目标类型或其子类型时才能成功，否则运行时抛出 `ClassCastException`。应先用 `instanceof` 判断。

**误区八：`instanceof` 对 null 会抛异常**

**错误。**

`null instanceof 任何类型` 结果都是 `false`，不会抛出空指针异常。

## 12.22 本章总结

```
方法重写：子类替换父类实例方法实现
↓
重写规则：方法名参数相同、返回兼容、权限不缩小、受检异常不扩大
↓
重载是编译期选择，重写是运行期选择
↓
多态：父类型引用指向不同子类对象表现不同行为
↓
动态绑定：实例方法看运行时类型，字段和静态方法看编译时类型
↓
向上转型自动，向下转型需显式并校验
↓
instanceof 模式匹配简化安全转型
↓
多态支撑面向抽象编程与扩展性
```

面试口述版：

- 方法重写是子类对父类可继承实例方法提供新实现，要求方法名和参数列表相同、返回类型兼容、访问权限不能缩小、受检异常不能扩大，`final`、`private`、`static` 方法不能被重写。重载是编译期根据参数类型选择方法，重写是运行期根据对象实际类型选择实现。多态的前提是继承或实现、父类型引用指向子类对象、子类重写父类方法、通过父类型引用调用。动态绑定只对可重写实例方法生效，字段、静态方法、`private` 和 `final` 方法没有运行时多态。向上转型自动完成且不改变对象，向下转型需要显式强转，类型不匹配会抛 `ClassCastException`，可用 `instanceof` 模式匹配安全转型。多态的价值是面向抽象编程、降低调用方与实现的耦合、支持扩展新实现时减少修改。
