## 12.2 多态是什么

多态表示：

> 同一个抽象类型的引用，可以指向不同具体类型的对象；调用同一个实例方法时，可以执行不同具体实现。

```java
Animal animal = new Dog();

animal.speak();
```

如果 `Dog` 重写了 `speak()`：

```text
引用类型
→ Animal

运行时对象
→ Dog

实际执行
→ Dog.speak()
```

### 12.2.1 多态的三个基础条件

常见运行时多态需要：

1. 存在继承或接口实现关系；
2. 子类重写实例方法；
3. 父类型或接口引用指向子类型对象。

### 12.2.2 多态的主要价值

- 调用方依赖抽象；
- 隔离具体实现；
- 支持新增实现；
- 降低条件分支；
- 便于替换和测试；
- 形成插件式扩展；
- 支持统一集合和统一处理流程。

### 12.2.3 多态不是“任何同名方法自动选择”

Java 多态只针对满足重写关系的实例方法。

以下成员不按同样方式动态分派：

- 字段；
- 静态方法；
- `private` 方法；
- 构造器；
- 重载方法集合本身。

## 12.3 编译时类型与运行时类型

```java
Animal animal = new Dog();
```

这里有两个不同概念：

```text
编译时类型
→ Animal

运行时类型
→ Dog
```

### 12.3.1 编译时类型决定什么

编译器根据 `Animal` 判断：

- 当前表达式能访问哪些成员；
- 哪些重载方法可参与候选；
- 是否需要强制类型转换；
- 赋值是否兼容；
- 返回值如何检查；
- 泛型类型约束。

### 12.3.2 运行时类型决定什么

对可重写实例方法：

- 最终执行哪个重写实现。

### 12.3.3 两者必须同时理解

多态调用不是单纯“运行时决定一切”。

更准确的流程：

```text
编译期
→ 先根据静态类型确认调用是否合法
→ 选择方法签名

运行期
→ 对该实例方法签名进行动态绑定
→ 选择实际实现
```

## 12.4 引用类型限制可见能力

父类：

```java
public class Animal {

    public void speak() {
    }
}
```

子类：

```java
public class Dog extends Animal {

    public void fetch() {
    }
}
```

调用：

```java
Animal animal = new Dog();

animal.speak();

// animal.fetch(); // 编译错误
```

### 12.4.1 对象具有能力，不代表引用可直接访问

运行时对象确实是 `Dog`，但变量的编译时类型是 `Animal`。

编译器只保证：

```text
所有 Animal 对象
都具有 Animal 声明的能力
```

不能假设所有 `Animal` 都有 `fetch()`。

### 12.4.2 这是类型安全边界

父类型引用只暴露父类型契约。

这正是依赖抽象的基础。

## 12.5 向上转型

把子类型引用赋给父类型或接口类型，称为向上转型。

```java
Dog dog = new Dog();

Animal animal = dog;
```

或者：

```java
Animal animal = new Dog();
```

### 12.5.1 通常自动完成

因为：

```text
Dog is an Animal
```

不需要显式强制转换。

### 12.5.2 不创建新对象

```java
Dog dog = new Dog();
Animal animal = dog;
```

`dog` 和 `animal` 保存的引用值指向同一个对象。

### 12.5.3 不丢失运行时类型

对象仍然是 `Dog`。

变化的是：

```text
通过该引用能直接使用的编译时能力范围
```

### 12.5.4 向上转型的价值

- 隐藏实现细节；
- 使用统一抽象；
- 放入父类型集合；
- 注入接口依赖；
- 运行时替换实现。

---

## 12.6 多级向上转型

```java
class Animal {
}

class Mammal extends Animal {
}

class Dog extends Mammal {
}
```

```java
Dog dog = new Dog();

Mammal mammal = dog;
Animal animal = dog;
Object object = dog;
```

都合法。

### 12.6.1 引用层次越高，可见成员越少

```text
Dog 引用
→ Dog + Mammal + Animal + Object 的可访问成员

Animal 引用
→ Animal + Object 的可访问成员

Object 引用
→ Object 的可访问成员
```

重写实例方法仍可能进入 `Dog` 实现。

### 12.6.2 不需要逐层显式转换

编译器可以识别继承链。

---

## 12.7 向下转型

把父类型引用转换为更具体子类型，称为向下转型。

```java
Animal animal = new Dog();

Dog dog = (Dog) animal;
```

### 12.7.1 必须显式转换

因为不是所有 `Animal` 都是 `Dog`。

### 12.7.2 转换成功条件

运行时对象必须是：

- 目标类型实例；
- 或目标类型子类型实例；
- 或引用值为 `null`。

### 12.7.3 转换不创建新对象

```java
Dog dog = (Dog) animal;
```

只是让新的引用变量以 `Dog` 类型访问同一个对象。

### 12.7.4 转换不改变对象

对象运行时类型在转换前后都没有改变。

---

## 12.8 ClassCastException

```java
Animal animal = new Cat();

Dog dog = (Dog) animal;
```

代码可以编译，因为编译时存在可能的继承关系。

运行时发现实际对象是 `Cat`，不是 `Dog`，抛出：

```text
ClassCastException
```

### 12.8.1 编译错误与运行时错误

完全无关类型：

```java
String text = "Java";

// Integer value = (Integer) text;
// 编译错误
```

存在类型关系但实际对象不匹配：

```java
Animal animal = new Cat();

Dog dog = (Dog) animal;
// 运行时异常
```

### 12.8.2 频繁强转是设计信号

大量：

```java
if (value instanceof TypeA) {
} else if (value instanceof TypeB) {
}
```

可能说明：

- 抽象能力不足；
- 父类型缺少行为；
- 调用方依赖具体实现；
- 需要策略或模式匹配；
- 外部数据模型尚未规范化。

## 12.9 instanceof

```java
if (animal instanceof Dog) {
    Dog dog = (Dog) animal;
    dog.fetch();
}
```

`instanceof` 用于检查：

```text
对象是否是指定类型或其子类型的实例
```

### 12.9.1 null 的结果

```java
Animal animal = null;

System.out.println(
        animal instanceof Dog
); // false
```

不会抛出 `NullPointerException`。

### 12.9.2 接口检查

```java
if (value instanceof AutoCloseable) {
}
```

对象只要实现该接口即可。

### 12.9.3 数组检查

```java
Object value = new String[0];

System.out.println(
        value instanceof String[]
); // true
```

## 12.10 instanceof 模式匹配

现代 Java 可以直接绑定模式变量：

```java
if (animal instanceof Dog dog) {
    dog.fetch();
}
```

同时完成：

- 类型判断；
- 安全转换；
- 局部变量声明。

### 12.10.1 避免重复强转

传统写法：

```java
if (value instanceof String) {
    String text = (String) value;
    System.out.println(text.length());
}
```

模式写法：

```java
if (value instanceof String text) {
    System.out.println(text.length());
}
```

### 12.10.2 模式变量类型明确

```java
text
```

在匹配成功路径中是 `String`。

---

## 12.11 模式变量的流作用域

```java
if (!(value instanceof String text)) {
    return;
}

System.out.println(text.length());
```

编译器知道：

```text
能够执行到后续代码
→ 前面的否定条件必定为 false
→ 匹配已经成功
```

因此 `text` 可用。

### 12.11.1 && 中的作用域

```java
if (
        value instanceof String text
        && !text.isBlank()
) {
    System.out.println(text);
}
```

右侧只在匹配成功时执行，因此可以使用 `text`。

### 12.11.2 || 中的限制

```java
// if (
//         value instanceof String text
//         || text.isBlank()
// ) {
// }
```

当左侧为 `false` 时，`text` 未绑定，右侧却可能执行，因此非法。

### 12.11.3 作用域由控制流决定

不能只根据花括号机械判断模式变量作用域。

## 12.12 getClass 与 instanceof

### 12.12.1 instanceof 接受子类型

```java
animal instanceof Animal
```

当对象是 `Dog` 时也为 `true`。

### 12.12.2 getClass 精确匹配运行时类

```java
animal.getClass() == Animal.class
```

对象必须恰好是 `Animal`。

如果对象是 `Dog`，结果为 `false`。

### 12.12.3 null 边界

```java
animal instanceof Animal
```

对 `null` 返回 `false`。

```java
animal.getClass()
```

对 `null` 抛出 `NullPointerException`。

### 12.12.4 选择原则

```text
需要包含子类型
→ instanceof

需要精确运行时类
→ getClass() == Type.class
```

在 `equals()` 中如何选择见 `18-equals与hashCode.md`。

## 12.13 动态绑定

动态绑定表示：

> 实例方法调用的最终实现，根据接收者对象的运行时类型确定。

```java
Animal animal = new Dog();

animal.speak();
```

编译器确认：

```text
Animal 中存在 speak()
```

运行时选择：

```text
Dog.speak()
```

### 12.13.1 也称晚绑定

相对于编译期即可完全确定的绑定，实例方法重写目标在运行时确定。

### 12.13.2 不是所有方法都晚绑定

主要适用于：

- 可继承；
- 可重写；
- 实例方法。

## 12.14 哪些方法参与动态绑定

### 12.14.1 普通可重写实例方法

```java
public void execute() {
}
```

参与动态绑定。

### 12.14.2 abstract 方法

具体实现由子类提供，调用时动态绑定。

### 12.14.3 接口实例方法

接口引用调用实现类方法，也使用动态绑定。

### 12.14.4 默认方法

接口默认方法也可能参与运行时实例分派，但还需要先处理接口冲突和类优先规则。

完整规则见 `14-接口设计.md`。

## 12.15 不参与普通动态绑定的成员

### 12.15.1 private 方法

对子类不可继承，不形成重写。

### 12.15.2 static 方法

属于类，发生隐藏，编译期解析。

### 12.15.3 final 方法

不能被重写，因此实现固定。

### 12.15.4 构造器

不是普通实例方法，也不被继承。

### 12.15.5 字段

字段访问由表达式编译时类型决定。

### 12.15.6 final 方法仍是实例调用

虽然不能重写，但仍需要对象接收者。

不能因此把它理解为静态方法。

## 12.16 字段没有多态

父类：

```java
class Parent {

    String name = "Parent";
}
```

子类：

```java
class Child extends Parent {

    String name = "Child";
}
```

调用：

```java
Parent value = new Child();

System.out.println(value.name);
```

输出：

```text
Parent
```

### 12.16.1 编译时类型决定字段

`value` 的编译时类型是 `Parent`，因此解析到：

```text
Parent.name
```

### 12.16.2 方法对比

```java
class Parent {

    String name() {
        return "Parent";
    }
}

class Child extends Parent {

    @Override
    String name() {
        return "Child";
    }
}
```

```java
Parent value = new Child();

System.out.println(value.name());
```

输出：

```text
Child
```

### 12.16.3 工程原则

需要多态行为时使用方法，不使用同名字段。

## 12.17 静态方法没有运行时多态

父类：

```java
class Parent {

    static void print() {
        System.out.println("Parent");
    }
}
```

子类：

```java
class Child extends Parent {

    static void print() {
        System.out.println("Child");
    }
}
```

调用：

```java
Parent value = new Child();

value.print();
```

通常解析为：

```text
Parent.print()
```

### 12.17.1 编译期绑定

静态方法目标由：

- 限定类名；
- 表达式编译时类型；

决定。

### 12.17.2 推荐写法

```java
Parent.print();
Child.print();
```

不通过实例调用静态方法。

## 12.18 重载是编译期选择

```java
static void print(Animal value) {
    System.out.println("Animal");
}

static void print(Dog value) {
    System.out.println("Dog");
}
```

```java
Animal animal = new Dog();

print(animal);
```

输出：

```text
Animal
```

### 12.18.1 为什么

编译器看到实参表达式类型是：

```text
Animal
```

因此选择：

```text
print(Animal)
```

不会在运行时根据对象是 `Dog` 重新选择 `print(Dog)`。

### 12.18.2 强转可以改变编译期选择

```java
print((Dog) animal);
```

现在选择：

```text
print(Dog)
```

前提是运行时对象确实可转为 `Dog`。

---

## 12.19 重载与重写的两阶段选择

父类：

```java
class Parent {

    void print(Animal value) {
        System.out.println(
                "Parent Animal"
        );
    }

    void print(Dog value) {
        System.out.println(
                "Parent Dog"
        );
    }
}
```

子类：

```java
class Child extends Parent {

    @Override
    void print(Animal value) {
        System.out.println(
                "Child Animal"
        );
    }

    @Override
    void print(Dog value) {
        System.out.println(
                "Child Dog"
        );
    }
}
```

调用：

```java
Parent receiver = new Child();
Animal argument = new Dog();

receiver.print(argument);
```

结果：

```text
Child Animal
```

### 12.19.1 第一阶段：编译期重载解析

接收者编译时类型：

```text
Parent
```

实参编译时类型：

```text
Animal
```

选择签名：

```text
print(Animal)
```

### 12.19.2 第二阶段：运行时动态绑定

接收者实际对象：

```text
Child
```

因此执行：

```text
Child.print(Animal)
```

### 12.19.3 关键结论

```text
先按编译时类型选择重载签名
再按运行时类型选择该签名的重写实现
```

这就是：

```text
先重载
后重写
```

## 12.20 参数对象运行时类型不会重新参与重载

```java
Animal argument = new Dog();
```

即使实际对象是 `Dog`，编译器已经选择：

```text
print(Animal)
```

运行时只对接收者进行实例方法动态分派。

不会再次根据参数对象运行时类型改选：

```text
print(Dog)
```

### 12.20.1 Java 默认是单分派

运行时实例方法分派主要根据：

```text
接收者对象运行时类型
```

而不是同时根据所有参数运行时类型。

### 12.20.2 多分派语言

某些语言可以根据多个参数的运行时类型选择方法。

Java 默认不具备普通多方法机制。

## 12.21 返回类型不参与普通重载选择

不能声明：

```java
// int value() {
//     return 1;
// }

// String value() {
//     return "1";
// }
```

调用：

```java
String result = value();
```

编译器不会单独根据目标返回类型选择重载。

### 12.21.1 泛型目标类型推断

泛型方法可能受到赋值目标类型影响，但这不是“只靠返回类型重载”。

### 12.21.2 API 设计

语义不同的结果使用不同方法名：

```java
readAsText()
readAsBytes()
```

比试图依赖目标类型更清晰。

## 12.22 接口多态

```java
public interface PaymentGateway {

    PaymentResult pay(
            PaymentRequest request
    );
}
```

不同实现：

```java
public final class CardGateway
        implements PaymentGateway {
}

public final class WalletGateway
        implements PaymentGateway {
}
```

调用方：

```java
PaymentGateway gateway =
        new CardGateway();

gateway.pay(request);
```

### 12.22.1 调用方依赖接口

调用方不需要知道：

- HTTP 客户端；
- 签名算法；
- 请求格式；
- 供应商 SDK；
- 重试细节。

### 12.22.2 运行时替换

```java
PaymentGateway gateway =
        config.useWallet()
        ? new WalletGateway()
        : new CardGateway();
```

调用逻辑保持不变。

### 12.22.3 测试替身

```java
PaymentGateway fake =
        request -> PaymentResult.success();
```

接口多态便于注入测试实现。

## 12.23 抽象类多态

```java
public abstract class Report {

    public final String generate() {
        Object data = loadData();
        return render(data);
    }

    protected abstract Object loadData();

    protected abstract String render(
            Object data
    );
}
```

子类提供差异实现。

### 12.23.1 抽象类可同时提供状态和模板

相比接口，抽象类可以：

- 保存实例字段；
- 提供构造器；
- 提供 `protected` 工具；
- 固定算法骨架。

### 12.23.2 多态调用

```java
Report report =
        new SalesReport();

String result =
        report.generate();
```

模板内部调用抽象钩子时会动态绑定。

### 12.23.3 风险

抽象类内部调用可重写方法时必须明确：

- 对象是否已构造完成；
- 调用顺序；
- 锁状态；
- 异常契约；
- 可重入性。

## 12.24 多态集合

```java
List<Animal> animals =
        List.of(
                new Dog(),
                new Cat()
        );
```

遍历：

```java
for (Animal animal : animals) {
    animal.speak();
}
```

每个元素执行自己的重写实现。

### 12.24.1 统一处理异构对象

集合元素可以是不同具体类型，只要都满足 `Animal` 契约。

### 12.24.2 不应频繁向下转型

不推荐：

```java
for (Animal animal : animals) {
    if (animal instanceof Dog dog) {
        dog.fetch();
    } else if (
            animal instanceof Cat cat
    ) {
        cat.climb();
    }
}
```

如果这些行为属于统一流程，应考虑把行为放入抽象方法。

### 12.24.3 类型特有操作确实存在时

可以：

- 拆分不同集合；
- 使用 Visitor；
- 使用模式匹配；
- 提供能力接口；
- 调整领域模型。

## 12.25 能力接口替代具体类型判断

不推荐：

```java
if (animal instanceof Dog dog) {
    dog.fetch();
}
```

若能力并非只有 `Dog` 独有，可以定义：

```java
public interface Fetchable {

    void fetch();
}
```

实现：

```java
public class Dog
        extends Animal
        implements Fetchable {
}
```

调用：

```java
if (animal instanceof Fetchable fetchable) {
    fetchable.fetch();
}
```

### 12.25.1 按能力建模

调用方依赖：

```text
能否 fetch
```

而不是：

```text
是不是 Dog
```

更符合接口隔离和依赖抽象。

## 12.26 多态与条件分支

### 12.26.1 条件分支实现

```java
switch (type) {
    case CARD -> payByCard();
    case WALLET -> payByWallet();
    case BANK -> payByBank();
}
```

### 12.26.2 多态实现

```java
gateway.pay(request);
```

### 12.26.3 多态适合

- 实现类型经常增加；
- 每种类型行为不同；
- 调用点很多；
- 具体实现需要独立依赖；
- 行为与对象类型稳定绑定。

### 12.26.4 switch 适合

- 类型集合封闭；
- 操作经常增加；
- 数据结构简单；
- 使用 sealed 类型；
- 分支只存在于少量集中位置；
- 需要穷尽性检查。

### 12.26.5 不存在绝对优劣

```text
开放实现集合
→ 多态更自然

封闭类型集合
→ 模式 switch 可能更自然
```

## 12.27 表达式问题与对象问题

### 12.27.1 对象导向扩展

新增子类型容易：

```text
已有操作无需修改
```

新增操作可能需要修改所有子类。

### 12.27.2 模式匹配导向扩展

新增操作容易：

```text
新增一个 switch 或访问器
```

新增子类型需要修改所有穷尽操作。

### 12.27.3 这是表达式问题

选择取决于系统更常变化的是：

```text
类型
还是
操作
```

不能机械规定所有分支都应改成多态。

## 12.28 sealed 类型与模式匹配

```java
sealed interface Shape
        permits Circle, Rectangle {
}

record Circle(double radius)
        implements Shape {
}

record Rectangle(
        double width,
        double height
) implements Shape {
}
```

计算面积：

```java
static double area(Shape shape) {
    return switch (shape) {
        case Circle circle ->
                Math.PI
                * circle.radius()
                * circle.radius();

        case Rectangle rectangle ->
                rectangle.width()
                * rectangle.height();
    };
}
```

### 12.28.1 封闭多态

sealed 限制子类型集合。

模式 `switch` 可以穷尽处理。

### 12.28.2 适合数据型层次

例如：

- 抽象语法树；
- 协议消息；
- 解析结果；
- 命令结果；
- 状态事件；
- 几何图形值。

### 12.28.3 与实例方法多态选择

若每种类型长期拥有同一个核心行为：

```java
shape.area()
```

可能更自然。

若系统频繁增加不同操作：

```text
面积
周长
序列化
渲染
导出
```

集中模式匹配可能更便于维护。

## 12.29 数组协变

Java 数组支持协变：

```java
Dog[] dogs = new Dog[2];

Animal[] animals = dogs;
```

因为：

```text
Dog 是 Animal 的子类型
```

所以：

```text
Dog[] 是 Animal[] 的子类型
```

### 12.29.1 读取安全

```java
Animal animal = animals[0];
```

`Dog` 一定可以作为 `Animal` 读取。

### 12.29.2 写入不完全安全

```java
animals[0] = new Cat();
```

编译器只看到 `Animal[]`，允许写入 `Cat`。

但真实数组是 `Dog[]`，运行时抛出：

```text
ArrayStoreException
```

### 12.29.3 数组保留运行时元素类型

JVM 知道该数组实际是 `Dog[]`，因此可以执行存储检查。

---

## 12.30 泛型默认不协变

```java
List<Dog> dogs =
        new ArrayList<>();

// List<Animal> animals = dogs;
// 编译错误
```

### 12.30.1 为什么禁止

若允许：

```java
List<Animal> animals = dogs;

animals.add(new Cat());
```

原 `List<Dog>` 将被放入 `Cat`，破坏类型安全。

### 12.30.2 泛型在编译期阻止风险

数组把错误推迟到运行时。

泛型默认不变，在编译期拒绝。

### 12.30.3 不变性

```text
Dog <: Animal
不代表
List<Dog> <: List<Animal>
```

## 12.31 ? extends

只读生产者场景：

```java
List<? extends Animal> animals =
        List.of(
                new Dog(),
                new Cat()
        );
```

### 12.31.1 可以读取为 Animal

```java
Animal animal = animals.get(0);
```

### 12.31.2 不能安全添加具体子类型

```java
// animals.add(new Dog());
// 编译错误
```

因为实际列表可能是：

```text
List<Cat>
```

### 12.31.3 可以添加 null

从类型系统角度：

```java
animals.add(null);
```

通常允许，但业务上不应滥用。

### 12.31.4 生产者原则

```text
Producer Extends
```

当集合主要提供数据时使用 `extends`。

## 12.32 ? super

消费者场景：

```java
List<? super Dog> dogs =
        new ArrayList<Animal>();
```

### 12.32.1 可以添加 Dog

```java
dogs.add(new Dog());
```

也可以添加 `Dog` 子类型。

### 12.32.2 读取只能安全视为 Object

```java
Object value = dogs.get(0);
```

实际列表可能是：

- `List<Dog>`；
- `List<Animal>`；
- `List<Object>`。

### 12.32.3 消费者原则

```text
Consumer Super
```

当集合主要接收数据时使用 `super`。

### 12.32.4 PECS

```text
Producer Extends
Consumer Super
```

完整规则见泛型专题。

## 12.33 数组与泛型的选择

### 12.33.1 数组

- 运行时保留元素类型；
- 支持协变；
- 可能运行时抛 `ArrayStoreException`；
- 与基本类型数组配合；
- 长度固定。

### 12.33.2 泛型集合

- 编译期类型检查更强；
- 默认不变；
- 通过通配符表达变型；
- 长度通常可变；
- 不支持直接创建泛型数组。

### 12.33.3 工程建议

普通业务集合优先使用泛型集合。

数组适合：

- 底层 API；
- 性能敏感数据；
- 固定长度结构；
- 字节和基本类型处理；
- 与现有接口兼容。

## 12.34 构造器中的动态绑定风险

父类：

```java
class Parent {

    Parent() {
        initialize();
    }

    void initialize() {
    }
}
```

子类：

```java
class Child extends Parent {

    private String name = "Java";

    @Override
    void initialize() {
        System.out.println(name);
    }
}
```

创建：

```java
new Child();
```

父类构造期间会动态调用：

```text
Child.initialize()
```

但 `Child.name` 可能还没有完成显式初始化。

### 12.34.1 可能观察默认值

输出可能是：

```text
null
```

### 12.34.2 避免方式

构造期间只调用：

- `private` 方法；
- `final` 方法；
- 静态纯函数；
- 不依赖子类状态的逻辑。

### 12.34.3 构造完成后再调用扩展点

```java
Child child = new Child();

child.initialize();
```

或者通过工厂在构造完成后触发生命周期。

## 12.35 this 调用与动态绑定

在实例方法中：

```java
this.execute();
```

对可重写实例方法仍然参与动态绑定。

父类：

```java
class Parent {

    void run() {
        this.execute();
    }

    void execute() {
        System.out.println("Parent");
    }
}
```

子类：

```java
class Child extends Parent {

    @Override
    void execute() {
        System.out.println("Child");
    }
}
```

调用：

```java
new Child().run();
```

输出：

```text
Child
```

### 12.35.1 省略 this 也一样

```java
execute();
```

在实例上下文中通常等价于：

```java
this.execute();
```

### 12.35.2 private 方法例外

若父类 `execute()` 是 `private`，不形成动态绑定。

## 12.36 super 调用绕过当前重写

```java
class Parent {

    void execute() {
        System.out.println("Parent");
    }
}

class Child extends Parent {

    @Override
    void execute() {
        super.execute();
        System.out.println("Child");
    }
}
```

`super.execute()` 明确调用直接父类实现。

### 12.36.1 不再回到子类版本

它不是对普通接收者的动态调用。

### 12.36.2 常见用途

- 扩展父类行为；
- 保留父类校验；
- 组合父类输出；
- 调用模板默认实现。

### 12.36.3 是否必须调用由契约决定

不能机械规定：

```text
所有重写都必须 super
```

## 12.37 单分派

Java 普通实例方法调用是单分派：

```text
运行时选择实现
主要根据接收者对象类型
```

例如：

```java
receiver.handle(argument);
```

运行时动态选择取决于：

```text
receiver 的运行时类型
```

`argument` 的运行时类型不会让 JVM重新选择另一个重载签名。

### 12.37.1 编译期已确定方法签名

参数运行时类型只会影响方法内部行为，除非代码显式判断或再次进行虚方法调用。

### 12.37.2 双重分派需求

当行为同时依赖两个对象的具体类型时：

```text
形状类型
+
渲染器类型
```

单分派可能不够直接。

## 12.38 双重分派

双重分派通过两次虚方法调用，让两个对象的运行时类型共同参与行为选择。

典型 Visitor：

```java
interface Shape {

    void accept(ShapeVisitor visitor);
}
```

```java
final class Circle
        implements Shape {

    @Override
    public void accept(
            ShapeVisitor visitor
    ) {
        visitor.visit(this);
    }
}
```

```java
interface ShapeVisitor {

    void visit(Circle circle);

    void visit(Rectangle rectangle);
}
```

调用：

```java
shape.accept(visitor);
```

### 12.38.1 第一次分派

根据 `shape` 运行时类型选择：

```text
Circle.accept()
或
Rectangle.accept()
```

### 12.38.2 第二次重载选择

在具体 `accept()` 中：

```java
visitor.visit(this);
```

此时 `this` 的编译时类型已经具体化为 `Circle` 或 `Rectangle`，从而选择对应重载。

随后还可对 `visitor` 进行动态绑定。

---

## 12.39 Visitor 的适用边界

Visitor 适合：

- 类型层次稳定；
- 经常新增操作；
- 需要双重分派；
- 不希望把所有操作塞进数据对象；
- 编译器或语法树处理；
- 文档结构遍历；
- 图形导出。

### 12.39.1 缺点

新增子类型时，需要修改所有 Visitor 接口和实现。

### 12.39.2 模式 switch 替代

对于 sealed 类型，模式匹配 `switch` 往往比传统 Visitor 更直接。

### 12.39.3 不要为了高级而使用

简单分支或普通实例方法已足够时，Visitor 会增加大量样板代码。

## 12.42 多态的性能边界

- 生产监控。

### 12.42.3 超多实现调用点

高度多态调用点可能较难内联，但是否构成瓶颈必须实际验证。

## 12.43 常见错误

### 12.43.1 认为父类引用会改变对象类型

向上转型只改变引用的编译时视图。

### 12.43.2 强转后认为对象变成子类

转换不改变对象运行时类型。

### 12.43.3 直接强转不做检查

可能抛 `ClassCastException`。

### 12.43.4 认为所有同名方法都动态选择

重载在编译期选择，字段和静态方法也不动态绑定。

### 12.43.5 认为参数运行时类型参与重载

Java 普通调用不会运行时重新选择重载签名。

### 12.43.6 使用字段表达多态状态

父类引用访问的是父类字段。

### 12.43.7 通过实例调用静态方法

容易误判为多态。

### 12.43.8 大量 instanceof 分支

可能说明抽象不完整或模型边界错误。

### 12.43.9 把所有 switch 都改成子类

封闭数据层次和新增操作场景下可能更糟。

### 12.43.10 构造器调用可重写方法

会访问半初始化子类状态。

## 12.46 易错点

### 误区一：父类引用会把子类对象变成父类对象

**错误。**

只改变引用的编译时视图，对象运行时类型不变。

### 误区二：向上转型会创建一个父类副本

**错误。**

多个引用仍指向同一个对象。

### 误区三：父类引用不能调用子类重写方法

**错误。**

对父类声明的可重写实例方法，会动态进入子类实现。

### 误区四：运行时对象有什么方法，父类引用就能直接调用什么方法

**错误。**

编译器先根据引用的编译时类型检查成员。

### 误区五：向下转型会把对象转换成目标类型对象

**错误。**

强转只改变引用表达式的类型视图。

### 误区六：任何父类引用都能安全转成任意子类

**错误。**

实际对象不匹配会抛 `ClassCastException`。

### 误区七：`instanceof` 遇到 null 会抛异常

**错误。**

结果为 `false`。

### 误区八：`getClass()` 和 `instanceof` 完全相同

**错误。**

前者精确匹配运行时类，后者接受子类型。

### 误区九：模式变量作用域只由大括号决定

**错误。**

还由控制流是否保证匹配成功决定。

### 误区十：所有实例方法都参与动态绑定

**错误。**

`private`、`final` 方法和构造器存在不同规则。

### 误区十一：final 方法等于静态方法

**错误。**

final 方法仍是实例方法，只是不能重写。

### 误区十二：字段也会按运行时对象类型动态选择

**错误。**

字段由表达式编译时类型解析。

### 误区十三：静态方法调用会根据运行时对象类型变化

**错误。**

静态方法在编译期绑定。

### 误区十四：重载在运行时根据实际参数对象类型选择

**错误。**

重载主要在编译期根据实参表达式类型选择。

### 误区十五：参数运行时类型会触发第二次重载解析

**错误。**

运行时只对已选中的实例方法签名进行接收者分派。

### 误区十六：返回类型可以帮助区分两个普通重载

**错误。**

不能只靠返回类型重载。

### 误区十七：重载与重写只能单独出现

**错误。**

同一方法集合可以同时存在重载和重写。

### 误区十八：接口引用不具备运行时多态

**错误。**

接口方法调用同样根据实现对象动态绑定。

### 误区十九：多态集合中的所有对象必须是同一个具体类

**错误。**

只需满足统一父类型或接口契约。

### 误区二十：频繁 instanceof 是多态的标准写法

**错误。**

它可能意味着抽象不足，也可能只是封闭数据处理，应结合场景判断。

### 误区二十一：所有 switch 都应该改为子类多态

**错误。**

封闭类型集合和频繁新增操作时，模式匹配可能更合适。

### 误区二十二：sealed 类型必须把所有行为都写成 switch

**错误。**

仍可使用实例方法多态。

### 误区二十三：数组协变在编译期完全安全

**错误。**

错误写入会在运行时抛 `ArrayStoreException`。

### 误区二十四：泛型集合像数组一样协变

**错误。**

Java 泛型默认不变。

### 误区二十五：`List<? extends Animal>` 可以添加任意 Animal

**错误。**

实际列表具体元素类型未知。

### 误区二十六：`List<? super Dog>` 读取元素可以直接赋给 Dog

**错误。**

只能安全视为 `Object`。

### 误区二十七：构造器调用重写方法时子类已经完成初始化

**错误。**

子类字段初始化可能尚未执行。

### 误区二十八：`this.method()` 一定调用当前类源码实现

**错误。**

可重写实例方法仍按运行时对象类型动态绑定。

### 误区二十九：`super.method()` 会再次进入子类重写方法

**错误。**

它明确选择直接父类实现。

### 误区三十：Java 普通方法支持根据所有参数运行时类型多分派

**错误。**

默认主要是接收者单分派。

### 误区三十一：Visitor 只是普通 if-else 的另一种写法

**不完整。**

它利用双重分派，并把操作从对象层次中分离。

### 误区三十二：Visitor 适合频繁新增子类型的系统

**错误。**

新增子类型通常要求修改全部 Visitor。

### 误区三十三：接口越多，多态设计越好

**错误。**

无真实角色和替换需求的接口会增加复杂度。

### 误区三十四：动态绑定一定很慢

**错误。**

JVM 可以内联和去虚拟化，性能需要实际测量。

### 误区三十五：多态可以自动保证里氏替换

**错误。**

语言只保证调用机制，不保证行为契约正确。

### 误区三十六：强转能解决所有抽象不足问题

**错误。**

强转会把具体类型耦合泄漏给调用方。

### 误区三十七：实现类变化不会影响接口调用方

**不一定。**

实现仍必须维持接口的异常、副作用、线程安全和性能契约。

### 误区三十八：抽象类模板调用钩子永远安全

**错误。**

构造期间、锁内和异常路径都可能产生风险。

### 误区三十九：父类型集合一定不包含 null

**错误。**

除非集合或业务契约明确禁止。

### 误区四十：理解多态只需记住“父类引用指向子类对象”

**错误。**

还必须理解编译期成员检查、重载解析和运行时重写分派。

## 12.47 工程实践建议

1. 调用方优先依赖稳定接口或抽象类型。
2. 使用向上转型隐藏实现细节，不滥用向下转型恢复具体类型。
3. 向下转型前使用模式匹配 `instanceof`，或重新设计抽象。
4. 频繁类型判断时先检查是否缺少能力接口或多态行为。
5. 字段不用于表达多态，使用实例方法。
6. 静态方法通过类名调用，避免实例语法误导。
7. 分析方法调用时始终区分接收者编译时类型与运行时类型。
8. 同时存在重载和重写时，按“先重载、后重写”分析。
9. 不假设参数对象运行时类型会重新选择重载。
10. 语义不同的返回结果使用不同方法名，不依赖目标类型猜测。
11. 多态集合通过统一契约处理，不在循环中大量向下转型。
12. 按能力定义小接口，而不是按具体类名判断。
13. 实现集合开放、行为稳定时优先多态。
14. 类型集合封闭、操作经常增加时考虑 sealed 与模式 `switch`。
15. 不为消除少量稳定分支引入复杂继承层次。
16. 数组协变写入时特别警惕 `ArrayStoreException`。
17. 泛型 API 使用 PECS 表达生产者和消费者。
18. 不在构造器中调用可重写方法。
19. 模板方法明确钩子调用时机、次数和锁状态。
20. `super.method()` 是否调用由父类契约决定。
21. 双重分派需求明确时再使用 Visitor。
22. sealed 类型优先评估模式匹配能否替代 Visitor 样板。
23. 接口围绕真实角色设计，不为测试机械创建接口。
24. 对所有实现执行统一契约测试。
25. 测试替身不应偏离真实实现的重要行为语义。
26. 不凭感觉把虚方法改成静态方法优化性能。
27. 性能热点使用 JMH 和生产分析工具验证。
28. 子类型必须维持父类型的前置条件、后置条件和异常契约。
29. 接口文档明确空值、线程安全、副作用和资源所有权。
30. 公共多态层次控制深度，避免过深继承。
31. 代码审查重点检查：错误强转、重载误判、字段隐藏和契约破坏。
32. 多态、组合、策略和模式匹配根据变化方向选择，而不是按“高级程度”选择。

### 12.49.7 面试口述版

Java 多态的关键是区分编译时类型和运行时类型。编译器根据引用和实参的编译时类型检查成员、选择重载签名；运行时再根据接收者对象的实际类型选择该实例方法签名的重写实现。因此同时存在重载和重写时，应按“先重载、后重写”分析，参数对象的运行时类型不会触发第二次重载解析。

向上转型不会创建新对象，也不会改变对象运行时类型，只会缩小引用可直接使用的能力范围。向下转型同样不会改变对象，但实际类型不匹配时会抛出 `ClassCastException`。模式匹配 `instanceof` 可以同时完成判断和安全绑定。

普通可重写实例方法参与动态绑定；字段、静态方法、构造器和 `private` 方法不按同样方式分派。数组支持协变，因此错误写入可能在运行时抛出 `ArrayStoreException`；泛型默认不变，并通过 `? extends` 和 `? super` 提供受限变型。

多态并不总是优于条件分支。实现类型经常增加而行为稳定时，多态更自然；类型集合封闭而操作经常增加时，sealed 类型和模式匹配可能更合适。最终目标不是消除所有分支，而是让变化落在最稳定、最容易维护的边界上。
