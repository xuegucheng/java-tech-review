## 3.3 算术运算符

常见算术运算符：
1 + - * / %
2 ++ --
3
### 3.3.1 加减乘除
1 int a = 10;
2 int b = 3;
3
4 System.out.println(a + b); // 13
5 System.out.println(a - b); // 7
6 System.out.println(a * b); // 30
7 System.out.println(a / b); // 3
8 System.out.println(a % b); // 1
9
两个整数相除时，结果仍然是整数，小数部分被截断：

1 int result = 5 / 2;
2
3 System.out.println(result); // 2
4
想得到浮点结果，至少有一个操作数需要是浮点类型：
1 double result = 5.0 / 2;
2
3 System.out.println(result); // 2.5
4
也可以显式转换：
1 double result = (double) 5 / 2;
2
### 3.3.2 字符串拼接
+ 除了表示数值加法，还可以用于字符串拼接：
1 String result = "Java" + "基础";
2
3 System.out.println(result); // Java基础
4
只要表达式中出现字符串，后续的 + 通常按字符串拼接处理：
1 System.out.println(1 + 2 + "3"); // 33
2 System.out.println("1" + 2 + 3); // 123
3
第一个表达式的计算过程：
1 1 + 2 + "3"
2 ↓
3 3 + "3"
4 ↓
5 "33"
6
第二个表达式：
1 "1" + 2 + 3
2 ↓
3 "12" + 3
4 ↓
5 "123"

6
因此：
+ 的结合方向是从左到右，是否执行数值加法取决于当前操作数类型。
建议避免依赖这种隐式转换表达复杂业务逻辑。
### 3.3.3 除零行为
整数除以零：
1 int result = 1 / 0;
2
会抛出：
1 ArithmeticException: / by zero
2
浮点数除以零：
1 double result = 1.0 / 0.0;
2
3 System.out.println(result); // Infinity
4
零除以零：
1 double result = 0.0 / 0.0;
2
3 System.out.println(result); // NaN
4
原因是浮点运算遵循 IEEE 754 规则。
### 3.3.4 取模运算
1 System.out.println(5 % 3); // 2
2 System.out.println(-5 % 3); // -2
3 System.out.println(5 % -3); // 2
4
Java 中余数结果的符号通常与被除数相同。
需要数学意义上的非负模时，可以使用：
1 Math.floorMod(-5, 3); // 1
2
这在循环索引、哈希分桶等场景中更安全。

## 3.4 自增与自减

### 3.4.1 前置与后置
1 int a = 1;
2 int b = a++;
3
执行后：
1 a = 2
2 b = 1
3
因为后置自增先返回旧值，再执行加一。
前置自增：
1 int a = 1;
2 int b = ++a;
3
执行后：
1 a = 2
2 b = 2
3
因为前置自增先加一，再返回新值。
### 3.4.2 自增表达式的求值顺序
1 int i = 1;
2 int result = i++ + ++i;
3
执行过程：
1 i++ 返回 1，随后 i 变成 2
2 ++i 先将 i 变成 3，再返回 3
3 result = 1 + 3 = 4
4 最终 i = 3
5
这类表达式虽然可以根据语言规则计算，但实际项目中应避免：
1 int result = i++ + ++i;
2

原因：
可读性极差
容易误判求值顺序
修改时容易引入缺陷
无实际工程价值
### 3.4.3 i = i++ 的结果
1 int i = 1;
2 i = i++;
3
4 System.out.println(i); // 1
5
可以近似理解为：
1 int temp = i;
2 i = i + 1;
3 i = temp;
4
虽然中间执行了自增，但最终旧值又被赋回给 i 。
这属于典型代码陷阱，不应在生产代码中使用。

## 3.5 关系运算符

关系运算符用于比较两个值：
1 > < >= <= == !=
2
返回结果是 boolean 。
1 int a = 10;
2 int b = 20;
3
4 boolean result = a < b;
5
### 3.5.1 基本类型的 ==
对于基本类型， == 比较数值是否相等：
1 int a = 10;
2 int b = 10;
3
4 System.out.println(a == b); // true
5

不同数值类型比较时，可能先发生数值提升：
1 int a = 10;
2 long b = 10L;
3
4 System.out.println(a == b); // true
5
这里 a 会提升为 long 后再比较。
### 3.5.2 引用类型的 ==
对于引用类型， == 比较的是：
两个引用值是否指向同一个对象。
1 User user1 = new User();
2 User user2 = user1;
3 User user3 = new User();
4
5 System.out.println(user1 == user2); // true
6 System.out.println(user1 == user3); // false
7
即使 user1 和 user3 的字段完全相同：
1 user1.name = "Java";
2 user3.name = "Java";
3
它们仍然可能是两个不同对象，因此：
1 user1 == user3
2
仍然为 false 。
对象内容是否相等，应通过 equals() 语义判断，后续 Object 章节展开。
### 3.5.3 null 比较
引用变量可以与 null 比较：
1 if (user == null) {
2 }
3
或者：
1 if (user != null) {
2 }
3

不能对基本类型与 null 比较：
1 int value = 10;
2
3 if (value == null) { // 编译错误
4 }
5

## 3.6 逻辑运算符

逻辑运算符主要用于布尔表达式：
1 && || ! & | ^
2
### 3.6.1 逻辑与、逻辑或、逻辑非
1 boolean a = true;
2 boolean b = false;
3
4 System.out.println(a && b); // false
5 System.out.println(a || b); // true
6 System.out.println(!a); // false
7
### 3.6.2 短路与 &&
1 if (user != null && user.isActive()) {
2 }
3
当：
1 user != null
2
为 false 时，右侧：
1 user.isActive()
2
不会执行。
这称为短路求值。
因此 && 常用于防止空指针：

1 if (list != null && !list.isEmpty()) {
2 }
3
### 3.6.3 短路或 ||
1 if (user == null || !user.isActive()) {
2 }
3
当左侧：
1 user == null
2
为 true 时，右侧不会执行。
### 3.6.4 & 和 | 用于布尔值
& 和 | 也可以用于布尔表达式，但不会短路。
1 boolean result = left() & right();
2
无论 left() 返回什么， right() 都会执行。
对比：
1 boolean result = left() && right();
2
当 left() 为 false 时， right() 不执行。
示例：
1 static boolean left() {
2 System.out.println("left");
3 return false;
4 }
5
6 static boolean right() {
7 System.out.println("right");
8 return true;
9 }
10
执行：
1 left() && right();

2
输出：
1 left
2
执行：
1 left() & right();
2
输出：
1 left
2 right
3
### 3.6.5 ^ 逻辑异或
1 System.out.println(true ^ true); // false
2 System.out.println(true ^ false); // true
3 System.out.println(false ^ true); // true
4 System.out.println(false ^ false); // false
5
异或规则：
两个布尔值不同时为 true，相同时为 false。
业务代码中较少直接使用布尔异或，但在状态互斥判断中可能出现。

## 3.7 位运算符

位运算针对整数类型的二进制位：
1 & | ^ ~
2
### 3.7.1 按位与
1 int result = 6 & 3;
2
二进制：
1 6 = 110
2 3 = 011

3 ---------
4 010 = 2
5
只有两位都为 1，结果位才为 1。
常见用途：
判断标志位
提取掩码
判断奇偶
例如：
1 boolean odd = (value & 1) == 1;
2
### 3.7.2 按位或
1 int result = 6 | 3;
2
1 6 = 110
2 3 = 011
3 ---------
4 111 = 7
5
只要任意一位为 1，结果位就是 1。
常用于设置标志位。
### 3.7.3 按位异或
1 int result = 6 ^ 3;
2
1 6 = 110
2 3 = 011
3 ---------
4 101 = 5
5
相同为 0，不同为 1。
常见性质：
1 a ^ a = 0
2 a ^ 0 = a
3 a ^ b ^ b = a

4
可以用于查找只出现一次的数字：
1 int result = 0;
2
3 for (int value : values) {
4 result ^= value;
5 }
6
前提是其他数字都成对出现。
### 3.7.4 按位取反
1 int result = ~value;
2
所有二进制位取反。
对于补码整数：
1 ~x = -x - 1
2
例如：
1 System.out.println(~5); // -6
2

## 3.8 移位运算符

Java 提供三种移位：
1 << >> >>>
2
### 3.8.1 左移 <<
1 int result = 3 << 2;
2
二进制：
1 3 = 00000011
2 左移 2 = 00001100
3 结果 = 12

4
在不溢出的情况下：
1 x << n ≈ x × 2ⁿ
2
但发生高位丢失时可能溢出。
### 3.8.2 算术右移 >>
1 int result = 12 >> 2; // 3
2
右移时保留符号位：
正数左侧补 0
负数左侧补 1
因此也称有符号右移。
在不涉及负数舍入差异时，可近似理解为：
1 x >> n ≈ x / 2ⁿ
2
但对负数不能简单等同于普通整数除法。
### 3.8.3 无符号右移 >>>
1 int result = -1 >>> 1;
2
无符号右移时左侧统一补 0，不保留符号位。
因此负数经过 >>> 后通常变成较大的正数。
### 3.8.4 移位位数的处理
对于 int ，实际移位位数只取低 5 位：
1 int result = 1 << 32;
2
实际等价于：
1 1 << 0
2
因此结果为：

1 1
2
因为：
1 32 & 0x1F = 0
2
对于 long ，实际移位位数只取低 6 位。
这属于语言规则中的易错点，实际开发中不应依赖异常移位值。

## 3.9 赋值运算符

基本赋值：
1 int value = 10;
2
复合赋值：
1 += -= *= /= %= &= |= ^= <<= >>= >>>=
2
### 3.9.1 复合赋值包含隐式转换
1 short value = 1;
2 value += 1;
3
可以编译。
其语义近似：
1 value = (short) (value + 1);
2
但：
1 short value = 1;
2 value = value + 1;
3
不能编译，因为 value + 1 的结果类型是 int 。
因此：
a += b 并不完全等同于 a = a + b ，前者还包含隐式窄化转换。
### 3.9.2 连续赋值

1 int a;
2 int b;
3 int c;
4
5 a = b = c = 10;
6
赋值运算符从右向左结合：
1 c = 10
2 b = c
3 a = b
4
虽然语法允许，但复杂连续赋值不利于可读性。

## 3.10 条件运算符

条件运算符，也称三元运算符：
1 条件 ? 表达式1 : 表达式2
2
示例：
1 int max = a > b ? a : b;
2
语义：
1 条件为 true → 返回表达式1
2 条件为 false → 返回表达式2
3
### 3.10.1 三元运算符具有返回值
与 if 不同，三元运算符本身是一个表达式：
1 String result = success ? "成功" : "失败";
2
因此适合简单值选择。
不建议嵌套过深：
1 String result = score >= 90 ? "A"
2 : score >= 80 ? "B"
3 : score >= 60 ? "C"
4 : "D";

5
虽然语法正确，但复杂逻辑更适合使用 if 或独立方法。
### 3.10.2 三元运算符的类型推断
1 double result = true ? 1 : 2.0;
2
结果类型是 double ，因为两个分支需要推导出兼容类型。
即使条件始终为 true ：
1 var result = true ? 1 : 2.0;
2
result 的类型仍然是 double 。
### 3.10.3 包装类型与拆箱风险
1 Integer value = null;
2 int result = condition ? value : 0;
3
如果 condition 为 true ，可能发生自动拆箱并抛出 NullPointerException 。
三元运算符的类型推断有时会触发：
自动装箱
自动拆箱
数值提升
因此复杂类型组合应格外谨慎。

## 3.11 instanceof 类型判断

传统写法：
1 if (obj instanceof String) {
2 String value = (String) obj;
3 System.out.println(value.length());
4 }
5
现代 Java 支持模式匹配：
1 if (obj instanceof String value) {
2 System.out.println(value.length());
3 }
4
这里 value 只在类型判断成立的作用域内有效。

### 3.11.1 null 与 instanceof
1 Object obj = null;
2
3 System.out.println(obj instanceof String); // false
4
null instanceof 任意类型 都是 false ，不会抛异常。
### 3.11.2 instanceof 的适用边界
instanceof 适用于：
安全向下转型
模式分支
外部数据类型判断
兼容旧接口返回值
如果业务代码中大量出现：
1 if (obj instanceof A) {
2 } else if (obj instanceof B) {
3 } else if (obj instanceof C) {
4 }
5
可能意味着：
多态设计不足
类型职责混乱
应考虑接口、策略模式或 sealed class

## 3.12 运算符优先级

Java 运算符存在优先级，例如：
1 int result = 1 + 2 * 3;
2
先执行乘法：
1 1 + 6 = 7
2
但在工程代码中，不建议依赖记忆复杂优先级。
推荐显式加括号：
1 boolean valid = enabled && (count > 0 || force);
2
而不是：
1 boolean valid = enabled && count > 0 || force;

2
即使两者结果符合预期，前者意图更清晰。
核心原则：
括号的价值不仅是改变优先级，更重要的是表达意图。
