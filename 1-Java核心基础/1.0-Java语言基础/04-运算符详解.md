## 4.2 运算符总体分类

Java 常见运算符可以分为：

```text
Java 运算符
├── 算术运算符
│   ├── +  -  *  /  %
│   └── ++  --
├── 一元运算符
│   ├── +  -
│   ├── !
│   └── ~
├── 关系与相等运算符
│   ├── <  <=  >  >=
│   └── ==  !=
├── 逻辑运算符
│   ├── &&  ||
│   └── !  &  |  ^
├── 位运算符
│   ├── &  |  ^  ~
│   └── <<  >>  >>>
├── 赋值运算符
│   ├── =
│   └── +=  -=  *=  /=  %=  &=  |=  ^=  <<=  >>=  >>>=
├── 条件运算符
│   └── ? :
├── 类型运算符
│   └── instanceof
└── 其他表达式语法
    ├── new
    ├── 方法调用
    ├── 数组访问
    └── 成员访问
```

需要注意：

- `new`、方法调用和成员访问通常也属于表达式语法的一部分；
- 不同资料对“运算符”的分类范围可能不同；
- 学习重点应放在语义和求值规则，而不是分类名称。

## 4.3 算术运算符

### 4.3.1 基本算术运算

```java
int first = 10;
int second = 3;

System.out.println(first + second); // 13
System.out.println(first - second); // 7
System.out.println(first * second); // 30
System.out.println(first / second); // 3
System.out.println(first % second); // 1
```

常见算术运算符：

| 运算符 | 含义 |
|---|---|
| `+` | 加法 |
| `-` | 减法 |
| `*` | 乘法 |
| `/` | 除法 |
| `%` | 余数 |

### 4.3.2 结果类型由操作数决定

```java
int first = 10;
long second = 20L;

var result = first + second;
```

`result` 的类型是 `long`。

表达式类型先由操作数和数值提升规则决定，再执行赋值。

完整提升规则见 `03-类型转换与精度陷阱.md`。

### 4.3.3 byte、short、char 参与运算通常提升为 int

```java
byte first = 10;
byte second = 20;

int result = first + second;
```

不能直接写：

```java
// byte result = first + second; // 编译错误
```

### 4.3.4 算术运算可能溢出

```java
int value = Integer.MAX_VALUE;
int result = value + 1;

System.out.println(result); // Integer.MIN_VALUE
```

普通整数运算不会自动抛出溢出异常。

关键计算可使用：

```java
int result = Math.addExact(first, second);
```

## 4.4 加号的多重语义

`+` 在 Java 中至少有两种主要语义：

```text
数值加法
字符串拼接
```

### 4.4.1 数值加法

```java
int result = 10 + 20;

System.out.println(result); // 30
```

### 4.4.2 字符串拼接

```java
String result = "Java" + " JVM";

System.out.println(result); // Java JVM
```

当任一操作数是 `String` 时，通常执行字符串拼接：

```java
String result = "count=" + 10;
```

### 4.4.3 从左到右求值会影响结果

```java
System.out.println(1 + 2 + "3");
```

结果：

```text
33
```

过程：

```text
1 + 2
→ 3

3 + "3"
→ "33"
```

而：

```java
System.out.println("1" + 2 + 3);
```

结果：

```text
123
```

过程：

```text
"1" + 2
→ "12"

"12" + 3
→ "123"
```

### 4.4.4 使用括号表达意图

```java
String result = "sum=" + (first + second);
```

不要写：

```java
String result = "sum=" + first + second;
```

后者可能得到字符串连续拼接，而不是数值和。

### 4.4.5 null 参与字符串拼接

```java
String value = null;

System.out.println("value=" + value);
```

输出：

```text
value=null
```

字符串拼接会通过 `String.valueOf()` 等机制处理 `null`，不会因为这一处直接抛出空指针。

但这不代表：

```java
value.length()
```

是安全的。

### 4.4.6 编译器可能优化字符串拼接

简单字符串拼接可能在编译期折叠：

```java
String value = "Java" + "JVM";
```

结果可能直接成为常量字符串。

循环中的动态拼接：

```java
String result = "";

for (String value : values) {
    result += value;
}
```

可能产生较多临时对象。

更适合：

```java
StringBuilder builder = new StringBuilder();

for (String value : values) {
    builder.append(value);
}
```

现代编译器和 JVM 会进行优化，但不能依赖优化掩盖明显低效的循环拼接。

## 4.5 除法运算

### 4.5.1 整数除法

```java
int result = 5 / 2;

System.out.println(result); // 2
```

整数除法向零截断。

```java
System.out.println(-5 / 2); // -2
```

### 4.5.2 浮点除法

```java
double result = 5.0 / 2;

System.out.println(result); // 2.5
```

只要任一操作数是浮点类型，通常执行浮点除法。

### 4.5.3 转换发生时机很重要

错误：

```java
double result = 5 / 2;

System.out.println(result); // 2.0
```

因为：

```text
5 / 2
→ 先按 int 除法得到 2

2
→ 再转换为 double
```

正确：

```java
double result = 5.0 / 2;
```

或者：

```java
double result = (double) 5 / 2;
```

### 4.5.4 整数除零

```java
int value = 1 / 0;
```

运行时抛出：

```text
ArithmeticException
```

### 4.5.5 浮点除零

```java
System.out.println(1.0 / 0.0);  // Infinity
System.out.println(-1.0 / 0.0); // -Infinity
System.out.println(0.0 / 0.0);  // NaN
```

浮点除零不会抛 `ArithmeticException`。

## 4.6 余数运算符

### 4.6.1 基本规则

```java
System.out.println(5 % 3); // 2
```

Java 的 `%` 更准确地说是余数运算。

### 4.6.2 负数余数

```java
System.out.println(-5 % 3); // -2
System.out.println(5 % -3); // 2
```

余数符号通常与被除数一致。

### 4.6.3 余数与数学模不同

数学中常希望模结果非负。

```java
int result = Math.floorMod(-5, 3);

System.out.println(result); // 1
```

适合：

- 环形数组；
- 周期编号；
- 时间分桶；
- 需要非负索引的场景。

### 4.6.4 浮点余数

```java
System.out.println(5.5 % 2.0); // 1.5
```

浮点数也可以使用 `%`。

但精度仍受二进制浮点近似影响。

## 4.7 一元正负运算符

### 4.7.1 一元正号

```java
int value = +10;
```

通常不改变数值。

### 4.7.2 一元负号

```java
int value = 10;
int result = -value;
```

### 4.7.3 byte、short、char 会提升为 int

```java
byte value = 10;

int result = -value;
```

不能直接写：

```java
// byte result = -value; // 编译错误
```

### 4.7.4 最小整数取负仍可能溢出

```java
int value = Integer.MIN_VALUE;

System.out.println(-value); // Integer.MIN_VALUE
```

因为对应正数超出 `int` 最大范围。

可以使用：

```java
Math.negateExact(value)
```

检测溢出。

## 4.8 自增与自减

### 4.8.1 后缀自增

```java
int first = 10;
int second = first++;

System.out.println(first);  // 11
System.out.println(second); // 10
```

后缀形式：

```text
先产生旧值
再更新变量
```

### 4.8.2 前缀自增

```java
int first = 10;
int second = ++first;

System.out.println(first);  // 11
System.out.println(second); // 11
```

前缀形式：

```text
先更新变量
再产生新值
```

### 4.8.3 自减

```java
int first = 10;
int second = first--;
int third = --first;
```

语义与自增对应。

### 4.8.4 自增表达式不应过度嵌套

不推荐：

```java
int result = value++ + ++value;
```

虽然 Java 规定求值顺序，但代码很难阅读和维护。

更好：

```java
int first = value;
value++;

value++;
int second = value;

int result = first + second;
```

### 4.8.5 自增不是原子操作

```java
count++;
```

大致包含：

```text
读取 count
加一
写回 count
```

多线程下可能发生丢失更新。

完整并发语义放在并发模块。

## 4.9 关系运算符

常见关系运算符：

```text
<
<=
>
>=
```

示例：

```java
int age = 18;

System.out.println(age >= 18); // true
```

### 4.9.1 只适用于可比较的数值类型

```java
char first = 'A';
char second = 'B';

System.out.println(first < second); // true
```

`char` 会按数值参与比较。

### 4.9.2 boolean 不能使用大小关系

```java
boolean first = true;
boolean second = false;

// System.out.println(first > second); // 编译错误
```

### 4.9.3 引用类型不能直接使用大小关系

```java
String first = "A";
String second = "B";

// System.out.println(first < second); // 编译错误
```

字符串排序使用：

```java
first.compareTo(second)
```

## 4.10 相等运算符

### 4.10.1 基本类型比较值

```java
int first = 10;
int second = 10;

System.out.println(first == second); // true
```

数值类型之间可能先发生数值提升：

```java
System.out.println(10 == 10L); // true
```

### 4.10.2 boolean 可以比较相等

```java
boolean first = true;
boolean second = false;

System.out.println(first == second); // false
```

但更推荐直接表达：

```java
if (enabled) {
}
```

而不是：

```java
if (enabled == true) {
}
```

### 4.10.3 引用类型比较身份

```java
String first = new String("Java");
String second = new String("Java");

System.out.println(first == second); // false
```

引用类型的 `==` 比较：

```text
两个引用值
是否指向同一对象
```

### 4.10.4 字符串常量池容易制造错觉

```java
String first = "Java";
String second = "Java";

System.out.println(first == second); // 常见为 true
```

这是因为字符串字面量可能复用同一对象。

不能据此使用 `==` 比较字符串内容。

正确：

```java
System.out.println(first.equals(second));
```

### 4.10.5 null 比较

```java
User user = null;

if (user == null) {
    System.out.println("empty");
}
```

判断是否为空引用应使用：

```java
user == null
```

不能调用：

```java
user.equals(null)
```

因为 `user` 可能是 `null`。

### 4.10.6 浮点相等

```java
System.out.println(0.1 + 0.2 == 0.3); // false
```

浮点比较要结合业务容差。

完整规则见 `03-类型转换与精度陷阱.md`。

### 4.10.7 equals 与 == 的边界

```text
==
→ 基本类型比较值
→ 引用类型比较对象身份

equals()
→ 由类定义逻辑相等语义
```

完整 `equals()` 契约见 `18-equals与hashCode.md`。

## 4.11 逻辑非运算符

```java
boolean enabled = true;

System.out.println(!enabled); // false
```

`!` 只能用于布尔表达式。

不能写：

```java
int value = 1;

// System.out.println(!value); // 编译错误
```

### 4.11.1 双重否定

```java
boolean result = !!enabled;
```

语法合法，但通常没有必要。

### 4.11.2 否定复杂条件

原条件：

```java
if (!(user != null && user.isEnabled())) {
}
```

更清晰：

```java
if (user == null || !user.isEnabled()) {
}
```

复杂否定应结合德摩根定律和可读性重写。

## 4.12 短路逻辑运算符

### 4.12.1 &&

```java
if (user != null && user.isEnabled()) {
}
```

当左侧为 `false` 时，右侧不再执行。

### 4.12.2 ||

```java
if (user == null || !user.isEnabled()) {
}
```

当左侧为 `true` 时，右侧不再执行。

### 4.12.3 短路避免异常

```java
if (text != null && !text.isEmpty()) {
}
```

先检查 `null`，再访问实例方法。

顺序错误：

```java
if (!text.isEmpty() && text != null) {
}
```

可能先抛 `NullPointerException`。

### 4.12.4 短路避免无效计算

```java
if (cache.containsKey(key) || loadFromDatabase(key)) {
}
```

当缓存命中时，不调用数据库。

### 4.12.5 不要依赖短路隐藏副作用

不推荐：

```java
if (ready && initialize()) {
}
```

如果 `initialize()` 同时执行重要副作用，条件变化会导致它不执行。

更清晰：

```java
if (!ready) {
    return;
}

boolean initialized = initialize();

if (initialized) {
}
```

### 4.12.6 布尔表达式从左到右求值

```java
checkFirst() && checkSecond()
```

先调用 `checkFirst()`。

只有其结果为 `true`，才调用 `checkSecond()`。

## 4.13 非短路布尔运算符

`&` 和 `|` 可以用于布尔值。

### 4.13.1 boolean &

```java
boolean result = firstCondition() & secondCondition();
```

两边都会执行。

### 4.13.2 boolean |

```java
boolean result = firstCondition() | secondCondition();
```

两边也都会执行。

### 4.13.3 与 &&、|| 的区别

| 运算符 | 左侧能否决定结果时跳过右侧 |
|---|---|
| `&&` | 是 |
| `||` | 是 |
| `&` | 否 |
| `|` | 否 |

### 4.13.4 boolean ^

异或：

```java
System.out.println(true ^ true);   // false
System.out.println(true ^ false);  // true
System.out.println(false ^ true);  // true
System.out.println(false ^ false); // false
```

适合表达：

```text
两个条件恰好一个为 true
```

示例：

```java
boolean exactlyOneProvided =
        usernameProvided ^ phoneProvided;
```

但复杂业务校验通常更适合显式计数或独立方法。

## 4.14 位运算符

位运算适用于整数类型：

```text
byte
short
int
long
char
```

但 `byte`、`short`、`char` 参与时通常提升为 `int`。

### 4.14.1 按位与 &

```java
int result = 0b1100 & 0b1010;

System.out.println(Integer.toBinaryString(result)); // 1000
```

规则：

```text
1 & 1 → 1
其他   → 0
```

常用于：

- 位掩码；
- 提取标志位；
- 权限判断；
- 协议解析。

### 4.14.2 按位或 |

```java
int result = 0b1100 | 0b1010;

System.out.println(Integer.toBinaryString(result)); // 1110
```

常用于设置标志位。

### 4.14.3 按位异或 ^

```java
int result = 0b1100 ^ 0b1010;

System.out.println(Integer.toBinaryString(result)); // 110
```

相同为 `0`，不同为 `1`。

性质：

```text
value ^ value = 0
value ^ 0     = value
```

### 4.14.4 按位取反 ~

```java
int value = 0;
int result = ~value;

System.out.println(result); // -1
```

`int` 使用补码表示，全部位取反后得到 `-1`。

### 4.14.5 位掩码示例

定义权限：

```java
static final int READ = 1 << 0;
static final int WRITE = 1 << 1;
static final int DELETE = 1 << 2;
```

组合权限：

```java
int permissions = READ | WRITE;
```

判断权限：

```java
boolean canWrite =
        (permissions & WRITE) != 0;
```

添加权限：

```java
permissions |= DELETE;
```

移除权限：

```java
permissions &= ~WRITE;
```

切换权限：

```java
permissions ^= READ;
```

位掩码适合底层协议和紧凑标志。

业务状态复杂时，优先使用：

- `EnumSet`；
- 专门权限对象；
- 明确字段。

## 4.15 左移运算符

```java
int result = value << distance;
```

### 4.15.1 基本语义

左移时：

- 低位补零；
- 高位被丢弃；
- 结果仍为左操作数提升后的整数类型。

```java
int value = 3;
int result = value << 2;

System.out.println(result); // 12
```

二进制：

```text
0011
↓ 左移 2 位
1100
```

### 4.15.2 与乘以 2 的幂

在不溢出的前提下：

```text
value << n
近似等于
value * 2^n
```

但左移可能溢出：

```java
int value = 1 << 31;

System.out.println(value); // Integer.MIN_VALUE
```

### 4.15.3 byte 左移结果是 int

```java
byte value = 1;

int result = value << 1;
```

不能直接赋给 `byte`，除非显式转换。

## 4.16 右移运算符

Java 有两种右移。

### 4.16.1 带符号右移 >>

```java
int value = -8;
int result = value >> 1;

System.out.println(result); // -4
```

高位使用符号位填充。

负数高位补 `1`，正数高位补 `0`。

### 4.16.2 无符号右移 >>>

```java
int value = -8;
int result = value >>> 1;

System.out.println(result); // 2147483644
```

高位统一补 `0`。

### 4.16.3 正数时两者通常相同

```java
int value = 8;

System.out.println(value >> 1);  // 4
System.out.println(value >>> 1); // 4
```

### 4.16.4 负数时差异明显

```text
>>
→ 保留符号趋势

>>>
→ 当作无符号位序列向右移动
```

### 4.16.5 Java 没有 unsigned int 基本类型

Java 8 起提供部分无符号工具方法：

```java
Integer.toUnsignedString(value)
Integer.compareUnsigned(first, second)
Integer.divideUnsigned(first, second)
Integer.remainderUnsigned(first, second)
```

这些方法以相同位模式解释无符号语义。

## 4.17 移位距离截断

### 4.17.1 int 只使用低 5 位

对于 `int`：

```text
实际移位距离
=
distance & 0x1F
```

即范围：

```text
0 ～ 31
```

示例：

```java
System.out.println(1 << 32);
```

等价于：

```java
System.out.println(1 << 0);
```

结果是：

```text
1
```

### 4.17.2 long 只使用低 6 位

对于 `long`：

```text
实际移位距离
=
distance & 0x3F
```

即范围：

```text
0 ～ 63
```

### 4.17.3 负移位距离也会截断

```java
int result = 1 << -1;
```

`-1` 的低 5 位相当于 `31`，因此等价于：

```java
1 << 31
```

语法合法，但极不直观。

工程代码不应依赖异常移位距离。

## 4.18 赋值运算符

### 4.18.1 基本赋值

```java
int value = 10;
```

赋值表达式本身有值。

```java
int first;
int second;

first = second = 10;
```

赋值运算符从右向左结合：

```text
second = 10
↓
first = second
```

### 4.18.2 连续赋值的可读性

虽然合法：

```java
first = second = third = 0;
```

复杂对象和业务状态不建议连续赋值。

### 4.18.3 赋值与对象引用

```java
User first = new User();
User second = first;
```

复制的是引用值，不是对象。

### 4.18.4 赋值表达式用于条件

Java 条件必须是 `boolean`。

```java
boolean enabled;

if (enabled = checkEnabled()) {
}
```

语法合法，但容易误读为比较。

更清晰：

```java
enabled = checkEnabled();

if (enabled) {
}
```

避免在条件中使用赋值表达式。

## 4.19 复合赋值运算符

常见复合赋值：

```text
+=  -=  *=  /=  %=
&=  |=  ^=
<<= >>= >>>=
```

### 4.19.1 包含隐式转换

```java
short value = 1;
value += 1;
```

可以编译。

近似：

```java
value = (short) (value + 1);
```

### 4.19.2 普通赋值不能直接通过

```java
short value = 1;

// value = value + 1; // 编译错误
```

### 4.19.3 可能发生静默溢出

```java
byte value = 127;
value += 1;

System.out.println(value); // -128
```

### 4.19.4 左侧只求值一次

假设：

```java
array[index()] += value;
```

`index()` 只调用一次。

而机械展开成：

```java
array[index()] =
        (int) (array[index()] + value);
```

会调用两次，不完全等价。

因此：

```text
E1 op= E2
```

不仅包含转换，还保证 `E1` 只求值一次。

## 4.20 条件运算符

条件运算符：

```java
condition ? whenTrue : whenFalse
```

### 4.20.1 本身是表达式

```java
String result =
        score >= 60 ? "PASS" : "FAIL";
```

可以直接产生值。

### 4.20.2 只求值一个分支

```java
String value =
        user != null
        ? user.getName()
        : "anonymous";
```

只有被选中的分支会执行。

### 4.20.3 类型推断

```java
var result = condition ? 1 : 2.0;
```

结果类型是 `double`。

### 4.20.4 包装类型拆箱风险

```java
Integer value = null;

int result =
        condition ? value : 0;
```

当条件为 `true` 时，可能拆箱并抛出 `NullPointerException`。

### 4.20.5 嵌套条件表达式

```java
String level =
        score >= 90 ? "A"
        : score >= 80 ? "B"
        : score >= 60 ? "C"
        : "D";
```

语法合法，但可读性较差。

更适合：

```java
String level;

if (score >= 90) {
    level = "A";
} else if (score >= 80) {
    level = "B";
} else if (score >= 60) {
    level = "C";
} else {
    level = "D";
}
```

### 4.20.6 条件表达式与 switch 表达式

简单二选一：

```java
condition ? first : second
```

多个离散分支：

```java
switch (type) {
    case A -> first;
    case B -> second;
    default -> fallback;
}
```

完整 `switch` 表达式见 `05-流程控制.md`。

## 4.21 instanceof 运算符

### 4.21.1 基本类型判断

```java
if (value instanceof String) {
    String text = (String) value;
    System.out.println(text.length());
}
```

### 4.21.2 模式匹配

现代 Java 推荐：

```java
if (value instanceof String text) {
    System.out.println(text.length());
}
```

同时完成：

- 类型检查；
- 类型转换；
- 模式变量声明。

### 4.21.3 null instanceof

```java
Object value = null;

System.out.println(value instanceof String); // false
```

不会抛异常。

### 4.21.4 模式变量的作用域

```java
if (!(value instanceof String text)) {
    return;
}

System.out.println(text.length());
```

编译器通过控制流分析确定后续路径中匹配成功，因此允许使用 `text`。

### 4.21.5 不要滥用 instanceof

大量代码：

```java
if (value instanceof TypeA) {
} else if (value instanceof TypeB) {
} else if (value instanceof TypeC) {
}
```

可能意味着：

- 多态设计不足；
- 类型职责混乱；
- 应使用策略模式；
- 应使用 sealed class 与模式匹配；
- 外部数据模型未被规范化。

`instanceof` 本身不是坏代码，关键是场景。

## 4.22 运算符优先级

Java 运算符存在优先级。

常见大致顺序：

```text
后缀
↓
一元
↓
乘除余
↓
加减
↓
移位
↓
关系
↓
相等
↓
按位与
↓
按位异或
↓
按位或
↓
逻辑与
↓
逻辑或
↓
条件运算符
↓
赋值
```

不建议机械背完整表。

### 4.22.1 乘法高于加法

```java
int result = 1 + 2 * 3;

System.out.println(result); // 7
```

### 4.22.2 && 高于 ||

```java
boolean result =
        enabled && count > 0 || force;
```

等价于：

```java
boolean result =
        (enabled && count > 0) || force;
```

但更推荐显式括号：

```java
boolean result =
        (enabled && count > 0) || force;
```

### 4.22.3 位运算与相等比较容易误读

```java
if ((flags & MASK) != 0) {
}
```

不要省略括号：

```java
// if (flags & MASK != 0) { } // 编译或语义问题
```

### 4.22.4 括号用于表达意图

括号的价值不仅是改变优先级，更重要的是让读者快速理解分组。

## 4.23 结合性

结合性决定相同优先级运算符如何分组。

### 4.23.1 左结合

大多数二元算术运算符左结合：

```java
int result = 10 - 3 - 2;
```

等价于：

```java
int result = (10 - 3) - 2;
```

结果是：

```text
5
```

### 4.23.2 赋值右结合

```java
first = second = 10;
```

等价于：

```java
first = (second = 10);
```

### 4.23.3 条件运算符右结合

```java
conditionA
        ? first
        : conditionB
        ? second
        : third;
```

等价于：

```java
conditionA
        ? first
        : (conditionB ? second : third);
```

语法合法，但嵌套过多应改写。

### 4.23.4 结合性不等于求值顺序

表达式如何分组，与操作数何时实际求值，不是同一个问题。

## 4.24 求值顺序

### 4.24.1 Java 通常从左到右求值操作数

```java
int result = first() + second();
```

先调用 `first()`，再调用 `second()`。

### 4.24.2 方法参数从左到右求值

```java
execute(first(), second(), third());
```

求值顺序：

```text
first()
↓
second()
↓
third()
↓
调用 execute
```

### 4.24.3 数组访问顺序

```java
array[index()] = value();
```

通常先求值：

```text
array
↓
index()
↓
value()
↓
执行赋值
```

### 4.24.4 短路运算可能跳过右侧

```java
first() && second()
```

只有 `first()` 返回 `true`，才调用 `second()`。

### 4.24.5 条件运算符只执行一个分支

```java
condition
        ? first()
        : second()
```

只执行一个分支。

### 4.24.6 不要用副作用测试求值规则

虽然 Java 规则明确：

```java
int result = value++ + ++value;
```

但代码难以维护。

工程原则：

```text
一个表达式
尽量只做一件事
```

## 4.25 运算符重载边界

Java 不允许用户为自定义类型定义新的运算符语义。

例如不能让：

```java
moneyA + moneyB
```

自动调用自定义 `Money.add()`。

应写：

```java
Money total = moneyA.add(moneyB);
```

### 4.25.1 String 的 + 是语言内建规则

```java
String result = first + second;
```

这不是用户可扩展的运算符重载机制，而是 Java 语言专门定义的字符串拼接规则。

### 4.25.2 数值包装类型依赖拆箱

```java
Integer first = 10;
Integer second = 20;

int result = first + second;
```

这里通常发生：

```text
拆箱
↓
int 加法
↓
得到 int
```

不是 `Integer` 自定义了 `+`。

### 4.25.3 为什么 Java 不开放自定义运算符重载

常见设计考虑：

- 保持语义可预测；
- 避免运算符含义被滥用；
- 减少阅读成本；
- 简化重载解析；
- 鼓励使用有意义的方法名。

## 4.26 常见表达式陷阱

### 4.26.1 拼接与加法混淆

```java
System.out.println("sum=" + first + second);
```

可能不是预期的数值和。

正确：

```java
System.out.println(
        "sum=" + (first + second)
);
```

### 4.26.2 整数除法后再赋给 double

```java
double result = first / second;
```

如果两边都是整数，先发生整数除法。

### 4.26.3 自增混入复杂表达式

```java
array[index++] = index;
```

代码虽短，语义不直观。

### 4.26.4 引用使用 == 比较内容

```java
if (first == second) {
}
```

对引用类型比较的是身份。

### 4.26.5 短路顺序错误

```java
if (text.length() > 0 && text != null) {
}
```

先访问对象，可能空指针。

### 4.26.6 使用 & 代替 &&

```java
if (user != null & user.isEnabled()) {
}
```

右侧总会执行，可能抛异常。

### 4.26.7 位掩码缺少括号

```java
if ((flags & MASK) != 0) {
}
```

位运算与比较应显式分组。

### 4.26.8 移位代替乘法造成可读性下降

```java
int result = value << 3;
```

除非代码明确处理位协议或底层算法，否则：

```java
int result = value * 8;
```

通常更清晰。

### 4.26.9 条件运算符嵌套过深

```java
String result =
        a ? b
        : c ? d
        : e ? f
        : g;
```

应改为 `if`、`switch` 或独立方法。

### 4.26.10 条件中赋值

```java
if (enabled = check()) {
}
```

虽然合法，但极易误读。

## 4.29 易错点

### 误区一：算术表达式的类型由目标变量决定

**错误。**

表达式先根据操作数确定类型，之后才执行赋值转换。

### 误区二：byte + byte 的结果仍是 byte

**错误。**

两边通常先提升为 `int`。

### 误区三：只要最终变量是 double，就一定执行浮点除法

**错误。**

如果两个操作数都是整数，会先执行整数除法。

### 误区四：Java 的 % 永远返回非负结果

**错误。**

负被除数可能得到负余数。

### 误区五：++ 只是语法更短，不会影响表达式结果

**错误。**

前缀和后缀形式产生的表达式值不同。

### 误区六：value++ + ++value 适合展示高级技巧

**错误。**

虽然规则明确，但可读性和维护性很差。

### 误区七：count++ 是原子操作

**错误。**

它通常包含读、改、写多个步骤。

### 误区八：字符串的 == 比较内容

**错误。**

引用类型 `==` 比较对象身份。

### 误区九：字符串字面量使用 == 返回 true，所以这种写法可靠

**错误。**

这可能来自字符串池复用，不能作为内容比较依据。

### 误区十：任何引用都可以安全调用 equals(null)

**错误。**

引用本身可能是 `null`。

### 误区十一：&& 与 & 对 boolean 完全相同

**错误。**

`&&` 会短路，`&` 总是求值两边。

### 误区十二：|| 与 | 对 boolean 完全相同

**错误。**

`||` 会短路，`|` 总是求值两边。

### 误区十三：短路表达式右侧一定会执行

**错误。**

结果可由左侧确定时，右侧不会执行。

### 误区十四：位运算只能用于二进制字面量

**错误。**

它用于整数值，字面量写法不影响位语义。

### 误区十五：左移永远等于乘法且不会溢出

**错误。**

左移可能丢弃高位并发生溢出。

### 误区十六：>> 与 >>> 对负数结果相同

**错误。**

前者补符号位，后者补零。

### 误区十七：Java 移位超过位宽会自动得到 0

**错误。**

移位距离会按低 5 位或低 6 位截断。

### 误区十八：负移位距离会编译失败

**错误。**

它会按截断规则得到实际距离，但代码不应依赖这种写法。

### 误区十九：复合赋值只是普通赋值的缩写

**错误。**

它还包含隐式转换，并保证左侧只求值一次。

### 误区二十：value += 1 能编译就代表不会溢出

**错误。**

写回原类型时可能静默回绕。

### 误区二十一：三元运算符会先计算两个分支再选一个

**错误。**

只执行被选中的分支。

### 误区二十二：三元运算符不会发生装箱或拆箱

**错误。**

结果类型推断可能触发装箱、拆箱和数值提升。

### 误区二十三：instanceof null 会抛空指针

**错误。**

结果是 `false`。

### 误区二十四：强制类型转换会改变对象的运行时类型

**错误。**

它只改变编译器对引用表达式的类型视图。

### 误区二十五：优先级决定实际求值顺序

**错误。**

优先级决定分组，求值顺序是另一套规则。

### 误区二十六：赋值运算符从左向右结合

**错误。**

赋值通常从右向左结合。

### 误区二十七：Java 不保证方法参数求值顺序

**错误。**

Java 规定从左到右求值。

### 误区二十八：括号只在改变优先级时才有意义

**错误。**

括号还用于表达意图和降低阅读成本。

### 误区二十九：Java 可以为自定义类重载 + 运算符

**错误。**

Java 不支持用户自定义运算符重载。

### 误区三十：Integer 使用 + 是因为 Integer 重载了运算符

**错误。**

通常发生自动拆箱后执行基本类型运算。

## 4.30 工程实践建议

1. 复杂表达式使用括号明确分组，不依赖读者记忆优先级。
2. 一个表达式尽量只完成一个主要动作。
3. 不在表达式中混入多个自增、自减和赋值副作用。
4. 字符串拼接与数值加法混合时显式加括号。
5. 循环中动态拼接大量字符串时使用 `StringBuilder`、`StringJoiner` 或 `Collectors.joining()`。
6. 整数除法前明确是否需要保留小数。
7. 涉及负数周期索引时优先考虑 `Math.floorMod()`。
8. 引用内容比较使用明确的逻辑相等方法，不依赖 `==`。
9. 常量放在 `equals()` 左侧只是一种防空指针技巧，不能替代清晰的空值契约。
10. 空值检查放在短路表达式左侧。
11. 不把重要副作用放在 `&&`、`||` 或三元表达式的被跳过分支中。
12. 位掩码表达式统一加括号：

    ```java
    (flags & MASK) != 0
    ```

13. 业务权限优先使用 `EnumSet` 或专门模型，除非确实需要紧凑位协议。
14. 移位用于底层位语义时写清注释，不用它炫技替代普通乘除法。
15. 不依赖超位宽或负移位距离。
16. 复合赋值处理小整数类型时检查边界和溢出。
17. 三元运算符只用于简短、纯表达式式二选一。
18. 多层条件优先使用 `if`、`switch` 或独立方法。
19. `instanceof` 用于边界适配和安全转型，不应成为替代多态的默认方案。
20. 代码审查时重点关注运算符旁的副作用、空值、溢出和类型提升。
21. 对位运算、移位、数值边界编写明确单元测试。
22. 并发代码中不要把 `++`、`+=` 误认为原子操作。

## 4.32 本章总结

### 4.32.1 算术主线

```text
算术表达式
→ 操作数先决定结果类型
→ 再执行运算
→ 最后进行赋值转换

整数运算
→ 可能溢出

浮点运算
→ 可能产生近似值、NaN 和无穷大
```

### 4.32.2 相等与逻辑主线

```text
基本类型 ==
→ 比较值

引用类型 ==
→ 比较对象身份

equals()
→ 比较类定义的逻辑相等

&& / ||
→ 短路求值

& / |
→ 两边都求值
```

### 4.32.3 位运算主线

```text
&  → 取共同位
|  → 设置位
^  → 切换不同位
~  → 全部取反

<< → 左移补零
>> → 右移补符号位
>>> → 右移补零
```

### 4.32.4 表达式主线

```text
优先级
→ 决定分组

结合性
→ 决定同级运算如何结合

求值顺序
→ Java 通常从左到右求值操作数

短路和条件表达式
→ 可能跳过部分表达式
```

### 4.32.5 面试口述版

Java 运算符的关键不只是记符号，而是理解操作数类型、表达式类型和求值顺序。算术运算会先进行数值提升，`byte`、`short`、`char` 通常先提升为 `int`。整数除法向零截断，浮点除零会得到无穷大或 `NaN`。字符串的 `+` 是语言内建拼接规则，表达式从左向右求值，因此字符串与数值混合时需要用括号表达意图。

`==` 对基本类型比较值，对引用类型比较对象身份；逻辑内容相等通常依赖 `equals()`。`&&` 和 `||` 会短路，`&` 和 `|` 对布尔值时会执行两边。位运算主要用于标志、协议和底层算法，`>>` 保留符号位，`>>>` 高位补零。复合赋值包含隐式类型转换，并保证左侧只求值一次。

优先级决定表达式如何分组，结合性决定同级运算如何结合，实际求值顺序则由 Java 单独规定。工程代码不应通过复杂副作用表达式展示技巧，而应优先保证语义清晰、空值安全和边界可测。
