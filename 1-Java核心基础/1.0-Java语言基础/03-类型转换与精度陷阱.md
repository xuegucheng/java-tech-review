# 类型转换与精度陷阱

## 2.9 变量作用域与变量遮蔽

**2.9.1 作用域**

变量只能在声明它的作用域内使用：

```
if (true) {
int value = 10;
}
```

4

```
System.out.println(value); // 编译错误
```

**2.9.2 局部变量遮蔽成员变量**

```java
public class User {
private String name;
```

3

```
public void setName(String name) {
name = name;
}
}
```

这里左右两边的 name 都是方法参数，实例变量没有被赋值。
正确：

```
public void setName(String name) {
this.name = name;
}
```

其中：
this.name ：当前对象的实例变量
name ：方法参数

**2.9.3 局部代码块不能重复声明同名变量**

```
int value = 10;
```

2

```
{
int value = 20; // 编译错误
}
```

Java 不允许局部作用域中的变量以这种方式遮蔽外层局部变量。
但是局部变量可以遮蔽成员变量。

## 2.10 自动类型转换

自动类型转换通常发生在从较小范围类型转换到较大范围类型时。

**2.10.1 基本转换方向**

```
byte
↓
short
↓
int
↓
long
↓
float
↓
double
```

12

```
char
↓
int
↓
long
↓
float
↓
double
```

示例：

```
byte b = 10;
int i = b;
long l = i;
double d = l;
```

这类转换通常称为宽化转换。

**2.10.2 宽化转换不一定完全保留精度**

容易误以为：
只要是自动转换，就一定不会丢失精度。
这不准确。
例如：

```
long value = 9_007_199_254_740_993L;
double result = value;
```

3

```
System.out.println(result);
```

double 的有效精度有限，某些较大的 long 转为 double 时可能丢失低位精度。
因此：
宽化转换通常不会溢出，但整数转浮点数仍可能丢失精度。

**2.10.3 char 与 short 不能相互自动转换**

尽管二者都是 16 位：

```
char c = 65;
short s = c; // 编译错误
```

因为：
char 是 0～65535
short 是 -32768～32767
两者的取值范围并不互相包含。

## 2.11 强制类型转换

**2.11.1 窄化转换**

```
double d = 10.8;
int i = (int) d;
```

3

```
System.out.println(i); // 10
```

浮点数转整数时：
小数部分直接截断
不是四舍五入

**2.11.2 整数溢出**

```
int value = 130;
byte result = (byte) value;
```

3

```
System.out.println(result); // -126
```

原因是只保留低 8 位。
可以理解为：

```
130 的低 8 位
10000010
```

作为有符号 byte 解释后为 -126 。
强制类型转换不会抛出溢出异常。

**2.11.3 溢出默认不会报错**

```
int value = Integer.MAX_VALUE;
value++;
```

3

```
System.out.println(value); // Integer.MIN_VALUE
```

Java 整数运算默认按照二进制补码回绕，不会自动抛异常。
需要检测溢出时，可以使用：

```
Math.addExact(a, b);
Math.multiplyExact(a, b);
Math.incrementExact(a);
```

发生溢出时会抛出：

```
ArithmeticException
```

## 2.12 整数运算中的类型提升

这是本章的重点。

**2.12.1 byte、short、char 运算会提升为 int**

```
byte a = 1;
byte b = 2;
```

3

```
byte c = a + b; // 编译错误
```

因为：

```
a + b
```

会先提升为：

```
(int) a + (int) b
```

结果类型是 int 。
正确写法：

```
int c = a + b;
```

或者：

```
byte c = (byte) (a + b);
```

但强制转换存在溢出风险。

**2.12.2 编译期常量的特殊情况**

```
byte value = 1 + 2;
```

可以编译。
因为 1 + 2 是编译期常量表达式，编译器直接计算为 3 ，并确认它在 byte 范围内。
但：

```
byte a = 1;
byte b = 2;
byte value = a + b; // 编译错误
```

即使运行时结果看起来肯定是 3，普通变量参与运算后结果类型仍然是 int 。
如果变量是编译期常量：

```
final byte a = 1;
final byte b = 2;
```

3

```
byte value = a + b;
```

通常可以编译，因为编译器能够在编译期计算结果。

**2.12.3 二元数值提升**

两个不同数值类型参与运算时，大致遵循：

```
有 double → 转 double
否则有 float → 转 float
否则有 long → 转 long
否则 → 转 int
```

例如：

```
int a = 10;
long b = 20L;
```

3

```
long result = a + b;
```

又如：

```
long a = 10L;
float b = 20F;
```

3

```
float result = a + b;
```

## 2.13 复合赋值运算

**2.13.1 += 隐含强制转换**

```
short value = 1;
value += 1;
```

可以编译。
其语义近似于：

```
value = (short) (value + 1);
```

而：

```
short value = 1;
value = value + 1;
```

编译错误，因为 value + 1 的结果是 int 。

**2.13.2 复合赋值也可能静默溢出**

```
byte value = 127;
value += 1;
```

3

```
System.out.println(value); // -128
```

因为复合赋值隐含窄化转换，没有编译错误。
因此不能简单认为：
+= 只是 a = a + b 的简写。
二者在类型转换上存在差异。

## 2.14 自增、自减运算

**2.14.1 前置与后置**

```
int a = 1;
int b = a++;
```

结果：

```
a = 2
b = 1
```

而：

```
int a = 1;
int b = ++a;
```

结果：

```
a = 2
b = 2
```

**2.14.2 自增隐含类型转换**

```
byte value = 1;
value++;
```

可以编译。
虽然普通加法：

```
value = value + 1;
```

不能编译，但 ++ 会把结果转换回变量原类型。
同样存在溢出风险：

```
byte value = 127;
value++;
```

3

```
System.out.println(value); // -128
```

**2.14.3 不推荐复杂自增表达式**

```
int i = 1;
i = i++;
```

结果仍然是：

```
i = 1
```

可以粗略理解为：

```
int temp = i;
i = i + 1;
i = temp;
```

这类表达式虽然可以考察求值顺序，但实际开发中应禁止使用。

## 2.15 整数除法与取模

**2.15.1 整数除法**

```
int result = 5 / 2;
```

2

```
System.out.println(result); // 2
```

两个操作数都是整数，结果也是整数，小数部分被截断。
想得到浮点结果：

```
double result = 5.0 / 2;
```

或者：

```
double result = (double) 5 / 2;
```

**2.15.2 除数为零**

整数除以零：

```
int result = 1 / 0;
```

抛出：

```
ArithmeticException
```

浮点数除以零：

```
double result = 1.0 / 0.0;
```

结果是：

```
Infinity
```

而：

```
double result = 0.0 / 0.0;
```

结果是：

```
NaN
```

**2.15.3 取模符号**

```
System.out.println(5 % 3); // 2
System.out.println(-5 % 3); // -2
System.out.println(5 % -3); // 2
```

Java 中 % 的结果符号跟随被除数。
需要数学意义上的非负模时，可以使用：

```
Math.floorMod(-5, 3); // 1
```

## 2.16 浮点数精度

**2.16.1 经典问题**

```
System.out.println(0.1 + 0.2);
```

可能输出：

```
0.30000000000000004
```

原因不是 Java 计算错误，而是：
许多十进制小数无法被有限位二进制浮点数精确表示。
类似十进制无法有限表示：

```
1 / 3 = 0.333333...
```

二进制中， 0.1 也是无限循环小数。

**2.16.2 不要直接用 == 比较浮点计算结果**

```
double result = 0.1 + 0.2;
```

2

```
System.out.println(result == 0.3); // false
```

通常使用误差范围：

```
double epsilon = 1e-10;
```

2

```
boolean equal = Math.abs(result - 0.3) < epsilon;
```

误差值需要根据业务场景设计，不能所有场景统一使用一个常数。

**2.16.3 金额为什么不能直接使用 double**

金额通常要求：
十进制语义
精确计算
明确舍入方式
可审计
double 是二进制浮点数，不适合精确金额计算。
推荐：

```
BigDecimal amount = new BigDecimal("0.1");
```

不推荐：

```
BigDecimal amount = new BigDecimal(0.1);
```

后者会把 double 已经存在的二进制误差带入 BigDecimal 。
也可以使用：

```
BigDecimal amount = BigDecimal.valueOf(0.1);
```

BigDecimal 的完整比较、除法和 scale 问题，后续包装类型与数值处理部分再展开。

**2.16.4 NaN 的特殊性**

```
double value = Double.NaN;
```

2

```
System.out.println(value == value); // false
```

NaN 与任何值比较都不相等，包括它自己。
判断应使用：

```
Double.isNaN(value);
```

## 2.17 常量与 final 变量

这一部分先讲变量语义， final 的完整规则放在后续专章。

**2.17.1 final 局部变量**

```
final int value = 10;
```

初始化后不能再次赋值：

```
value = 20; // 编译错误
```

**2.17.2 空白 final**

```
final int value;
```

2

```
if (condition) {
value = 1;
} else {
value = 2;
}
```

只要编译器能确定它最终只被赋值一次，就可以。

**2.17.3 final 引用**

```
final List<String> list = new ArrayList<>();
list.add("Java");
```

可以修改对象内容。
但不能重新赋值：

```
list = new ArrayList<>(); // 编译错误
```

所以：
final 引用保证引用值不再变化，不保证引用对象不可变。

**2.17.4 final 变量不一定是编译期常量**

```
final int a = 10;
```

这是编译期常量。
但：

```
final int b = Integer.parseInt("10");
```

虽然 b 不能再次赋值，但其值需要运行时计算，不属于编译期常量。
编译期常量通常需要满足：
基本类型或 String
使用 final
声明时初始化
初始化表达式本身是常量表达式
