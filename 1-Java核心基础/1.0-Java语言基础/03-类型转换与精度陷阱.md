## 3.2 自动类型转换

自动类型转换通常发生在从较小范围类型转换到较大范围类型时。

**3.2.1 基本转换方向**

```
byte
↓
short
↓
int
↓
long
↓
float
↓
double
char
↓
int
↓
long
↓
float
↓
double
```

示例：

```
byte b = 10;
int i = b;
long l = i;
double d = l;
```

这类转换通常称为宽化转换。

**3.2.2 宽化转换不一定完全保留精度**

容易误以为：

- 只要是自动转换，就一定不会丢失精度。
- 这不准确。

例如：

```java
long value = 9_007_199_254_740_993L;
double result = value;
System.out.println(result);
```

double 的有效精度有限，某些较大的 long 转为 double 时可能丢失低位精度。
因此：
宽化转换通常不会溢出，但整数转浮点数仍可能丢失精度。

**3.2.3 char 与 short 不能相互自动转换**

尽管二者都是 16 位：

```
char c = 65;
short s = c; // 编译错误
```

因为：

- char 是 0～65535
- short 是 -32768～32767

两者的取值范围并不互相包含。

## 3.3 强制类型转换

**3.3.1 窄化转换**

```java
double d = 10.8;
int i = (int) d;
System.out.println(i); // 10
```

浮点数转整数时：

- 小数部分直接截断
- 不是四舍五入

**3.3.2 整数溢出**

```java
int value = 130;
byte result = (byte) value;
System.out.println(result); // -126
```

原因是只保留低 8 位。
可以理解为：

```
130 的低 8 位
10000010
```

作为有符号 byte 解释后为 -126 。
强制类型转换不会抛出溢出异常。

**3.3.3 溢出默认不会报错**

```java
int value = Integer.MAX_VALUE;
value++;
System.out.println(value); // Integer.MIN_VALUE
```

Java 整数运算默认按照二进制补码回绕，不会自动抛异常。
需要检测溢出时，可以使用：

```
Math.addExact(a, b);
Math.multiplyExact(a, b);
Math.incrementExact(a);
```

发生溢出时会抛出：

```
ArithmeticException
```

## 3.4 整数运算中的类型提升

这是本章的重点。

**3.4.1 byte、short、char 运算会提升为 int**

```
byte a = 1;
byte b = 2;
byte c = a + b; // 编译错误
```

因为：

```
a + b
```

会先提升为：

```
(int) a + (int) b
```

结果类型是 int 。
正确写法：

```
int c = a + b;
```

或者：

```
byte c = (byte) (a + b);
```

但强制转换存在溢出风险。

**3.4.2 编译期常量的特殊情况**

```
byte value = 1 + 2;
```

可以编译。
因为 1 + 2 是编译期常量表达式，编译器直接计算为 3 ，并确认它在 byte 范围内。
但：

```
byte a = 1;
byte b = 2;
byte value = a + b; // 编译错误
```

即使运行时结果看起来肯定是 3，普通变量参与运算后结果类型仍然是 int 。
如果变量是编译期常量：

```
final byte a = 1;
final byte b = 2;
byte value = a + b;
```

通常可以编译，因为编译器能够在编译期计算结果。

**3.4.3 二元数值提升**

两个不同数值类型参与运算时，大致遵循：

```
有 double → 转 double
否则有 float → 转 float
否则有 long → 转 long
否则 → 转 int
```

例如：

```
int a = 10;
long b = 20L;
long result = a + b;
```

又如：

```
long a = 10L;
float b = 20F;
float result = a + b;
```

## 3.5 复合赋值运算

**3.5.1 += 隐含强制转换**

```
short value = 1;
value += 1;
```

可以编译。
其语义近似于：

```
value = (short) (value + 1);
```

而：

```
short value = 1;
value = value + 1;
```

编译错误，因为 value + 1 的结果是 int 。

**3.5.2 复合赋值也可能静默溢出**

```java
byte value = 127;
value += 1;
System.out.println(value); // -128
```

因为复合赋值隐含窄化转换，没有编译错误。
因此不能简单认为：
+= 只是 a = a + b 的简写。
二者在类型转换上存在差异。

## 3.6 自增隐含类型转换

自增、自减的完整求值规则见 04-运算符详解。本节只关注其会将结果隐式转换回变量原类型，因此 byte、short、char 仍可能静默溢出。

```java
byte value = 127;
value++;
System.out.println(value); // -128
```

## 3.8 浮点数精度

**3.8.1 经典问题**

```java
System.out.println(0.1 + 0.2);
```

可能输出：

```
0.30000000000000004
```

原因不是 Java 计算错误，而是：
许多十进制小数无法被有限位二进制浮点数精确表示。
类似十进制无法有限表示：

```
1 / 3 = 0.333333...
```

二进制中， 0.1 也是无限循环小数。

**3.8.2 不要直接用 == 比较浮点计算结果**

```java
double result = 0.1 + 0.2;
System.out.println(result == 0.3); // false
```

通常使用误差范围：

```
double epsilon = 1e-10;
boolean equal = Math.abs(result - 0.3) < epsilon;
```

误差值需要根据业务场景设计，不能所有场景统一使用一个常数。

**3.8.3 金额为什么不能直接使用 double**

金额通常要求：

- 十进制语义
- 精确计算
- 明确舍入方式
- 可审计

double 是二进制浮点数，不适合精确金额计算。
推荐：

```
BigDecimal amount = new BigDecimal("0.1");
```

不推荐：

```
BigDecimal amount = new BigDecimal(0.1);
```

后者会把 double 已经存在的二进制误差带入 BigDecimal 。
也可以使用：

```
BigDecimal amount = BigDecimal.valueOf(0.1);
```

BigDecimal 的完整比较、除法和 scale 问题，后续包装类型与数值处理部分再展开。

**3.8.4 NaN 的特殊性**

```java
double value = Double.NaN;
System.out.println(value == value); // false
```

NaN 与任何值比较都不相等，包括它自己。
判断应使用：

```
Double.isNaN(value);
```
