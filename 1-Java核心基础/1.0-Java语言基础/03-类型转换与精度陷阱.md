## 3.2 Java 类型转换体系

Java 中常见的转换可以分为：

```text
类型转换
├── 基本类型转换
│   ├── 自动宽化
│   ├── 强制窄化
│   ├── 一元数值提升
│   ├── 二元数值提升
│   ├── 复合赋值中的隐式转换
│   └── 常量表达式窄化
├── 基本类型与包装类型
│   ├── 装箱
│   └── 拆箱
└── 引用类型转换
    ├── 向上转型
    ├── 向下转型
    └── 接口与数组转换
```

本章核心关注基本数值转换。

### 3.2.1 隐式转换与显式转换

隐式转换由编译器自动完成：

```java
int count = 100;
long total = count;
```

显式转换需要程序员写出目标类型：

```java
long total = 100L;
int count = (int) total;
```

是否需要显式转换，取决于：

- 源类型；
- 目标类型；
- 转换是否可能丢失范围或精度；
- 当前语法上下文；
- 表达式是否为编译期常量。

### 3.2.2 合法转换不等于安全转换

以下代码合法：

```java
int value = 16_777_217;
float result = value;
```

但结果可能变成：

```text
16777216.0
```

原因不是转换非法，而是 `float` 无法精确表示该整数。

因此应区分：

```text
编译是否允许
≠
值是否保持完全不变
≠
业务结果是否可接受
```

## 3.3 基本数值类型的范围关系

常见整数类型：

```text
byte
→ short
→ int
→ long
```

浮点类型：

```text
float
→ double
```

但 Java 的数值转换并不是一条简单直线。

### 3.3.1 常见自动宽化路径

```text
byte  → short → int → long → float → double
short → int   → long → float → double
char  → int   → long → float → double
int   → long  → float → double
long  → float → double
float → double
```

注意：

- `byte` 与 `char` 之间不能自动转换；
- `short` 与 `char` 之间不能自动转换；
- `boolean` 不参与任何数值转换。

### 3.3.2 范围扩大不代表精度一定保留

整数转更宽整数通常可以保留值：

```java
int value = 100;
long result = value;
```

但整数转浮点即使属于宽化转换，也可能丢失精度：

```java
long value = Long.MAX_VALUE;
double result = value;
```

`double` 的数值范围很大，但有效精度有限。

因此：

```text
范围更大
不一定
精确表示能力更强
```

## 3.4 自动宽化转换

### 3.4.1 整数类型宽化

```java
byte source = 100;
int target = source;
```

值保持不变。

```java
int source = 100;
long target = source;
```

同样安全。

### 3.4.2 char 宽化为整数

```java
char letter = 'A';
int codeUnit = letter;

System.out.println(codeUnit); // 65
```

`char` 可以自动转换为：

```text
int
long
float
double
```

但不能自动转为：

```text
byte
short
```

因为 `char` 的范围是 `0～65535`，与 `byte`、`short` 的范围并非包含关系。

### 3.4.3 int 转 long

```java
int source = Integer.MAX_VALUE;
long target = source;
```

`long` 可以精确表示全部 `int` 值。

### 3.4.4 int 转 float 可能丢失精度

```java
int source = 16_777_217;
float target = source;

System.out.println(target); // 1.6777216E7
```

`float` 只有约 24 位二进制有效精度，无法精确表示所有 32 位整数。

可以理解为：

```text
int
→ 范围较小，但整数精确

float
→ 范围更大，但有效精度有限
```

### 3.4.5 long 转 double 也可能丢失精度

```java
long source = 9_007_199_254_740_993L;
double target = source;

System.out.println((long) target);
```

可能得到：

```text
9007199254740992
```

`double` 能精确表示的连续整数范围大致到：

```text
-2^53 ～ 2^53
```

超过这个范围后，相邻整数可能映射到同一个 `double`。

### 3.4.6 float 转 double 不会恢复丢失精度

```java
float first = 0.1F;
double second = first;
```

`second` 会精确保存当前 `float` 的值，但无法恢复最初十进制 `0.1` 已经丢失的部分。

```text
十进制 0.1
↓ 转成 float 时近似
float 近似值
↓ 转成 double
更高精度地保存这个近似值
```

## 3.5 强制窄化转换

### 3.5.1 基本语法

```java
long source = 100L;
int target = (int) source;
```

显式强转代表：

> 程序员要求编译器允许这次转换，并自行承担可能的值变化风险。

### 3.5.2 大整数转小整数

```java
int source = 130;
byte target = (byte) source;

System.out.println(target); // -126
```

过程可以理解为：

```text
130 的二进制低 8 位
→ 10000010
→ 按 byte 补码解释
→ -126
```

整数窄化通常保留低位，丢弃高位。

### 3.5.3 强转不会自动检查越界

```java
long source = Long.MAX_VALUE;
int target = (int) source;

System.out.println(target); // -1
```

不会抛出异常。

因此，不能把强制转换理解成：

```text
如果超范围就报错
```

更准确的是：

```text
按语言规则截断或转换
可能得到完全不同的值
```

### 3.5.4 char 与负数

```java
int source = -1;
char target = (char) source;

System.out.println((int) target); // 65535
```

`char` 是无符号 16 位整数类型，窄化后按低 16 位解释。

### 3.5.5 浮点转整数

```java
double source = 12.9;
int target = (int) source;

System.out.println(target); // 12
```

浮点转整数会向零截断：

```text
12.9  → 12
-12.9 → -12
```

这不是四舍五入。

### 3.5.6 NaN 转整数

```java
int value = (int) Double.NaN;

System.out.println(value); // 0
```

### 3.5.7 无穷大转整数

```java
System.out.println((int) Double.POSITIVE_INFINITY);
System.out.println((int) Double.NEGATIVE_INFINITY);
```

结果分别为：

```text
Integer.MAX_VALUE
Integer.MIN_VALUE
```

浮点转整数的规则包括：

```text
NaN
→ 0

正无穷或超出最大范围
→ 目标整数最大值

负无穷或低于最小范围
→ 目标整数最小值

普通有限值
→ 向零截断
```

### 3.5.8 浮点转整数不会取模回绕

整数到小整数通常保留低位。

浮点到整数则不同：

```text
整数窄化
→ 截断高位

浮点转整数
→ 向零取整后进行范围饱和
```

不能混为同一种规则。

## 3.6 常量表达式窄化

### 3.6.1 编译期常量可以直接赋给较小整数类型

```java
byte first = 127;
short second = 32_767;
char third = 65;
```

虽然整数字面量默认是 `int`，但编译器可以证明这些常量值位于目标类型范围内，因此允许赋值。

### 3.6.2 超出范围会编译失败

```java
// byte value = 128; // 编译错误
```

因为 `128` 超出 `byte` 范围。

### 3.6.3 变量不享受同样规则

```java
int source = 127;

// byte target = source; // 编译错误
```

虽然运行时 `source` 当前等于 `127`，但它不是编译期常量变量。

### 3.6.4 final 常量变量

```java
final int source = 127;
byte target = source;
```

如果满足编译期常量变量条件，可以直接窄化。

但下面不行：

```java
final int source = Integer.parseInt("127");

// byte target = source; // 编译错误
```

因为初始化表达式需要运行时计算。

完整的常量变量和编译期常量规则见 `17-final与常量设计.md`。

### 3.6.5 常量表达式计算后再窄化

```java
byte value = 100 + 20;
```

`100 + 20` 是编译期常量表达式，结果 `120` 在 `byte` 范围内，因此可以编译。

```java
// byte value = 100 + 30; // 编译错误
```

结果 `130` 超出范围。

## 3.7 一元数值提升

一元数值提升常见于：

- 一元 `+`；
- 一元 `-`；
- 按位取反 `~`。

### 3.7.1 byte、short、char 会提升为 int

```java
byte value = 10;
int result = -value;
```

`-value` 的结果类型是 `int`。

错误：

```java
byte value = 10;

// byte result = -value; // 编译错误
```

需要显式转换：

```java
byte result = (byte) -value;
```

### 3.7.2 char 按位取反

```java
char value = 'A';
int result = ~value;
```

结果类型同样是 `int`。

### 3.7.3 一元提升不改变变量本身类型

```java
byte value = 10;
int result = -value;
```

这里：

```text
value 的类型
→ 仍然是 byte

表达式 -value 的类型
→ int
```

## 3.8 二元数值提升

### 3.8.1 基本规则

对两个数值操作数，Java 通常按以下优先级提升：

```text
如果任一操作数是 double
→ 两边转为 double

否则如果任一操作数是 float
→ 两边转为 float

否则如果任一操作数是 long
→ 两边转为 long

否则
→ 两边转为 int
```

### 3.8.2 byte + byte 为什么是 int

```java
byte first = 10;
byte second = 20;

// byte result = first + second; // 编译错误
int result = first + second;
```

`byte`、`short` 和 `char` 参与算术运算时，通常先提升为 `int`。

### 3.8.3 short + short

```java
short first = 10;
short second = 20;

int result = first + second;
```

结果仍然是 `int`。

### 3.8.4 char + char

```java
char first = 'A';
char second = 1;

int result = first + second;

System.out.println(result); // 66
```

结果类型是 `int`，不是 `char`。

### 3.8.5 int 与 long

```java
int first = 10;
long second = 20L;

long result = first + second;
```

`int` 被提升为 `long`。

### 3.8.6 long 与 float

```java
long first = 9_007_199_254_740_993L;
float second = 1.0F;

float result = first + second;
```

`long` 会转为 `float`，可能丢失大量精度。

### 3.8.7 float 与 double

```java
float first = 0.1F;
double second = 0.2;

double result = first + second;
```

`float` 会转为 `double`，但不能恢复原先已经丢失的精度。

## 3.9 复合赋值中的隐式转换

### 3.9.1 += 隐含强制转换

```java
short value = 1;
value += 1;
```

可以编译。

其语义近似：

```java
value = (short) (value + 1);
```

### 3.9.2 普通赋值不能直接通过

```java
short value = 1;

// value = value + 1; // 编译错误
```

因为：

```text
value + 1
→ int

int
→ 不能隐式赋给 short
```

### 3.9.3 隐式窄化可能溢出

```java
byte value = 127;
value += 1;

System.out.println(value); // -128
```

`+=` 可以编译，不代表结果安全。

### 3.9.4 复合赋值不完全等价于普通赋值

```java
E1 op= E2
```

大致等价于：

```java
E1 = (T) (E1 op E2)
```

其中 `T` 是左侧变量类型。

还要注意：

- 左侧表达式只求值一次；
- 包含隐式转换；
- 可能发生溢出；
- 对数组元素和字段访问尤其重要。

## 3.10 自增与自减

### 3.10.1 byte 可以直接自增

```java
byte value = 127;
value++;

System.out.println(value); // -128
```

`++` 内部包含加一和转换回原变量类型的语义。

### 3.10.2 ++ 不等于普通加法赋值

```java
byte value = 1;

value++;
```

可以编译。

但：

```java
// value = value + 1; // 编译错误
```

### 3.10.3 前缀与后缀

```java
int first = 10;
int second = first++;
```

结果：

```text
second = 10
first = 11
```

前缀：

```java
int first = 10;
int second = ++first;
```

结果：

```text
first = 11
second = 11
```

完整求值顺序见 `04-运算符详解.md`。

### 3.10.4 ++ 仍可能溢出

```java
int value = Integer.MAX_VALUE;
value++;

System.out.println(value); // Integer.MIN_VALUE
```

自增不会自动抛出溢出异常。

## 3.11 条件运算符的类型推断

三元运算符：

```java
条件 ? 表达式一 : 表达式二
```

本身是一个表达式，需要推导统一结果类型。

### 3.11.1 int 与 double

```java
var result = condition ? 1 : 2.0;
```

`result` 类型是 `double`。

即使运行时总是选择第一个分支，也不改变编译期类型推断。

### 3.11.2 byte 与 int 常量

```java
byte value = 10;
var result = condition ? value : 20;
```

如果 `20` 是可表示为 `byte` 的整型常量，结果类型可能保持为 `byte`。

但复杂规则不建议依赖记忆，应通过显式类型或局部变量提高可读性。

### 3.11.3 基本类型与包装类型

```java
Integer value = null;
int result = condition ? value : 0;
```

当选择 `value` 分支时，可能触发拆箱并抛出 `NullPointerException`。

这类问题来自：

- 条件表达式类型推断；
- 自动装箱和拆箱；
- `null`。

完整包装类型规则放在对应专题。

### 3.11.4 引用类型的公共父类型

```java
var result = condition
        ? new ArrayList<String>()
        : new LinkedList<String>();
```

编译器会推导可兼容的引用类型。

复杂泛型场景可能得到交叉类型或不直观类型，业务代码不应过度依赖 `var` 隐藏结果类型。

## 3.12 方法调用中的转换

### 3.12.1 方法调用允许部分宽化转换

```java
static void print(long value) {
}

print(10);
```

`int` 实参可以宽化为 `long`。

### 3.12.2 窄化通常不能自动发生

```java
static void print(byte value) {
}

// print(10); // 通常编译错误
```

虽然字面量 `10` 可以直接赋给 `byte` 变量，但方法调用转换不直接套用所有赋值上下文中的常量窄化规则。

应显式写：

```java
print((byte) 10);
```

### 3.12.3 重载选择与转换

```java
static void print(long value) {
    System.out.println("long");
}

static void print(float value) {
    System.out.println("float");
}

print(10);
```

编译器会根据重载规则选择更合适的方法。

重载涉及：

- 精确匹配；
- 基本类型宽化；
- 装箱；
- 可变参数；
- 更具体方法判断。

完整规则见 `06-方法定义与重载.md`。

### 3.12.4 不要用强转“修复”不清晰 API

```java
print((short) value);
```

强转可能让代码通过，但也可能掩盖：

- API 参数类型设计错误；
- 数据范围不匹配；
- 上游校验缺失；
- 溢出风险。

强转应表达明确、可证明的业务约束，而不是消除编译错误的快捷方式。

## 3.13 引用类型转换概览

本章只建立引用转换边界。

### 3.13.1 向上转型

```java
Dog dog = new Dog();
Animal animal = dog;
```

通常可以隐式完成。

向上转型：

- 不创建新对象；
- 复制引用值；
- 缩小编译期可见能力；
- 保留运行时对象类型。

### 3.13.2 向下转型

```java
Animal animal = new Dog();
Dog dog = (Dog) animal;
```

需要显式转换。

如果实际对象不是目标类型：

```java
Animal animal = new Cat();
Dog dog = (Dog) animal;
```

运行时抛出：

```text
ClassCastException
```

### 3.13.3 instanceof

```java
if (animal instanceof Dog dog) {
    dog.fetch();
}
```

模式匹配可以同时完成类型判断和安全转换。

### 3.13.4 强转不改变对象类型

```java
Animal animal = new Dog();
Dog dog = (Dog) animal;
```

强转改变的是：

```text
编译器如何看待这个引用表达式
```

不是把 `Dog` 对象转换成另一个对象。

完整规则见 `12-多态与动态绑定.md`。

## 3.14 整数溢出

### 3.14.1 int 溢出

```java
int value = Integer.MAX_VALUE;
value++;

System.out.println(value); // Integer.MIN_VALUE
```

Java 整数运算通常按固定宽度补码规则回绕。

### 3.14.2 编译器会检查常量表达式越界

```java
// int value = 2_147_483_648; // 编译错误
```

但运行时运算可以溢出：

```java
int value = Integer.MAX_VALUE;
int result = value + 1;
```

### 3.14.3 long 乘法中的提前溢出

```java
long result = 24 * 60 * 60 * 1000 * 1000;
```

前面的字面量默认是 `int`，表达式先以 `int` 运算，可能在赋给 `long` 前已经溢出。

正确：

```java
long result = 24L * 60 * 60 * 1000 * 1000;
```

关键点：

```text
最终变量是 long
不代表
中间表达式自动使用 long
```

### 3.14.4 求绝对值的边界

```java
System.out.println(Math.abs(Integer.MIN_VALUE));
```

结果仍然是：

```text
Integer.MIN_VALUE
```

因为正数范围比负数范围少一个值：

```text
int 最小值
→ -2147483648

对应正数
→ 2147483648
→ 超出 int 最大值
```

### 3.14.5 取负也可能溢出

```java
int value = Integer.MIN_VALUE;
int result = -value;

System.out.println(result); // Integer.MIN_VALUE
```

## 3.17 浮点除法、无穷大与 NaN

## 3.19 浮点精度

### 3.19.1 0.1 为什么不能精确表示

`double` 使用二进制浮点表示。

十进制 `0.1` 转成二进制后是无限循环小数，只能保存近似值。

```text
十进制 0.1
→ 二进制无限循环
→ 截断并舍入
→ 保存最接近的 double
```

### 3.19.2 典型现象

```java
double result = 0.1 + 0.2;

System.out.println(result);
```

常见输出：

```text
0.30000000000000004
```

### 3.19.3 误差不是 Java 独有

这是 IEEE 754 二进制浮点模型的普遍特征，不是 JVM 或 Java 编译器故障。

### 3.19.4 先运算再转换无法恢复精度

```java
double source = 0.1 + 0.2;
BigDecimal result = BigDecimal.valueOf(source);
```

`BigDecimal` 只能精确保存当前传入值的十进制表示，不能自动知道业务原意是精确的 `0.3`。

### 3.19.5 运算顺序可能影响结果

```java
double first = (large + small) - large;
double second = small + (large - large);
```

浮点加法不满足数学上的严格结合律。

因此：

```text
(a + b) + c
可能不等于
a + (b + c)
```

编译器和 JVM 的优化不能随意破坏 Java 对可观察浮点语义的要求。

## 3.20 double 比较策略

### 3.20.1 不是所有 double 都不能用 ==

下面可以使用 `==`：

```java
double value = 0.0;

if (value == 0.0) {
    // 某些明确语义
}
```

也可以比较已知来自相同离散编码的浮点值。

问题主要出现在：

```text
经过计算得到的近似值
与
理论十进制结果
直接比较
```

### 3.20.2 绝对误差

```java
static boolean approximatelyEqual(
        double first,
        double second,
        double epsilon
) {
    return Math.abs(first - second) <= epsilon;
}
```

适合数值尺度相近的场景。

### 3.20.3 相对误差

当数值跨度很大时，可以考虑：

```java
static boolean approximatelyEqual(
        double first,
        double second,
        double epsilon
) {
    double scale = Math.max(
            1.0,
            Math.max(Math.abs(first), Math.abs(second))
    );

    return Math.abs(first - second) <= epsilon * scale;
}
```

### 3.20.4 epsilon 不能固定套用

`epsilon` 应根据业务确定：

- 坐标计算；
- 科学计算；
- 图形渲染；
- 传感器误差；
- 百分比；
- 汇率展示；

所需容差完全不同。

不能把：

```java
1e-6
```

当成适用于所有场景的万能常量。

### 3.20.5 Double.compare

排序时优先使用：

```java
Double.compare(first, second)
```

它对：

- `NaN`；
- 正零；
- 负零；
- 无穷大；

定义了稳定顺序。

不要手写：

```java
return (int) (first - second);
```

这种写法存在精度、溢出和零差异问题。

## 3.21 金额计算与 BigDecimal

### 3.21.1 为什么金额通常不用 double

假设商品单价为 `¥0.10`，购买三件：

```java
double price = 0.10;
double total = price * 3;

System.out.println(total);
```

结果可能不是精确的：

```text
0.30
```

而是其附近的二进制浮点近似值。

金额计算通常要求：

- 十进制语义；
- 明确小数位；
- 可控舍入；
- 可审计；
- 可复现。

因此常使用 `BigDecimal`。

### 3.21.2 推荐使用字符串构造

```java
BigDecimal price = new BigDecimal("0.10");
BigDecimal quantity = new BigDecimal("3");

BigDecimal total = price.multiply(quantity);

System.out.println(total); // 0.30
```

### 3.21.3 不推荐 new BigDecimal(double)

```java
BigDecimal value = new BigDecimal(0.1);
```

它会精确保存 `double 0.1` 当前的二进制近似值，对应的十进制展开可能很长。

### 3.21.4 BigDecimal.valueOf

```java
BigDecimal value = BigDecimal.valueOf(0.1);
```

`valueOf(double)` 通常通过 `Double.toString()` 的规范字符串构造，结果更符合人类看到的十进制字面量。

但业务金额仍更推荐：

```java
new BigDecimal("0.10")
```

或者从数据库十进制列、文本协议等精确来源获得。

### 3.21.5 BigDecimal 是不可变对象

```java
BigDecimal amount = new BigDecimal("10.00");

amount.add(new BigDecimal("2.00"));

System.out.println(amount); // 10.00
```

需要接收返回值：

```java
amount = amount.add(new BigDecimal("2.00"));
```

## 3.22 BigDecimal 的 scale 与精度

### 3.22.1 scale

```java
BigDecimal first = new BigDecimal("10.00");
BigDecimal second = new BigDecimal("10");
```

二者数值相同，但 scale 不同：

```text
first.scale()  → 2
second.scale() → 0
```

### 3.22.2 precision

```java
BigDecimal value = new BigDecimal("123.45");

System.out.println(value.precision()); // 5
System.out.println(value.scale());     // 2
```

- `precision`：有效数字总位数；
- `scale`：小数位数。

### 3.22.3 stripTrailingZeros

```java
BigDecimal value = new BigDecimal("10.00");
BigDecimal normalized = value.stripTrailingZeros();
```

结果的 scale 可能变化，甚至可能出现负 scale。

因此不能把：

```text
stripTrailingZeros 后 scale 一定是 0
```

当成固定规则。

### 3.22.4 setScale

```java
BigDecimal amount = new BigDecimal("12.345");

BigDecimal rounded = amount.setScale(
        2,
        RoundingMode.HALF_UP
);
```

结果：

```text
12.35
```

如果缩小 scale 且存在非零被舍弃位，又没有指定舍入模式，可能抛出：

```text
ArithmeticException
```

## 3.23 BigDecimal 除法与舍入

### 3.23.1 无限循环小数

```java
BigDecimal first = new BigDecimal("1");
BigDecimal second = new BigDecimal("3");

// first.divide(second); // ArithmeticException
```

因为结果是无限循环小数，无法用有限 scale 精确表示。

### 3.23.2 指定 scale 和舍入模式

```java
BigDecimal result = first.divide(
        second,
        4,
        RoundingMode.HALF_UP
);

System.out.println(result); // 0.3333
```

### 3.23.3 使用 MathContext

```java
MathContext context = new MathContext(
        10,
        RoundingMode.HALF_EVEN
);

BigDecimal result = first.divide(second, context);
```

`MathContext` 控制的是有效数字精度，不等同于固定小数位数。

### 3.23.4 常见舍入模式

| 模式 | 含义 |
|---|---|
| `UP` | 远离零 |
| `DOWN` | 向零 |
| `CEILING` | 向正无穷 |
| `FLOOR` | 向负无穷 |
| `HALF_UP` | 五入，常见业务舍入 |
| `HALF_DOWN` | 五舍 |
| `HALF_EVEN` | 银行家舍入，向偶数 |
| `UNNECESSARY` | 不允许发生舍入 |

### 3.23.5 舍入规则必须属于业务规则

例如：

- 商品展示金额；
- 账单结算；
- 利息；
- 税额；
- 汇率换算；
- 分摊；
- 退款；

可能使用不同舍入规则。

不能由开发人员随意选择：

```java
RoundingMode.HALF_UP
```

就认为业务一定正确。

## 3.24 BigDecimal 比较陷阱

### 3.24.1 equals 同时比较值和 scale

```java
BigDecimal first = new BigDecimal("10.0");
BigDecimal second = new BigDecimal("10.00");

System.out.println(first.equals(second)); // false
```

### 3.24.2 compareTo 比较数值大小

```java
System.out.println(first.compareTo(second)); // 0
```

### 3.24.3 业务相等通常使用 compareTo

```java
boolean sameAmount =
        first.compareTo(second) == 0;
```

### 3.24.4 集合中的影响

```java
Set<BigDecimal> hashSet = new HashSet<>();
hashSet.add(new BigDecimal("10.0"));
hashSet.add(new BigDecimal("10.00"));
```

可能得到两个元素，因为 `HashSet` 依赖 `equals()` 与 `hashCode()`。

而排序集合：

```java
Set<BigDecimal> treeSet = new TreeSet<>();
```

使用自然顺序 `compareTo()`，可能只保留一个。

这会形成：

```text
equals 不相等
但 compareTo 等于 0
```

使用 `BigDecimal` 作为集合键时必须明确规范化策略。

## 3.25 金额建模边界

### 3.25.1 BigDecimal 不自动等于金额模型

```java
BigDecimal amount = new BigDecimal("100.00");
```

只表达一个十进制数，不包含：

- 币种；
- 小数位规则；
- 舍入方式；
- 正负限制；
- 上下限；
- 税费语义。

更完整的金额模型可能是：

```java
public record Money(
        BigDecimal amount,
        Currency currency
) {
}
```

### 3.25.2 元与分

金额也可以使用最小货币单位整数表示：

```java
long amountInFen = 10_520L;
```

表示：

```text
¥105.20
```

优点：

- 整数精确；
- 比较和累加简单；
- 无小数二进制误差。

但仍需处理：

- 溢出；
- 币种；
- 不同币种小数位；
- 税率和汇率；
- 展示格式；
- 分摊余数。

### 3.25.3 选择原则

```text
固定最小单位、范围可控
→ 可考虑 long

需要通用十进制、小数位和舍入
→ BigDecimal

复杂货币业务
→ Money 值对象
```

不要直接用 `double` 作为核心账务金额。

## 3.28 易错点

### 误区一：自动宽化转换一定不会丢失信息

**错误。**

整数转浮点虽然属于宽化转换，但可能丢失精度。

### 误区二：float 的范围比 int 大，所以能精确保存所有 int

**错误。**

范围和有效精度不是同一概念。

### 误区三：强制类型转换越界时会自动抛异常

**错误。**

整数窄化通常静默截断高位。

### 误区四：浮点转整数使用四舍五入

**错误。**

普通强转向零截断。

### 误区五：整数窄化和浮点转整数使用同一种规则

**错误。**

整数窄化保留低位，浮点转整数先向零取整，再按范围饱和。

### 误区六：整数字面量默认会根据目标类型自动选择 byte 或 short

**错误。**

整数字面量通常默认是 `int`，只是赋值上下文允许部分编译期常量窄化。

### 误区七：final int 一定属于编译期常量

**错误。**

只有使用常量表达式初始化并满足规则时才是常量变量。

### 误区八：byte + byte 仍然是 byte

**错误。**

二元数值提升通常先把两边提升为 `int`。

### 误区九：char + char 的结果是 char

**错误。**

结果通常是 `int`。

### 误区十：value += 1 与 value = value + 1 完全相同

**错误。**

复合赋值包含隐式转换，并且左侧只求值一次。

### 误区十一：++ 不会发生溢出

**错误。**

自增会按变量类型规则写回，仍可能回绕。

### 误区十二：目标变量是 long，中间表达式就一定按 long 计算

**错误。**

表达式类型先由操作数决定，赋值发生在运算之后。

### 误区十三：整数溢出会抛 ArithmeticException

**错误。**

普通加减乘和自增通常静默回绕。

### 误区十四：Math.abs() 对所有负数都能得到正数

**错误。**

最小整数值没有对应的同范围正数。

### 误区十五：整数除零和浮点除零都会抛异常

**错误。**

整数除零抛异常，浮点除零产生无穷大或 `NaN`。

### 误区十六：NaN 等于它自己

**错误。**

`NaN == NaN` 为 `false`，应使用 `Double.isNaN()`。

### 误区十七：0.0 与 -0.0 在所有比较规则中都完全相同

**错误。**

基本类型 `==` 认为相等，但倒数和 `Double.equals()` 等行为不同。

### 误区十八：double 精度高，所以适合所有金额计算

**错误。**

二进制浮点无法精确表示许多十进制金额。

### 误区十九：所有 double 都不能使用 == 比较

**不准确。**

问题在于计算产生的近似值和业务容差，不是语法层禁止使用 `==`。

### 误区二十：epsilon 统一设置为 1e-6 就适用于所有场景

**错误。**

容差必须根据数值尺度和业务误差模型确定。

### 误区二十一：把 double 转成 BigDecimal 就能恢复精确十进制原值

**错误。**

如果误差已经产生，后续转换不能自动恢复业务原意。

### 误区二十二：new BigDecimal(0.1) 得到精确的十进制 0.1

**错误。**

它精确保存的是 `double 0.1` 的二进制近似值。

### 误区二十三：BigDecimal 的 add 会修改原对象

**错误。**

`BigDecimal` 不可变，运算返回新对象。

### 误区二十四：BigDecimal 除法一定能直接得到结果

**错误。**

无限循环小数未指定精度或舍入时会抛异常。

### 误区二十五：HALF_UP 是所有财务业务的标准舍入方式

**错误。**

舍入方式必须由具体业务和监管规则决定。

### 误区二十六：BigDecimal.equals() 只比较数值大小

**错误。**

它同时考虑数值和 scale。

### 误区二十七：compareTo() 为 0 就表示 equals() 一定为 true

**错误。**

`BigDecimal` 是典型反例。

### 误区二十八：public static final BigDecimal 一定是安全常量

**不一定。**

`BigDecimal` 本身不可变，但常量的业务语义、scale 和可见性仍需设计；若是可变集合则更不安全。

### 误区二十九：使用 long 表示分就不可能出现金额错误

**错误。**

仍可能溢出，并且需要处理币种、小数位、分摊和汇率。

### 误区三十：强制转换可以用来消除所有类型不匹配问题

**错误。**

强转只能改变编译器允许的转换路径，不能修复错误的数据范围和 API 设计。

## 3.29 工程实践建议

1. 不把“编译通过”当作“转换安全”。
2. 数值跨类型前先确认范围、精度和业务容忍度。
3. 将外部 `long` 数据转 `int` 时，优先考虑 `Math.toIntExact()`。
4. 计数、容量、金额最小单位等关键运算需要考虑溢出检测。
5. 表达式需要 `long` 运算时，让至少一个早期操作数使用 `L` 后缀。
6. 不依赖 `byte`、`short` 运算自动保持原类型。
7. 谨慎使用 `+=` 和 `++` 处理边界值。
8. 不通过强转掩盖方法参数设计不合理。
9. 涉及负数取模时，确认业务需要余数还是数学模。
10. 浮点排序优先使用 `Double.compare()`。
11. 浮点近似比较使用与业务尺度匹配的绝对误差或相对误差。
12. 对 `NaN`、无穷大和负零建立显式处理策略。
13. 金额核心计算不使用 `float` 或 `double`。
14. 从文本或数据库十进制数据创建金额时，直接使用精确十进制来源。
15. 不使用 `new BigDecimal(double)` 表达人工输入十进制金额。
16. 所有 `BigDecimal` 除法显式确定精度或 scale 与舍入模式。
17. 业务金额比较通常使用 `compareTo()`，但集合键需要统一 scale 或规范化策略。
18. 舍入规则写入业务契约和测试，不散落在代码中。
19. 金额对象同时建模数值、币种和规则，不把裸 `BigDecimal` 当作完整领域语义。
20. 使用整数最小单位时，同样执行溢出检查。
21. 公共 API 文档明确单位，例如“元”“分”“毫秒”“字节”，避免只暴露裸整数。
22. 对精度敏感代码编写边界测试、随机测试和历史回归样例。

## 3.31 本章总结

### 3.31.1 转换主线

```text
基本数值转换
├── 自动宽化
│   └── 编译允许，但整数转浮点仍可能丢失精度
├── 强制窄化
│   ├── 整数转小整数：保留低位
│   └── 浮点转整数：向零取整并按范围饱和
├── 常量表达式窄化
│   └── 编译器可证明值在目标范围内
└── 数值提升
    ├── byte、short、char 通常提升为 int
    └── 按 double、float、long、int 顺序统一类型
```

### 3.31.2 溢出主线

```text
普通整数运算
→ 固定宽度
→ 溢出通常静默回绕

关键计算
→ Math.*Exact
→ 溢出时抛 ArithmeticException
```

### 3.31.3 浮点主线

```text
float / double
→ 二进制浮点近似
→ 可能出现 NaN、无穷大、正零和负零
→ 运算不满足严格数学结合律
→ 比较需要结合业务容差
```

### 3.31.4 金额主线

```text
金额计算
→ 不使用 double
→ 使用 BigDecimal 或最小货币单位整数
→ 明确 scale、精度和舍入模式
→ 比较时区分 equals 与 compareTo
→ 复杂业务使用 Money 值对象
```

### 3.31.5 面试口述版

Java 数值转换分为自动宽化、强制窄化、常量表达式窄化和数值提升。宽化转换不一定完全保留精度，例如 `int` 转 `float`、`long` 转 `double` 都可能丢失低位。整数窄化通常保留低位，浮点转整数则先向零截断，再对超范围值进行饱和处理。

`byte`、`short` 和 `char` 参与算术运算时通常会提升为 `int`，所以 `byte + byte` 的结果是 `int`。复合赋值和自增隐含转换回原变量类型，因此虽然能够编译，仍可能发生溢出。普通整数溢出不会自动抛异常，关键计算可以使用 `Math.addExact()`、`Math.multiplyExact()` 和 `Math.toIntExact()`。

`float` 和 `double` 使用二进制浮点表示，许多十进制小数只能近似保存，因此金额计算通常使用 `BigDecimal` 或整数最小货币单位。创建 `BigDecimal` 时优先使用字符串或精确十进制来源，除法必须明确精度和舍入规则；业务数值相等通常使用 `compareTo()`，而不是只依赖 `equals()`。
