# 接口设计

## 14.1 本章定位

接口用于描述一组能力或行为契约，是 Java 实现多能力组合和面向抽象编程的核心机制。

上一章讨论了抽象类，抽象类适合表达具有共享状态和统一生命周期的父类型；而接口更强调"能做什么"，不要求实现类共享同一份实例状态。

本章主要解决以下问题：

- 接口是什么？它和抽象类有什么区别？
- 接口中的方法有哪些类型？
- 接口默认方法解决了什么问题？
- 接口静态方法和私有方法的适用场景是什么？
- 接口字段有什么特殊性？
- 一个类如何实现多个接口？
- 接口之间能否继承？
- 默认方法冲突如何解决？
- 接口与 Object 方法有什么关系？

本章核心主线：

```
接口表达行为契约
↓
抽象方法声明能力，实现类提供具体实现
↓
default 方法提供兼容性与默认实现
↓
static 与 private 方法承载工具与内部逻辑
↓
多实现组合多个独立能力
↓
接口继承扩展契约层次
```

本章暂不深入：

- 抽象类与接口的比较与选择：见 15-组合与设计原则。
- Lambda 与函数式接口：见高级语言特性笔记。
- 依赖倒置与面向接口编程：见 15-组合与设计原则。
- Spring 依赖注入：放在 Spring 模块。
- JVM 接口调用指令：放在 JVM 模块。

## 14.2 接口

接口用于描述一组能力或行为契约：

```java
public interface PaymentProcessor {
    void pay();
}
```

实现类：

```java
public class AlipayProcessor implements PaymentProcessor {
    @Override
    public void pay() {
        System.out.println("支付宝支付");
    }
}
```

调用：

```
PaymentProcessor processor = new AlipayProcessor();
processor.pay();
```

接口强调的是：
实现类能够提供某种能力，而不强制要求共享同一份实例状态或父类实现。

**14.2.1 接口不能直接实例化**

错误：

```
PaymentProcessor processor = new PaymentProcessor();
```

接口只是契约，不是具体实现。
但接口可以作为引用类型：

```
PaymentProcessor processor = new AlipayProcessor();
```

**14.2.2 类使用 implements 实现接口**

```java
public class AlipayProcessor
implements PaymentProcessor {
}
```

一个类可以实现多个接口：

```java
public class SmartDevice
implements Startable, Stoppable, Monitorable {
}
```

这使 Java 能够组合多个独立能力。

## 14.3 接口中的抽象方法

传统接口方法：

```java
public interface PaymentProcessor {
    public abstract void pay();
}
```

可以简写为：

```java
public interface PaymentProcessor {
    void pay();
}
```

接口中的普通实例方法默认是：

```java
public abstract
```

因此以下几种写法语义相同：

```java
void pay();
public void pay();
public abstract void pay();
```

实际开发推荐使用最简写法：

```
void pay();
```

**14.3.1 实现方法必须是 public**

接口方法默认是 public：

```java
public interface Processor {
    void execute();
}
```

实现类必须使用 public：

```java
public class DefaultProcessor implements Processor {
    @Override
    public void execute() {
    }
}
```

不能降低访问权限：

```java
@Override
void execute() {
}
```

因为默认访问权限小于 public，编译失败。

**14.3.2 实现类必须完成全部接口方法**

```java
public interface Processor {
    void validate();
    void execute();
}
```

普通实现类必须全部实现：

```java
public class DefaultProcessor implements Processor {
    @Override
    public void validate() {
    }
    @Override
    public void execute() {
    }
}
```

如果实现类不完整，它必须声明为抽象类：

```java
public abstract class BaseProcessor implements Processor {
    @Override
    public void validate() {
    }
}
```

剩余的 execute() 交给子类实现。

## 14.4 接口中的字段

接口可以定义字段：

```java
public interface Config {
    int DEFAULT_TIMEOUT = 30;
}
```

接口字段默认是：

```java
public static final
```

因此完整写法是：

```java
public static final int DEFAULT_TIMEOUT = 30;
```

但通常省略修饰符。

**14.4.1 接口字段必须初始化**

错误：

```java
public interface Config {
    int TIMEOUT;
}
```

接口字段是常量，必须在声明时初始化。

**14.4.2 接口没有实例字段**

接口字段属于接口本身：

```
Config.DEFAULT_TIMEOUT
```

不是每个实现对象各有一份。
因此不能用接口定义对象实例状态：

```java
public interface User {
    String name = null;
}
```

这里的 name 是静态常量，而不是用户对象字段。

**14.4.3 不建议滥用常量接口**

例如：

```java
public interface OrderConstants {
    String CREATED = "CREATED";
    String COMPLETED = "COMPLETED";
}
```

然后类实现它：

```java
public class Order implements OrderConstants {
}
```

只是为了直接使用常量。
这种设计称为常量接口反模式。

问题：

- 实现关系没有业务语义
- 污染类型层次
- 常量成为类公共 API
- 调用方难以判断类真正具备什么能力
- 更推荐：

```java
public final class OrderConstants {
    public static final String CREATED = "CREATED";
    private OrderConstants() {
    }
}
```

或者使用枚举：

```java
public enum OrderStatus {
    CREATED,
    COMPLETED
}
```

## 14.5 接口默认方法

接口可以使用 default 提供实例方法实现：

```java
public interface Processor {
    void execute();
    default void logStart() {
        System.out.println("开始执行");
    }
}
```

实现类可以直接使用：

```java
public class DefaultProcessor implements Processor {
    @Override
    public void execute() {
        logStart();
        System.out.println("执行任务");
    }
}
```

**14.5.1 默认方法的主要目的**

默认方法最初的重要目的之一是：
在不破坏已有实现类的情况下，为接口增加新方法。
假设已有接口：

```java
public interface Collection {
    int size();
}
```

已经存在大量实现类。
如果直接新增抽象方法：

```
void stream();
```

所有旧实现类都必须立刻修改。
如果新增默认方法：

```
default Stream<?> stream() {
// 默认实现
}
```

原有实现类可以继续工作，同时允许需要的实现类自行重写。

**14.5.2 默认方法可以被重写**

```java
public interface Processor {
    default void execute() {
        System.out.println("默认实现");
    }
}
```

实现类：

```java
public class CustomProcessor implements Processor {
    @Override
    public void execute() {
        System.out.println("自定义实现");
    }
}
```

调用时执行实现类版本。

**14.5.3 默认方法仍然是实例方法**

默认方法通过对象调用：

```
processor.execute();
```

它参与实例方法的动态绑定。
默认方法不是静态方法，也不是接口对象自身状态的方法。

## 14.6 接口静态方法

接口可以定义静态方法：

```java
public interface PaymentProcessor {

    void pay();

    static PaymentProcessor noop() {
        return () -> {
        };
    }
}
```

调用：

```
PaymentProcessor processor =
PaymentProcessor.noop();
```

接口静态方法属于接口本身。
不能通过实现类继承调用：

```
AlipayProcessor.noop();
```

通常不允许。
应直接使用：

```
PaymentProcessor.noop();
```

**14.6.1 接口静态方法的适用场景**

- 静态工厂方法
- 与接口强相关的工具方法
- 创建默认实现
- 参数校验
- 组合接口实例

例如：

```java
public interface Predicate<T> {
    boolean test(T value);
    static <T> Predicate<T> alwaysTrue() {
        return value -> true;
    }
}
```

## 14.7 接口私有方法

接口可以定义私有方法，用于复用默认方法或静态方法中的内部逻辑：

```java
public interface Logger {
    default void info(String message) {
        log("INFO", message);
    }
    default void error(String message) {
        log("ERROR", message);
    }
    private void log(String level, String message) {
        System.out.println(
        "[" + level + "] " + message
        );
    }
}
```

私有接口方法：

- 只能在接口内部使用
- 不能被实现类调用
- 不能被实现类重写
- 用于减少默认方法的重复代码

**14.7.1 接口方法类型总结**

接口中可以定义：

- 方法类型 是否有方法体 是否可继承调用 是否可重写
- 抽象方法 否 是 必须或可以实现
- default 方法 是 是 可以
- static 方法 是 否 不能
- private 方法 是 否 不能
- private static 方法 是 否 不能


> 接口方法中只有抽象方法可以成为函数式接口的目标方法，配合 Lambda 使用。Lambda 与函数式接口的完整规则见高级语言特性笔记。

## 14.8 接口的多实现

一个类可以实现多个接口：

```java
public class SmartMachine
implements Startable, Stoppable, Monitorable {
    @Override
    public void start() {
    }
    @Override
    public void stop() {
    }
    @Override
    public void monitor() {
    }
}
```

这解决了类只能单继承的问题。
一个类可以同时具备：

```
可启动
可停止
可监控
```

多个独立能力。

**14.8.1 多实现不等于多继承状态**

实现多个接口通常组合的是：

```
行为契约
```

而不是继承多份实例状态。
因为接口没有普通实例字段和构造过程。
因此它避免了传统类多继承中的大量状态冲突。

## 14.9 接口继承接口

接口可以继承一个或多个接口：

```java
public interface Readable {
    String read();
}
public interface Writable {
    void write(String value);
}
public interface ReadWrite
extends Readable, Writable {
}
```

实现类：

```java
public class FileChannel
implements ReadWrite {
    @Override
    public String read() {
        return "data";
    }
    @Override
    public void write(String value) {
    }
}
```

接口支持多继承：

```
interface C extends A, B {
}
```

这里继承的是多个行为契约。

## 14.10 默认方法冲突

多个接口可能定义相同签名的默认方法：

```java
public interface A {
    default void execute() {
        System.out.println("A");
    }
}
public interface B {
    default void execute() {
        System.out.println("B");
    }
}
```

实现类：

```java
public class C implements A, B {
}
```

会编译失败。
因为编译器无法确定应该继承哪个默认实现。

**14.10.1 实现类必须显式解决冲突**

```java
public class C implements A, B {
    @Override
    public void execute() {
        System.out.println("C");
    }
}
```

或者选择某个接口的默认实现：

```java
public class C implements A, B {
    @Override
    public void execute() {
        A.super.execute();
    }
}
```

也可以组合两个实现：

```java
@Override
public void execute() {
    A.super.execute();
    B.super.execute();
}
```

## 14.11 类优先原则

如果父类中已经存在具体方法，而接口中提供同签名默认方法，通常父类方法优先。
父类：

```java
public class Parent {
    public void execute() {
        System.out.println("Parent");
    }
}
```

接口：

```java
public interface Executor {
    default void execute() {
        System.out.println("Interface");
    }
}
```

子类：

```java
public class Child
extends Parent
implements Executor {
}
```

调用：

```
new Child().execute();
```

通常输出：

```
Parent
```

规则可以概括为：
类定义的方法优先于接口默认方法。

**14.11.1 为什么类方法优先**

- 接口默认方法主要是兼容性和能力扩展机制。
- 它不能悄悄改变原有类继承体系中的方法行为。
- 否则一个接口新增默认方法后，可能意外覆盖已有父类行为。

## 14.12 更具体接口优先

接口存在继承关系时，更具体的接口默认方法优先。

```java
public interface Parent {
    default void execute() {
        System.out.println("Parent");
    }
}
public interface Child extends Parent {
    @Override
    default void execute() {
        System.out.println("Child");
    }
}
```

实现类：

```java
public class DefaultExecutor
implements Child {
}
```

调用：

```
new DefaultExecutor().execute();
```

输出：

```
Child
```

因为 Child 比 Parent 更具体。

## 14.13 接口与 Object 方法

接口不能通过默认方法覆盖 Object 中的某些核心实例方法。
例如不应在接口中定义：

```
default String toString() {
}
```

因为所有实现类最终都继承 Object，类方法优先于接口默认方法。
接口可以声明 Object 方法契约：

```java
public interface ValueObject {
    boolean equals(Object other);
    int hashCode();
}
```

但真正实现仍由具体类提供。

## 14.14 建议实验

实验一：接口作为引用类型

```java
public interface PaymentProcessor {
    void pay();
}

public class AlipayProcessor implements PaymentProcessor {
    @Override
    public void pay() { System.out.println("支付宝支付"); }
}

public class Demo {
    public static void main(String[] args) {
        PaymentProcessor processor = new AlipayProcessor();
        processor.pay();
    }
}
```

验证接口引用指向实现类对象的多态调用。

实验二：默认方法与重写

```java
public interface Processor {
    default void execute() { System.out.println("默认实现"); }
}

public class CustomProcessor implements Processor {
    @Override
    public void execute() { System.out.println("自定义实现"); }
    public static void main(String[] args) {
        new CustomProcessor().execute();
    }
}
```

观察默认方法被重写后执行子类实现。

实验三：默认方法冲突

```java
public interface A {
    default void execute() { System.out.println("A"); }
}
public interface B {
    default void execute() { System.out.println("B"); }
}

// public class C implements A, B {} // 编译错误
public class C implements A, B {
    @Override
    public void execute() { A.super.execute(); }
    public static void main(String[] args) { new C().execute(); }
}
```

观察多接口同名默认方法导致的冲突，以及通过 `A.super.execute()` 的解决方式。

实验四：类优先原则

```java
public class Parent {
    public void execute() { System.out.println("Parent"); }
}
public interface Executor {
    default void execute() { System.out.println("Interface"); }
}
public class Child extends Parent implements Executor {
    public static void main(String[] args) { new Child().execute(); }
}
```

观察父类具体方法优先于接口默认方法。

实验五：接口静态方法

```java
public interface PaymentProcessor {
    void pay();
    static PaymentProcessor noop() {
        return () -> {};
    }
}

public class Demo {
    public static void main(String[] args) {
        PaymentProcessor processor = PaymentProcessor.noop();
    }
}
```

验证接口静态方法通过接口名调用，不能通过实现类继承。

实验六：接口私有方法复用

```java
public interface Logger {
    default void info(String message) { log("INFO", message); }
    default void error(String message) { log("ERROR", message); }
    private void log(String level, String message) {
        System.out.println("[" + level + "] " + message);
    }
}

public class Demo {
    public static void main(String[] args) {
        Logger logger = new Logger() {};
        logger.info("hello");
        logger.error("fail");
    }
}
```

观察私有方法在默认方法之间的复用，且不能被实现类调用或重写。

## 14.16 易错点

**误区一：接口方法可以任意降低访问权限**

**错误。**

接口方法默认是 `public`，实现类必须使用 `public`，否则编译失败。不能用包级私有或 `protected` 实现。

**误区二：接口字段是实例字段**

**错误。**

接口字段默认是 `public static final`，属于接口本身，不是每个实现对象各有一份。不能用接口定义对象实例状态。

**误区三：接口字段可以不初始化**

**错误。**

接口字段是常量，必须在声明时初始化。

**误区四：实现类不实现全部接口方法也能编译通过**

**错误。**

普通实现类必须实现全部抽象方法，否则编译失败。只有把实现类声明为 `abstract`，未完成的方法才能继续向下传递。

**误区五：默认方法不能被重写**

**错误。**

默认方法提供默认实现，实现类可以选择直接使用，也可以 `@Override` 重写为自己的实现。

**误区六：接口静态方法可以通过实现类继承调用**

**错误。**

接口静态方法属于接口本身，只能通过接口名调用，不能通过实现类继承，也不能通过实现类对象调用。

**误区七：接口私有方法可以被实现类调用或重写**

**错误。**

接口私有方法只能在接口内部使用，用于复用默认方法或静态方法的内部逻辑，实现类既不能调用也不能重写。

**误区八：默认方法冲突时编译器会自动选择**

**错误。**

多个接口提供同签名默认方法时，编译器不会自动选择，实现类必须显式重写该方法，或通过 `X.super.method()` 指明使用哪个接口的默认实现。

**误区九：接口可以通过默认方法覆盖 Object 的核心方法**

**错误。**

所有实现类最终继承 `Object`，类方法优先于接口默认方法。接口不应通过默认方法覆盖 `toString`、`equals` 等 Object 方法，但可以声明这些方法的契约由实现类提供真正实现。

## 14.17 本章总结

```
接口表达行为契约，不要求共享实例状态
↓
抽象方法默认 public abstract，实现类必须 public 实现
↓
接口字段默认 public static final，必须初始化
↓
default 方法提供兼容性与默认实现，可被重写
↓
static 方法属于接口本身，不能被继承
↓
private 方法复用接口内部逻辑
↓
一个类可实现多个接口，接口可多继承接口
↓
默认方法冲突需显式解决，类方法优先于接口默认方法
```

面试口述版：

- 接口用于描述一组能力或行为契约，强调"能做什么"而不是"是什么"，不要求实现类共享实例状态。接口方法默认是 `public abstract`，实现类必须用 `public` 实现；接口字段默认是 `public static final` 且必须初始化，不能用接口定义实例状态。接口可以定义默认方法、静态方法和私有方法：默认方法为兼容性提供默认实现，可被实现类重写；静态方法属于接口本身，只能通过接口名调用，不能被继承；私有方法只能在接口内部复用逻辑。一个类可以实现多个接口，接口之间可以多继承。多个接口出现同签名默认方法时，实现类必须显式重写或用 `X.super.method()` 指定来源；父类具体方法优先于接口默认方法，更具体的接口默认方法优先于父接口。接口不应通过默认方法覆盖 Object 的核心方法。抽象类与接口的比较与选择、Lambda 与函数式接口的完整规则见 15-组合与设计原则和高级语言特性笔记。
