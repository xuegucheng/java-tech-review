# 第7章：接口设计

## 7.8 接口

接口用于描述一组能力或行为契约：
1 public interface PaymentProcessor {
2
3 void pay();
4 }
5
实现类：
1 public class AlipayProcessor implements PaymentProcessor {
2
3 @Override
4 public void pay() {
5 System.out.println("支付宝支付");
6 }
7 }
8
调用：
1 PaymentProcessor processor = new AlipayProcessor();
2 processor.pay();
3
接口强调的是：
实现类能够提供某种能力，而不强制要求共享同一份实例状态或父类实现。
### 7.8.1 接口不能直接实例化
错误：
1 PaymentProcessor processor = new PaymentProcessor();
2
接口只是契约，不是具体实现。
但接口可以作为引用类型：
1 PaymentProcessor processor = new AlipayProcessor();

2
### 7.8.2 类使用 implements 实现接口
1 public class AlipayProcessor
2 implements PaymentProcessor {
3 }
4
一个类可以实现多个接口：
1 public class SmartDevice
2 implements Startable, Stoppable, Monitorable {
3 }
4
这使 Java 能够组合多个独立能力。

## 7.9 接口中的抽象方法

传统接口方法：
1 public interface PaymentProcessor {
2
3 public abstract void pay();
4 }
5
可以简写为：
1 public interface PaymentProcessor {
2
3 void pay();
4 }
5
接口中的普通实例方法默认是：
1 public abstract
2
因此以下几种写法语义相同：
1 void pay();
2

1 public void pay();
2
1 public abstract void pay();
2
实际开发推荐使用最简写法：
1 void pay();
2
### 7.9.1 实现方法必须是 public
接口方法默认是 public：
1 public interface Processor {
2
3 void execute();
4 }
5
实现类必须使用 public：
1 public class DefaultProcessor implements Processor {
2
3 @Override
4 public void execute() {
5 }
6 }
7
不能降低访问权限：
1 @Override
2 void execute() {
3 }
4
因为默认访问权限小于 public，编译失败。
### 7.9.2 实现类必须完成全部接口方法
1 public interface Processor {
2
3 void validate();
4
5 void execute();

6 }
7
普通实现类必须全部实现：
1 public class DefaultProcessor implements Processor {
2
3 @Override
4 public void validate() {
5 }
6
7 @Override
8 public void execute() {
9 }
10 }
11
如果实现类不完整，它必须声明为抽象类：
1 public abstract class BaseProcessor implements Processor {
2
3 @Override
4 public void validate() {
5 }
6 }
7
剩余的 execute() 交给子类实现。

## 7.10 接口中的字段

接口可以定义字段：
1 public interface Config {
2
3 int DEFAULT_TIMEOUT = 30;
4 }
5
接口字段默认是：
1 public static final
2
因此完整写法是：
1 public static final int DEFAULT_TIMEOUT = 30;
2
但通常省略修饰符。

### 7.10.1 接口字段必须初始化
错误：
1 public interface Config {
2
3 int TIMEOUT;
4 }
5
接口字段是常量，必须在声明时初始化。
### 7.10.2 接口没有实例字段
接口字段属于接口本身：
1 Config.DEFAULT_TIMEOUT
2
不是每个实现对象各有一份。
因此不能用接口定义对象实例状态：
1 public interface User {
2
3 String name = null;
4 }
5
这里的 name 是静态常量，而不是用户对象字段。
### 7.10.3 不建议滥用常量接口
例如：
1 public interface OrderConstants {
2
3 String CREATED = "CREATED";
4 String COMPLETED = "COMPLETED";
5 }
6
然后类实现它：
1 public class Order implements OrderConstants {
2 }
3
只是为了直接使用常量。
这种设计称为常量接口反模式。
问题：
实现关系没有业务语义
污染类型层次
常量成为类公共 API

调用方难以判断类真正具备什么能力
更推荐：
1 public final class OrderConstants {
2
3 public static final String CREATED = "CREATED";
4
5 private OrderConstants() {
6 }
7 }
8
或者使用枚举：
1 public enum OrderStatus {
2 CREATED,
3 COMPLETED
4 }
5

## 7.11 接口默认方法

接口可以使用 default 提供实例方法实现：
1 public interface Processor {
2
3 void execute();
4
5 default void logStart() {
6 System.out.println("开始执行");
7 }
8 }
9
实现类可以直接使用：
1 public class DefaultProcessor implements Processor {
2
3 @Override
4 public void execute() {
5 logStart();
6 System.out.println("执行任务");
7 }
8 }
9
### 7.11.1 默认方法的主要目的
默认方法最初的重要目的之一是：
在不破坏已有实现类的情况下，为接口增加新方法。
假设已有接口：

1 public interface Collection {
2
3 int size();
4 }
5
已经存在大量实现类。
如果直接新增抽象方法：
1 void stream();
2
所有旧实现类都必须立刻修改。
如果新增默认方法：
1 default Stream<?> stream() {
2 // 默认实现
3 }
4
原有实现类可以继续工作，同时允许需要的实现类自行重写。
### 7.11.2 默认方法可以被重写
1 public interface Processor {
2
3 default void execute() {
4 System.out.println("默认实现");
5 }
6 }
7
实现类：
1 public class CustomProcessor implements Processor {
2
3 @Override
4 public void execute() {
5 System.out.println("自定义实现");
6 }
7 }
8
调用时执行实现类版本。
### 7.11.3 默认方法仍然是实例方法
默认方法通过对象调用：
1 processor.execute();

2
它参与实例方法的动态绑定。
默认方法不是静态方法，也不是接口对象自身状态的方法。

## 7.12 接口静态方法

接口可以定义静态方法：
1 public interface PaymentProcessor {
2
3 static PaymentProcessor noop() {
4 return amount -> {
5 };
6 }
7 }
8
调用：
1 PaymentProcessor processor =
2 PaymentProcessor.noop();
3
接口静态方法属于接口本身。
不能通过实现类继承调用：
1 AlipayProcessor.noop();
2
通常不允许。
应直接使用：
1 PaymentProcessor.noop();
2
### 7.12.1 接口静态方法的适用场景
静态工厂方法
与接口强相关的工具方法
创建默认实现
参数校验
组合接口实例
例如：
1 public interface Predicate<T> {
2
3 boolean test(T value);
4
5 static <T> Predicate<T> alwaysTrue() {
6 return value -> true;

7 }
8 }
9

## 7.13 接口私有方法

接口可以定义私有方法，用于复用默认方法或静态方法中的内部逻辑：
1 public interface Logger {
2
3 default void info(String message) {
4 log("INFO", message);
5 }
6
7 default void error(String message) {
8 log("ERROR", message);
9 }
10
11 private void log(String level, String message) {
12 System.out.println(
13 "[" + level + "] " + message
14 );
15 }
16 }
17
私有接口方法：
只能在接口内部使用
不能被实现类调用
不能被实现类重写
用于减少默认方法的重复代码
### 7.13.1 接口方法类型总结
接口中可以定义：
方法类型 是否有方法体 是否可继承调用 是否可重写
抽象方法 否 是 必须或可以实现
default 方法 是 是 可以
static 方法 是 否 不能
private 方法 是 否 不能
private static 方法 是 否 不能

## 7.14 接口的多实现

一个类可以实现多个接口：
1 public class SmartMachine
2 implements Startable, Stoppable, Monitorable {
3
4 @Override
5 public void start() {

6 }
7
8 @Override
9 public void stop() {
10 }
11
12 @Override
13 public void monitor() {
14 }
15 }
16
这解决了类只能单继承的问题。
一个类可以同时具备：
1 可启动
2 可停止
3 可监控
4
多个独立能力。
### 7.14.1 多实现不等于多继承状态
实现多个接口通常组合的是：
1 行为契约
2
而不是继承多份实例状态。
因为接口没有普通实例字段和构造过程。
因此它避免了传统类多继承中的大量状态冲突。

## 7.15 接口继承接口

接口可以继承一个或多个接口：
1 public interface Readable {
2
3 String read();
4 }
5
1 public interface Writable {
2
3 void write(String value);
4 }
5
1 public interface ReadWrite
2 extends Readable, Writable {

3 }
4
实现类：
1 public class FileChannel
2 implements ReadWrite {
3
4 @Override
5 public String read() {
6 return "data";
7 }
8
9 @Override
10 public void write(String value) {
11 }
12 }
13
接口支持多继承：
1 interface C extends A, B {
2 }
3
这里继承的是多个行为契约。

## 7.16 默认方法冲突

多个接口可能定义相同签名的默认方法：
1 public interface A {
2
3 default void execute() {
4 System.out.println("A");
5 }
6 }
7
1 public interface B {
2
3 default void execute() {
4 System.out.println("B");
5 }
6 }
7
实现类：
1 public class C implements A, B {
2 }

3
会编译失败。
因为编译器无法确定应该继承哪个默认实现。
### 7.16.1 实现类必须显式解决冲突
1 public class C implements A, B {
2
3 @Override
4 public void execute() {
5 System.out.println("C");
6 }
7 }
8
或者选择某个接口的默认实现：
1 public class C implements A, B {
2
3 @Override
4 public void execute() {
5 A.super.execute();
6 }
7 }
8
也可以组合两个实现：
1 @Override
2 public void execute() {
3 A.super.execute();
4 B.super.execute();
5 }
6

## 7.17 类优先原则

如果父类中已经存在具体方法，而接口中提供同签名默认方法，通常父类方法优先。
父类：
1 public class Parent {
2
3 public void execute() {
4 System.out.println("Parent");
5 }
6 }
7
接口：

1 public interface Executor {
2
3 default void execute() {
4 System.out.println("Interface");
5 }
6 }
7
子类：
1 public class Child
2 extends Parent
3 implements Executor {
4 }
5
调用：
1 new Child().execute();
2
通常输出：
1 Parent
2
规则可以概括为：
类定义的方法优先于接口默认方法。
### 7.17.1 为什么类方法优先
接口默认方法主要是兼容性和能力扩展机制。
它不能悄悄改变原有类继承体系中的方法行为。
否则一个接口新增默认方法后，可能意外覆盖已有父类行为。

## 7.18 更具体接口优先

接口存在继承关系时，更具体的接口默认方法优先。
1 public interface Parent {
2
3 default void execute() {
4 System.out.println("Parent");
5 }
6 }
7
1 public interface Child extends Parent {
2
3 @Override

4 default void execute() {
5 System.out.println("Child");
6 }
7 }
8
实现类：
1 public class DefaultExecutor
2 implements Child {
3 }
4
调用：
1 new DefaultExecutor().execute();
2
输出：
1 Child
2
因为 Child 比 Parent 更具体。

## 7.19 接口与 Object 方法

接口不能通过默认方法覆盖 Object 中的某些核心实例方法。
例如不应在接口中定义：
1 default String toString() {
2 }
3
因为所有实现类最终都继承 Object，类方法优先于接口默认方法。
接口可以声明 Object 方法契约：
1 public interface ValueObject {
2
3 boolean equals(Object other);
4
5 int hashCode();
6 }
7
但真正实现仍由具体类提供。
