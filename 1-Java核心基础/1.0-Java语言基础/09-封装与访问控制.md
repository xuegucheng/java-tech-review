## 9.2 封装是什么

封装不只是：

```text
字段改成 private
+
生成 Getter 和 Setter
```

更完整的封装包括：

```text
隐藏内部表示
+
限制状态修改入口
+
维护对象不变量
+
控制依赖方向
+
隔离未来变化
+
暴露稳定业务协议
```

### 9.2.1 隐藏内部表示

调用方只需要知道：

```java
account.deposit(amountInFen);
```

不需要知道：

- 余额字段如何保存；
- 是否使用 `long` 或 `BigDecimal`；
- 是否记录流水；
- 是否执行溢出检查；
- 是否有冻结状态。

### 9.2.2 控制状态修改

不推荐：

```java
account.setBalanceInFen(
        account.getBalanceInFen()
        + amountInFen
);
```

推荐：

```java
account.deposit(amountInFen);
```

### 9.2.3 隔离变化

如果调用方只依赖：

```java
order.totalAmount()
```

内部可以从：

```text
实时计算
```

改成：

```text
缓存
数据库投影
预计算字段
```

而不要求所有调用方修改。

## 9.3 封装不等于 Getter/Setter

### 9.3.1 全字段开放

```java
public class Order {

    private OrderStatus status;

    public OrderStatus getStatus() {
        return status;
    }

    public void setStatus(
            OrderStatus status
    ) {
        this.status = status;
    }
}
```

任何调用方都可以：

```java
order.setStatus(
        OrderStatus.COMPLETED
);
```

绕过支付、发货和收货流程。

### 9.3.2 使用业务行为

```java
public void pay() {
    if (status != OrderStatus.CREATED) {
        throw new IllegalStateException();
    }

    status = OrderStatus.PAID;
}
```

### 9.3.3 Getter 也可能破坏封装

```java
public List<OrderItem> getItems() {
    return items;
}
```

调用方可以：

```java
order.getItems().clear();
```

### 9.3.4 Getter/Setter 的合理场景

适合：

- DTO；
- 配置对象；
- ORM 映射；
- 框架绑定；
- 简单数据载体；
- 明确可变属性。

关键是：

```text
访问器是否符合对象职责
而不是
是否机械存在
```

## 9.4 Java 访问级别概览

Java 成员访问级别：

| 修饰符 | 当前类或同一顶层嵌套体系 | 同包 | 跨包子类 | 其他包普通代码 |
|---|---|---|---|---|
| `private` | 是 | 否 | 否 | 否 |
| 包级访问 | 是 | 是 | 否 | 否 |
| `protected` | 是 | 是 | 受限制 | 否 |
| `public` | 是 | 是 | 是 | 是 |

“包级访问”表示没有显式访问修饰符：

```java
class PackageType {
}

void execute() {
}
```

它也常被称为：

```text
package-private
default access
```

但不要与：

```java
default
```

接口默认方法关键字混淆。

### 9.4.1 可见性还受外层类型影响

```java
class HiddenOuter {

    public static class PublicNested {
    }
}
```

即使嵌套类声明为 `public`，外层类本身包级不可见时，其他包仍无法通过正常源码访问它。

### 9.4.2 模块也可能限制 public

跨模块访问一个 `public` 类型，还要求：

- 类型所在包被模块导出；
- 依赖模块可读取该模块；
- 其他模块规则允许访问。

因此：

```text
public
不一定意味着
对整个应用所有模块都可见
```

## 9.5 public

`public` 表示在满足类型、包和模块可访问条件时，可以从更广范围访问。

```java
public class UserService {

    public User find(UserId id) {
        return null;
    }
}
```

### 9.5.1 public 是 API 承诺

一旦成员公开，调用方可能依赖：

- 名称；
- 参数；
- 返回类型；
- 异常；
- 副作用；
- 空值；
- 线程安全；
- 性能；
- 二进制兼容。

因此不应因为“以后可能用到”就全部声明为 `public`。

### 9.5.2 最小可见性

推荐顺序：

```text
先 private
↓
确需同包协作时包级
↓
确需继承扩展时 protected
↓
确需对外契约时 public
```

### 9.5.3 public 字段

除常量或特殊数据结构外，通常不公开可变字段：

```java
public int balance;
```

因为无法控制：

- 合法范围；
- 修改时机；
- 并发保护；
- 日志；
- 未来表示方式。

## 9.6 private

`private` 用于隐藏实现细节和限制状态访问。

```java
public class Account {

    private long balanceInFen;
}
```

### 9.6.1 private 成员的作用域

普通理解：

```text
只允许声明它的类内部访问
```

但 Java 的嵌套类型存在同一顶层嵌套体系访问能力。

```java
public class Outer {

    private int value;

    static class Nested {

        static int read(Outer outer) {
            return outer.value;
        }
    }
}
```

嵌套类可以访问外部类的 `private` 成员。

外部类也可以访问嵌套类的 `private` 成员。

### 9.6.2 private 方法

适合：

- 分解实现；
- 复用内部步骤；
- 表达内部子流程；
- 隐藏算法细节；
- 收敛状态修改。

```java
private void validateAmount(
        long amountInFen
) {
}
```

### 9.6.3 private 不等于安全边界

反射、序列化框架、JVM 工具和模块开放配置可能绕过或参与访问。

`private` 主要是语言和设计层封装，不应替代：

- 权限校验；
- 加密；
- 密钥管理；
- 进程隔离；
- 数据库权限。

## 9.7 包级访问

不写访问修饰符：

```java
class OrderAssembler {
}
```

或者：

```java
void rebuild() {
}
```

表示同包代码可访问。

### 9.7.1 适合同一实现模块协作

例如：

```text
order 包
├── Order
├── OrderFactory
├── OrderPolicy
└── OrderAssembler
```

部分实现可以保持包级，不对整个模块公开。

### 9.7.2 包级测试

测试代码如果位于同包，可以访问包级成员。

这有时用于测试内部协作，而不必扩大到 `public`。

### 9.7.3 不要为了测试把 private 改 public

可考虑：

- 通过公共行为测试；
- 调整职责；
- 使用包级协作者；
- 提取独立类；
- 使用测试替身。

### 9.7.4 包名相同的边界

语言源码层通常按包名判断同包关系。

JVM 运行时访问控制还会受到类加载器和运行时包身份影响。完整机制放在 JVM 模块。

## 9.8 protected

`protected` 有两层语义：

```text
同包访问
+
跨包子类的受限访问
```

### 9.8.1 同包访问

在同一个包中，`protected` 与包级访问相近：

```java
package first;

public class Parent {

    protected int value;
}
```

同包普通类可以访问：

```java
package first;

class Helper {

    void print(Parent parent) {
        System.out.println(parent.value);
    }
}
```

### 9.8.2 跨包子类访问

```java
package second;

public class Child
        extends Parent {

    void print() {
        System.out.println(value);
    }
}
```

子类可以通过继承上下文访问。

### 9.8.3 跨包限制

在跨包子类中，不能通过任意 `Parent` 实例访问：

```java
package second;

public class Child
        extends Parent {

    void print(Parent parent) {
        // System.out.println(parent.value);
        // 编译错误
    }
}
```

### 9.8.4 通过子类类型访问

```java
void print(Child child) {
    System.out.println(child.value);
}
```

通常允许，因为访问发生在子类继承边界内，并且限定对象类型符合要求。

### 9.8.5 为什么有该限制

`protected` 的目标不是：

```text
让所有子类成为父类对象的万能检查器
```

而是：

```text
让子类实现访问其继承部分
```

---

## 9.9 protected 访问示例

父类：

```java
package parent;

public class Parent {

    protected int value = 10;
}
```

子类：

```java
package child;

import parent.Parent;

public class Child extends Parent {

    void first() {
        System.out.println(value);
    }

    void second(Child child) {
        System.out.println(child.value);
    }

    void third(Parent parent) {
        // System.out.println(parent.value);
        // 跨包下不允许
    }
}
```

### 9.9.1 强转不能随意绕过

```java
void print(Parent parent) {
    Child child = (Child) parent;
    System.out.println(child.value);
}
```

即使编译可通过：

- 实际对象可能不是 `Child`；
- 可能抛 `ClassCastException`；
- 设计语义通常也不合理。

### 9.9.2 protected 构造器

`protected` 构造器常用于：

- 允许同包创建；
- 允许子类构造链调用；
- 阻止其他包普通代码直接实例化。

访问 `protected` 构造器的规则与普通成员存在细节差异，应结合实际继承和创建表达式判断。

## 9.10 顶层类型的访问修饰符

顶层类和接口只能使用：

```text
public
或
包级访问
```

合法：

```java
public class PublicType {
}
```

```java
class PackageType {
}
```

非法：

```java
// private class PrivateType {
// }
```

```java
// protected class ProtectedType {
// }
```

### 9.10.1 一个源文件的 public 顶层类型

传统命名规则下，一个源文件通常最多声明一个 `public` 顶层类型，并且文件名与该类型名一致。

```text
User.java
→ public class User
```

同一文件可以有其他包级顶层类型，但通常不建议堆放大量无关类型。

### 9.10.2 嵌套类型

嵌套类型可以使用：

- `public`；
- `protected`；
- 包级访问；
- `private`。

```java
public class Outer {

    private static class Helper {
    }
}
```

## 9.11 成员可见性与声明类型

访问控制先判断：

- 声明成员的类型是否可访问；
- 成员本身是否可访问；
- 当前包和继承上下文；
- 限定表达式是否满足 `protected` 规则；
- 模块是否导出包。

### 9.11.1 public 成员但类型不可访问

```java
class HiddenType {

    public void execute() {
    }
}
```

其他包无法正常声明或创建 `HiddenType`，因此其 `public` 方法也无法作为普通公共 API 使用。

### 9.11.2 返回不可访问类型

```java
public HiddenType query() {
    return null;
}
```

这会形成难以使用的公开 API。

公共方法的参数和返回类型也应当具有合适可见性。

## 9.12 包

包用于组织类型并提供命名和访问边界。

```java
package com.example.order;
```

### 9.12.1 主要价值

- 避免类型名冲突；
- 组织代码；
- 建立包级可见性；
- 表达模块或业务边界；
- 支持部署和模块化；
- 提供稳定命名空间。

### 9.12.2 包名惯例

通常采用反向域名：

```text
com.example.project
```

并使用小写。

### 9.12.3 包声明位置

传统编译单元中，包声明位于：

- 注释和空白之后；
- 导入声明之前；
- 类型声明之前。

```java
package com.example.order;

import java.util.List;

public class Order {
}
```

## 9.13 子包不是父包成员

```text
com.example
com.example.order
```

是两个不同包。

### 9.13.1 包级成员不可跨子包访问

`com.example` 中的包级类型或成员，不会自动对：

```text
com.example.order
```

可见。

### 9.13.2 protected 也不能靠包名前缀获得

子包不是“更深层的同包”。

需要：

- `public`；
- 合法继承访问；
- 模块导出；
- 其他明确 API。

### 9.13.3 目录层级不等于访问继承

包名中的点只是名称结构，不形成父子访问权限。

## 9.14 import

`import` 的主要作用是：

> 允许在当前编译单元中使用类型或静态成员的简单名称。

没有导入：

```java
java.util.List<String> values;
```

导入后：

```java
import java.util.List;

List<String> values;
```

### 9.14.1 import 不复制代码

不会把类源码复制到当前文件。

### 9.14.2 import 不建立继承关系

导入 `List` 不代表当前类继承或实现 `List`。

### 9.14.3 import 不改变访问级别

导入一个包级类型仍然不能跨包访问。

### 9.14.4 import 不等于运行时类加载

`import` 是编译期名称解析机制。

类是否以及何时由 JVM 加载，取决于：

- 字节码引用；
- 执行路径；
- 类初始化触发；
- 反射；
- 类加载器；
- JVM 实现。

同一编译单元中的类型可以按作用域规则直接引用。

## 9.16 单类型导入

```java
import java.util.List;
```

优点：

- 来源明确；
- 避免通配符冲突；
- 便于代码审查；
- IDE 自动管理。

### 9.16.1 同名类型冲突

```java
java.util.Date
java.sql.Date
```

不能同时通过单类型导入后都使用简单名。

可以：

```java
import java.util.Date;
```

另一个使用完全限定名：

```java
java.sql.Date sqlDate;
```

### 9.16.2 import 不支持别名

Java 没有普通语法：

```java
// import java.util.Date as UtilDate;
```

---

## 9.17 通配符导入

```java
import java.util.*;
```

表示按需使用该包中可访问的类型简单名。

### 9.17.1 不导入子包

```java
import java.util.*;
```

不包含：

```text
java.util.concurrent
java.util.function
java.util.stream
```

子包需要独立导入。

### 9.17.2 不造成运行时性能下降

通配符导入主要影响编译期名称解析和源码可读性。

不会导致：

- JVM 加载整个包；
- 应用包体自动增大；
- 运行时扫描所有类。

### 9.17.3 可能造成名称歧义

```java
import java.awt.*;
import java.util.*;
```

两者都有 `List`，使用简单名会歧义。

### 9.17.4 工程选择

团队通常偏好显式导入，原因是：

- 来源清晰；
- 冲突少；
- diff 稳定；
- 静态分析更明确。

这属于风格和可维护性，不是运行性能要求。

## 9.18 静态导入

```java
import static java.lang.Math.max;
```

调用：

```java
int result = max(first, second);
```

### 9.18.1 适合场景

- 测试断言；
- 数学函数；
- 少量高频常量；
- DSL 风格 API。

```java
import static org.junit.jupiter.api.Assertions.assertEquals;
```

### 9.18.2 风险

过多静态导入会让来源不清：

```java
execute();
create();
value();
```

读者难以判断成员来自哪个类型。

### 9.18.3 静态通配符导入

```java
import static java.lang.Math.*;
```

同样不会导致所有成员在运行时加载，但可能增加名称冲突和阅读成本。

---

## 9.19 Java 25 模块导入声明概览

Java 25 提供模块导入声明：

```java
import module java.base;
```

其目标是：

> 允许当前编译单元按简单名称使用指定模块所导出包中的可访问顶层类型。

### 9.19.1 与普通包通配符不同

```java
import java.util.*;
```

只针对一个包。

```java
import module java.base;
```

涉及模块导出的多个包。

### 9.19.2 不能突破模块封装

模块导入不会让未导出的包突然可见。

### 9.19.3 仍然只是名称解析

它不是：

- 运行时加载模块中所有类；
- 自动开放反射权限；
- 自动添加任意模块依赖；
- 替代完整模块声明。

### 9.19.4 使用边界

大型工程通常仍应保持清晰导入。

模块导入更适合：

- 教学；
- 小型程序；
- 需要大量标准 API 的编译单元；
- 特定开发便利场景。

---

## 9.20 构造器是什么

构造器用于参与类实例创建和初始化。

```java
public class User {

    private final String name;

    public User(String name) {
        this.name = name;
    }
}
```

### 9.20.1 构造器名称

构造器名称与类名相同：

```java
User(String name) {
}
```

### 9.20.2 没有返回类型

不能写：

```java
// void User(String name) {
// }
```

这会变成名为 `User` 的普通方法，而不是构造器。

### 9.20.3 构造器不是普通方法调用

创建对象：

```java
new User("Java");
```

显式构造器链：

```java
this("default");
super();
```

不能写：

```java
user.User("Java");
```

---

## 9.21 构造器不是成员

Java 语言规范中，构造器不属于类成员。

因此构造器：

- 不被继承；
- 不被重写；
- 不被隐藏；
- 不能通过普通方法调用语法调用。

### 9.21.1 不能声明为 final

```java
// public final User() {
// }
```

没有意义，也不允许。

### 9.21.2 不能声明为 static

```java
// public static User() {
// }
```

构造器参与创建实例，不是类级普通方法。

### 9.21.3 可以重载

```java
public User() {
}

public User(String name) {
}

public User(
        String name,
        int age
) {
}
```

参数列表不同即可。

---

## 9.22 默认构造器与无参构造器

### 9.22.1 默认构造器

当一个类没有声明任何构造器时，编译器可能自动提供默认构造器。

```java
public class User {
}
```

概念上类似：

```java
public User() {
    super();
}
```

其可见性通常与类的可见性对应。

### 9.22.2 无参构造器

任何参数列表为空的构造器都是无参构造器：

```java
public User() {
    this.name = "anonymous";
}
```

这是程序员显式声明的无参构造器，不应称为编译器生成的默认构造器。

### 9.22.3 声明任意构造器后不再自动生成

```java
public class User {

    public User(String name) {
    }
}
```

此时：

```java
// new User(); // 编译错误
```

除非显式补充无参构造器。

### 9.22.4 父类没有可访问无参构造器

```java
class Parent {

    Parent(String name) {
    }
}

class Child extends Parent {

    Child() {
        // 编译错误：隐式 super() 不可用
    }
}
```

需要：

```java
Child() {
    super("default");
}
```

---

## 9.23 构造器访问级别

构造器可以使用：

- `public`；
- `protected`；
- 包级访问；
- `private`。

### 9.23.1 public 构造器

允许广泛创建：

```java
public User(String name) {
}
```

### 9.23.2 包级构造器

只允许同包创建：

```java
User(String name) {
}
```

适合：

- 包内工厂；
- 限制创建入口；
- 框架内部实现。

### 9.23.3 protected 构造器

适合：

- 子类构造链；
- 同包创建；
- 抽象基类；
- 扩展点。

### 9.23.4 private 构造器

阻止类外直接实例化：

```java
private Utility() {
}
```

适合：

- 工具类；
- 静态工厂控制创建；
- 单例；
- 枚举式实例控制；
- 只允许内部嵌套类型创建。

完整创建模式见 `10`。

---

## 9.24 this

`this` 表示当前实例的引用。

```java
public class User {

    private String name;

    public void rename(String name) {
        this.name = name;
    }
}
```

### 9.24.1 区分字段和参数

```text
this.name
→ 当前对象字段

name
→ 当前方法参数
```

### 9.24.2 返回当前对象

```java
public User rename(String name) {
    this.name = name;
    return this;
}
```

可以支持链式调用。

但可变对象链式 API 应评估：

- 副作用是否清晰；
- 中间状态是否合法；
- 并发安全；
- 调试难度。

### 9.24.3 静态上下文没有 this

```java
public static void execute() {
    // System.out.println(this);
}
```

静态方法没有当前实例。

### 9.24.4 this 不能随意用于构造早期阶段

Java 25 灵活构造器体允许部分语句位于 `super(...)` 前，但不能任意读取、调用或泄漏当前对象。

---

## 9.25 super

`super` 用于引用当前对象的直接父类部分。

### 9.25.1 调用父类构造器

```java
public Child(String name) {
    super(name);
}
```

### 9.25.2 访问父类成员

```java
@Override
public void execute() {
    super.execute();
    audit();
}
```

### 9.25.3 访问被隐藏字段

```java
System.out.println(super.value);
```

字段隐藏见 `11`。

### 9.25.4 super 不是独立父类对象

父类状态与子类状态共同属于同一个子类对象。

不存在：

```text
子类对象内部嵌套一个可独立取出的父类对象
```

这种简单模型。

### 9.25.5 不能使用 super.super

```java
// super.super.execute();
```

只能直接引用当前类的直接父类视图。

---

## 9.26 this(...) 构造器调用

```java
public User() {
    this("anonymous");
}

public User(String name) {
    this.name = name;
}
```

### 9.26.1 同类构造器委托

`this(...)` 调用同一个类中的另一个构造器。

### 9.26.2 复用初始化逻辑

避免：

```java
public User() {
    this.name = "anonymous";
    this.enabled = true;
}

public User(String name) {
    this.name = name;
    this.enabled = true;
}
```

可以收敛：

```java
public User() {
    this("anonymous");
}

public User(String name) {
    this.name = name;
    this.enabled = true;
}
```

### 9.26.3 构造器链必须终止

不能循环：

```java
// User() {
//     this("A");
// }

// User(String name) {
//     this();
// }
```

会产生递归构造器调用编译错误。

---

## 9.27 super(...) 构造器调用

```java
public Child(String name) {
    super(name);
}
```

### 9.27.1 每个构造链最终到达父类

如果没有显式写 `this(...)` 或 `super(...)`，编译器通常插入：

```java
super();
```

前提是父类存在可访问无参构造器。

### 9.27.2 Object 终止继承构造链

普通类最终继承 `Object`。

构造过程会沿父类链完成初始化。

### 9.27.3 this 与 super 不能在同一构造器中同时作为显式构造器调用

```java
public User() {
    // this("A");
    // super();
}
```

一个构造器最多包含一个显式构造器调用。

如果调用 `this(...)`，被委托构造器最终会负责调用父类构造器。

---

## 9.28 Java 25 之前的第一语句规则

传统规则要求：

```java
this(...)
或
super(...)
```

作为构造器体第一条语句。

因此下面在旧版本中不能编译：

```java
public PositiveValue(int value) {
    if (value <= 0) {
        throw new IllegalArgumentException();
    }

    super(Integer.toString(value));
}
```

开发者常需要把校验塞入：

- 静态辅助方法；
- 构造器参数表达式；
- 父类构造器；
- 重复逻辑。

该限制在 Java 25 被灵活构造器体放宽。

---

## 9.29 Java 25 灵活构造器体

Java 25 正式允许：

> 在显式 `super(...)` 或 `this(...)` 调用之前执行满足限制的语句。

示例：

```java
public class PositiveBigInteger
        extends java.math.BigInteger {

    public PositiveBigInteger(long value) {
        if (value <= 0) {
            throw new IllegalArgumentException(
                    "value must be positive"
            );
        }

        super(Long.toString(value));
    }
}
```

### 9.29.1 构造器前段与后段

可以概念上分为：

```text
构造器前段
→ 显式构造器调用之前

显式 this(...) 或 super(...)
↓
构造器后段
→ 显式构造器调用之后
```

### 9.29.2 主要价值

- 先校验父类构造参数；
- 先执行参数转换；
- 避免难读的静态辅助方法；
- 可以在安全规则下提前初始化字段；
- 减少父类构造器调用可重写方法时看到未初始化字段的风险。

### 9.29.3 仍然只有一个显式构造器调用

灵活构造器体没有取消构造链规则。

---

## 9.30 构造早期上下文限制

Java 25 并不是允许在 `super(...)` 前随意使用当前对象。

在构造早期上下文中，不能：

- 任意读取当前实例字段；
- 调用当前实例方法；
- 使用当前对象执行一般操作；
- 把 `this` 泄漏给外部代码；
- 访问尚未完成父类构造的实例行为；
- 通过 `super` 调用实例成员。

### 9.30.1 合法的参数校验

```java
public Child(int value) {
    if (value < 0) {
        throw new IllegalArgumentException();
    }

    super(value);
}
```

### 9.30.2 合法的局部计算

```java
public Child(String text) {
    String normalized = text.trim();

    if (normalized.isEmpty()) {
        throw new IllegalArgumentException();
    }

    super(normalized);
}
```

### 9.30.3 不能读取实例状态

```java
public Child(int value) {
    // System.out.println(this.value);
    // printState();
    // hashCode();

    super(value);
}
```

### 9.30.4 可以进行受限字段初始化

Java 25 允许在早期阶段通过简单赋值初始化当前类字段，但不能借此任意读取或使用当前对象。

```java
public Child(int value) {
    this.value = value;
    super(value);
}
```

设计时应避免同一字段同时被：

- 早期赋值；
- 字段初始化器；
- 实例初始化块；
- 构造器后段；

重复覆盖。

---

## 9.31 Java 25 并未取消构造安全边界

错误理解：

```text
Java 25 后
super(...) 不再重要
```

正确理解：

```text
Java 25 允许安全准备工作
↓
仍必须完成显式或隐式构造链
↓
构造早期仍不能正常使用 this
```

### 9.31.1 不允许任意调用实例方法

```java
public Child(int value) {
    // validateCurrentState();
    super(value);
}
```

实例方法可能：

- 读取未初始化字段；
- 被重写；
- 泄漏当前对象；
- 依赖父类状态。

### 9.31.2 不允许提前发布 this

```java
public Child() {
    // Registry.register(this);
    super();
}
```

对象还未完成构造。

### 9.31.3 版本兼容

使用灵活构造器体编写的源码需要相应 Java 25 或更高版本编译器。

面向旧版本发布时不能使用该语法。

---

## 9.32 对象实例初始化顺序概览

不考虑 Java 25 构造器前段细节时，可以建立以下主线：

```text
为对象字段设置默认值
↓
执行当前构造器的安全前段语句
↓
调用同类其他构造器或父类构造器
↓
父类完成初始化
↓
执行当前类实例字段初始化器
与实例初始化块
↓
执行当前构造器后段
↓
对象构造完成
```

### 9.32.1 字段声明顺序

实例字段初始化器和实例初始化块通常按源码顺序执行。

```java
private int first = print("first");

{
    print("block");
}

private int second = print("second");
```

### 9.32.2 构造器委托

使用 `this(...)` 时：

- 被委托构造器负责主要初始化；
- 实例初始化器不会为每层 `this(...)` 重复执行；
- 构造链最终只完成一轮实例初始化流程。

### 9.32.3 不依赖复杂初始化副作用

字段初始化器和实例初始化块中应避免：

- 外部 I/O；
- 启动线程；
- 注册全局对象；
- 调用可重写方法；
- 复杂异常恢复。

---

## 9.33 实例初始化块

```java
public class User {

    {
        System.out.println(
                "instance initializer"
        );
    }

    public User() {
    }
}
```

### 9.33.1 每次创建对象执行

实例初始化块会参与每次实例初始化。

### 9.33.2 适合共享构造初始化

多个构造器共享的简单实例初始化逻辑可以放入初始化块。

### 9.33.3 通常优先使用构造器或字段初始化

初始化块容易让执行顺序分散。

推荐优先级通常是：

```text
简单默认值
→ 字段初始化器

需要参数和校验
→ 构造器

复杂共享创建逻辑
→ 私有方法、静态工厂或 Builder
```

---

## 9.34 构造器中的动态绑定风险

### 9.34.1 父类构造器调用可重写方法

```java
class Parent {

    Parent() {
        print();
    }

    void print() {
        System.out.println("Parent");
    }
}
```

子类：

```java
class Child extends Parent {

    private String name = "Java";

    @Override
    void print() {
        System.out.println(name);
    }
}
```

创建：

```java
new Child();
```

父类构造期间调用 `print()`，动态绑定可能进入子类实现。

此时子类字段初始化可能尚未完成，输出可能是：

```text
null
```

### 9.34.2 构造器中避免调用可重写方法

包括：

- 普通非 `final` 实例方法；
- 由子类实现的抽象方法；
- 间接调用可重写方法；
- 发布回调后由外部反调对象。

### 9.34.3 安全选择

构造期间优先调用：

- `private` 方法；
- `final` 方法；
- 静态纯函数；
- 不依赖子类状态的明确逻辑。

但仍要避免 `this` 逃逸和复杂副作用。

---

## 9.35 this 逃逸

`this` 逃逸表示：

> 对象尚未构造完成，当前对象引用已经被外部代码观察或保存。

### 9.35.1 注册监听器

```java
public User(EventBus bus) {
    bus.register(this);
}
```

### 9.35.2 启动线程

```java
public Worker() {
    new Thread(this::run).start();
}
```

### 9.35.3 放入静态集合

```java
public User() {
    Registry.add(this);
}
```

### 9.35.4 调用外部可回调代码

```java
public User(Plugin plugin) {
    plugin.initialize(this);
}
```

外部代码可能立即调用当前对象。

### 9.35.5 风险

外部可能看到：

- 默认值；
- 半初始化集合；
- 未建立不变量；
- 未完成父类状态；
- 未安全发布的字段；
- 竞态条件。

---

## 9.36 避免构造期间发布对象

### 9.36.1 工厂完成后再注册

```java
public static Worker create(
        EventBus bus
) {
    Worker worker = new Worker();
    bus.register(worker);

    return worker;
}
```

### 9.36.2 显式启动

```java
Worker worker = new Worker();
worker.start();
```

构造器只建立状态，不启动异步行为。

### 9.36.3 容器生命周期

由依赖注入容器管理时，可以使用：

- 构造完成回调；
- 生命周期接口；
- 明确启动阶段；
- 应用事件。

但仍需理解容器何时发布对象。

---

## 9.37 构造器校验

### 9.37.1 创建即合法

```java
public User(String name) {
    if (
            name == null
            || name.isBlank()
    ) {
        throw new IllegalArgumentException(
                "name must not be blank"
        );
    }

    this.name = name;
}
```

### 9.37.2 校验后规范化

```java
String normalized = name.trim();

if (normalized.isEmpty()) {
    throw new IllegalArgumentException();
}

this.name = normalized;
```

Java 25 在需要传给父类时，可以先执行该逻辑再调用 `super(...)`。

### 9.37.3 不保留非法输入引用

集合参数：

```java
this.items = List.copyOf(items);
```

避免调用方后续修改。

### 9.37.4 异常类型

- `NullPointerException`：明确非空参数违反；
- `IllegalArgumentException`：值不合法；
- 领域异常：业务规则不满足；
- `IllegalStateException`：当前对象状态不允许。

应保持项目内一致。

---

## 9.38 构造器参数与字段同名

常见写法：

```java
public User(String name) {
    this.name = name;
}
```

### 9.38.1 左右含义

```text
this.name
→ 当前对象字段

name
→ 构造器参数
```

### 9.38.2 错误写法

```java
public User(String name) {
    name = name;
}
```

只把参数值重新赋给参数自身，字段仍保持默认值。

### 9.38.3 命名不必刻意不同

不需要写：

```java
public User(String userNameValue) {
    name = userNameValue;
}
```

字段与参数同名配合 `this` 通常更清晰。

---

## 9.39 构造器重载与委托

### 9.39.1 委托到主构造器

```java
public User() {
    this("anonymous", true);
}

public User(String name) {
    this(name, true);
}

public User(
        String name,
        boolean enabled
) {
    this.name = requireName(name);
    this.enabled = enabled;
}
```

### 9.39.2 选择一个主初始化路径

优点：

- 校验集中；
- 默认值一致；
- 减少字段遗漏；
- 减少重复代码。

### 9.39.3 重载爆炸

参数组合持续增加时：

```text
name
name + age
name + age + address
name + age + address + enabled
```

应考虑：

- 静态工厂；
- Builder；
- 参数对象；
- 值对象；
- 拆分类职责。

完整规则见 `10`。

## 9.40 只读属性与受控修改

### 9.40.1 只提供 Getter

```java
public String name() {
    return name;
}
```

不提供通用 Setter。

### 9.40.2 提供业务方法

```java
public void rename(String newName) {
    this.name = requireName(newName);
}
```

### 9.40.3 集合返回快照

```java
public List<OrderItem> items() {
    return List.copyOf(items);
}
```

### 9.40.4 可变元素仍需注意

即使列表不可修改，如果 `OrderItem` 可变，调用方仍可能修改元素。

完整防御性复制见 `07` 和 `10`。

## 9.41 API 可见性设计

### 9.41.1 公开稳定能力

```java
public void cancel() {
}
```

### 9.41.2 隐藏实现步骤

```java
private void validateCancelable() {
}
```

### 9.41.3 包内协作者

```java
class OrderPolicy {
}
```

不需要对整个应用公开。

### 9.41.4 谨慎 protected

`protected` 会形成继承扩展契约。

子类可能依赖：

- 调用顺序；
- 字段；
- 异常；
- 状态；
- 可重写钩子。

公开 `protected` 成员前，应确认类确实为继承设计并有文档。

## 9.42 包作为模块边界

在未使用 Java 模块系统时，包仍可作为轻量边界：

```text
com.example.order.api
com.example.order.domain
com.example.order.internal
```

### 9.42.1 internal 只是约定

包名包含：

```text
internal
```

不会自动阻止访问。

需要结合：

- 包级可见性；
- 模块不导出；
- 构建拆分；
- ArchUnit 等架构测试；
- 代码审查。

### 9.42.2 对外包保持小

公共 API 包应尽量只包含：

- 稳定接口；
- 请求和响应模型；
- 明确异常；
- 必要值对象。

实现类保持包级或模块内部。

## 9.43 反射与访问控制边界

反射可以查询：

```java
Class<?> type = User.class;
```

并获取：

- 构造器；
- 字段；
- 方法；
- 注解。

### 9.43.1 深反射可能受模块限制

现代 Java 模块系统会限制未开放包的深反射访问。

### 9.43.2 setAccessible 不是万能钥匙

是否允许绕过访问检查取决于：

- 模块开放；
- 运行参数；
- 安全策略；
- JDK 版本；
- 调用上下文。

### 9.43.3 框架访问 private 不代表封装无意义

框架通常根据明确配置访问内部结构。

业务代码仍应遵循公开 API，不应把反射当作常规调用方式。

## 9.44 常见封装坏味道

### 9.44.1 public 可变字段

```java
public List<Item> items;
```

### 9.44.2 全字段 Setter

任何状态组合都能被外部构造。

### 9.44.3 Getter 返回内部集合

导致封装泄漏。

### 9.44.4 业务规则位于 Controller

对象成为数据容器。

### 9.44.5 protected 字段过多

子类直接修改父类状态，父类难以维护不变量。

### 9.44.6 构造器执行外部 I/O

创建对象可能：

- 很慢；
- 失败原因复杂；
- 难测试；
- 隐藏副作用。

### 9.44.7 构造器启动线程

造成 `this` 逃逸和生命周期混乱。

### 9.44.8 import 通配符堆积

来源不清且容易冲突，虽然不影响运行性能。

## 9.47 易错点

### 误区一：字段使用 private 就已经完成封装

**错误。**

还需要控制行为入口、不变量、集合暴露和依赖边界。

### 误区二：所有字段都应该有 Getter 和 Setter

**错误。**

通用 Setter 可能破坏对象状态，Getter 也可能泄漏内部结构。

### 误区三：public 表示对所有模块和所有代码绝对可见

**错误。**

还受外层类型、模块导出和可读性约束。

### 误区四：private 只能被声明它的那一个类体访问

**不完整。**

同一顶层嵌套体系中的嵌套类型可以按 Java 规则访问彼此 private 成员。

### 误区五：private 可以替代业务权限校验

**错误。**

它是语言封装机制，不是用户授权和数据安全机制。

### 误区六：包级访问只对当前源文件可见

**错误。**

它对同包可访问代码可见。

### 误区七：子包天然拥有父包的包级访问权

**错误。**

子包是独立包。

### 误区八：protected 只允许子类访问

**错误。**

同包普通代码也可以访问。

### 误区九：跨包子类可以通过任意 Parent 对象访问 protected 字段

**错误。**

跨包继承访问存在限定对象类型限制。

### 误区十：protected 字段比 private 字段更方便，所以应优先使用

**错误。**

它会扩大状态修改边界并形成继承契约。

### 误区十一：顶层类可以声明为 private

**错误。**

顶层类型只能是 `public` 或包级访问。

### 误区十二：import 会把类加载进 JVM

**错误。**

它主要是编译期名称解析。

### 误区十三：import 会改变类型的访问权限

**错误。**

不可访问类型导入后仍不可访问。

### 误区十四：通配符导入会加载包中所有类

**错误。**

不会产生这种运行时行为。

### 误区十五：import java.util.* 包含 java.util.concurrent

**错误。**

导入不递归到子包。

### 误区十六：Java import 支持 as 别名

**错误。**

普通 Java 导入没有别名语法。

### 误区十七：静态导入越多代码越简洁

**错误。**

可能让成员来源难以判断。

### 误区十八：模块导入会自动打开所有包供反射访问

**错误。**

模块导入只影响编译单元名称可见性。

### 误区十九：构造器是一个没有返回值的普通方法

**错误。**

构造器有独立声明和调用规则，并且不是类成员。

### 误区二十：构造器返回当前对象

**错误。**

构造器没有返回类型，实例创建表达式产生对象引用结果。

### 误区二十一：写了 void User() 就声明了构造器

**错误。**

这是一个普通方法。

### 误区二十二：构造器会被子类继承

**错误。**

子类必须声明自己的构造器，并通过构造链调用父类构造器。

### 误区二十三：构造器可以被重写

**错误。**

构造器不参与方法重写。

### 误区二十四：没有写无参构造器时编译器永远会生成

**错误。**

只要类声明了任意构造器，编译器就不会自动生成默认构造器。

### 误区二十五：默认构造器等于所有无参构造器

**错误。**

默认构造器专指编译器在特定条件下自动生成的构造器。

### 误区二十六：this 是对象本身而不是引用表达式

**不准确。**

`this` 是表示当前实例的引用表达式。

### 误区二十七：super 是子类对象中的独立父类对象

**错误。**

它是访问当前对象父类部分的受限语法。

### 误区二十八：一个构造器可以先 this() 再 super()

**错误。**

一个构造器最多有一个显式构造器调用。

### 误区二十九：Java 25 完全取消了显式构造器调用规则

**错误。**

只放宽了调用前可执行语句，构造链仍然存在。

### 误区三十：Java 25 后可以在 super 前任意调用实例方法

**错误。**

构造早期上下文禁止正常使用未构造完成的当前实例。

### 误区三十一：Java 25 后可以在 super 前把 this 注册到全局容器

**错误。**

提前泄漏当前对象仍不允许且不安全。

### 误区三十二：Java 25 的构造器前段可以任意读取实例字段

**错误。**

简单初始化与读取、调用当前对象是不同规则。

### 误区三十三：实例初始化块只执行一次

**错误。**

每次创建对象都会参与实例初始化。

### 误区三十四：使用 this() 委托会让实例初始化块重复执行多次

**错误。**

同一对象的构造链不会为每层委托重复完整实例初始化。

### 误区三十五：构造器中调用可重写方法可以让子类提前初始化

**错误。**

动态绑定可能访问尚未初始化的子类字段。

### 误区三十六：构造器中启动线程只是一种简洁写法

**错误。**

可能造成 `this` 逃逸和竞态条件。

### 误区三十七：构造器中注册监听器没有风险

**错误。**

外部系统可能立即回调半初始化对象。

### 误区三十八：name = name 会把参数赋给字段

**错误。**

两边都解析为参数变量。

### 误区三十九：私有构造器只能用于单例

**错误。**

还可用于工具类、工厂控制和限制实例化。

### 误区四十：反射可以在所有情况下无条件绕过模块和 private

**错误。**

现代模块系统和运行时配置会限制深反射。

## 9.48 工程实践建议

1. 访问级别遵循最小可见性原则。
2. `public` 成员只暴露稳定、明确的 API 契约。
3. 可变字段保持 `private`，通过业务方法修改。
4. 不机械生成所有 Getter 和 Setter。
5. 集合 Getter 返回不可修改快照或受控视图。
6. 包级访问用于同一实现边界协作，不为方便全部改 `public`。
7. `protected` 只用于真正为继承设计的扩展点。
8. 父类字段优先 `private`，通过受控方法供子类使用。
9. 公共方法的参数和返回类型也必须具有合理可见性。
10. 包名按业务能力组织，不只按 Controller、Service、DAO 技术层堆放。
11. 不把子包当作父包的访问子域。
12. 导入优先使用 IDE 管理的显式导入。
13. 通配符导入的主要问题是可读性和冲突，不是运行性能。
14. 静态导入只用于来源非常明确的少量成员。
15. 模块导入用于合适场景，不用它掩盖依赖边界。
16. 构造器只负责建立合法对象，不执行复杂外部 I/O。
17. 构造器参数在保存前完成校验和规范化。
18. 可变集合、数组和日期对象在构造边界进行防御性复制。
19. 多个构造器委托到一个主初始化路径。
20. 构造参数组合持续增长时使用静态工厂、Builder 或参数对象。
21. 不在构造器中调用可重写方法。
22. 不在构造器中启动线程、注册监听器或发布 `this`。
23. 使用显式 `start()` 或工厂在构造完成后启动行为。
24. Java 25 构造器前段只做参数校验、局部计算和受限安全初始化。
25. 不在 Java 25 构造器前段读取当前对象或调用实例方法。
26. 字段初始化器和实例初始化块保持简单、无外部副作用。
27. 私有构造器的意图通过类名、工厂和文档明确表达。
28. 不为了单元测试扩大生产代码访问权限。
29. 使用架构测试验证包和模块依赖规则。
30. `internal` 包名配合包级可见性或模块不导出才形成真实边界。
31. 反射访问内部成员只用于框架边界，不作为普通业务调用方式。
32. 代码审查重点检查：过度公开、状态泄漏、构造器副作用和 `this` 逃逸。

## 9.50 本章总结

### 9.50.1 封装主线

```text
封装
├── 隐藏内部表示
├── 控制状态修改
├── 维护对象不变量
├── 限制依赖范围
└── 隔离实现变化
```

### 9.50.2 访问级别

```text
private
→ 当前顶层嵌套体系内部

包级访问
→ 同包

protected
→ 同包
→ 跨包子类受限访问

public
→ 满足类型、包和模块边界时广泛访问
```

### 9.50.3 包与导入

```text
package
→ 组织类型和建立访问边界

import
→ 编译期简单名称解析
→ 不加载类
→ 不改变访问权限

通配符导入
→ 不递归到子包
→ 不造成运行时全包加载
```

### 9.50.4 构造器

```text
构造器
→ 参与实例创建和初始化
→ 没有返回类型
→ 不是类成员
→ 不继承、不重写
→ 可以重载
```

### 9.50.5 构造链

```text
this(...)
→ 委托同类构造器

super(...)
→ 调用父类构造器

一个构造器
→ 最多一个显式构造器调用

整个构造链
→ 必须终止
```

### 9.50.6 Java 25 灵活构造器体

```text
显式构造器调用之前
→ 可以执行安全语句
→ 可以校验和转换参数
→ 可以进行受限字段初始化

仍然不能
→ 任意读取当前实例
→ 调用实例方法
→ 泄漏 this
→ 绕过父类构造
```

### 9.50.7 面试口述版

封装不仅是把字段声明为 `private`，而是隐藏内部表示、限制状态修改入口、维护对象不变量并暴露稳定业务协议。访问级别应遵循最小可见性原则：`private` 用于内部实现，包级访问用于同包协作，`protected` 同时提供同包访问和跨包子类受限访问，`public` 还受到外层类型和模块导出边界影响。

`import` 只是编译期名称解析，不会加载类，也不会改变访问权限。通配符导入不会递归子包，也不会导致 JVM 加载整个包。包名中的子包是独立包，不继承父包的包级访问权。

构造器没有返回类型，不是类成员，不会被继承或重写，但可以重载。编译器只在类没有声明任何构造器时提供默认构造器。`this(...)` 委托同类构造器，`super(...)` 调用父类构造器，一个构造器最多有一个显式构造器调用。

Java 25 正式交付灵活构造器体，允许在 `super(...)` 或 `this(...)` 前进行参数校验、局部计算和受限安全初始化，但仍不能任意读取当前对象、调用实例方法或泄漏 `this`。构造器应只负责建立合法对象，不应调用可重写方法、启动线程或注册监听器。
