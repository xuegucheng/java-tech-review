# 封装与访问控制

## 5.8 构造方法

构造方法用于初始化新创建的对象。

```java
public class User {
    private String name;
    public User(String name) {
        this.name = name;
    }
}
```

创建：

```
User user = new User("Java");
```

**5.8.1 构造方法的特点**

构造方法：

- 名称必须与类名相同
- 没有返回类型
- 不能声明 void
- 创建对象时自动调用
- 可以重载
- 不能被普通方式继承
- 不能被子类重写
- 可以调用其他构造方法
- 正确：

```
public User() {
}
```

错误：

```java
public void User() {
}
```

后者不是构造方法，而是名为 User 的普通方法。

**5.8.2 默认构造方法**

如果一个类没有显式声明任何构造方法，编译器会提供一个无参构造方法：

```java
public class User {
}
```

近似于：

```java
public class User {
    public User() {
        super();
    }
}
```

但一旦显式声明任何构造方法：

```
public User(String name) {
this.name = name;
}
```

编译器就不会再自动生成无参构造方法。
此时：

```
new User();
```

会编译失败。
需要无参构造时必须显式定义：

```
public User() {
}
```

**5.8.3 默认构造方法不一定是 public**

编译器生成的默认构造方法，其访问权限通常与类的访问权限一致。
例如包级类：

```
class User {
}
```

默认构造方法也是包级访问权限，而不是固定为 public 。

**5.8.4 构造方法重载**

```java
public class User {
    private String name;
    private int age;
    public User() {
    }
    public User(String name) {
        this.name = name;
    }
    public User(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

不同构造方法通过参数列表区分。

## 5.9 构造方法链与 this()

构造方法可以通过 this() 调用当前类的其他构造方法。

```java
public class User {
    private String name;
    private int age;
    public User() {
        this("unknown", 0);
    }
    public User(String name) {
        this(name, 0);
    }
    public User(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

优点：

- 避免重复初始化逻辑
- 保证多个构造方法遵循相同校验规则
- 形成统一的主构造方法

**5.9.1 this() 的位置规则**

Java 24 及之前，显式 this(...) 必须是构造方法体中的第一条语句。

正确：

```
public User() {
this("unknown");
}
```

错误（Java 24 及之前）：

```java
public User() {
    System.out.println("create");
    this("unknown");
}
```

原因是构造链必须先确定对象初始化路径。

Java 25 起，Flexible Constructor Bodies 允许在显式构造器调用之前执行受限制的安全语句，例如参数校验。但在父类构造完成之前，不能任意访问尚未完成初始化的当前对象。

**5.9.2 this() 不能形成循环调用**

错误：

```
public User() {
this("A");
}
public User(String name) {
this();
}
```

这样会形成构造方法递归，编译器会报错。

**5.9.3 this() 和 super() 不能同时显式调用**

因为两者都必须位于构造方法第一行：

```
public User() {
this("A");
super();
}
```

无法成立。
如果使用 this() 调用当前类其他构造方法，最终某个构造方法会调用父类构造方法。
父类构造机制下一章展开。

## 5.10 this 关键字

this 表示当前正在执行方法或构造方法的对象。

```java
public class User {
    private String name;
    public void printName() {
        System.out.println(this.name);
    }
}
```

当执行：

```
user.printName();
```

方法内部的 this 指向 user 当前所指向的对象。

**5.10.1 区分字段与参数**

```java
public class User {
    private String name;
    public void setName(String name) {
        this.name = name;
    }
}
```

其中：

```
this.name → 当前对象的字段
name → 方法参数
```

如果写成：

```java
public void setName(String name) {
    name = name;
}
```

左右两侧都是局部参数，字段不会被修改。

**5.10.2 返回当前对象**

```
public User rename(String name) {
this.name = name;
return this;
}
```

可以支持链式调用：

```
user.rename("Java")
.activate();
```

但链式 API 应控制副作用和可读性，不应为了链式调用而机械返回 this 。

**5.10.3 将当前对象作为参数传递**

```java
public void register(Registry registry) {
    registry.register(this);
}
```

这里把当前对象的引用值传给其他方法。

**5.10.4 static 上下文不能使用 this**

错误：

```java
public static void execute() {
    System.out.println(this);
}
```

静态方法属于类级别调用，不依赖某个具体对象，因此没有当前对象 this 。
静态机制后续章节详细讨论。

## 5.11 实例初始化顺序

对于不涉及继承的普通类，对象实例初始化顺序可以简化为：

```
字段先获得默认值
↓
按源码顺序执行字段初始化表达式
↓
按源码顺序执行实例代码块
↓
执行构造方法体
```

示例：

```java
public class InitializationDemo {
    private int a = print("字段 a", 1);
    {
        System.out.println("实例代码块");
    }
    private int b = print("字段 b", 2);
    public InitializationDemo() {
        System.out.println("构造方法");
    }
    private int print(String message, int value) {
        System.out.println(message);
        return value;
    }
}
```

创建：

```
new InitializationDemo();
```

输出：

```
字段 a
实例代码块
字段 b
构造方法
```

因为字段初始化表达式和实例代码块按照源码出现顺序执行。

**5.11.1 默认值先于显式初始化**

```java
public class Example {
    private int value = initialize();
    private int initialize() {
        System.out.println(value);
        return 10;
    }
}
```

创建对象时， initialize() 中读到的 value 可能是：

```
0
```

因为对象字段先获得默认值，再执行显式初始化。

**5.11.2 实例代码块**

```java
{
System.out.println("实例初始化");
}
```

实例代码块会在每次创建对象时执行，并且先于构造方法体。

其常见作用：

- 多个构造方法共享初始化逻辑
- 匿名内部类初始化
- 少数框架或生成代码场景

普通业务代码中不宜滥用，优先使用明确的构造方法或私有初始化方法。

## 5.12 封装

封装是面向对象的核心特性之一。
封装不仅是：

```
字段使用 private
提供 Getter 和 Setter
```

更准确的定义是：
将对象的内部状态和实现细节隐藏起来，只通过受控的接口暴露必要行为，并确保对象始终处于合法状态。

封装包括：

- 隐藏内部数据结构
- 限制状态修改入口
- 对输入进行校验
- 维护业务不变量
- 隐藏实现细节
- 降低模块耦合
- 允许内部实现独立演进

**5.12.1 没有封装的问题**

```java
public class Inventory {
    public int availableStock;
}
```

外部代码：

```
inventory.availableStock = -100;
```

问题：

- 无法校验
- 无法记录变更日志
- 无法限制状态转换
- 无法保证线程安全
- 无法统一触发领域事件
- 内部实现难以修改

**5.12.2 使用方法控制状态修改**

```java
public class Inventory {
    private int availableStock;
    public void deduct(int quantity) {
        if (quantity <= 0) {
            throw new IllegalArgumentException("扣减数量必须大于 0");
        }
        if (availableStock < quantity) {
            throw new IllegalStateException("库存不足");
        }
        availableStock -= quantity;
    }
    public int getAvailableStock() {
        return availableStock;
    }
}
```

此时外部不能直接制造负库存。

**5.12.3 Getter 不代表破坏封装**

只读 Getter 通常不会直接破坏封装：

```
public int getAvailableStock() {
return availableStock;
}
```

但如果返回内部可变对象：

```
public List<OrderItem> getItems() {
return items;
}
```

外部可以：

```
order.getItems().clear();
```

这会破坏封装。
更安全：

```
public List<OrderItem> getItems() {
return List.copyOf(items);
}
```

或者暴露受控行为：

```java
public void addItem(OrderItem item) {
    // 校验和维护规则
}
```

## 5.13 Getter 和 Setter 的设计

Getter、Setter 是访问字段的一种方式，但不应机械生成。

**5.13.1 机械 Setter 的问题**

```java
public void setStatus(OrderStatus status) {
    this.status = status;
}
```

外部可以进行任意状态跳转：

```
order.setStatus(OrderStatus.COMPLETED);
order.setStatus(OrderStatus.CREATED);
order.setStatus(null);
```

无法保证状态机合法。
更合理：

```java
public void complete() {
    if (status != OrderStatus.PROCESSING) {
        throw new IllegalStateException("只有处理中订单才能完成");
    }
    status = OrderStatus.COMPLETED;
}
```

**5.13.2 Getter 也应根据需要提供**

并非所有字段都需要 Getter。
例如：

```java
private String passwordHash;
```

通常不应提供：

```
public String getPasswordHash() {
return passwordHash;
}
```

对象应只暴露外部真正需要的信息和行为。

**5.13.3 计算属性不必对应字段**

Getter 不一定只是返回字段：

```
public boolean isCompleted() {
return status == OrderStatus.COMPLETED;
}
```

也可以返回派生状态：

```
public BigDecimal getTotalAmount() {
return items.stream()
.map(OrderItem::getAmount)
.reduce(BigDecimal.ZERO, BigDecimal::add);
}
```

因此：
对象的公共 API 应表达业务语义，而不是机械映射内部字段。

**5.13.4 JavaBean 规范与领域模型**

JavaBean 风格通常强调：

- 无参构造方法
- 私有字段
- Getter
- Setter
- 这种形式适合：
- DTO
- 配置对象
- 表单对象
- ORM 映射对象
- 序列化对象

但领域对象不一定适合全部字段可写。
可以区分：

```
DTO / DO
→ 偏数据承载
→ Getter/Setter 较多
领域对象
→ 承载业务规则
→ 通过行为修改状态
```

## 5.14 访问控制符

Java 提供四种访问级别：

```
private
默认访问权限
protected
public
```

**5.14.1 访问范围**

- 修饰符 当前类 同包类 不同包子类 不同包普通类
- private ✅ ❌ ❌ ❌
- 默认 ✅ ✅ ❌ ❌
- protected ✅ ✅ ✅ ❌
- public ✅ ✅ ✅ ✅

默认访问权限也称：

- package-private
- 包级访问权限
- 它没有关键字：

```
class User {
}
```

## 5.15 private

private 成员只能在当前类内部直接访问。

```java
public class User {
    private String name;
    private void validate() {
    }
}
```

外部不能直接调用：

```
user.validate();
```

也不能直接访问：

```
user.name;
```

private 适合：

- 内部状态
- 内部辅助方法
- 实现细节
- 不希望外部依赖的成员

**5.15.1 private 是类级别访问控制**

同一个类中的不同对象可以访问彼此的 private 字段：

```java
public class User {
    private int age;
    public boolean olderThan(User other) {
        return this.age > other.age;
    }
}
```

虽然访问的是 other.age ，但代码位于 User 类内部，因此合法。
因此：
private 限制的是类外访问，不是对象之间互相不可访问。

## 5.16 默认访问权限

没有显式修饰符时，成员只能在同一个包内访问。

```
class PackageService {
void execute() {
}
}
```

适合：

- 包内部实现
- 不希望暴露给包外的协作类
- 模块内部辅助组件
- 测试可见但不对外公开的逻辑

包级封装常被忽略，但它是减少公共 API 的有效方式。

## 5.17 protected

protected 允许：

- 当前类访问
- 同包类访问
- 不同包的子类访问

但跨包子类访问存在重要边界。
假设：

```java
package parent;
public class Parent {
    protected int value;
}
```

子类位于另一个包：

```java
package child;
public class Child extends Parent {
    public void test(Child child) {
        this.value = 1;
        child.value = 2;
    }
}
```

通常可以通过当前子类实例或子类类型引用访问。
但不应简单认为：
子类可以通过任意 Parent 对象访问 protected 成员。
例如跨包场景中：

```java
public void test(Parent parent) {
    parent.value = 1;
}
```

通常不允许。
核心理解：
protected 在跨包子类中提供的是继承关系上的访问能力，而不是把成员变成对子类所在包完全公开。

## 5.18 public

public 表示成员对所有能够访问当前类的代码可见。

```java
public class Order {
    public void cancel() {
    }
}
```

但“可以 public”不代表“应该 public”。

公共 API 一旦被外部依赖：

- 修改成本更高
- 兼容性要求更高
- 测试范围更大
- 实现细节更难调整
- 设计原则：

默认使用最小可见性，只有确实需要对外暴露时才提升访问权限。

## 5.19 顶层类的访问控制

顶层类只能使用：

- public
- 默认包级权限
- 不能使用：
- private
- protected
- 错误：

```java
private class User {
}
```

一个 .java 文件中可以定义多个顶层类，但最多只有一个 public 顶层类，并且文件名通常必须与该 public 类名一致。
例如：

```java
public class User {
}
class UserValidator {
}
```

文件名应为：

```
User.java
```

## 5.20 包与类组织

包用于组织类并避免命名冲突。

```
package com.example.order.domain;
```

完全限定类名：

```
com.example.order.domain.Order
```

**5.20.1 包名与目录**

通常目录结构与包名对应：

```bash
src/main/java/
└── com/
└── example/
└── order/
└── domain/
└── Order.java
```

**5.20.2 import**

```java
import java.util.List;
```

import 用于在源码中简化类型名称。
没有 import 时可以使用完全限定名：

```
java.util.List<String> list;
```

import 不等于加载类，也不会直接创建对象。
它主要影响编译期名称解析。

**5.20.3 java.lang 自动导入**

java.lang 包中的类型会自动导入，例如：

- String
- Object
- Integer
- System
- Math
- Thread
- 因此不需要：

```java
import java.lang.String;
```

**5.20.4 同名类冲突**

如果两个包中存在同名类：

```
java.util.Date
java.sql.Date
```

不能同时通过简单类名区分。
可以：

```java
import java.util.Date;
java.sql.Date sqlDate;
Date utilDate;
```

或者都使用完全限定名。
Java 不支持 import 别名语法。
