# 封装与访问控制

## 9.1 本章定位

本章覆盖构造方法、this、封装与访问控制，解决以下问题：

- 构造方法与普通方法有什么区别？
- 默认构造方法在什么条件下存在？
- 构造方法重载如何使用？
- this 表示什么？
- this(...) 有什么作用？
- 实例初始化顺序是怎样的？
- 封装是否只是把字段设置成 private？
- Getter、Setter 是否应该机械生成？
- public、protected、默认访问权限、private 分别能控制什么范围？
- 包与访问边界有什么关系？

本章核心主线：

```
构造方法建立初始状态
→ this 表示当前对象
→ 封装隐藏内部实现
→ 访问控制限定可见范围
→ 方法作为合法状态变更入口
```

本章暂不深入：

- 工厂、Builder、不可变对象和复杂对象创建：见 10。
- 继承中的 protected 细节：见 11。

## 9.2 构造方法

构造方法用于初始化新创建的对象。

```java
public class User {
    private String name;
    public User(String name) {
        this.name = name;
    }
}
```

创建：

```
User user = new User("Java");
```

**1.1 构造方法的特点**

构造方法：

- 名称必须与类名相同
- 没有返回类型
- 不能声明 void
- 创建对象时自动调用
- 可以重载
- 不能被普通方式继承
- 不能被子类重写
- 可以调用其他构造方法
- 正确：

```
public User() {
}
```

错误：

```java
public void User() {
}
```

后者不是构造方法，而是名为 User 的普通方法。

**1.2 默认构造方法**

如果一个类没有显式声明任何构造方法，编译器会提供一个无参构造方法：

```java
public class User {
}
```

近似于：

```java
public class User {
    public User() {
        super();
    }
}
```

但一旦显式声明任何构造方法：

```
public User(String name) {
this.name = name;
}
```

编译器就不会再自动生成无参构造方法。
此时：

```
new User();
```

会编译失败。
需要无参构造时必须显式定义：

```
public User() {
}
```

**1.3 默认构造方法不一定是 public**

编译器生成的默认构造方法，其访问权限通常与类的访问权限一致。
例如包级类：

```
class User {
}
```

默认构造方法也是包级访问权限，而不是固定为 public 。

**1.4 构造方法重载**

```java
public class User {
    private String name;
    private int age;
    public User() {
    }
    public User(String name) {
        this.name = name;
    }
    public User(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

不同构造方法通过参数列表区分。

## 9.3 构造方法链与 this()

构造方法可以通过 this() 调用当前类的其他构造方法。

```java
public class User {
    private String name;
    private int age;
    public User() {
        this("unknown", 0);
    }
    public User(String name) {
        this(name, 0);
    }
    public User(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

优点：

- 避免重复初始化逻辑
- 保证多个构造方法遵循相同校验规则
- 形成统一的主构造方法

**3.1 this() 的位置规则**

Java 21 及之前，显式 this(...) 必须是构造方法体中的第一条语句。

Java 22 首次以预览特性提供构造器调用前语句；Java 23 进行第二次预览；Java 24 进行第三次预览。在 Java 22～24 中使用该能力，需要启用对应版本的预览特性。

Java 25 起，Flexible Constructor Bodies 正式交付，不再属于预览特性。

传统规则（Java 21 及之前）：

正确：

```
public User() {
this("unknown");
}
```

错误（Java 21 及之前）：

```java
public User() {
    System.out.println("create");
    this("unknown");
}
```

原因是构造链必须先确定对象初始化路径。

Java 25 起允许的写法：

```java
public User(String name) {
    if (name == null || name.isBlank()) {
        throw new IllegalArgumentException("name 不能为空");
    }

    this(name, 0);
}

public User(String name, int age) {
    this.name = name;
    this.age = age;
}
```

以上写法在 Java 25 中正式支持；Java 22～24 需要启用预览特性；Java 21 及之前不能编译。

前置代码读取的是构造参数或局部变量，不能读取当前对象实例字段，不能调用当前对象实例方法，不能让 this 在父类构造完成前逸出。Java 25 只是允许显式构造器调用前存在受限制的 prologue，并不是允许任意操作当前对象。

限制说明：
* 构造器调用前不是任意代码区域；
* 前置代码只能访问构造参数和局部变量；
* 不能通过 this 读取当前对象实例状态；
* 不能调用当前对象的实例方法；
* 不能让当前对象在父类构造完成前逸出；
* 不要写成"super 可以放在构造方法任意位置"。

**3.2 this() 不能形成循环调用**

错误：

```
public User() {
this("A");
}
public User(String name) {
this();
}
```

这样会形成构造方法递归，编译器会报错。

**3.3 this() 和 super() 不能同时显式调用**

一个构造器只能选择一条显式构造委托路径。显式构造器调用只能是 `this(...)` 或 `super(...)` 二者之一。

`this(...)` 表示先委托当前类的另一个构造器，被委托的构造器最终会直接或间接执行父类构造。不能在同一个构造器中既显式执行 `this(...)`，又显式执行 `super(...)`。

```
public User() {
this("A");
super();
}
```

无法成立。
如果使用 this() 调用当前类其他构造方法，最终某个构造方法会调用父类构造方法。
父类构造机制下一章展开。

## 9.4 this 关键字

this 表示当前正在执行方法或构造方法的对象。

```java
public class User {
    private String name;
    public void printName() {
        System.out.println(this.name);
    }
}
```

当执行：

```
user.printName();
```

方法内部的 this 指向 user 当前所指向的对象。

**4.1 区分字段与参数**

```java
public class User {
    private String name;
    public void setName(String name) {
        this.name = name;
    }
}
```

其中：

```
this.name → 当前对象的字段
name → 方法参数
```

如果写成：

```java
public void setName(String name) {
    name = name;
}
```

左右两侧都是局部参数，字段不会被修改。

**4.2 返回当前对象**

```
public User rename(String name) {
this.name = name;
return this;
}
```

可以支持链式调用：

```
user.rename("Java")
.activate();
```

但链式 API 应控制副作用和可读性，不应为了链式调用而机械返回 this 。

**4.3 将当前对象作为参数传递**

```java
public void register(Registry registry) {
    registry.register(this);
}
```

这里把当前对象的引用值传给其他方法。

**4.4 static 上下文不能使用 this**

错误：

```java
public static void execute() {
    System.out.println(this);
}
```

静态方法属于类级别调用，不依赖某个具体对象，因此没有当前对象 this 。
静态机制后续章节详细讨论。

## 9.5 实例初始化顺序

对于不涉及继承的普通类，对象实例初始化顺序可以简化为：

```
字段先获得默认值
↓
按源码顺序执行字段初始化表达式
↓
按源码顺序执行实例代码块
↓
执行构造方法体
```

示例：

```java
public class InitializationDemo {
    private int a = print("字段 a", 1);
    {
        System.out.println("实例代码块");
    }
    private int b = print("字段 b", 2);
    public InitializationDemo() {
        System.out.println("构造方法");
    }
    private int print(String message, int value) {
        System.out.println(message);
        return value;
    }
}
```

创建：

```
new InitializationDemo();
```

输出：

```
字段 a
实例代码块
字段 b
构造方法
```

因为字段初始化表达式和实例代码块按照源码出现顺序执行。

**5.1 默认值先于显式初始化**

```java
public class Example {
    private int value = initialize();
    private int initialize() {
        System.out.println(value);
        return 10;
    }
}
```

创建对象时， initialize() 中读到的 value 可能是：

```
0
```

因为对象字段先获得默认值，再执行显式初始化。

**5.2 实例代码块**

```java
{
System.out.println("实例初始化");
}
```

实例代码块会在每次创建对象时执行，并且先于构造方法体。

其常见作用：

- 多个构造方法共享初始化逻辑
- 匿名内部类初始化
- 少数框架或生成代码场景

普通业务代码中不宜滥用，优先使用明确的构造方法或私有初始化方法。

## 9.6 封装

封装是面向对象的核心特性之一。
封装不仅是：

```
字段使用 private
提供 Getter 和 Setter
```

更准确的定义是：
将对象的内部状态和实现细节隐藏起来，只通过受控的接口暴露必要行为，并确保对象始终处于合法状态。

封装包括：

- 隐藏内部数据结构
- 限制状态修改入口
- 对输入进行校验
- 维护业务不变量
- 隐藏实现细节
- 降低模块耦合
- 允许内部实现独立演进

**6.1 没有封装的问题**

```java
public class Inventory {
    public int availableStock;
}
```

外部代码：

```
inventory.availableStock = -100;
```

问题：

- 无法校验
- 无法记录变更日志
- 无法限制状态转换
- 无法保证线程安全
- 无法统一触发领域事件
- 内部实现难以修改

**6.2 使用方法控制状态修改**

```java
public class Inventory {
    private int availableStock;
    public void deduct(int quantity) {
        if (quantity <= 0) {
            throw new IllegalArgumentException("扣减数量必须大于 0");
        }
        if (availableStock < quantity) {
            throw new IllegalStateException("库存不足");
        }
        availableStock -= quantity;
    }
    public int getAvailableStock() {
        return availableStock;
    }
}
```

此时外部不能直接制造负库存。

**6.3 Getter 不代表破坏封装**

只读 Getter 通常不会直接破坏封装：

```
public int getAvailableStock() {
return availableStock;
}
```

但如果返回内部可变对象：

```
public List<OrderItem> getItems() {
return items;
}
```

外部可以：

```
order.getItems().clear();
```

这会破坏封装。
更安全：

```
public List<OrderItem> getItems() {
return List.copyOf(items);
}
```

或者暴露受控行为：

```java
public void addItem(OrderItem item) {
    // 校验和维护规则
}
```

## 9.7 Getter 和 Setter 的设计

Getter、Setter 是访问字段的一种方式，但不应机械生成。

**7.1 机械 Setter 的问题**

```java
public void setStatus(OrderStatus status) {
    this.status = status;
}
```

外部可以进行任意状态跳转：

```
order.setStatus(OrderStatus.COMPLETED);
order.setStatus(OrderStatus.CREATED);
order.setStatus(null);
```

无法保证状态机合法。
更合理：

```java
public void complete() {
    if (status != OrderStatus.PROCESSING) {
        throw new IllegalStateException("只有处理中订单才能完成");
    }
    status = OrderStatus.COMPLETED;
}
```

**7.2 Getter 也应根据需要提供**

并非所有字段都需要 Getter。
例如：

```java
private String passwordHash;
```

通常不应提供：

```
public String getPasswordHash() {
return passwordHash;
}
```

对象应只暴露外部真正需要的信息和行为。

**7.3 计算属性不必对应字段**

Getter 不一定只是返回字段：

```
public boolean isCompleted() {
return status == OrderStatus.COMPLETED;
}
```

也可以返回派生状态：

```
public BigDecimal getTotalAmount() {
return items.stream()
.map(OrderItem::getAmount)
.reduce(BigDecimal.ZERO, BigDecimal::add);
}
```

因此：
对象的公共 API 应表达业务语义，而不是机械映射内部字段。

**7.4 JavaBean 规范与领域模型**

JavaBean 风格通常强调：

- 无参构造方法
- 私有字段
- Getter
- Setter
- 这种形式适合：
- DTO
- 配置对象
- 表单对象
- ORM 映射对象
- 序列化对象

但领域对象不一定适合全部字段可写。
可以区分：

```
DTO / DO
→ 偏数据承载
→ Getter/Setter 较多
领域对象
→ 承载业务规则
→ 通过行为修改状态
```

## 9.8 访问控制符

| 修饰符 | 当前类 | 同包类 | 不同包子类 | 不同包普通类 |
|---|---|---|---|---|
| `private` | ✅ | ❌ | ❌ | ❌ |
| package-private | ✅ | ✅ | ❌ | ❌ |
| `protected` | ✅ | ✅ | ✅¹ | ❌ |
| `public` | ✅ | ✅ | ✅ | ✅ |

> ¹ `protected` 对不同包子类的访问仅限于该子类自身通过继承关系访问父类的 `protected` 成员，不能通过父类引用在其他包子类中访问。


Java 提供四种访问级别：

```
private
默认访问权限
protected
public
```

**8.1 访问范围**

- 修饰符 当前类 同包类 不同包子类 不同包普通类
- private ✅ ❌ ❌ ❌
- 默认 ✅ ✅ ❌ ❌
- protected ✅ ✅ ✅ ❌
- public ✅ ✅ ✅ ✅

默认访问权限也称：

- package-private
- 包级访问权限
- 它没有关键字：

```
class User {
}
```

## 9.9 private

private 成员只能在当前类内部直接访问。

```java
public class User {
    private String name;
    private void validate() {
    }
}
```

外部不能直接调用：

```
user.validate();
```

也不能直接访问：

```
user.name;
```

private 适合：

- 内部状态
- 内部辅助方法
- 实现细节
- 不希望外部依赖的成员

**9.1 private 是类级别访问控制**

同一个类中的不同对象可以访问彼此的 private 字段：

```java
public class User {
    private int age;
    public boolean olderThan(User other) {
        return this.age > other.age;
    }
}
```

虽然访问的是 other.age ，但代码位于 User 类内部，因此合法。
因此：
private 限制的是类外访问，不是对象之间互相不可访问。

## 9.10 默认访问权限

没有显式修饰符时，成员只能在同一个包内访问。

```
class PackageService {
void execute() {
}
}
```

适合：

- 包内部实现
- 不希望暴露给包外的协作类
- 模块内部辅助组件
- 测试可见但不对外公开的逻辑

包级封装常被忽略，但它是减少公共 API 的有效方式。

## 9.11 protected

protected 允许：

- 当前类访问
- 同包类访问
- 不同包的子类访问

但跨包子类访问存在重要边界。
假设：

```java
package parent;
public class Parent {
    protected int value;
}
```

子类位于另一个包：

```java
package child;
public class Child extends Parent {
    public void test(Child child) {
        this.value = 1;
        child.value = 2;
    }
}
```

通常可以通过当前子类实例或子类类型引用访问。
但不应简单认为：
子类可以通过任意 Parent 对象访问 protected 成员。
例如跨包场景中：

```java
public void test(Parent parent) {
    parent.value = 1;
}
```

通常不允许。
核心理解：
protected 在跨包子类中提供的是继承关系上的访问能力，而不是把成员变成对子类所在包完全公开。

## 9.12 public

public 表示成员对所有能够访问当前类的代码可见。

```java
public class Order {
    public void cancel() {
    }
}
```

但“可以 public”不代表“应该 public”。

公共 API 一旦被外部依赖：

- 修改成本更高
- 兼容性要求更高
- 测试范围更大
- 实现细节更难调整
- 设计原则：

默认使用最小可见性，只有确实需要对外暴露时才提升访问权限。

## 9.13 顶层类的访问控制

顶层类只能使用：

- public
- 默认包级权限
- 不能使用：
- private
- protected
- 错误：

```java
private class User {
}
```

一个 .java 文件中可以定义多个顶层类，但最多只有一个 public 顶层类，并且文件名通常必须与该 public 类名一致。
例如：

```java
public class User {
}
class UserValidator {
}
```

文件名应为：

```
User.java
```

## 9.14 包与类组织

包用于组织类并避免命名冲突。

```
package com.example.order.domain;
```

完全限定类名：

```
com.example.order.domain.Order
```

**14.1 包名与目录**

通常目录结构与包名对应：

```bash
src/main/java/
└── com/
└── example/
└── order/
└── domain/
└── Order.java
```

**14.2 import**

```java
import java.util.List;
```

import 用于在源码中简化类型名称。
没有 import 时可以使用完全限定名：

```
java.util.List<String> list;
```

import 不等于加载类，也不会直接创建对象。
它主要影响编译期名称解析。

**14.3 java.lang 自动导入**

java.lang 包中的类型会自动导入，例如：

- String
- Object
- Integer
- System
- Math
- Thread
- 因此不需要：

```java
import java.lang.String;
```

**14.4 同名类冲突**

如果两个包中存在同名类：

```
java.util.Date
java.sql.Date
```

不能同时通过简单类名区分。
可以：

```java
import java.util.Date;
java.sql.Date sqlDate;
Date utilDate;
```

或者都使用完全限定名。
Java 不支持 import 别名语法。

## 9.17 易错点

**误区五：构造方法有 void 返回类型**

**错误。**

写了 void 就是普通方法，不是构造方法。

**误区六：编译器永远会生成无参构造方法**

**错误。**

只有类没有显式声明任何构造方法时，才会生成默认构造方法。

**误区七：默认构造方法一定是 public**

**错误。**

其访问权限通常与类的访问权限一致。

**误区八：封装就是字段私有化并生成 Getter/Setter**

不完整。

真正的封装还包括：

- 控制状态修改
- 隐藏实现
- 维护对象不变量
- 限制可见性
- 防止内部可变对象泄漏
- 误区九：private 字段不能被其他对象访问

不准确。
同一个类内部可以访问另一个同类对象的 private 字段。

**误区十：protected 对所有子类对象都等同于 public**

**错误。**

跨包子类访问 protected 成员受到继承关系和引用类型限制。

- 误区十三：构造方法越复杂越好

**错误。**

构造方法应主要完成必要初始化和不变量校验，不宜执行外部 IO 或复杂业务流程。


## 9.18 工程实践建议

- 构造完成后对象应立即处于合法状态。
- 必填参数通过构造器保证，不依赖 Setter。
- 构造器不执行网络、数据库和复杂 IO。
- 不机械生成所有 Setter，最小可见性原则。
- 返回内部集合时防止可变状态泄漏。

## 9.19 本章总结

```
构造方法建立初始状态
→ this 表示当前对象
→ 封装隐藏内部实现
→ 访问控制限定可见范围
→ 方法作为合法状态变更入口
```
