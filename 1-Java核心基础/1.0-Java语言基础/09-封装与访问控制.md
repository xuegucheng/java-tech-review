# 第5章：封装与访问控制

## 5.8 构造方法

构造方法用于初始化新创建的对象。
1 public class User {
2
3 private String name;
4
5 public User(String name) {
6 this.name = name;
7 }
8 }
9
创建：
1 User user = new User("Java");
2
### 5.8.1 构造方法的特点
构造方法：
名称必须与类名相同
没有返回类型
不能声明 void
创建对象时自动调用

可以重载
不能被普通方式继承
不能被子类重写
可以调用其他构造方法
正确：
1 public User() {
2 }
3
错误：
1 public void User() {
2 }
3
后者不是构造方法，而是名为 User 的普通方法。
### 5.8.2 默认构造方法
如果一个类没有显式声明任何构造方法，编译器会提供一个无参构造方法：
1 public class User {
2 }
3
近似于：
1 public class User {
2
3 public User() {
4 super();
5 }
6 }
7
但一旦显式声明任何构造方法：
1 public User(String name) {
2 this.name = name;
3 }
4
编译器就不会再自动生成无参构造方法。
此时：
1 new User();
2
会编译失败。
需要无参构造时必须显式定义：

1 public User() {
2 }
3
### 5.8.3 默认构造方法不一定是 public
编译器生成的默认构造方法，其访问权限通常与类的访问权限一致。
例如包级类：
1 class User {
2 }
3
默认构造方法也是包级访问权限，而不是固定为 public 。
### 5.8.4 构造方法重载
1 public class User {
2
3 private String name;
4 private int age;
5
6 public User() {
7 }
8
9 public User(String name) {
10 this.name = name;
11 }
12
13 public User(String name, int age) {
14 this.name = name;
15 this.age = age;
16 }
17 }
18
不同构造方法通过参数列表区分。

## 5.9 构造方法链与 this()

构造方法可以通过 this() 调用当前类的其他构造方法。
1 public class User {
2
3 private String name;
4 private int age;
5
6 public User() {
7 this("unknown", 0);
8 }
9
10 public User(String name) {

11 this(name, 0);
12 }
13
14 public User(String name, int age) {
15 this.name = name;
16 this.age = age;
17 }
18 }
19
优点：
避免重复初始化逻辑
保证多个构造方法遵循相同校验规则
形成统一的主构造方法
### 5.9.1 this() 必须放在第一行
正确：
1 public User() {
2 this("unknown");
3 }
4
错误：
1 public User() {
2 System.out.println("create");
3 this("unknown");
4 }
5
原因是构造链必须先确定对象初始化路径。
### 5.9.2 this() 不能形成循环调用
错误：
1 public User() {
2 this("A");
3 }
4
5 public User(String name) {
6 this();
7 }
8
这样会形成构造方法递归，编译器会报错。
### 5.9.3 this() 和 super() 不能同时显式调用
因为两者都必须位于构造方法第一行：

1 public User() {
2 this("A");
3 super();
4 }
5
无法成立。
如果使用 this() 调用当前类其他构造方法，最终某个构造方法会调用父类构造方法。
父类构造机制下一章展开。

## 5.10 this 关键字

this 表示当前正在执行方法或构造方法的对象。
1 public class User {
2
3 private String name;
4
5 public void printName() {
6 System.out.println(this.name);
7 }
8 }
9
当执行：
1 user.printName();
2
方法内部的 this 指向 user 当前所指向的对象。
### 5.10.1 区分字段与参数
1 public class User {
2
3 private String name;
4
5 public void setName(String name) {
6 this.name = name;
7 }
8 }
9
其中：
1 this.name → 当前对象的字段
2 name → 方法参数
3
如果写成：

1 public void setName(String name) {
2 name = name;
3 }
4
左右两侧都是局部参数，字段不会被修改。
### 5.10.2 返回当前对象
1 public User rename(String name) {
2 this.name = name;
3 return this;
4 }
5
可以支持链式调用：
1 user.rename("Java")
2 .activate();
3
但链式 API 应控制副作用和可读性，不应为了链式调用而机械返回 this 。
### 5.10.3 将当前对象作为参数传递
1 public void register(Registry registry) {
2 registry.register(this);
3 }
4
这里把当前对象的引用值传给其他方法。
### 5.10.4 static 上下文不能使用 this
错误：
1 public static void execute() {
2 System.out.println(this);
3 }
4
静态方法属于类级别调用，不依赖某个具体对象，因此没有当前对象 this 。
静态机制后续章节详细讨论。

## 5.11 实例初始化顺序

对于不涉及继承的普通类，对象实例初始化顺序可以简化为：

1 字段先获得默认值
2 ↓
3 按源码顺序执行字段初始化表达式
4 ↓
5 按源码顺序执行实例代码块
6 ↓
7 执行构造方法体
8
示例：
1 public class InitializationDemo {
2
3 private int a = print("字段 a", 1);
4
5 {
6 System.out.println("实例代码块");
7 }
8
9 private int b = print("字段 b", 2);
10
11 public InitializationDemo() {
12 System.out.println("构造方法");
13 }
14
15 private int print(String message, int value) {
16 System.out.println(message);
17 return value;
18 }
19 }
20
创建：
1 new InitializationDemo();
2
输出：
1 字段 a
2 实例代码块
3 字段 b
4 构造方法
5
因为字段初始化表达式和实例代码块按照源码出现顺序执行。
### 5.11.1 默认值先于显式初始化
1 public class Example {
2
3 private int value = initialize();

4
5 private int initialize() {
6 System.out.println(value);
7 return 10;
8 }
9 }
10
创建对象时， initialize() 中读到的 value 可能是：
1 0
2
因为对象字段先获得默认值，再执行显式初始化。
### 5.11.2 实例代码块
1 {
2 System.out.println("实例初始化");
3 }
4
实例代码块会在每次创建对象时执行，并且先于构造方法体。
其常见作用：
多个构造方法共享初始化逻辑
匿名内部类初始化
少数框架或生成代码场景
普通业务代码中不宜滥用，优先使用明确的构造方法或私有初始化方法。

## 5.12 封装

封装是面向对象的核心特性之一。
封装不仅是：
1 字段使用 private
2 提供 Getter 和 Setter
3
更准确的定义是：
将对象的内部状态和实现细节隐藏起来，只通过受控的接口暴露必要行为，并确保对象始终处于合法状态。
封装包括：
隐藏内部数据结构
限制状态修改入口
对输入进行校验
维护业务不变量
隐藏实现细节
降低模块耦合
允许内部实现独立演进
### 5.12.1 没有封装的问题

1 public class Inventory {
2
3 public int availableStock;
4 }
5
外部代码：
1 inventory.availableStock = -100;
2
问题：
无法校验
无法记录变更日志
无法限制状态转换
无法保证线程安全
无法统一触发领域事件
内部实现难以修改
### 5.12.2 使用方法控制状态修改
1 public class Inventory {
2
3 private int availableStock;
4
5 public void deduct(int quantity) {
6 if (quantity <= 0) {
7 throw new IllegalArgumentException("扣减数量必须大于 0");
8 }
9
10 if (availableStock < quantity) {
11 throw new IllegalStateException("库存不足");
12 }
13
14 availableStock -= quantity;
15 }
16
17 public int getAvailableStock() {
18 return availableStock;
19 }
20 }
21
此时外部不能直接制造负库存。
### 5.12.3 Getter 不代表破坏封装
只读 Getter 通常不会直接破坏封装：
1 public int getAvailableStock() {
2 return availableStock;
3 }

4
但如果返回内部可变对象：
1 public List<OrderItem> getItems() {
2 return items;
3 }
4
外部可以：
1 order.getItems().clear();
2
这会破坏封装。
更安全：
1 public List<OrderItem> getItems() {
2 return List.copyOf(items);
3 }
4
或者暴露受控行为：
1 public void addItem(OrderItem item) {
2 // 校验和维护规则
3 }
4

## 5.13 Getter 和 Setter 的设计

Getter、Setter 是访问字段的一种方式，但不应机械生成。
### 5.13.1 机械 Setter 的问题
1 public void setStatus(OrderStatus status) {
2 this.status = status;
3 }
4
外部可以进行任意状态跳转：
1 order.setStatus(OrderStatus.COMPLETED);
2 order.setStatus(OrderStatus.CREATED);
3 order.setStatus(null);
4
无法保证状态机合法。
更合理：

1 public void complete() {
2 if (status != OrderStatus.PROCESSING) {
3 throw new IllegalStateException("只有处理中订单才能完成");
4 }
5
6 status = OrderStatus.COMPLETED;
7 }
8
### 5.13.2 Getter 也应根据需要提供
并非所有字段都需要 Getter。
例如：
1 private String passwordHash;
2
通常不应提供：
1 public String getPasswordHash() {
2 return passwordHash;
3 }
4
对象应只暴露外部真正需要的信息和行为。
### 5.13.3 计算属性不必对应字段
Getter 不一定只是返回字段：
1 public boolean isCompleted() {
2 return status == OrderStatus.COMPLETED;
3 }
4
也可以返回派生状态：
1 public BigDecimal getTotalAmount() {
2 return items.stream()
3 .map(OrderItem::getAmount)
4 .reduce(BigDecimal.ZERO, BigDecimal::add);
5 }
6
因此：
对象的公共 API 应表达业务语义，而不是机械映射内部字段。
### 5.13.4 JavaBean 规范与领域模型
JavaBean 风格通常强调：
无参构造方法

私有字段
Getter
Setter
这种形式适合：
DTO
配置对象
表单对象
ORM 映射对象
序列化对象
但领域对象不一定适合全部字段可写。
可以区分：
1 DTO / DO
2 → 偏数据承载
3 → Getter/Setter 较多
4
5 领域对象
6 → 承载业务规则
7 → 通过行为修改状态
8

## 5.15 private

private 成员只能在当前类内部直接访问。
1 public class User {
2
3 private String name;
4
5 private void validate() {
6 }
7 }
8
外部不能直接调用：
1 user.validate();
2
也不能直接访问：
1 user.name;
2
private 适合：
内部状态
内部辅助方法
实现细节
不希望外部依赖的成员
### 5.15.1 private 是类级别访问控制
同一个类中的不同对象可以访问彼此的 private 字段：
1 public class User {
2
3 private int age;
4
5 public boolean olderThan(User other) {
6 return this.age > other.age;
7 }
8 }
9
虽然访问的是 other.age ，但代码位于 User 类内部，因此合法。
因此：
private 限制的是类外访问，不是对象之间互相不可访问。

## 5.16 默认访问权限

没有显式修饰符时，成员只能在同一个包内访问。
1 class PackageService {
2

3 void execute() {
4 }
5 }
6
适合：
包内部实现
不希望暴露给包外的协作类
模块内部辅助组件
测试可见但不对外公开的逻辑
包级封装常被忽略，但它是减少公共 API 的有效方式。

## 5.17 protected

protected 允许：
当前类访问
同包类访问
不同包的子类访问
但跨包子类访问存在重要边界。
假设：
1 package parent;
2
3 public class Parent {
4
5 protected int value;
6 }
7
子类位于另一个包：
1 package child;
2
3 public class Child extends Parent {
4
5 public void test(Child child) {
6 this.value = 1;
7 child.value = 2;
8 }
9 }
10
通常可以通过当前子类实例或子类类型引用访问。
但不应简单认为：
子类可以通过任意 Parent 对象访问 protected 成员。
例如跨包场景中：
1 public void test(Parent parent) {
2 parent.value = 1;
3 }
4
通常不允许。
核心理解：

protected 在跨包子类中提供的是继承关系上的访问能力，而不是把成员变成对子类所在包完全公开。

## 5.18 public

public 表示成员对所有能够访问当前类的代码可见。
1 public class Order {
2
3 public void cancel() {
4 }
5 }
6
但“可以 public”不代表“应该 public”。
公共 API 一旦被外部依赖：
修改成本更高
兼容性要求更高
测试范围更大
实现细节更难调整
设计原则：
默认使用最小可见性，只有确实需要对外暴露时才提升访问权限。

## 5.19 顶层类的访问控制

顶层类只能使用：
public
默认包级权限
不能使用：
private
protected
错误：
1 private class User {
2 }
3
一个 .java 文件中可以定义多个顶层类，但最多只有一个 public 顶层类，并且文件名通常必须与该 public 类名一致。
例如：
1 public class User {
2 }
3
4 class UserValidator {
5 }
6
文件名应为：
1 User.java
2

## 5.20 包与类组织

包用于组织类并避免命名冲突。
1 package com.example.order.domain;
2
完全限定类名：
1 com.example.order.domain.Order
2
### 5.20.1 包名与目录
通常目录结构与包名对应：
1 src/main/java/
2 └── com/
3 └── example/
4 └── order/
5 └── domain/
6 └── Order.java
7
### 5.20.2 import
1 import java.util.List;
2
import 用于在源码中简化类型名称。
没有 import 时可以使用完全限定名：
1 java.util.List<String> list;
2
import 不等于加载类，也不会直接创建对象。
它主要影响编译期名称解析。
### 5.20.3 java.lang 自动导入
java.lang 包中的类型会自动导入，例如：
String
Object
Integer
System
Math
Thread
因此不需要：

1 import java.lang.String;
2
### 5.20.4 同名类冲突
如果两个包中存在同名类：
1 java.util.Date
2 java.sql.Date
3
不能同时通过简单类名区分。
可以：
1 import java.util.Date;
2
3 java.sql.Date sqlDate;
4 Date utilDate;
5
或者都使用完全限定名。
Java 不支持 import 别名语法。
