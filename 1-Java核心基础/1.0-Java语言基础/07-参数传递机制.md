# 参数传递机制

## 4.1 本章定位

参数传递是 Java 基础中最容易长期混淆的问题之一。

很多开发者会说：

- 基本类型是值传递
- 对象是引用传递
- 方法可以修改对象，所以 Java 存在引用传递
- String 比较特殊，传进去以后改不了
- 数组传参可以修改原数组，因此是引用传递
这些说法都不够准确。

本章主要解决以下问题：

- Java 到底是值传递还是引用传递？
- 基本类型参数传递的是什么？
- 引用类型参数传递的是什么？
- 为什么方法内部可以修改对象，却不能替换调用方的对象？
- 引用变量、引用值和对象有什么区别？
- String、包装类型、数组作为参数时分别有什么表现？
- final 参数能限制什么？
- 返回对象引用时是否会造成封装泄漏？
- 浅拷贝、深拷贝与参数传递有什么关系？

本章核心结论：

- Java 只有值传递。
- 基本类型传递的是基本值的副本，引用类型传递的是引用值的副本。

## 4.2 什么是参数传递

方法调用通常包含两个角色：

```java
public static void main(String[] args) {
    int value = 10;
    print(value);
}
static void print(int number) {
    System.out.println(number);
}
```

其中：

```
value → 实参
number → 形参
```

**4.2.1 实参**

实参是调用方法时实际提供的值：

```
print(value);
```

这里的 value 是实参表达式。
实参也可以是：

```
print(10);
print(a + b);
print(queryValue());
```

因此实参不一定是变量，也可以是字面量或表达式。

**4.2.2 形参**

形参是方法定义中用于接收调用值的局部变量：

```
static void print(int number)
```

这里的 number 是形参。
方法被调用后，形参会获得实参计算结果的副本。
核心理解：
形参是方法内部新创建的局部变量，不是调用方变量本身。

## 4.3 值传递与引用传递

**4.3.1 值传递**

值传递的含义是：

- 调用方法时，把实参的值复制一份，赋给形参。
- 方法中修改形参，只会修改这份副本，不会直接修改调用方变量。
例如：

```java
public class ValuePassDemo {
    public static void main(String[] args) {
        int value = 10;
        change(value);
        System.out.println(value); // 10
    }
static void change(int number) {
    number = 20;
}
}
```

调用过程：

```
调用前：
value = 10
调用 change(value)：
复制 value 中的数值 10
↓
number = 10
方法内部：
number = 20
调用结束：
number 消失
value 仍然是 10
```

**4.3.2 真正的引用传递**

引用传递通常意味着：

- 方法接收到的不是变量值的副本，而是调用方变量本身的别名。
- 如果语言支持真正的引用传递，那么方法中重新给参数赋值，应当能够直接改变调用方变量。
概念示例：

```
调用方变量 user
↑
方法参数 parameter
```

二者代表同一个变量存储位置。
但 Java 中不是这种情况。
Java 方法收到的是：

```
调用方引用变量中保存的引用值的副本
```

而不是调用方引用变量本身。

## 4.4 基本类型参数传递

**4.4.1 基本类型传递数值副本**

```java
public class PrimitivePassDemo {
    public static void main(String[] args) {
        int original = 10;
        modify(original);
        System.out.println(original); // 10
    }
static void modify(int value) {
    value = 100;
}
}
```

内存关系可以抽象为：

```
main 方法：
original = 10
调用 modify(original) 后：
original = 10
value = 10
方法内部执行：
value = 100
最终：
original = 10
value = 100
```

两个变量相互独立。

**4.4.2 交换两个基本类型变量**

经典错误示例：

```java
public class SwapDemo {
    public static void main(String[] args) {
        int a = 1;
        int b = 2;
        swap(a, b);
        System.out.println(a); // 1
        System.out.println(b); // 2
    }
static void swap(int x, int y) {
    int temp = x;
    x = y;
    y = temp;
}
}
```

swap() 内部确实交换了：

```
x 和 y
```

但没有交换：

```
a 和 b
```

调用时发生的是：

```
a 的值 1 复制给 x
b 的值 2 复制给 y
```

因此：

```
调用方：
a = 1
b = 2
方法内部：
x = 2
y = 1
```

调用结束后， x 和 y 被销毁， a 和 b 不受影响。

## 4.5 引用类型参数传递

**4.5.1 引用变量保存的是什么**

```
User user = new User();
```

这里至少包含三个概念：

```
user 引用值 User 对象
引用变量 → 某个引用值 → 对象实例
```

需要准确区分：

- user 是变量名。
- user 变量保存一个引用值。
- 引用值用于定位对象。
- new User() 创建对象。
- 引用变量不是对象本身。
- 引用值也不是对象本身。

**4.5.2 引用类型传递引用值副本**

```java
public class ReferencePassDemo {
    public static void main(String[] args) {
        User user = new User();
        user.name = "A";
        modify(user);
        System.out.println(user.name); // B
    }
static void modify(User parameter) {
    parameter.name = "B";
}
static class User {
    String name;
}
}
```

调用前：

```
user ───────→ User 对象{name="A"}
```

调用 modify(user) 时，复制的是 user 中的引用值：

```text
user ───────┐
├────→ User 对象{name="A"}
parameter ───────┘
```

此时：

- user 和 parameter 是两个独立变量。
- 两个变量中保存了相同的引用值。
- 因而它们指向同一个对象。
执行：

```
parameter.name = "B";
```

修改的是共同指向的对象，所以调用方通过 user 也能看到变化。
这并不代表 Java 使用引用传递。
准确描述是：
Java 按值传递了对象引用的副本，两个引用变量随后指向同一个对象。

## 4.6 修改对象与修改引用的区别

这是本章最核心的区分。

**4.6.1 修改对象状态**

```
static void modify(User parameter) {
parameter.name = "B";
}
```

这里修改的是：

```
parameter 所指向对象的 name 字段
```

调用方变量和形参指向同一个对象，因此调用方可以看到修改。

**4.6.2 重新给形参赋值**

```java
public class ReassignDemo {
    public static void main(String[] args) {
        User user = new User();
        user.name = "A";
        replace(user);
        System.out.println(user.name); // A
    }
static void replace(User parameter) {
    parameter = new User();
    parameter.name = "B";
}
static class User {
    String name;
}
}
```

调用开始时：

```text
user ───────┐
├────→ 对象A{name="A"}
parameter ───────┘
```

执行：

```
parameter = new User();
```

之后：

```
user ───────────→ 对象A{name="A"}
parameter ───────────→ 对象B{name="B"}
```

这里只改变了形参 parameter 保存的引用值。
调用方变量 user 仍然指向原对象。
因此最终输出：

```
A
```

**4.6.3 核心判断标准**

判断参数传递问题时，可以问：
方法修改的是对象内容，还是重新给形参赋值？
如果是：

```
parameter.setName("B");
```

修改对象状态，调用方通常可见。
如果是：

```
parameter = new User();
```

只修改形参自己的引用值，调用方不可见。

## 4.7 为什么这不是引用传递

假设 Java 使用真正的引用传递，那么下面的方法应当能替换调用方的引用：

```
static void replace(User parameter) {
parameter = new User();
}
```

调用：

```
User user = oldUser;
replace(user);
```

如果 parameter 是 user 的别名，那么执行后：

```
user 应该指向新对象
```

但实际没有发生。
原因是：

```
user 和 parameter 是两个不同变量
```

它们最初保存相同的引用值，但后续可以各自重新赋值。
因此：
能通过参数修改对象，不能证明存在引用传递；只能证明两个引用值指向同一个可变对象。

## 4.8 引用类型交换为什么失败

```java
public class ReferenceSwapDemo {
    public static void main(String[] args) {
        User user1 = new User("A");
        User user2 = new User("B");
        swap(user1, user2);
        System.out.println(user1.name); // A
        System.out.println(user2.name); // B
    }
static void swap(User a, User b) {
    User temp = a;
    a = b;
    b = temp;
}
static class User {
    String name;
    User(String name) {
        this.name = name;
    }
}
}
```

调用前：

```
user1 ──→ 对象A
user2 ──→ 对象B
```

调用时复制引用值：

```
user1 ──→ 对象A ←── a
user2 ──→ 对象B ←── b
```

方法内部交换后：

```
a ──→ 对象B
b ──→ 对象A
```

但调用方仍然是：

```
user1 ──→ 对象A
user2 ──→ 对象B
```

因此交换无效。

## 4.9 数组作为参数

**4.9.1 数组是对象**

```
int[] values = {1, 2, 3};
```

这里：

- values 是引用变量。
- int[] 是数组对象。
- 数组元素是对象内部的数据。

**4.9.2 可以修改数组元素**

```java
public class ArrayPassDemo {
    public static void main(String[] args) {
        int[] values = {1, 2, 3};
        modify(values);
        System.out.println(values[0]); // 100
    }
static void modify(int[] parameter) {
    parameter[0] = 100;
}
}
```

调用后：

```text
values ───────┐
├────→ int[]{1, 2, 3}
parameter ───────┘
```

修改：

```
parameter[0] = 100;
```

实际修改的是共同指向的数组对象。

**4.9.3 重新给数组形参赋值无效**

```
static void replace(int[] parameter) {
parameter = new int[]{100, 200};
}
```

不会改变调用方变量。
示例：

```java
public class ArrayReplaceDemo {
    public static void main(String[] args) {
        int[] values = {1, 2, 3};
        replace(values);
        System.out.println(values[0]); // 1
    }
static void replace(int[] parameter) {
    parameter = new int[]{100, 200};
}
}
```

因为修改的是形参自身保存的引用值。

## 4.10 String 作为参数

String 经常让人误以为其参数传递规则特殊。
实际上：
String 与其他引用类型一样，传递的也是引用值的副本。
区别只在于：
String 是不可变对象。

**4.10.1 重新赋值不会修改调用方**

```java
public class StringPassDemo {
    public static void main(String[] args) {
        String text = "A";
        modify(text);
        System.out.println(text); // A
    }
static void modify(String parameter) {
    parameter = "B";
}
}
```

调用开始：

```text
text ───────┐
├────→ String 对象"A"
parameter ───────┘
```

执行：

```
parameter = "B";
```

之后：

```
text ───────────→ String 对象"A"
parameter ───────────→ String 对象"B"
```

所以调用方仍然是 "A" 。

**4.10.2 String 没有可修改内部状态的方法**

普通可变对象可以：

```
user.setName("B");
```

而 String 没有类似：

```
text.setCharacter(0, 'B');
```

这样的原地修改方法。
例如：

```
parameter.concat("B");
```

不会修改原字符串：

```
static void modify(String parameter) {
parameter.concat("B");
}
```

concat() 返回一个新字符串，但返回值未被接收。

**4.10.3 正确接收新字符串**

```
static String modify(String parameter) {
return parameter.concat("B");
}
```

调用：

```
text = modify(text);
```

本质上是调用方主动接收新的引用值。

## 4.11 包装类型作为参数

包装类型包括：

- Integer
- Long
- Double
- Boolean
- Character
- 其他基本类型包装类
包装类型也是引用类型，并且通常是不可变对象。
示例：

```java
public class IntegerPassDemo {
    public static void main(String[] args) {
        Integer value = 10;
        modify(value);
        System.out.println(value); // 10
    }
static void modify(Integer parameter) {
    parameter = 20;
}
}
```

parameter = 20 实际上可能发生：

```
自动装箱
Integer.valueOf(20)
```

然后让形参指向新的 Integer 对象。
调用方变量不受影响。

**4.11.1 自增包装类型参数**

```
static void modify(Integer parameter) {
parameter++;
}
```

近似过程：

```
int temp = parameter.intValue();
temp++;
parameter = Integer.valueOf(temp);
```

仍然只是让形参重新指向新的包装对象。
因此调用方不会改变。

## 4.12 可变对象与不可变对象

参数传递效果差异，本质上通常来自对象是否可变。

**4.12.1 可变对象**

```
class User {
String name;
}
```

可以修改：

```
user.name = "B";
```

如果两个引用指向同一个对象，一个引用修改状态，另一个引用可以观察到。

**4.12.2 不可变对象**

典型不可变对象：

- String
- Integer
- Long
- BigInteger
- 部分时间类，如 LocalDate
- 所谓不可变：
对象创建后，其可观察状态不能被改变。
例如：

```
LocalDate date = LocalDate.of(2026, 7, 22);
LocalDate nextDay = date.plusDays(1);
```

plusDays() 返回新对象，不修改原对象。

**4.12.3 参数传递规则没有变化**

无论对象可变还是不可变：

```
Java 都传递引用值的副本
```

区别在于：

- 可变对象允许通过引用修改内部状态。
- 不可变对象只能创建新对象并重新赋值。
因此不要说：
String 是值传递，普通对象是引用传递。
这是错误的。

## 4.13 StringBuilder 作为参数

StringBuilder 是可变对象，因此可以观察到和 String 不同的结果。

```java
public class StringBuilderPassDemo {
    public static void main(String[] args) {
        StringBuilder builder = new StringBuilder("A");
        modify(builder);
        System.out.println(builder); // AB
    }
static void modify(StringBuilder parameter) {
    parameter.append("B");
}
}
```

调用时两个引用指向同一个 StringBuilder ：

```text
builder ───────┐
├────→ StringBuilder("A")
parameter ───────┘
```

append() 修改了对象内部状态，所以调用方可见。

**4.13.1 重新赋值仍然无效**

```
static void replace(StringBuilder parameter) {
parameter = new StringBuilder("B");
}
```

不会替换调用方引用。
再次说明：
是否可见取决于修改的是对象还是形参，而不是对象参数是否采用引用传递。

## 4.14 集合作为参数

集合是引用类型，且大多数集合实现是可变对象。

```java
public class CollectionPassDemo {
    public static void main(String[] args) {
        List<String> list = new ArrayList<>();
        list.add("A");
        modify(list);
        System.out.println(list); // [A, B]
    }
static void modify(List<String> parameter) {
    parameter.add("B");
}
}
```

add() 修改的是集合对象。

**4.14.1 重新赋值集合形参**

```
static void replace(List<String> parameter) {
parameter = new ArrayList<>();
parameter.add("B");
}
```

调用方集合不会被替换。

**4.14.2 清空集合会影响调用方**

```
static void clear(List<String> parameter) {
parameter.clear();
}
```

因为 clear() 修改原集合对象。
这类方法具有明显副作用，API 设计时应清楚表达。
例如：

```
clearOrders(orders);
```

比：

```
process(orders);
```

更容易看出方法会修改入参。

## 4.15 final 参数

方法参数可以使用 final ：

```
static void execute(final User user) {
}
```

**4.15.1 final 基本类型参数**

```
static void execute(final int value) {
value = 20; // 编译错误
}
```

final 表示形参不能再次赋值。

**4.15.2 final 引用类型参数**

```
static void execute(final User user) {
user = new User(); // 编译错误
}
```

但可以修改对象：

```
static void execute(final User user) {
user.setName("B"); // 可以
}
```

因此：
final 引用参数限制引用变量不能重新赋值，不限制所指向对象的状态变化。

**4.15.3 final 参数不会改变传递机制**

final 只是限制方法内部的形参赋值行为。

它不会让：

- 值传递变成引用传递
- 引用值副本变成调用方变量
- 对象自动变成不可变对象

## 4.16 方法返回引用

参数传递讨论的是“值进入方法”，返回值讨论的是“值离开方法”。
Java 返回对象时，通常返回的是：

```
对象引用值
```

例如：

```
static User createUser() {
User user = new User();
return user;
}
```

返回的是引用值，不是把整个对象复制一份。

**4.16.1 返回内部可变对象的风险**

```java
public class Order {
    private final List<String> items = new ArrayList<>();
    public List<String> getItems() {
        return items;
    }
}
```

外部代码可以：

```
order.getItems().clear();
```

这会直接修改对象内部状态。

这种问题通常称为：

- 表示暴露
- 封装泄漏
- 可变对象泄漏

**4.16.2 返回防御性副本**

```
public List<String> getItems() {
return new ArrayList<>(items);
}
```

调用方修改返回集合，不会影响内部集合。

**4.16.3 返回不可修改视图**

```
public List<String> getItems() {
return Collections.unmodifiableList(items);
}
```

或者：

```
public List<String> getItems() {
return List.copyOf(items);
}
```

需要注意：
unmodifiableList 通常是原集合的只读视图。
原集合变化后，视图内容可能变化。
List.copyOf() 通常创建不可修改的快照式列表。
集合元素本身如果可变，仍可能被修改。

## 4.17 防御性复制

防御性复制用于防止外部通过共享引用修改对象内部状态。

**4.17.1 构造方法接收可变对象**

错误示例：

```java
public class Order {
    private final List<String> items;
    public Order(List<String> items) {
        this.items = items;
    }
}
```

调用：

```
List<String> source = new ArrayList<>();
source.add("A");
Order order = new Order(source);
source.clear();
```

由于 source 和 order.items 指向同一个集合，对外部列表的修改会影响 Order。

**4.17.2 构造时复制**

```
public Order(List<String> items) {
this.items = new ArrayList<>(items);
}
```

或者：

```
public Order(List<String> items) {
this.items = List.copyOf(items);
}
```

这可以避免外部后续修改原列表影响对象内部状态。

**4.17.3 输入复制与输出复制**

完整防御性设计通常包括：

```
输入时复制
+
输出时不暴露内部可变对象
```

示例：

```java
public class Order {
    private final List<String> items;
    public Order(List<String> items) {
        this.items = List.copyOf(items);
    }
public List<String> getItems() {
    return items;
}
}
```

因为 items 本身是不可修改列表，可以安全直接返回。

## 4.18 浅拷贝与深拷贝

参数传递不会自动复制对象。

```
User user2 = user1;
```

只是复制引用值，不是对象拷贝。

**4.18.1 引用复制**

```
User user2 = user1;
```

结果：

```text
user1 ──┐
├──→ 同一个 User 对象
user2 ──┘
```

没有创建新对象。

**4.18.2 浅拷贝**

浅拷贝会创建新的外层对象，但内部引用字段仍然共享。
例如：

```
class Order {
String orderNo;
List<String> items;
}
```

浅拷贝后：

```text
order1 ──→ Order对象1 ──┐
├──→ 同一个 items 列表
order2 ──→ Order对象2 ──┘
```

修改：

```
order2.items.add("B");
```

可能影响 order1.items 。

**4.18.3 深拷贝**

深拷贝不仅创建新外层对象，也复制内部可变对象：

```
order1 ──→ Order对象1 ──→ items列表1
order2 ──→ Order对象2 ──→ items列表2
```

两份对象图相互独立。

**4.18.4 不要依赖 clone 完成复杂深拷贝**

Object.clone() 默认更接近字段级浅拷贝。

复杂对象深拷贝更推荐：

- 拷贝构造方法
- 静态工厂方法
- 显式映射
- MapStruct
- 根据领域模型重新构造对象
不建议通过 Java 序列化实现常规深拷贝，因为性能、异常处理和语义都不理想。

## 4.19 通过容器实现“返回多个结果”

由于方法不能通过重新给参数赋值来替换调用方变量，有时会看到使用数组或包装对象传递结果。

**4.19.1 数组作为可变容器**

```
static void calculate(int a, int b, int[] result) {
result[0] = a + b;
result[1] = a - b;
}
```

调用：

```
int[] result = new int[2];
calculate(10, 5, result);
```

这是通过修改数组对象传回结果。
技术上可行，但可读性较差。

**4.19.2 使用结果对象**

更推荐：

```
record CalculateResult(int sum, int difference) {
}
```

方法：

```
static CalculateResult calculate(int a, int b) {
return new CalculateResult(a + b, a - b);
}
```

调用：

```
CalculateResult result = calculate(10, 5);
```

优点：

- 字段含义清晰
- 类型安全
- 无需修改入参
- 易于扩展
- 更符合函数式设计

## 4.20 使用 AtomicReference 能否实现引用传递

有时会看到：

```
AtomicReference<User> reference = new AtomicReference<>(oldUser);
```

方法：

```
static void replace(AtomicReference<User> reference) {
reference.set(new User());
}
```

调用后，外部可以通过：

```
reference.get();
```

看到新对象。
但这仍然不是 Java 语言层面的引用传递。
实际发生的是：

```
Java 按值传递 AtomicReference 的引用值副本
↓
方法内部修改共同指向的 AtomicReference 对象状态
```

本质与修改 List 、数组、普通对象相同。

## 4.21 方法副作用

当方法通过引用参数修改对象状态时，这种行为称为副作用之一。
例如：

```
static void normalize(User user) {
user.setName(user.getName().trim());
}
```

调用后，传入对象被修改。

**4.21.1 有副作用的方法**

```
void clear(List<String> list)
void sort(List<Order> orders)
void updateStatus(Order order)
```

这些方法会修改传入对象。

**4.21.2 无副作用的方式**

```
List<Order> sorted = sortCopy(orders);
Order updated = order.withStatus(COMPLETED);
```

方法返回新对象，不修改原对象。

无副作用设计通常具有以下优点：

- 更容易理解
- 更容易测试
- 更适合并发
- 更少隐式耦合
- 更容易回滚和组合
但可能增加对象创建和复制成本。

**4.21.3 API 应明确表达是否修改参数**

不清晰：

```
process(order);
```

更明确：

```
updateOrderStatus(order);
```

或者：

```
Order updatedOrder = updateStatus(order);
```

方法命名应尽量体现副作用。

## 4.22 null 参数

引用类型参数可能接收到 null ：

```
static void execute(User user) {
user.getName();
}
```

调用：

```
execute(null);
```

会抛出 NullPointerException 。

**4.22.1 参数校验**

```
static void execute(User user) {
Objects.requireNonNull(user, "user must not be null");
}
```

requireNonNull() 可以：

- 提前失败
- 明确错误参数
- 避免在更深处出现难定位的 NPE

**4.22.2 是否允许 null 应形成契约**

方法设计应明确：

- 参数能否为 null
- null 表示什么
- null 时返回什么
- 是否抛异常
- 不建议把 null 同时表示：
- 未提供
- 不存在
- 查询失败
- 无权限
- 空值
不同语义应使用不同模型表达。

## 4.23 方法参数设计

**4.23.1 参数数量不宜过多**

不推荐：

```
createOrder(
String orderNo,
String customerCode,
String warehouseCode,
String address,
String phone,
int priority,
boolean urgent,
boolean splitAllowed
);
```

参数过多容易出现：

- 顺序传错
- 含义不清
- 方法难扩展
- 测试组合过多

**4.23.2 参数对象**

推荐：

```java
public class CreateOrderCommand {
    private String orderNo;
    private String customerCode;
    private String warehouseCode;
    private String address;
    private String phone;
    private int priority;
    private boolean urgent;
    private boolean splitAllowed;
}
```

方法：

```
createOrder(command);
```

优点：

- 语义集中
- 容易扩展
- 参数顺序不敏感
- 便于校验
- 便于记录日志

**4.23.3 避免布尔参数**

例如：

```
execute(order, true, false);
```

调用方很难理解两个布尔值分别表示什么。
更好：

```
execute(order, ExecutionOptions.urgentWithoutSplit());
```

或者使用枚举：

```
execute(order, Priority.HIGH, SplitPolicy.FORBIDDEN);
```

## 4.24 参数传递与并发

如果多个线程获得同一个可变对象引用：

```text
线程A引用 ──┐
├──→ 同一个可变对象
线程B引用 ──┘
```

多个线程修改对象时可能产生线程安全问题。
例如：

```
List<String> list = new ArrayList<>();
```

将同一个 list 传给多个线程，多个线程同时执行：

```
list.add(value);
```

可能发生并发安全问题。
关键点：
引用值复制不会复制对象，也不会自动提供线程隔离。

要实现隔离，可以：

- 创建对象副本
- 使用不可变对象
- 使用线程安全集合
- 使用锁
- 避免共享
- 使用 ThreadLocal
具体放在并发模块展开。

## 4.25 参数传递与方法重载

方法重载在编译期根据实参静态类型选择。

```
static void print(Object value) {
System.out.println("Object");
}
static void print(String value) {
System.out.println("String");
}
```

调用：

```
Object value = "Java";
print(value);
```

输出：

```
Object
```

因为实参变量的编译时类型是 Object 。
尽管运行时对象是 String，重载选择仍然发生在编译期。

这与参数传递规则不同，但容易混淆：

- 重载决定调用哪个方法。
- 值传递决定实参值如何进入形参。

## 4.28 易错点

误区一：基本类型是值传递，对象是引用传递
错误。
Java 所有参数都是值传递。

区别是：

- 基本类型复制基本值。
- 引用类型复制引用值。
误区二：方法能修改对象，所以是引用传递
错误。
方法能修改对象，是因为：

```
调用方引用和形参引用指向同一个对象
```

不是因为形参是调用方变量的别名。
误区三：引用值就是对象地址
不够准确。
Java 规范不要求程序把引用简单理解成裸内存地址。
更安全的表述是：
引用值用于定位或访问对象，具体表示由 JVM 实现决定。
误区四：引用类型赋值会复制对象
错误。

```
User user2 = user1;
```

复制的是引用值，不是 User 对象。
误区五：重新给对象参数赋值会替换调用方对象
错误。

```
parameter = new User();
```

只会改变形参自己的引用值。
误区六：String 使用值传递，普通对象使用引用传递
错误。
二者都传递引用值副本。
String 的区别是不可变。
误区七：final 参数使对象不可变
错误。
final 只限制形参不能重新赋值，不限制对象内部状态。
误区八：数组作为参数是引用传递
错误。
数组是对象，传递的是数组引用值的副本。
误区九：返回对象相当于复制整个对象
错误。
通常返回的是对象引用值。
误区十：浅拷贝等于引用复制
错误。
引用复制不创建新对象。
浅拷贝创建新外层对象，但共享内部引用字段。
误区十一：不可修改集合等于元素完全不可变
错误。

```
List<User> users = List.copyOf(source);
```

列表结构不可修改，但其中的 User 对象如果可变，仍可被修改。
误区十二：AtomicReference 可以让 Java 变成引用传递
错误。
AtomicReference 只是一个可变容器对象。
方法修改的是该容器的内部状态。

## 4.29 工程实践建议

**4.29.1 优先返回结果，少修改入参**

不推荐：

```
void calculate(Order order, Result result)
```

推荐：

```
Result calculate(Order order)
```

返回值通常比输出参数更直观。

**4.29.2 修改入参时明确命名**

不推荐：

```
process(order);
```

推荐：

```
normalizeInPlace(order);
updateOrderStatus(order);
clearOrderItems(order);
```

方法名应体现副作用。

**4.29.3 领域对象尽量维护自身状态**

不推荐：

```
order.setStock(order.getStock() - quantity);
```

推荐：

```
order.deductStock(quantity);
```

对象内部负责：

- 参数校验
- 状态约束
- 业务规则
- 不变量维护

**4.29.4 公开 API 避免暴露内部集合**

推荐：

```
public List<Item> getItems() {
return List.copyOf(items);
}
```

或者直接使用不可变内部表示。

**4.29.5 参数对象尽量不可变**

例如使用 Record：

```
public record CreateOrderCommand(
String orderNo,
String warehouseCode,
boolean urgent
) {
}
```

不可变参数对象：

- 更容易校验
- 更容易传递
- 更适合并发
- 更少意外修改
- 更易测试

**4.29.6 不要用 null 作为多个语义的混合标记**

可考虑：

- 明确异常
- 空集合
- Optional 返回值
- 状态枚举
- 专门结果对象
应根据业务语义选择，而不是机械禁止 null。

## 4.30 本章知识链路

```
方法调用
↓
实参表达式计算
↓
实参值复制给形参
↓
基本类型：复制基本值
引用类型：复制引用值
↓
形参与调用方变量相互独立
↓
两个引用可能指向同一个对象
↓
修改对象状态：调用方可见
重新给形参赋值：调用方不可见
↓
可变对象、不可变对象
↓
防御性复制与封装设计
```

面试口述版：

- Java 只有值传递。基本类型作为参数时，传递的是基本值的副本；引用类型作为参数时，传递的是引用值的副本。调用方引用变量和方法形参是两个独立变量，只是
- 它们最初保存了相同的引用值，因此指向同一个对象。方法通过形参修改对象字段时，调用方能够看到变化；但如果方法重新给形参赋值，只会改变形参自己的引用
值，不会替换调用方的引用。String 和包装类型并不是特殊的传递方式，它们同样传递引用值副本，只是对象本身不可变。
