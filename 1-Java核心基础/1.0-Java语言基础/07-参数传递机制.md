## 7.2 核心结论：Java 只有值传递

Java 方法调用时，传给参数变量的是：

```text
实参表达式求得的值的副本
```

这个值可能是：

```text
基本值
或
引用值
```

因此：

```text
基本类型实参
→ 复制基本值

引用类型实参
→ 复制引用值

两者都属于
→ 值传递
```

### 7.2.1 什么是值传递

值传递的核心是：

> 被调用方法获得一个独立的参数变量，参数变量中保存的是调用方实参值的副本。

方法内对参数变量重新赋值，不会直接改写调用方变量。

### 7.2.2 什么不是引用传递

真正的引用传递通常意味着：

> 被调用方法获得调用方变量本身的别名，可以直接让调用方变量改为保存另一个值。

Java 普通参数不具备这种能力。

### 7.2.3 为什么容易被误解

引用类型参数可以通过复制后的引用值访问同一个对象：

```text
调用方变量
→ 保存引用值 A

参数变量
→ 保存引用值 A 的副本

两个引用值
→ 访问同一个对象
```

因此方法内修改对象状态时，调用方能够观察到变化。

这容易被误说成：

```text
对象按引用传递
```

正确说法应是：

```text
对象引用按值传递
```

或者更准确地说：

```text
引用值按值传递
```

## 7.3 参数变量与调用方变量

### 7.3.1 两个独立变量

```java
public static void change(int value) {
    value = 100;
}
```

调用：

```java
int number = 10;
change(number);
```

概念模型：

```text
调用前：

number
→ 10

调用时复制：

number 的值 10
↓
参数 value
→ 10

方法内重新赋值：

value
→ 100

number
→ 仍然是 10
```

### 7.3.2 参数名与实参变量名无关

```java
int count = 10;
change(count);
```

方法参数叫 `value`，调用方变量叫 `count`。

即使都叫同一个名字：

```java
int value = 10;
change(value);
```

它们也属于不同作用域中的两个变量。

### 7.3.3 参数变量生命周期

参数变量通常在方法调用期间存在。

方法返回后：

- 参数变量本身不再可访问；
- 参数变量曾指向的对象可能继续存在；
- 对象是否可回收取决于是否仍有可达引用。

具体内存和 GC 规则放在 JVM 模块。

## 7.4 基本类型参数

### 7.4.1 基本值副本

```java
public class PrimitiveParameterDemo {

    static void change(int value) {
        value = 100;
    }

    public static void main(String[] args) {
        int number = 10;

        change(number);

        System.out.println(number); // 10
    }
}
```

方法内修改参数：

```java
value = 100;
```

只修改参数变量。

### 7.4.2 多次赋值也不影响调用方

```java
static void calculate(int value) {
    value++;
    value *= 2;
    value = 0;
}
```

调用方变量仍保持原值。

### 7.4.3 返回值用于传回新结果

```java
static int increment(int value) {
    return value + 1;
}
```

调用：

```java
int number = 10;
number = increment(number);
```

要改变调用方变量保存的值，需要调用方显式接收返回值。

### 7.4.4 基本类型没有对象状态可修改

```java
int value = 10;
```

`int` 参数中只有基本值副本，不存在“共享同一个 int 对象”的问题。

## 7.5 引用类型参数

### 7.5.1 复制引用值

```java
public class ReferenceParameterDemo {

    static void rename(User user) {
        user.name = "Java";
    }

    public static void main(String[] args) {
        User user = new User();
        user.name = "Old";

        rename(user);

        System.out.println(user.name); // Java
    }

    static class User {
        String name;
    }
}
```

调用时：

```text
main 中的 user
→ 引用值 A

rename 参数 user
→ 引用值 A 的副本

引用值 A
→ 同一个 User 对象
```

### 7.5.2 修改对象状态

```java
user.name = "Java";
```

修改的是共享对象的字段。

调用方通过自己的引用再次访问同一对象，因此能看到变化。

### 7.5.3 不是修改调用方变量

方法没有直接修改：

```text
main 中 user 变量
```

它只通过参数引用访问并修改对象。

这一区分非常重要：

```text
修改参数变量
≠
修改参数指向的对象
```

## 7.6 修改对象与替换引用

### 7.6.1 修改对象

```java
static void rename(User user) {
    user.name = "Java";
}
```

效果：

```text
原对象状态变化
调用方可观察
```

### 7.6.2 替换参数引用

```java
static void replace(User user) {
    user = new User();
    user.name = "New";
}
```

调用方变量不会改变。

### 7.6.3 完整示例

```java
public class ReplaceReferenceDemo {

    static void rename(User user) {
        user.name = "Renamed";
    }

    static void replace(User user) {
        user = new User();
        user.name = "Replacement";
    }

    public static void main(String[] args) {
        User user = new User();
        user.name = "Original";

        rename(user);
        System.out.println(user.name); // Renamed

        replace(user);
        System.out.println(user.name); // Renamed
    }

    static class User {
        String name;
    }
}
```

### 7.6.4 图示

```text
调用 replace 前：

调用方 user ──────┐
                  ├──→ 原 User 对象
参数 user ────────┘

参数重新赋值后：

调用方 user ─────────→ 原 User 对象

参数 user ───────────→ 新 User 对象
```

方法返回后，新对象如果没有其他引用，可能变得不可达。

## 7.7 为什么 Java 不能直接交换两个变量

### 7.7.1 基本类型交换失败

```java
static void swap(int first, int second) {
    int temporary = first;
    first = second;
    second = temporary;
}
```

调用：

```java
int left = 10;
int right = 20;

swap(left, right);

System.out.println(left);  // 10
System.out.println(right); // 20
```

方法只交换了两个参数变量中的副本。

### 7.7.2 引用变量交换也失败

```java
static void swap(User first, User second) {
    User temporary = first;
    first = second;
    second = temporary;
}
```

调用方两个引用变量不会交换。

### 7.7.3 通过容器修改元素

```java
static void swap(int[] values) {
    int temporary = values[0];
    values[0] = values[1];
    values[1] = temporary;
}
```

这里能成功，是因为方法修改了共享数组对象的元素。

不是因为 Java 突然变成引用传递。

### 7.7.4 返回结果对象

更清晰的设计：

```java
record Pair(int first, int second) {
}

static Pair swap(int first, int second) {
    return new Pair(second, first);
}
```

调用方显式接收：

```java
Pair result = swap(left, right);
```

## 7.8 数组参数

### 7.8.1 数组是对象

```java
int[] values = {1, 2, 3};
```

`values` 是引用类型变量，保存数组引用值。

### 7.8.2 修改数组元素

```java
static void clear(int[] values) {
    Arrays.fill(values, 0);
}
```

调用方可观察到数组元素变化。

### 7.8.3 替换参数数组

```java
static void replace(int[] values) {
    values = new int[]{9, 9, 9};
}
```

不会让调用方变量自动改指向新数组。

### 7.8.4 完整示例

```java
import java.util.Arrays;

public class ArrayParameterDemo {

    static void modify(int[] values) {
        values[0] = 100;
    }

    static void replace(int[] values) {
        values = new int[]{7, 8, 9};
    }

    public static void main(String[] args) {
        int[] values = {1, 2, 3};

        modify(values);
        System.out.println(
                Arrays.toString(values)
        );

        replace(values);
        System.out.println(
                Arrays.toString(values)
        );
    }
}
```

输出：

```text
[100, 2, 3]
[100, 2, 3]
```

## 7.9 二维数组参数

### 7.9.1 Java 二维数组是数组的数组

```java
int[][] matrix = {
        {1, 2},
        {3, 4}
};
```

概念结构：

```text
matrix
→ 外层数组
  ├── 引用第一个 int[]
  └── 引用第二个 int[]
```

### 7.9.2 修改内部元素

```java
static void modify(int[][] matrix) {
    matrix[0][0] = 100;
}
```

调用方可以观察。

### 7.9.3 替换某一行

```java
static void replaceRow(int[][] matrix) {
    matrix[0] = new int[]{7, 8};
}
```

这是修改外层数组对象的元素，因此调用方可以观察到第一行被替换。

### 7.9.4 替换整个参数

```java
static void replaceMatrix(int[][] matrix) {
    matrix = new int[][]{
            {9, 9},
            {9, 9}
    };
}
```

不会改变调用方变量。

## 7.10 String 参数

### 7.10.1 String 是引用类型

```java
String text = "Java";
```

传参时复制的是引用值。

### 7.10.2 String 不可变

```java
static void append(String text) {
    text = text + " JVM";
}
```

`text + " JVM"` 产生新的字符串结果，随后参数变量指向新字符串。

调用方变量仍指向原字符串。

### 7.10.3 完整示例

```java
public class StringParameterDemo {

    static void append(String text) {
        text = text + " JVM";

        System.out.println(text);
    }

    public static void main(String[] args) {
        String text = "Java";

        append(text);

        System.out.println(text);
    }
}
```

输出：

```text
Java JVM
Java
```

### 7.10.4 不是因为 String 使用特殊传递方式

`String` 仍然是引用值按值传递。

表现不同的原因是：

```text
String 对象不可变
+
参数重新指向新对象
```

## 7.11 包装类型参数

### 7.11.1 包装类型是引用类型

```java
Integer value = 10;
```

`Integer` 是对象类型。

### 7.11.2 包装类型不可变

```java
static void increment(Integer value) {
    value++;
}
```

`value++` 大致涉及：

```text
拆箱 Integer
↓
int 加一
↓
装箱为新的 Integer 引用值
↓
参数变量重新赋值
```

调用方变量不变。

### 7.11.3 示例

```java
public class WrapperParameterDemo {

    static void increment(Integer value) {
        value++;
        System.out.println(value);
    }

    public static void main(String[] args) {
        Integer value = 10;

        increment(value);

        System.out.println(value);
    }
}
```

输出：

```text
11
10
```

### 7.11.4 缓存不改变传递语义

某些包装类型存在缓存。

但无论是否复用对象：

```text
参数传递
仍然是
引用值按值传递
```

包装类型缓存完整规则放在包装类型专题。

## 7.12 可变对象与不可变对象

### 7.12.1 可变对象

```java
List<String> values =
        new ArrayList<>();
```

方法可以通过共享引用修改对象：

```java
static void addValue(
        List<String> values
) {
    values.add("Java");
}
```

### 7.12.2 不可变对象

```java
BigDecimal amount =
        new BigDecimal("10.00");
```

方法不能修改原 `BigDecimal`：

```java
static void add(
        BigDecimal amount
) {
    amount = amount.add(
            new BigDecimal("1.00")
    );
}
```

调用方变量仍指向原对象。

### 7.12.3 不可变降低共享风险

不可变对象可以安全共享，因为调用方和被调用方都不能改变其内部状态。

这会降低：

- 参数传递副作用；
- 别名风险；
- 并发同步需求；
- 防御性复制成本；
- 缓存失效风险。

### 7.12.4 不可变不等于无状态

不可变对象仍然具有状态，只是创建后状态不能改变。

## 7.13 final 参数

### 7.13.1 限制参数变量重新赋值

```java
static void execute(
        final User user
) {
    // user = new User(); // 编译错误
}
```

### 7.13.2 不限制对象状态

```java
static void rename(
        final User user
) {
    user.name = "Java";
}
```

合法。

### 7.13.3 final 不改变传递方式

```text
final 参数
→ 仍然是值传递
→ 只是方法内不能给参数变量重新赋值
```

### 7.13.4 是否应给所有参数加 final

优点：

- 明确参数不重新赋值；
- 防止意外覆盖；
- 某些团队风格统一；
- 有助于较长方法阅读。

缺点：

- 增加视觉噪声；
- 不能保证对象不可变；
- 不能替代短方法和清晰命名。

不应机械规定所有参数都必须加 `final`。

完整规则见 `17-final与常量设计.md`。

## 7.14 可变参数仍然是数组参数

```java
static void print(String... values) {
}
```

调用方可以写：

```java
print("A", "B");
```

方法体内：

```java
values
```

按 `String[]` 使用。

### 7.14.1 修改参数数组

```java
static void clear(String... values) {
    Arrays.fill(values, null);
}
```

如果调用方显式传入数组：

```java
String[] values = {"A", "B"};
clear(values);
```

调用方数组会被修改。

### 7.14.2 分散实参调用

```java
clear("A", "B");
```

编译器通常创建一个临时数组。

调用方没有变量引用该数组，因此修改影响通常仅存在于方法内部。

### 7.14.3 API 设计提醒

可变参数方法如果会修改数组内容，应明确文档。

更好的习惯是：

```text
输入型可变参数
→ 只读使用
```

## 7.15 别名共享

### 7.15.1 什么是别名

多个变量引用同一个对象：

```java
List<String> first =
        new ArrayList<>();

List<String> second = first;
```

`first` 和 `second` 是同一对象的两个别名。

### 7.15.2 别名带来的影响

```java
second.add("Java");

System.out.println(first);
```

`first` 可以观察到变化。

### 7.15.3 参数会增加临时别名

```java
process(values);
```

调用期间：

```text
调用方变量 values
+
参数变量
```

都可能访问同一对象。

### 7.15.4 别名风险

- 修改来源难以追踪；
- 方法副作用不明显；
- 缓存结果失效；
- 不变量被破坏；
- 并发竞争；
- 测试相互污染；
- 封装泄漏。

### 7.15.5 降低别名风险

- 使用不可变对象；
- 缩小对象可见范围；
- 防御性复制；
- 不返回内部可变状态；
- 使用明确命令方法；
- 避免全局可变对象；
- 文档说明修改契约。

## 7.16 输入参数是否允许被修改

API 必须明确参数是：

```text
只读输入
可修改输入
消费型输入
输出容器
```

### 7.16.1 只读输入

```java
static BigDecimal sum(
        List<BigDecimal> values
) {
}
```

通常不应修改 `values`。

### 7.16.2 可修改输入

```java
static void sortInPlace(
        List<Integer> values
) {
    values.sort(null);
}
```

方法名明确表示原地修改。

### 7.16.3 消费型输入

某些 API 会接管对象或资源：

```java
static void submit(Task task) {
}
```

需要说明：

- 调用后调用方能否继续使用；
- 对象是否异步持有；
- 是否复制；
- 是否可能关闭资源。

### 7.16.4 输出参数

不推荐：

```java
static void calculate(
        Input input,
        ResultHolder output
) {
}
```

更推荐直接返回：

```java
static Result calculate(Input input) {
}
```

除非：

- 性能敏感；
- 与底层 API 对接；
- 需要多个可变输出；
- 使用明确缓冲区协议。

## 7.17 返回引用值

### 7.17.1 返回对象引用

```java
static User createUser() {
    return new User();
}
```

返回的是引用值。

### 7.17.2 返回内部对象

```java
public List<String> getItems() {
    return items;
}
```

调用方获得内部集合引用。

### 7.17.3 封装泄漏

```java
order.getItems().clear();
```

如果 Getter 直接返回内部集合，外部可以绕过对象规则修改状态。

### 7.17.4 返回值同样是值传递

方法返回时也可以理解为：

```text
把返回表达式的值
传回调用点
```

返回引用值不代表复制对象。

## 7.18 防御性复制

防御性复制用于隔离可变对象的共享。

### 7.18.1 构造器输入复制

危险：

```java
public Order(List<String> items) {
    this.items = items;
}
```

调用方后续：

```java
items.clear();
```

会影响 `Order`。

改进：

```java
public Order(List<String> items) {
    this.items =
            new ArrayList<>(items);
}
```

### 7.18.2 Getter 返回复制

```java
public List<String> getItems() {
    return new ArrayList<>(items);
}
```

调用方修改副本，不影响内部集合。

### 7.18.3 使用不可修改快照

```java
public List<String> getItems() {
    return List.copyOf(items);
}
```

返回一个不可修改快照。

### 7.18.4 防御性复制有成本

- 分配新对象；
- 复制元素引用；
- 大集合耗时；
- 可能改变元素身份预期；
- 深层对象仍可能共享。

应根据：

- 对象大小；
- 可变性；
- 调用频率；
- 安全边界；
- API 契约；

决定策略。

## 7.19 三种集合隔离方式

### 7.19.1 new ArrayList

```java
List<String> copy =
        new ArrayList<>(source);
```

特点：

- 新的列表结构；
- 可以修改；
- 与源列表结构隔离；
- 元素对象仍然共享。

### 7.19.2 Collections.unmodifiableList

```java
List<String> view =
        Collections.unmodifiableList(
                source
        );
```

特点：

- 返回不可修改视图；
- 不能通过视图增删；
- 源列表变化可被视图观察；
- 元素对象仍然共享。

### 7.19.3 List.copyOf

```java
List<String> snapshot =
        List.copyOf(source);
```

特点：

- 返回不可修改列表；
- 通常与源列表结构隔离；
- 不允许 `null` 元素；
- 如果来源本身符合条件，规范允许复用实例；
- 元素对象仍然共享。

### 7.19.4 对比表

| 方式 | 新结构 | 调用方可修改返回列表 | 源列表变化是否可见 | 元素是否深拷贝 |
|---|---|---|---|---|
| `new ArrayList<>(source)` | 是 | 是 | 否 | 否 |
| `unmodifiableList(source)` | 视图 | 否 | 是 | 否 |
| `List.copyOf(source)` | 不可修改快照语义 | 否 | 通常否 | 否 |

## 7.20 浅拷贝

浅拷贝通常表示：

```text
复制外层对象或容器
但内部引用仍指向原有对象
```

### 7.20.1 集合浅拷贝

```java
List<User> copy =
        new ArrayList<>(source);
```

结构隔离：

```text
source 列表
与
copy 列表
是不同对象
```

元素共享：

```text
source.get(0)
与
copy.get(0)
可能是同一个 User 对象
```

### 7.20.2 修改列表结构

```java
copy.clear();
```

不影响 `source` 的列表结构。

### 7.20.3 修改元素状态

```java
copy.get(0).setName("Java");
```

调用方通过 `source.get(0)` 也会看到变化。

## 7.21 深拷贝

深拷贝通常表示：

```text
复制外层对象
并复制需要隔离的内部可变对象
```

### 7.21.1 手工映射

```java
List<User> copy = source.stream()
        .map(User::copyOf)
        .toList();
```

### 7.21.2 拷贝构造器

```java
public User(User source) {
    this.name = source.name;
    this.address =
            new Address(source.address);
}
```

### 7.21.3 深拷贝没有统一自动定义

需要明确：

- 哪些字段必须复制；
- 哪些不可变对象可共享；
- 哪些资源不能复制；
- 对象图中的环如何处理；
- 身份是否需要保留；
- 缓存和代理如何处理。

### 7.21.4 深拷贝不是越深越好

复制：

- 数据库连接；
- 线程；
- 文件句柄；
- Spring Bean；
- 缓存客户端；

通常没有合理语义。

应围绕领域边界定义复制，而不是追求“所有对象递归复制”。

## 7.22 数组复制

### 7.22.1 clone

```java
int[] copy = source.clone();
```

对一维基本类型数组：

- 新数组；
- 元素值复制；
- 结构独立。

### 7.22.2 Arrays.copyOf

```java
int[] copy =
        Arrays.copyOf(
                source,
                source.length
        );
```

### 7.22.3 System.arraycopy

```java
System.arraycopy(
        source,
        0,
        target,
        0,
        source.length
);
```

适合指定范围复制。

### 7.22.4 对象数组仍是浅拷贝

```java
User[] copy = source.clone();
```

新数组中的元素引用仍指向原 `User` 对象。

### 7.22.5 二维数组 clone 只复制外层

```java
int[][] copy = source.clone();
```

外层数组不同，但每一行数组仍共享。

需要逐行复制：

```java
int[][] copy =
        new int[source.length][];

for (int index = 0;
     index < source.length;
     index++) {

    copy[index] =
            source[index].clone();
}
```

## 7.23 StringBuilder 参数

`StringBuilder` 是可变对象。

### 7.23.1 修改内容

```java
static void append(
        StringBuilder builder
) {
    builder.append(" JVM");
}
```

调用方可观察变化。

### 7.23.2 替换参数引用

```java
static void replace(
        StringBuilder builder
) {
    builder = new StringBuilder(
            "New"
    );
}
```

调用方变量不变。

### 7.23.3 与 String 对比

```text
String
→ 不可变
→ “修改”产生新对象

StringBuilder
→ 可变
→ append 修改原对象
```

传递方式没有区别，差异来自对象可变性。

## 7.24 Map、Set 与集合参数

### 7.24.1 集合参数通常共享

```java
static void addDefault(
        Set<String> values
) {
    values.add("DEFAULT");
}
```

调用方集合被修改。

### 7.24.2 输入集合默认应只读

除非方法名或文档明确：

```java
normalizeInPlace(values)
sortInPlace(values)
removeInvalid(values)
```

否则通常不应修改调用方传入的集合。

### 7.24.3 返回新集合

```java
static List<String> normalized(
        List<String> values
) {
    return values.stream()
            .map(String::trim)
            .filter(value -> !value.isEmpty())
            .toList();
}
```

优点：

- 副作用少；
- 调用关系更清晰；
- 便于测试；
- 更适合并发和缓存。

### 7.24.4 大集合的性能权衡

返回新集合会增加：

- 内存；
- 分配；
- 遍历成本。

需要在：

```text
性能
与
隔离性
```

之间做明确选择。

## 7.25 Optional 参数边界

`Optional` 主要用于表达返回值可能不存在。

### 7.25.1 不推荐作为普通参数默认选择

```java
void send(
        Optional<String> message
) {
}
```

调用方可能传：

```java
null
```

仍然破坏语义。

### 7.25.2 更常见的替代

- 方法重载；
- 可空参数加明确注解；
- 参数对象；
- 默认值；
- 专门领域类型。

### 7.25.3 Optional 本身不可变

传递 `Optional` 仍是引用值按值传递。

但内部值对象是否可变，取决于其类型。

## 7.26 记录类与参数传递

record 实例通常用于不可变数据载体。

```java
record Point(int x, int y) {
}
```

### 7.26.1 组件是 final 字段语义

`Point` 创建后不能重新赋值组件。

### 7.26.2 组件对象仍可能可变

```java
record Group(
        List<String> members
) {
}
```

`members` 列表仍可能被修改。

### 7.26.3 紧凑构造器中防御性复制

```java
record Group(
        List<String> members
) {
    Group {
        members = List.copyOf(members);
    }
}
```

### 7.26.4 record 不自动深度不可变

record 提供：

- 数据载体语义；
- final 组件字段；
- 自动访问器；
- 值语义方法。

但仍需处理内部可变对象。

## 7.27 方法链与共享对象

```java
order.getCustomer()
        .getAddress()
        .setCity("深圳");
```

这条调用链可能修改 `order` 内部深层对象。

### 7.27.1 Getter 不一定是纯查询

如果 Getter 返回可变内部对象，调用方可以继续修改。

### 7.27.2 链式调用隐藏副作用

代码看起来像读取：

```java
order.getCustomer().getAddress()
```

但最终：

```java
setCity(...)
```

修改了对象图。

### 7.27.3 封装改进

```java
order.changeShippingCity("深圳");
```

由聚合根维护规则。

## 7.28 异步调用中的参数对象

### 7.28.1 调用结束后对象仍可能被持有

```java
executor.submit(
        () -> process(order)
);
```

异步任务捕获了 `order` 的引用值。

方法返回后，任务仍可能访问对象。

### 7.28.2 调用方继续修改

```java
executor.submit(
        () -> process(order)
);

order.cancel();
```

异步任务看到的状态取决于：

- 执行时机；
- 同步机制；
- 对象线程安全；
- 内存可见性。

### 7.28.3 使用不可变快照

```java
OrderSnapshot snapshot =
        OrderSnapshot.from(order);

executor.submit(
        () -> process(snapshot)
);
```

可降低共享可变状态风险。

完整并发规则见并发模块。

## 7.29 跨线程传递不是新的参数传递方式

无论同步还是异步：

```text
Java 引用值
仍然按值复制
```

差异在于：

- 对象生命周期更长；
- 多线程共享；
- 可见性；
- 竞态条件；
- 发布安全；
- 原子性。

不要把：

```text
跨线程共享对象
```

误解为：

```text
按引用传递
```

这是两个不同问题。

## 7.30 参数传递与内存模型边界

### 7.30.1 常见入门图

```text
参数局部变量
→ 栈帧

对象
→ 堆
```

用于入门可以理解。

### 7.30.2 不能作为语言绝对保证

JVM 可能：

- 将值放入寄存器；
- 标量替换对象；
- 消除分配；
- 内联方法；
- 优化栈帧；
- 移动对象；
- 使用压缩引用。

### 7.30.3 语言层只需抓住

```text
方法调用
→ 实参表达式求值
→ 值复制给参数变量

参数变量
→ 独立变量

引用值副本
→ 可以访问同一对象
```

物理存储位置不改变这套可观察语义。

## 7.31 方法返回与对象生命周期

### 7.31.1 返回局部创建对象是安全的

```java
static User create() {
    User user = new User();
    return user;
}
```

方法返回后，对象不会因为局部变量消失就立即被回收。

调用方接收到引用值后，对象仍然可达。

### 7.31.2 返回局部数组

```java
static int[] create() {
    int[] values = {1, 2, 3};
    return values;
}
```

同样合法。

### 7.31.3 不存在 C/C++ 式栈对象悬空引用问题

Java 对象由 JVM 管理。

不能简单套用：

```text
返回局部变量地址
→ 悬空指针
```

这种 C/C++ 模型。

### 7.31.4 仍需防止封装泄漏

返回局部新对象通常安全。

返回内部共享可变对象则可能破坏封装。

## 7.32 输入校验与参数传递

### 7.32.1 参数已赋值不代表参数合法

```java
static void process(User user) {
}
```

即使参数变量已确定赋值，也可能保存：

```text
null
非法状态对象
过期对象
错误实现
```

### 7.32.2 前置条件

```java
static void process(User user) {
    Objects.requireNonNull(
            user,
            "user must not be null"
    );
}
```

### 7.32.3 可变对象校验后的变化

```java
validate(command);
execute(command);
```

如果 `command` 被其他代码或线程修改，校验结果可能失效。

### 7.32.4 建立不可变命令对象

```java
record CreateOrderCommand(
        String userId,
        List<String> itemIds
) {
    CreateOrderCommand {
        itemIds = List.copyOf(itemIds);
    }
}
```

能让：

```text
校验
与
执行
```

之间的状态更稳定。

## 7.33 参数对象模式

### 7.33.1 参数过多

```java
createOrder(
        userId,
        warehouseCode,
        address,
        couponCode,
        urgent,
        split,
        remark
```

存在：

- 顺序易错；
- 布尔含义不明；
- 扩展困难；
- 调用冗长；
- 校验分散。

### 7.33.2 参数对象

```java
record CreateOrderCommand(

```

调用：

```java
createOrder(command);
```

### 7.33.3 参数对象仍可能需要复制

如果内部包含：

- 集合；
- 数组；
- 日期可变对象；
- 自定义可变对象；

仍需防御性复制。

### 7.33.4 参数对象不是 Map

不推荐：

```java
Map<String, Object> parameters
```

除非边界层确实处理动态数据。

## 7.34 输出参数与返回对象

### 7.34.1 输出参数

```java
static void parse(
        String text,
        ResultHolder holder
) {
    holder.value = Integer.parseInt(text);
}
```

### 7.34.2 返回对象

```java
static ParseResult parse(
        String text
) {
    return new ParseResult(
            Integer.parseInt(text)
    );
}
```

通常更清晰。

### 7.34.3 输出参数的适用场景

- 复用大缓冲区；
- 底层性能优化；
- 与本地 API 对接；
- 明确可变累加器；
- 迭代器或流式协议。

### 7.34.4 不应把所有返回值都改成可变 holder

否则会：

- 隐藏副作用；
- 增加共享状态；
- 降低可组合性；
- 增加线程安全风险。

## 7.35 方法契约中的所有权

参数对象的所有权需要明确。

### 7.35.1 借用

方法临时读取：

```text
调用方保留所有权
方法不长期保存
方法不修改
```

### 7.35.2 共享

方法可能长期保存引用：

```java
this.listener = listener;
```

调用方和对象共同持有。

### 7.35.3 转移

方法接管资源：

```java
submit(buffer)
```

调用后调用方不应继续修改。

Java 语言没有内建所有权类型系统，因此需要：

- API 命名；
- 文档；
- 不可变对象；
- 复制；
- 生命周期管理；

来表达。

## 7.36 常见错误示例

### 7.36.1 试图修改基本参数

```java
static void reset(int value) {
    value = 0;
}
```

调用方不变。

### 7.36.2 试图替换引用参数

```java
static void reset(User user) {
    user = new User();
}
```

调用方变量不变。

### 7.36.3 意外修改输入集合

```java
static List<String> normalize(
        List<String> values
) {
    values.removeIf(String::isBlank);
    return values;
}
```

调用方集合被修改。

### 7.36.4 返回内部数组

```java
public byte[] getSecret() {
    return secret;
}
```

外部可以修改内部数据。

### 7.36.5 构造器直接保存外部列表

```java
public Order(List<Item> items) {
    this.items = items;
}
```

外部后续修改会破坏对象状态。

### 7.36.6 误以为 unmodifiableList 是快照

```java
List<String> view =
        Collections.unmodifiableList(
                source
        );

source.clear();
```

`view` 也会观察到变化。

### 7.36.7 误以为浅拷贝复制元素对象

```java
List<User> copy =
        new ArrayList<>(source);
```

修改 `copy` 中的 `User`，原列表中的同一对象也变化。

## 7.39 易错点

### 误区一：Java 对基本类型按值传递，对对象按引用传递

**错误。**

Java 对所有参数都按值传递。引用类型传递的是引用值副本。

### 误区二：引用类型参数就是调用方变量本身

**错误。**

参数变量是独立变量，只是初始保存相同引用值。

### 误区三：方法内修改对象状态说明 Java 是引用传递

**错误。**

这是两个引用值访问同一对象造成的共享状态效果。

### 误区四：方法内给参数重新赋值会改变调用方变量

**错误。**

只改变当前参数变量。

### 误区五：Java 可以通过普通方法交换两个 int

**错误。**

方法只能交换参数副本。

### 误区六：Java 可以通过普通方法交换两个对象变量

**错误。**

只能交换参数中的引用值副本。

### 误区七：数组是特殊的引用传递

**错误。**

数组是对象，数组引用值仍然按值传递。

### 误区八：替换数组参数会让调用方数组变量改变

**错误。**

只有修改共享数组对象内容才对调用方可见。

### 误区九：String 使用特殊的按值传递规则

**错误。**

String 仍是引用值按值传递，差异来自不可变性。

### 误区十：Integer 自增会修改原 Integer 对象

**错误。**

包装对象不可变，自增通常产生新的装箱结果并重新赋给参数变量。

### 误区十一：包装类型缓存说明参数可能按引用传递

**错误。**

缓存只影响对象复用，不改变传递机制。

### 误区十二：final 参数表示对象不可变

**错误。**

只限制参数变量不能重新赋值。

### 误区十三：给所有参数加 final 就能消除副作用

**错误。**

对象状态仍然可能被修改。

### 误区十四：可变参数不是数组

**错误。**

方法体内可变参数按数组使用。

### 误区十五：调用 varargs 时方法修改数组不会影响调用方

**错误。**

调用方显式传入现有数组时，双方共享同一个数组对象。

### 误区十六：两个变量指向同一对象时互不影响

**错误。**

通过任一引用修改对象，其他别名都可能观察到。

### 误区十七：返回对象时会自动复制对象

**错误。**

返回的是引用值。

### 误区十八：Getter 返回内部集合只是读取，不会破坏封装

**错误。**

调用方可能通过返回引用修改内部状态。

### 误区十九：构造器保存调用方集合引用没有风险

**错误。**

调用方后续修改集合会影响对象内部状态。

### 误区二十：unmodifiableList 会创建独立快照

**错误。**

它通常是不可修改视图，源集合变化仍可见。

### 误区二十一：List.copyOf 会深拷贝所有元素

**错误。**

它只提供列表结构的不可修改快照语义，元素对象仍可能共享。

### 误区二十二：new ArrayList<>(source) 是深拷贝

**错误。**

只复制列表结构和元素引用。

### 误区二十三：深拷贝就是递归复制所有字段

**错误。**

复制边界必须结合领域语义定义。

### 误区二十四：对象数组 clone 会复制所有元素对象

**错误。**

只复制数组和元素引用。

### 误区二十五：二维数组 clone 会完整复制矩阵

**错误。**

只复制外层数组。

### 误区二十六：record 一定深度不可变

**错误。**

组件引用的对象仍可能可变。

### 误区二十七：Optional 作为参数可以彻底消除 null

**错误。**

调用方仍可能传入 `null`。

### 误区二十八：异步任务中的参数在方法返回后就无效

**错误。**

任务持有引用时，对象仍可达。

### 误区二十九：跨线程传递对象是一种引用传递

**错误。**

传递机制仍然是引用值按值复制，线程问题属于共享和内存可见性。

### 误区三十：局部创建对象返回后会形成悬空引用

**错误。**

只要调用方持有返回引用，对象仍然可达。

### 误区三十一：参数传递规则要求变量必须物理位于栈上

**错误。**

语言语义不依赖 JIT 优化后的物理存储位置。

### 误区三十二：参数已赋值就代表对象状态合法

**错误。**

参数可能为 `null` 或处于非法业务状态。

### 误区三十三：校验过的可变对象之后一定保持合法

**错误。**

共享对象可能在校验后再次被修改。

### 误区三十四：参数对象模式自动保证不可变

**错误。**

内部可变字段仍需复制和约束。

### 误区三十五：输出参数总比返回对象性能更好

**错误。**

需要实际测量，并权衡可读性、副作用和线程安全。

### 误区三十六：方法不修改参数变量，就一定没有副作用

**错误。**

仍可能修改参数指向的对象或外部系统。

### 误区三十七：只读接口类型就能保证对象不被修改

**错误。**

接口是否暴露修改方法、底层对象是否可变、是否存在其他别名都需要考虑。

### 误区三十八：防御性复制越多越好

**错误。**

复制有成本，应在明确边界上使用。

### 误区三十九：原地修改一定是坏设计

**错误。**

排序、缓冲区处理和性能敏感算法可以明确采用原地修改契约。

### 误区四十：理解 Java 参数传递必须先掌握所有 JVM 内存细节

**错误。**

语言层只需掌握值复制和共享对象语义。

## 7.40 工程实践建议

1. 对外说明时使用“Java 只有值传递”。
2. 引用类型应表述为“引用值按值传递”，不要说“对象按引用传递”。
3. 方法名明确是否会原地修改参数，例如 `sortInPlace()`。
4. 默认把输入集合和对象视为只读，除非契约明确允许修改。
5. 不通过重新赋值参数试图修改调用方变量。
6. 需要返回新值时使用返回值或结果对象。
7. 不使用可变 holder 模拟普通多返回值，除非性能或底层协议确有需要。
8. 构造器接收可变集合、数组或日期对象时执行防御性复制。
9. Getter 不直接暴露内部可变数组和集合。
10. 区分不可修改视图、可修改副本和不可修改快照。
11. `List.copyOf()` 不能替代元素级深拷贝。
12. 使用浅拷贝前明确元素共享是否可接受。
13. 深拷贝围绕领域边界设计，不递归复制资源对象。
14. 不把 `final` 参数当作不可变保证。
15. 可变参数方法默认只读使用参数数组。
16. 大量数据传递优先使用集合或流式接口，而不是超长 varargs。
17. 参数过多时引入明确的参数对象，不使用无类型 Map 代替。
18. 参数对象内部仍需处理可变成员。
19. 异步调用优先传递不可变快照。
20. 跨线程共享可变对象时使用正确同步机制。
21. 不依赖栈、堆的简化图解释 API 行为。
22. 返回新对象通常比修改输入参数更易组合和测试。
23. 性能敏感原地算法应在名称、文档和测试中明确副作用。
24. 对输入参数的空值、范围、所有权和生命周期写入契约。
25. API 明确是否长期保存调用方传入的引用。
26. 资源型参数明确由谁关闭。
27. 集合参数明确是否允许 `null` 元素。
28. 防御性复制和不可变设计优先放在边界对象中集中处理。
29. 单元测试同时验证结果和输入参数是否被意外修改。
30. 代码审查重点检查：别名、内部状态泄漏、异步共享和浅拷贝误用。

## 7.42 本章总结

### 7.42.1 核心传递模型

```text
方法调用
↓
计算实参表达式
↓
复制结果值
↓
初始化参数变量
```

```text
基本类型
→ 复制基本值

引用类型
→ 复制引用值
→ 两个引用值可能访问同一对象
```

### 7.42.2 修改与替换

```text
修改参数变量
→ 不影响调用方变量

修改共享对象
→ 调用方可观察

替换参数引用
→ 不改变调用方引用变量
```

### 7.42.3 可变性

```text
可变对象
→ 共享引用可能产生副作用

不可变对象
→ 可安全共享
→ 降低别名复杂度
```

### 7.42.4 防御性复制

```text
构造器输入
→ 防止外部后续修改

Getter 输出
→ 防止内部状态泄漏

浅拷贝
→ 只隔离外层结构

深拷贝
→ 按领域边界复制内部可变对象
```

### 7.42.5 面试口述版

Java 只有值传递。基本类型参数传递基本值的副本，引用类型参数传递引用值的副本。调用方变量和参数变量始终是两个独立变量，因此方法内给参数重新赋值不会改变调用方变量。

引用类型容易产生误解，是因为两个引用值可以访问同一个对象。方法通过参数修改对象字段、数组元素或集合内容时，调用方能观察到共享对象状态变化；但如果方法只是让参数指向新对象，调用方引用不会改变。因此准确表述应是“引用值按值传递”，而不是“对象按引用传递”。

共享可变对象会带来别名、副作用和封装泄漏。构造器接收可变集合时应考虑防御性复制，Getter 不应直接暴露内部可变状态。`new ArrayList<>(source)` 是可修改浅拷贝，`Collections.unmodifiableList(source)` 是不可修改视图，`List.copyOf(source)` 提供不可修改快照语义，但它们都不会自动深拷贝元素。不可变对象和明确的输入输出契约，是降低参数传递复杂度的主要手段。
