## 5.2 流程控制总体结构

Java 控制流可以分为：

```text
流程控制
├── 顺序结构
│   └── 语句按源码顺序执行
├── 分支结构
│   ├── if
│   ├── if-else
│   └── switch
├── 循环结构
│   ├── for
│   ├── 增强 for
│   ├── while
│   └── do-while
└── 跳转结构
    ├── break
    ├── continue
    ├── return
    └── 标签语句
```

实际程序通常是这些结构的组合。

工程上需要关注的不是“能不能写”，而是：

- 条件是否具有清晰业务语义；
- 分支是否完整；
- 循环是否一定能够结束；
- 跳转是否破坏可读性；
- 是否存在重复判断；
- 是否应该重构为对象行为或状态模型。

## 5.3 顺序结构

默认情况下，语句从上到下依次执行：

```java
int first = 10;
int second = 20;
int total = first + second;

System.out.println(total);
```

执行顺序：

```text
声明并初始化 first
↓
声明并初始化 second
↓
计算 total
↓
输出 total
```

### 5.3.1 表达式内部也有求值顺序

```java
int result = first() + second();
```

Java 通常从左到右求值操作数：

```text
first()
↓
second()
↓
执行加法
```

完整规则见 `04-运算符详解.md`。

### 5.3.2 顺序结构不代表每行一定执行

以下语句可能改变后续流程：

- `if`；
- `switch`；
- 循环；
- `break`；
- `continue`；
- `return`；
- `throw`；
- 异常传播；
- `System.exit()` 等进程终止行为。

因此，应从“控制流路径”而不是单纯源码行号理解程序。

## 5.4 if 条件语句

### 5.4.1 基本语法

```java
if (condition) {
    execute();
}
```

只有 `condition` 为 `true` 时才执行代码块。

### 5.4.2 条件必须是 boolean

合法：

```java
int count = 10;

if (count > 0) {
    System.out.println("positive");
}
```

非法：

```java
int count = 10;

// if (count) { } // 编译错误
```

Java 不会自动把非零整数转换为 `true`。

### 5.4.3 单语句可以省略大括号

```java
if (enabled)
    execute();
```

语法合法，但工程代码通常不推荐。

原因：

```java
if (enabled)
    execute();
    audit();
```

实际等价于：

```java
if (enabled) {
    execute();
}

audit();
```

更安全的写法：

```java
if (enabled) {
    execute();
    audit();
}
```

团队代码应统一保留大括号。

### 5.4.4 条件使用正向业务语义

不清晰：

```java
if (!disabled && !deleted && !expired) {
}
```

可以重构为：

```java
if (isAvailable()) {
}
```

条件表达式越复杂，越应该提取为有业务含义的方法。

## 5.5 if-else

### 5.5.1 二选一分支

```java
if (score >= 60) {
    result = "PASS";
} else {
    result = "FAIL";
}
```

两个分支中只会执行一个。

### 5.5.2 分支都应表达完整语义

不推荐：

```java
if (user != null) {
    process(user);
} else {
    // 什么也不做
}
```

如果 `else` 无意义，可以删除：

```java
if (user != null) {
    process(user);
}
```

### 5.5.3 简单赋值可使用条件运算符

```java
String result =
        score >= 60 ? "PASS" : "FAIL";
```

但当分支包含：

- 多条语句；
- 副作用；
- 异常处理；
- 日志；
- 多层判断；

应使用 `if-else`。

---

## 5.6 else-if 多分支

```java
if (score >= 90) {
    level = "A";
} else if (score >= 80) {
    level = "B";
} else if (score >= 60) {
    level = "C";
} else {
    level = "D";
}
```

### 5.6.1 分支按顺序判断

第一个满足的分支执行后，后续分支不再判断。

因此顺序很重要。

错误：

```java
if (score >= 60) {
    level = "C";
} else if (score >= 90) {
    level = "A";
}
```

`score >= 90` 永远先满足 `score >= 60`，因此第二个分支不可到达。

### 5.6.2 范围判断应从严格到宽松

推荐：

```text
>= 90
↓
>= 80
↓
>= 60
↓
其他
```

### 5.6.3 多分支不一定适合 if-else

当条件是同一个离散值的多个分支时：

```java
if (type == 1) {
} else if (type == 2) {
} else if (type == 3) {
}
```

可能更适合：

- `switch`；
- 枚举；
- 策略表；
- 多态。

---

## 5.7 悬空 else

### 5.7.1 问题示例

```java
if (first)
    if (second)
        execute();
    else
        fallback();
```

`else` 会匹配最近且尚未匹配 `else` 的 `if`。

实际等价于：

```java
if (first) {
    if (second) {
        execute();
    } else {
        fallback();
    }
}
```

### 5.7.2 大括号消除歧义

如果业务想表达：

```text
first 为 false
→ fallback
```

应明确写：

```java
if (first) {
    if (second) {
        execute();
    }
} else {
    fallback();
}
```

### 5.7.3 工程规则

始终使用大括号，可以避免：

- 悬空 `else`；
- 缩进误导；
- 后续维护误插语句；
- 代码审查理解偏差。

## 5.8 卫语句

卫语句用于尽早处理不满足前置条件的情况。

### 5.8.1 深层嵌套

不推荐：

```java
public void process(Order order) {
    if (order != null) {
        if (order.isValid()) {
            if (!order.isCancelled()) {
                execute(order);
            }
        }
    }
}
```

### 5.8.2 使用卫语句

```java
public void process(Order order) {
    if (order == null) {
        return;
    }

    if (!order.isValid()) {
        return;
    }

    if (order.isCancelled()) {
        return;
    }

    execute(order);
}
```

优点：

- 主路径更清晰；
- 减少缩进；
- 每个失败原因独立；
- 便于增加日志和异常；
- 更容易测试。

### 5.8.3 卫语句不等于静默返回

下面可能掩盖错误：

```java
if (order == null) {
    return;
}
```

如果 `null` 违反契约，更适合：

```java
Objects.requireNonNull(order, "order must not be null");
```

或抛出业务异常。

卫语句应明确：

```text
这是合法的提前结束
还是
异常输入处理
```

## 5.9 条件表达式设计

### 5.9.1 提取复杂条件

不推荐：

```java
if (
        user != null
        && user.isEnabled()
        && !user.isLocked()
        && user.getExpiredAt() != null
        && user.getExpiredAt().isAfter(now)
) {
}
```

推荐：

```java
if (userCanLogin(user, now)) {
}
```

### 5.9.2 不重复计算条件

不推荐：

```java
if (calculateAmount(order).compareTo(limit) > 0) {
    log(calculateAmount(order));
}
```

推荐：

```java
BigDecimal amount = calculateAmount(order);

if (amount.compareTo(limit) > 0) {
    log(amount);
}
```

### 5.9.3 避免布尔参数驱动复杂分支

```java
execute(order, true, false);
```

调用方很难理解。

更适合：

```java
execute(
        order,
        ExecutionMode.URGENT,
        SplitPolicy.FORBIDDEN
);
```

### 5.9.4 使用业务谓词

```java
if (order.canCancel()) {
    order.cancel();
}
```

通常优于：

```java
if (
        order.getStatus() == CREATED
        || order.getStatus() == PAID
) {
    order.setStatus(CANCELLED);
}
```

前者把规则放回领域对象。

## 5.10 传统 switch 语句

### 5.10.1 基本语法

```java
switch (status) {
    case 1:
        System.out.println("CREATED");
        break;
    case 2:
        System.out.println("PAID");
        break;
    default:
        System.out.println("UNKNOWN");
}
```

传统 `switch` 使用冒号标签和语句块。

### 5.10.2 支持的选择器类型

现代 Java 中常见可用于 `switch` 的类型包括：

- `byte`、`short`、`char`、`int`；
- 对应包装类型；
- `String`；
- 枚举；
- 引用类型模式匹配场景。

不能直接使用：

```text
long
float
double
boolean
```

作为传统常量型 `switch` 选择器。

### 5.10.3 case 标签必须满足规则

常量型 `case` 通常要求：

- 编译期常量；
- 类型与选择器兼容；
- 不能重复；
- 不能在运行时动态计算。

错误示例：

```java
int target = Integer.parseInt("1");

// case target: // 编译错误
```

## 5.11 case 穿透

### 5.11.1 穿透示例

```java
switch (level) {
    case 1:
        System.out.println("one");
    case 2:
        System.out.println("two");
    default:
        System.out.println("default");
}
```

如果 `level == 1`，可能连续输出：

```text
one
two
default
```

原因是传统冒号标签不会自动结束分支。

### 5.11.2 使用 break

```java
switch (level) {
    case 1:
        System.out.println("one");
        break;
    case 2:
        System.out.println("two");
        break;
    default:
        System.out.println("default");
}
```

### 5.11.3 有意穿透

有时多个 case 共享逻辑：

```java
switch (month) {
    case 1:
    case 3:
    case 5:
    case 7:
    case 8:
    case 10:
    case 12:
        days = 31;
        break;
    default:
        days = 30;
}
```

现代写法更清晰：

```java
switch (month) {
    case 1, 3, 5, 7, 8, 10, 12 ->
            days = 31;
    default ->
            days = 30;
}
```

### 5.11.4 穿透必须显式表达

如果必须使用传统穿透，建议写注释：

```java
case CREATED:
    audit();
    // fall through
case PAID:
    notifyUser();
    break;
```

否则后续维护者容易误加 `break` 或误认为是缺陷。

## 5.12 switch 表达式

### 5.12.1 switch 可以产生值

```java
String text = switch (status) {
    case CREATED -> "created";
    case PAID -> "paid";
    case CANCELLED -> "cancelled";
};
```

这里 `switch` 是表达式，可以赋值给变量。

### 5.12.2 箭头标签不会穿透

```java
case CREATED -> "created";
```

执行当前分支后不会继续进入下一个分支。

### 5.12.3 多个标签共享分支

```java
int days = switch (month) {
    case 1, 3, 5, 7, 8, 10, 12 -> 31;
    case 4, 6, 9, 11 -> 30;
    case 2 -> 28;
    default -> throw new IllegalArgumentException();
};
```

### 5.12.4 分支可以执行代码块

```java
String result = switch (status) {
    case CREATED -> {
        audit(status);
        yield "created";
    }
    case PAID -> {
        notifyUser();
        yield "paid";
    }
    default -> "unknown";
};
```

## 5.13 yield

`yield` 用于在 `switch` 表达式的代码块中产生结果。

```java
int result = switch (type) {
    case A -> {
        int value = calculateA();
        yield value * 2;
    }
    case B -> {
        yield calculateB();
    }
};
```

### 5.13.1 yield 与 return 不同

```text
yield
→ 返回当前 switch 表达式的值

return
→ 返回当前方法
```

### 5.13.2 单表达式分支不需要 yield

```java
case A -> calculateA();
```

只有代码块形式需要：

```java
case A -> {
    int value = calculateA();
    yield value;
}
```

### 5.13.3 yield 不是普通方法调用

`yield` 是受语法控制的关键字形式，不能任意写在普通代码块中。

## 5.14 switch 的穷尽性

### 5.14.1 表达式必须有结果

```java
String result = switch (status) {
    case CREATED -> "created";
    case PAID -> "paid";
};
```

如果 `status` 还有其他可能值，编译器会要求补全。

### 5.14.2 使用 default

```java
String result = switch (status) {
    case CREATED -> "created";
    case PAID -> "paid";
    default -> "unknown";
};
```

### 5.14.3 枚举穷尽

```java
enum Status {
    CREATED,
    PAID,
    CANCELLED
}
```

```java
String result = switch (status) {
    case CREATED -> "created";
    case PAID -> "paid";
    case CANCELLED -> "cancelled";
};
```

所有枚举常量都被覆盖时，可以不写 `default`。

### 5.14.4 sealed 类型穷尽

对于 sealed 类型层次，编译器可以根据许可子类型检查穷尽性。

```java
sealed interface Result
        permits Success, Failure {
}
```

```java
String text = switch (result) {
    case Success success ->
            success.value();
    case Failure failure ->
            failure.message();
};
```

完整 sealed 类型规则放在高级语言特性章节。

## 5.15 枚举 switch 与 default

### 5.15.1 不写 default 的价值

对枚举写穷尽分支：

```java
return switch (status) {
    case CREATED -> "created";
    case PAID -> "paid";
    case CANCELLED -> "cancelled";
};
```

以后新增枚举常量时，重新编译调用代码可能直接发现分支遗漏。

### 5.15.2 写 default 的价值

```java
return switch (status) {
    case CREATED -> "created";
    case PAID -> "paid";
    default -> "other";
};
```

适合：

- 外部不可信数据；
- 兼容未知值；
- 明确业务兜底；
- 旧客户端与新服务交互。

### 5.15.3 default 可能掩盖新增枚举值

如果新增：

```java
REFUNDED
```

已有 `default` 会继续编译，可能让业务静默进入错误兜底。

因此选择取决于目标：

```text
内部封闭领域枚举
→ 倾向穷尽列举

外部协议或前向兼容
→ 需要明确兜底
```

不能机械规定“枚举 switch 永远写 default”或“永远不写 default”。

## 5.16 switch 与 null

### 5.16.1 传统常量 switch 的 null

```java
String value = null;

switch (value) {
    case "A":
        break;
    default:
        break;
}
```

传统情况下通常会在选择器求值时抛出 `NullPointerException`。

### 5.16.2 显式 case null

现代模式匹配 `switch` 可以显式处理：

```java
String result = switch (value) {
    case null -> "empty";
    case "A" -> "alpha";
    default -> "other";
};
```

### 5.16.3 default 不一定处理 null

不要想当然地认为：

```text
default
=
所有未匹配情况
=
包括 null
```

`null` 是否匹配需要根据当前 `switch` 形式和语言规则判断。

为了可读性，涉及空值时应显式写：

```java
case null -> ...
```

或者在进入 `switch` 前先校验。

## 5.17 模式匹配 switch

### 5.17.1 基本类型模式

```java
String format(Object value) {
    return switch (value) {
        case null -> "null";
        case Integer number ->
                "int:" + number;
        case Long number ->
                "long:" + number;
        case String text ->
                "text:" + text;
        default ->
                "other";
    };
}
```

模式标签同时完成：

- 类型判断；
- 类型转换；
- 模式变量绑定。

### 5.17.2 传统 instanceof 链

```java
if (value instanceof Integer) {
    Integer number = (Integer) value;
} else if (value instanceof String) {
    String text = (String) value;
}
```

模式 `switch` 可以让多类型分支更集中。

### 5.17.3 它不替代所有多态

当分支基于对象自身行为时：

```java
processor.process();
```

通常优于：

```java
switch (processor) {
    case AlipayProcessor value -> ...
    case WechatProcessor value -> ...
}
```

模式 `switch` 更适合：

- 封闭类型层次；
- 外部数据解包；
- 语法树处理；
- 协议消息分派；
- 不适合修改原类型的边界适配。

## 5.18 模式守卫、支配与顺序

### 5.18.1 when 守卫

```java
String result = switch (value) {
    case Integer number
            when number > 0 ->
            "positive";
    case Integer number ->
            "non-positive";
    default ->
            "other";
};
```

守卫用于对匹配成功的模式增加额外布尔条件。

### 5.18.2 更具体模式应放在前面

错误逻辑：

```java
switch (value) {
    case Object object -> "object";
    case String text -> "string";
}
```

`Object` 可以匹配所有非空引用，后面的 `String` 分支被支配。

正确思路：

```text
更具体
↓
更一般
```

### 5.18.3 守卫不会自动解决所有支配问题

```java
case String text when text.isEmpty() -> ...
case String text -> ...
```

顺序合理。

反过来：

```java
case String text -> ...
case String text when text.isEmpty() -> ...
```

后者永远无法执行。

### 5.18.4 分支顺序是语义

模式 `switch` 不是无序规则集合。

代码审查需要检查：

- 是否存在过宽模式；
- 是否遮蔽更具体模式；
- 守卫条件是否重复；
- `default` 是否吞掉本应显式处理的类型。

## 5.19 for 循环

### 5.19.1 基本结构

```java
for (
        int index = 0;
        index < values.length;
        index++
) {
    System.out.println(values[index]);
}
```

三个部分：

```text
初始化
→ 只执行一次

条件
→ 每轮开始前判断

更新
→ 每轮结束后执行
```

### 5.19.2 执行顺序

```text
初始化
↓
判断条件
↓ true
执行循环体
↓
执行更新
↓
再次判断条件
```

条件为 `false` 时结束。

### 5.19.3 三部分都可以省略

```java
for (;;) {
}
```

表示无限循环。

### 5.19.4 多个初始化或更新表达式

```java
for (
        int left = 0, right = values.length - 1;
        left < right;
        left++, right--
) {
}
```

语法合法，但过于复杂时应提取变量或方法。

### 5.19.5 循环变量作用域

```java
for (int index = 0; index < 10; index++) {
    System.out.println(index);
}

// System.out.println(index); // 编译错误
```

`index` 的作用域限于 `for` 语句。

## 5.20 增强 for

### 5.20.1 遍历数组

```java
for (int value : values) {
    System.out.println(value);
}
```

### 5.20.2 遍历 Iterable

```java
for (String value : list) {
    System.out.println(value);
}
```

增强 `for` 适合：

- 从头到尾遍历；
- 不需要索引；
- 不需要显式控制迭代器。

### 5.20.3 重新赋值循环变量不修改元素

```java
int[] values = {1, 2, 3};

for (int value : values) {
    value = 0;
}
```

数组仍然是：

```text
1, 2, 3
```

因为循环变量保存的是当前元素值的副本。

引用类型：

```java
for (User user : users) {
    user = new User();
}
```

不会替换集合中的元素引用。

但修改对象状态：

```java
for (User user : users) {
    user.setEnabled(true);
}
```

会影响原对象。

### 5.20.4 需要索引时使用普通 for

```java
for (int index = 0; index < values.size(); index++) {
    System.out.println(index + ":" + values.get(index));
}
```

不要为了获取索引手工维护额外计数器，除非确有必要。

### 5.20.5 遍历时修改集合

```java
for (String value : values) {
    values.remove(value);
}
```

很多集合可能抛出：

```text
ConcurrentModificationException
```

更适合：

- 使用迭代器的 `remove()`；
- 使用 `removeIf()`；
- 收集待删除项；
- 使用适合并发修改的集合。

完整规则放在集合专题。

## 5.21 while 循环

### 5.21.1 基本语法

```java
while (condition) {
    execute();
}
```

先判断条件，再执行循环体。

### 5.21.2 可能一次都不执行

```java
int count = 0;

while (count > 0) {
    System.out.println(count);
}
```

循环体不会执行。

### 5.21.3 适合未知次数循环

例如：

```java
while (iterator.hasNext()) {
    process(iterator.next());
}
```

或：

```java
while (!task.isCompleted()) {
    poll();
}
```

### 5.21.4 条件必须最终可能改变

危险：

```java
while (!completed) {
    execute();
}
```

如果 `completed` 永远不变，会形成死循环。

并发场景下，还需考虑可见性和同步问题。

## 5.22 do-while 循环

### 5.22.1 基本语法

```java
do {
    execute();
} while (condition);
```

注意结尾分号。

### 5.22.2 至少执行一次

```java
int count = 0;

do {
    System.out.println(count);
} while (count > 0);
```

仍然会输出一次：

```text
0
```

### 5.22.3 适用场景

- 菜单至少展示一次；
- 输入至少读取一次；
- 重试逻辑先执行一次；
- 分页游标先请求第一页；
- 先处理再判断是否继续。

### 5.22.4 不要为了少写一行强行使用

很多业务代码使用普通 `while` 更直观。

如果“至少一次”不是业务核心，优先选择更清晰的结构。

## 5.23 循环选择原则

### 5.23.1 普通 for

适合：

- 次数明确；
- 需要索引；
- 有清晰初始化和更新步骤；
- 双指针或步长控制。

### 5.23.2 增强 for

适合：

- 顺序遍历；
- 不需要索引；
- 不需要修改集合结构；
- 代码应突出“对每个元素执行”。

### 5.23.3 while

适合：

- 次数未知；
- 由状态决定；
- 读取直到结束；
- 轮询或消费。

### 5.23.4 do-while

适合：

- 循环体至少执行一次；
- 执行后才能得到继续条件。

### 5.23.5 选择标准

```text
重点是索引和次数
→ for

重点是每个元素
→ 增强 for

重点是持续条件
→ while

重点是至少执行一次
→ do-while
```

不要为了个人习惯把所有循环都写成同一种形式。

## 5.24 break

### 5.24.1 结束当前循环

```java
for (String value : values) {
    if (value.isBlank()) {
        break;
    }

    process(value);
}
```

遇到空字符串后，整个循环结束。

### 5.24.2 结束传统 switch

```java
switch (status) {
    case CREATED:
        process();
        break;
    default:
        fallback();
}
```

### 5.24.3 break 只影响最近的可中断结构

在嵌套循环中：

```java
for (...) {
    for (...) {
        break;
    }
}
```

只结束内层循环。

### 5.24.4 break 不返回方法

```java
break;
```

只离开循环或 `switch`。

方法后续代码仍会执行。

## 5.25 continue

### 5.25.1 跳过当前轮剩余代码

```java
for (String value : values) {
    if (value == null) {
        continue;
    }

    process(value);
}
```

遇到 `null` 时，直接进入下一轮。

### 5.25.2 普通 for 中的 continue

```java
for (
        int index = 0;
        index < 10;
        index++
) {
    if (index % 2 == 0) {
        continue;
    }

    System.out.println(index);
}
```

`continue` 后会先执行更新表达式 `index++`，再判断下一轮条件。

### 5.25.3 while 中的 continue 风险

危险：

```java
int index = 0;

while (index < 10) {
    if (index % 2 == 0) {
        continue;
    }

    index++;
}
```

当 `index == 0` 时：

- 进入 `continue`；
- 跳过 `index++`；
- 永远停在 `0`。

正确：

```java
while (index < 10) {
    int current = index;
    index++;

    if (current % 2 == 0) {
        continue;
    }

    System.out.println(current);
}
```

或使用 `for`。

## 5.26 return

### 5.26.1 结束当前方法

```java
public void process(Order order) {
    if (order == null) {
        return;
    }

    execute(order);
}
```

### 5.26.2 返回值

```java
public int max(int first, int second) {
    if (first >= second) {
        return first;
    }

    return second;
}
```

### 5.26.3 return 与 break 的区别

```text
break
→ 结束循环或 switch
→ 方法继续执行

return
→ 结束整个方法
→ 返回调用方
```

### 5.26.4 多个 return 是否可接受

多个 `return` 并非天然坏代码。

卫语句：

```java
if (invalid) {
    return;
}
```

通常能提高可读性。

需要避免的是：

- 到处散落返回；
- 返回前必须执行的清理逻辑被遗漏；
- 状态修改一半后提前返回；
- 复杂方法存在大量互相交错出口。

资源释放应依赖 `try-with-resources` 或 `finally`，而不是手工记住每个返回点。

## 5.27 标签语句

### 5.27.1 标签基本语法

```java
outer:
for (int row = 0; row < matrix.length; row++) {
    for (int column = 0;
         column < matrix[row].length;
         column++) {

        if (matrix[row][column] == target) {
            break outer;
        }
    }
}
```

`break outer` 结束指定标签对应的外层循环。

### 5.27.2 带标签 continue

```java
outer:
for (int row = 0; row < matrix.length; row++) {
    for (int column = 0;
         column < matrix[row].length;
         column++) {

        if (matrix[row][column] < 0) {
            continue outer;
        }
    }

    processRow(matrix[row]);
}
```

遇到负数时进入下一行。

### 5.27.3 标签不是 goto

Java 标签只能配合：

- `break`；
- `continue`；

跳转到受限制的外层控制结构。

不能任意跳入另一个代码位置。

### 5.27.4 使用边界

标签适合：

- 少量双层循环；
- 搜索后退出；
- 跳过当前外层迭代；
- 替代额外布尔标志。

如果出现：

- 多层标签；
- 标签互相跳转；
- 很长的嵌套逻辑；

应提取方法或重构算法。

## 5.28 无限循环与终止条件

### 5.28.1 常见无限循环

```java
while (true) {
}
```

```java
for (;;) {
}
```

两者都常用于：

- 服务事件循环；
- 消费者循环；
- 重试循环；
- 服务器监听；
- 游戏主循环。

### 5.28.2 无限循环不一定是缺陷

如果内部具有明确退出机制：

```java
while (true) {
    Task task = queue.take();

    if (task == POISON_PILL) {
        break;
    }

    process(task);
}
```

逻辑可以成立。

### 5.28.3 隐式死循环

```java
int index = 0;

while (index < 10) {
    System.out.println(index);
}
```

缺少更新。

### 5.28.4 整数溢出导致异常循环

```java
for (
        int value = Integer.MAX_VALUE - 1;
        value <= Integer.MAX_VALUE;
        value++
) {
}
```

`value` 到达最大值后再自增会回绕为最小值，条件可能继续成立。

### 5.28.5 并发终止条件

```java
boolean running = true;

while (running) {
}
```

多线程下，另一个线程修改 `running = false` 不一定能被当前线程及时观察。

需要：

- `volatile`；
- 锁；
- 原子变量；
- 中断机制；
- 并发工具。

完整规则见并发模块。

## 5.29 循环边界与 off-by-one

### 5.29.1 常见数组遍历

正确：

```java
for (
        int index = 0;
        index < values.length;
        index++
) {
}
```

错误：

```java
for (
        int index = 0;
        index <= values.length;
        index++
) {
    System.out.println(values[index]);
}
```

最后一次会访问：

```text
values[values.length]
```

导致越界。

### 5.29.2 半开区间

Java 代码常采用：

```text
[start, end)
```

即：

```text
包含 start
不包含 end
```

例如：

```java
for (int index = start; index < end; index++) {
}
```

优点：

- 长度等于 `end - start`；
- 空区间可表示为 `start == end`；
- 与数组和集合 API 一致；
- 相邻区间容易拼接。

### 5.29.3 反向遍历

```java
for (
        int index = values.length - 1;
        index >= 0;
        index--
) {
}
```

需要特别注意空数组：

```text
values.length - 1
→ -1
```

条件 `index >= 0` 立即为假，循环安全结束。

### 5.29.4 无符号类型思维不适用于 int 索引

Java 数组索引使用 `int`。

不要把其他语言中的无符号循环习惯直接迁入 Java。

## 5.30 空循环与空语句

### 5.30.1 分号可以构成空语句

危险：

```java
while (condition);
{
    execute();
}
```

实际循环体是：

```java
;
```

后面的代码块与循环无关。

### 5.30.2 for 后多余分号

```java
for (int index = 0; index < 10; index++);
{
    System.out.println("once");
}
```

循环空转十次，之后代码块只执行一次。

### 5.30.3 有意空循环

某些极底层代码可能出现忙等待：

```java
while (!ready) {
    Thread.onSpinWait();
}
```

但必须考虑：

- CPU 占用；
- 内存可见性；
- 退避策略；
- 是否应该阻塞等待；
- 是否有超时。

普通业务代码中空循环通常是缺陷。

## 5.31 可达性基础

### 5.31.1 return 后的语句不可达

```java
public int value() {
    return 1;

    // System.out.println("never"); // 编译错误
}
```

### 5.31.2 无限循环后的语句

```java
while (true) {
}

// System.out.println("never"); // 通常不可达
```

如果循环包含可能执行的 `break`，后续代码可以到达：

```java
while (true) {
    if (condition) {
        break;
    }
}

System.out.println("reachable");
```

### 5.31.3 if(false) 的特殊规则

```java
if (false) {
    System.out.println("not executed");
}
```

Java 允许这种形式，常用于条件编译式调试或常量开关分析。

但：

```java
while (false) {
    // 编译错误：循环体不可达
}
```

语言对不同语句的可达性规则并不完全相同。

### 5.31.4 可达性不等于业务一定能执行

```java
if (userInput) {
    execute();
}
```

编译器认为 `execute()` 可达，但运行时可能永远没有输入使条件成立。

可达性是语言层静态规则，不是业务覆盖率证明。

## 5.32 分支复杂度与重构

### 5.32.1 深层嵌套

```java
if (user != null) {
    if (user.isEnabled()) {
        if (order != null) {
            if (order.isPayable()) {
                pay(order);
            }
        }
    }
}
```

使用卫语句降低嵌套。

### 5.32.2 大量类型分支

```java
if (processor instanceof AlipayProcessor) {
} else if (processor instanceof WechatProcessor) {
} else if (processor instanceof BankProcessor) {
}
```

可能重构为：

```java
processor.process();
```

### 5.32.3 大量状态分支

```java
switch (order.getStatus()) {
    case CREATED -> ...
    case PAID -> ...
    case SHIPPED -> ...
    case COMPLETED -> ...
}
```

如果不同状态行为持续增长，可以考虑：

- 状态模式；
- 状态机；
- 领域对象行为；
- 规则表；
- 工作流引擎。

### 5.32.4 大量参数组合

```java
if (urgent && split && retry) {
} else if (urgent && split) {
} else if (urgent && retry) {
}
```

可能需要：

- 参数对象；
- 策略组合；
- 配置对象；
- 决策表；
- 规则引擎。

### 5.32.5 分支本身不是坏代码

简单、稳定、明确的分支通常比过度设计更好。

重构条件：

- 分支持续增长；
- 同一条件散落多个位置；
- 每次新增类型都要修改旧代码；
- 分支之间共享大量状态；
- 单元测试组合爆炸；
- 业务规则难以解释。

## 5.35 易错点

### 误区一：Java 会把非零整数自动当作 true

**错误。**

条件表达式必须是 `boolean`。

### 误区二：单行 if 不写大括号永远安全

**错误。**

后续新增语句、悬空 `else` 和缩进误导都可能造成缺陷。

### 误区三：else 根据缩进匹配 if

**错误。**

语法匹配与排版缩进无关。

### 误区四：卫语句就是遇到问题静默 return

**错误。**

非法输入可能应该抛异常或记录错误。

### 误区五：else-if 分支顺序不影响结果

**错误。**

第一个满足的分支会阻止后续分支执行。

### 误区六：传统 switch 每个 case 会自动结束

**错误。**

冒号标签默认可能穿透。

### 误区七：传统 switch 中 default 必须写在最后

**错误。**

语法上可以放在其他位置，但为可读性通常放最后。

### 误区八：switch 只能用于整数

**错误。**

还可以用于字符串、枚举以及现代模式匹配引用类型。

### 误区九：case 可以使用任意运行时变量

**错误。**

常量型 case 通常要求编译期常量。

### 误区十：箭头标签也会发生 case 穿透

**错误。**

箭头标签不会穿透到下一个分支。

### 误区十一：switch 表达式可以缺少部分结果路径

**错误。**

每条可能路径都必须产生结果或抛出异常。

### 误区十二：yield 会返回整个方法

**错误。**

`yield` 只产生当前 `switch` 表达式的值。

### 误区十三：枚举 switch 永远应该写 default

**不准确。**

内部封闭枚举不写 `default` 可以保留新增常量的编译期检查能力。

### 误区十四：枚举 switch 永远不应该写 default

**不准确。**

外部协议和兼容场景可能需要兜底。

### 误区十五：default 一定可以处理 null

**错误。**

`null` 处理取决于 `switch` 形式，现代代码应显式写 `case null` 或提前校验。

### 误区十六：模式 switch 分支顺序无关

**错误。**

过宽模式可能支配后续更具体模式。

### 误区十七：模式匹配 switch 可以替代所有多态

**错误。**

对象自身行为通常仍应使用多态分派。

### 误区十八：for 的更新表达式在循环体之前执行

**错误。**

更新发生在本轮循环体结束之后。

### 误区十九：增强 for 可以直接获得索引

**错误。**

它只提供当前元素变量。

### 误区二十：增强 for 中给变量重新赋值会替换集合元素

**错误。**

只改变局部循环变量。

### 误区二十一：增强 for 遍历集合时可以随意删除元素

**错误。**

很多集合会触发并发修改异常。

### 误区二十二：while 循环至少执行一次

**错误。**

条件第一次为假时一次也不执行。

### 误区二十三：do-while 的结尾不需要分号

**错误。**

语法要求 `while (condition);`。

### 误区二十四：continue 会结束整个循环

**错误。**

它只跳过当前轮剩余代码。

### 误区二十五：break 会结束当前方法

**错误。**

它只结束最近的循环或 `switch`。

### 误区二十六：return 只结束当前循环

**错误。**

它结束整个方法。

### 误区二十七：while 中 continue 不会影响更新逻辑

**错误。**

如果更新写在 `continue` 之后，可能被跳过并形成死循环。

### 误区二十八：标签语句就是 Java 版 goto

**错误。**

Java 标签只能与受限制的 `break`、`continue` 配合。

### 误区二十九：无限循环一定是 bug

**错误。**

服务循环和事件循环可能有意无限运行，但必须具备明确退出和阻塞策略。

### 误区三十：for(int i = 0; i <= array.length; i++) 是完整遍历

**错误。**

最后一次访问会越界。

### 误区三十一：循环后的分号只是格式问题

**错误。**

它可能形成空循环体。

### 误区三十二：if(false) 内部代码一定编译失败

**错误。**

Java 对 `if(false)` 有特殊可达性规则。

### 误区三十三：编译器认为可达的代码就一定能在业务中执行

**错误。**

可达性只是静态语言规则。

### 误区三十四：分支越少，代码设计一定越好

**错误。**

为了消除简单分支而引入复杂抽象，可能是过度设计。

### 误区三十五：switch 表达式一定比 if 更高级

**错误。**

应根据离散值、范围判断和业务可读性选择。

## 5.36 工程实践建议

1. 所有 `if`、`else`、循环和传统 `switch` 分支统一使用大括号。
2. 条件表达式使用有业务意义的方法名，避免超长布尔表达式。
3. 使用卫语句减少嵌套，但不要静默吞掉违反契约的输入。
4. 范围分支从更严格条件到更宽松条件排列。
5. 同一离散值的多分支优先考虑 `switch`、枚举或映射表。
6. 传统 `switch` 只有确需穿透时才省略 `break`，并写明确注释。
7. 新代码优先使用箭头标签 `switch`，减少意外穿透。
8. `switch` 表达式的每个分支保持纯粹，复杂逻辑提取方法。
9. 枚举内部业务分支优先穷尽列举，外部协议场景设计明确兜底。
10. `null` 在进入 `switch` 前校验，或使用显式 `case null`。
11. 模式 `switch` 中按“具体到一般”排列标签。
12. 不用模式 `switch` 取代本应由对象承担的行为。
13. 次数和索引明确时使用普通 `for`。
14. 单纯遍历元素时使用增强 `for`。
15. 循环次数未知且由状态驱动时使用 `while`。
16. 只有“至少执行一次”是核心语义时使用 `do-while`。
17. 循环条件、更新变量和退出路径放在容易发现的位置。
18. 避免在循环体内修改当前遍历集合结构。
19. `continue` 前检查是否会跳过关键更新。
20. 双层循环需要提前退出时，可以谨慎使用一个清晰标签。
21. 多层标签和复杂跳转应重构为独立方法。
22. 循环边界优先使用半开区间 `[start, end)`。
23. 对空数组、单元素、首尾边界编写测试。
24. 不写无注释的空循环和忙等待。
25. 并发循环使用中断、原子变量或同步机制控制终止。
26. `return` 前不要遗留未完成的状态修改。
27. 资源释放使用 `try-with-resources`，不要依赖每个返回路径手工关闭。
28. 大量状态分支持续增长时考虑状态机。
29. 大量类型分支持续增长时考虑多态或 sealed 类型。
30. 只在复杂度已经形成实际维护成本时引入设计模式。
31. 代码审查重点检查：分支遗漏、case 穿透、空值、死循环、越界和跳转副作用。
32. 使用单元测试覆盖分支边界，而不是只覆盖主流程。

## 5.38 本章总结

### 5.38.1 分支主线

```text
连续条件和范围判断
→ if / else-if

简单二选一值
→ 条件运算符

同一离散值多分支
→ switch

封闭类型多分支
→ 模式 switch 或多态
```

### 5.38.2 switch 主线

```text
传统冒号标签
→ 可能穿透
→ 需要 break

箭头标签
→ 不穿透

switch 表达式
→ 必须穷尽
→ 每条路径产生值或抛异常

代码块分支
→ 使用 yield 产生表达式值
```

### 5.38.3 循环主线

```text
次数与索引明确
→ for

遍历每个元素
→ 增强 for

次数未知、先判断
→ while

至少执行一次
→ do-while
```

### 5.38.4 跳转主线

```text
break
→ 结束当前循环或 switch

continue
→ 跳过当前轮剩余部分

return
→ 结束整个方法

标签
→ 在嵌套结构中指定 break 或 continue 目标
```

### 5.38.5 面试口述版

Java 流程控制包括顺序、分支、循环和跳转。`if` 的条件必须是 `boolean`，多层嵌套可以通过卫语句提前处理异常路径。传统 `switch` 使用冒号标签时可能发生 case 穿透，需要 `break`；现代箭头标签不会穿透，`switch` 表达式必须覆盖所有可能路径，并在代码块分支中通过 `yield` 产生结果。

普通 `for` 适合索引和次数明确的循环，增强 `for` 适合顺序遍历元素，`while` 适合次数未知的状态循环，`do-while` 保证至少执行一次。`break` 结束循环或 `switch`，`continue` 跳过当前轮，`return` 结束整个方法。工程代码应重点防止分支遗漏、case 穿透、空值、死循环、越界和复杂跳转；当类型或状态分支持续膨胀时，再考虑多态、策略或状态机。
