## 11.2 继承是什么

继承表示一个类基于另一个类建立子类型关系。

```java
public class Dog extends Animal {
}
```

其中：

```text
Animal
→ 父类、超类、基类

Dog
→ 子类、派生类
```

### 11.2.1 继承表达 is-a 关系

```text
Dog is an Animal
```

意味着在父类契约成立的地方，子类对象原则上也应当可以使用。

### 11.2.2 继承不仅复用代码

继承同时带来：

- 子类型关系；
- 成员继承；
- 方法重写；
- 动态绑定；
- 构造链；
- 访问控制约束；
- API 兼容责任；
- 父子类耦合。

因此不能只因为：

```text
两个类有一些相同代码
```

就使用继承。

### 11.2.3 继承不是源码复制

子类不会把父类源码复制一份。

编译器和 JVM 仍然把父类与子类视为不同类型，并按继承关系解析成员和方法。

---

## 11.3 Java 类的单继承

一个普通类最多只能直接继承一个类：

```java
public class Dog extends Animal {
}
```

不能写：

```java
// public class Hybrid
//         extends First, Second {
// }
```

### 11.3.1 为什么限制类多继承

多继承会带来：

- 同名字段冲突；
- 方法实现冲突；
- 构造顺序复杂；
- 状态所有权不清；
- 菱形继承问题；
- 父类契约组合困难。

Java 通过：

```text
单继承类
+
多实现接口
+
对象组合
```

提供复用和多态能力。

### 11.3.2 可以实现多个接口

```java
public class FileTask
        extends BaseTask
        implements Runnable, AutoCloseable {
}
```

一个类可以：

- 直接继承一个类；
- 同时实现多个接口。

接口冲突规则见 `14-接口设计.md`。

## 11.4 隐式继承 Object

没有显式 `extends` 的普通类：

```java
public class User {
}
```

直接父类是：

```text
java.lang.Object
```

概念上相当于：

```java
public class User extends Object {
}
```

### 11.4.1 Object 提供基础方法

常见方法：

- `equals()`；
- `hashCode()`；
- `toString()`；
- `getClass()`；
- `clone()`；
- `wait()`；
- `notify()`；
- `notifyAll()`；
- `finalize()`，已废弃并逐步移除相关机制。

### 11.4.2 Object 自身没有父类

```text
Object
→ 类继承链根节点
```

### 11.4.3 接口不直接继承 Object

接口可以声明与 `Object` 公共方法签名相关的方法，但不能简单表述为：

```text
接口 extends Object
```

接口继承模型与类继承模型不同。

## 11.5 子类对象的父类状态

```java
public class Animal {

    private String name;
}

public class Dog extends Animal {

    private String breed;
}
```

创建：

```java
Dog dog = new Dog();
```

这个 `Dog` 对象同时具有：

- `Animal` 定义的实例状态；
- `Dog` 自己定义的实例状态。

### 11.5.1 private 字段仍属于对象状态

`Animal.name` 虽然不能被 `Dog` 源码直接访问，但它仍是 `Dog` 对象中父类定义的状态。

错误理解：

```text
private 字段不会被子类继承
→ 所以子类对象里没有该字段
```

更准确地说：

```text
private 字段不能被子类按名称直接访问
但父类状态仍存在于子类实例中
```

### 11.5.2 通过父类行为访问

```java
public class Animal {

    private String name;

    protected final String name() {
        return name;
    }
}
```

子类通过父类提供的受控方法使用状态，而不是直接暴露字段。

## 11.6 成员继承概览

类成员包括：

- 字段；
- 方法；
- 成员类型。

构造器不是类成员，因此不被继承。

### 11.6.1 public 与 protected 成员

在满足访问规则时可以被子类继承和使用。

### 11.6.2 包级成员

同包子类可以继承和访问。

跨包子类通常不能访问，也不能按普通重写关系处理不可访问的包级方法。

### 11.6.3 private 成员

不被子类按成员名继承访问。

子类可以声明同名成员，但它与父类私有成员是两个独立声明。

### 11.6.4 静态成员

静态成员属于类。

子类可以通过继承关系解析到可访问静态成员，但推荐使用声明类名称访问：

```java
Parent.CONSTANT
Parent.utility()
```

避免误解为实例多态。

## 11.7 构造器不被继承

```java
public class Parent {

    public Parent(String name) {
    }
}

public class Child extends Parent {

    public Child(String name) {
        super(name);
    }
}
```

`Child` 必须声明自己的构造器。

### 11.7.1 父类构造器参与构造链

虽然不被继承，但子类构造过程必须调用父类构造器。

### 11.7.2 不能重写构造器

构造器名称与类名绑定，不参与方法重写。

### 11.7.3 不能普通调用父类构造器

```java
// parent.Parent("A");
```

只能通过：

```java
super(...)
```

参与当前对象的构造链。

完整规则见 `09-封装与访问控制.md`。

## 11.8 方法重写

方法重写表示：

> 子类为继承得到的实例方法提供符合规则的新实现。

```java
public class Animal {

    public void speak() {
        System.out.println("Animal");
    }
}

public class Dog extends Animal {

    @Override
    public void speak() {
        System.out.println("Dog");
    }
}
```

### 11.8.1 重写发生在实例方法之间

普通方法重写要求父类和子类之间存在继承关系。

### 11.8.2 方法名称和参数必须匹配

```java
void speak()
```

子类必须声明覆盖等价签名的方法。

### 11.8.3 返回类型与异常必须兼容

不能只看方法名和参数，还需满足：

- 返回类型可替换；
- 访问权限不缩小；
- 受检异常不扩大；
- 父方法不是 `final`；
- 父方法对子类可继承。

---

## 11.9 @Override

```java
@Override
public void speak() {
}
```

`@Override` 让编译器检查：

- 是否确实重写父类方法；
- 是否实现接口方法；
- 方法名是否拼错；
- 参数是否错误；
- 泛型签名是否匹配。

### 11.9.1 典型错误

```java
public class Parent {

    public void execute(int value) {
    }
}

public class Child extends Parent {

    // 拼错且参数不同
    public void excute(long value) {
    }
}
```

没有 `@Override` 时，它只是一个新方法。

加上：

```java
@Override
```

编译器会立即报错。

### 11.9.2 工程原则

所有重写或接口实现方法都应加 `@Override`。

它没有运行时性能成本。

## 11.10 重写与重载

### 11.10.1 重写

```text
父子类之间
方法签名覆盖等价
子类替换实例实现
运行时动态绑定参与选择
```

### 11.10.2 重载

```text
同一个可见方法集合中
方法名相同
参数列表不同
编译期根据实参类型选择
```

### 11.10.3 同时发生

```java
public class Parent {

    public void print(Object value) {
    }
}

public class Child extends Parent {

    @Override
    public void print(Object value) {
    }

    public void print(String value) {
    }
}
```

其中：

```text
print(Object)
→ 重写

print(String)
→ 重载
```

调用结果需要同时考虑：

1. 编译期重载解析；
2. 运行时对选中实例签名进行动态绑定。

完整过程见 `12-多态与动态绑定.md`。

## 11.11 重写方法的访问权限

子类重写方法不能缩小访问权限。

父类：

```java
public void execute() {
}
```

子类不能：

```java
// protected void execute() {
// }
```

### 11.11.1 可扩大权限

父类：

```java
protected void execute() {
}
```

子类可以：

```java
@Override
public void execute() {
}
```

### 11.11.2 常见范围顺序

```text
private
<
包级访问
<
protected
<
public
```

但 `protected` 与包级访问的实际可见性关系包含包和继承语义，不能只作为简单数字比较理解。

### 11.11.3 为什么不能缩小

父类型调用方已经被承诺可以访问父方法。

若子类缩小权限：

```text
父类可用
但子类替换后不可用
```

会破坏替换关系。

## 11.12 返回类型规则

### 11.12.1 相同返回类型

```java
public Number value() {
    return 1;
}
```

子类可以继续返回 `Number`。

### 11.12.2 协变返回类型

```java
public class Parent {

    public Number value() {
        return 1;
    }
}

public class Child extends Parent {

    @Override
    public Integer value() {
        return 1;
    }
}
```

`Integer` 是 `Number` 的子类型，因此合法。

### 11.12.3 void 必须保持 void

父类：

```java
public void execute() {
}
```

子类不能改为返回某个值。

### 11.12.4 基本类型不支持协变

父类：

```java
public int value() {
    return 1;
}
```

子类不能改为：

```java
// public long value() {
//     return 1L;
// }
```

基本类型之间的宽化不等于返回类型协变。

---

## 11.13 协变返回的价值

父类返回抽象类型：

```java
public class Document {

    public Document copy() {
        return new Document();
    }
}
```

子类：

```java
public class PdfDocument
        extends Document {

    @Override
    public PdfDocument copy() {
        return new PdfDocument();
    }
}
```

调用：

```java
PdfDocument copy =
        pdfDocument.copy();
```

不需要额外强制类型转换。

### 11.13.1 工厂方法中的协变返回

父类创建方法可以由子类返回更具体对象。

### 11.13.2 泛型与桥接

协变返回和泛型擦除可能让编译器生成桥接方法，以保持 JVM 方法分派兼容。

## 11.14 重写方法的异常规则

父类：

```java
public void load()
        throws IOException {
}
```

子类可以：

```java
@Override
public void load()
        throws FileNotFoundException {
}
```

因为 `FileNotFoundException` 是 `IOException` 的子类。

### 11.14.1 可以不声明受检异常

```java
@Override
public void load() {
}
```

合法。

### 11.14.2 不能扩大受检异常

```java
// @Override
// public void load()
//         throws Exception {
// }
```

`Exception` 比 `IOException` 更宽，不能新增给父类型调用方。

### 11.14.3 可以声明其他兼容子异常

若父方法声明多个受检异常，子类异常必须能被其中某个父异常覆盖。

### 11.14.4 非受检异常

子类可以声明或抛出新的：

- `RuntimeException`；
- `Error`；

语言不会要求与父类受检异常列表保持同样限制。

但 API 行为仍应遵守父类契约。

---

## 11.15 为什么受检异常不能扩大

父类型调用方：

```java
Parent value = create();

try {
    value.load();
} catch (IOException exception) {
}
```

调用方只被要求处理 `IOException`。

若子类重写允许抛出：

```text
SQLException
```

父类型调用方将无法预先处理。

因此重写必须保证：

```text
子类不会要求调用方承担比父类契约更多的受检异常责任
```

## 11.16 private 方法不能被重写

父类：

```java
public class Parent {

    private void execute() {
    }
}
```

子类声明：

```java
public class Child extends Parent {

    public void execute() {
    }
}
```

这是一个新的独立方法，不是重写。

### 11.16.1 @Override 会报错

```java
// @Override
public void execute() {
}
```

父类私有方法对子类不可继承。

### 11.16.2 父类内部调用

```java
public class Parent {

    public void run() {
        execute();
    }

    private void execute() {
        System.out.println("Parent");
    }
}
```

即使子类声明同名 `execute()`，父类 `run()` 仍调用父类私有实现。

### 11.16.3 私有方法适合固定内部步骤

它不会成为子类扩展点。

---

## 11.17 包级方法的跨包边界

父类：

```java
package parent;

public class Parent {

    void execute() {
    }
}
```

跨包子类：

```java
package child;

public class Child
        extends parent.Parent {

    public void execute() {
    }
}
```

`Child.execute()` 不是对父类包级方法的正常重写，因为父方法在跨包子类中不可继承访问。

### 11.17.1 @Override 可以检查

```java
@Override
public void execute() {
}
```

会产生编译错误。

### 11.17.2 同包子类

若 `Child` 与 `Parent` 在同包，包级方法可以参与重写。

### 11.17.3 迁移包的兼容风险

把子类移动到另一个包，可能悄悄改变：

- 包级方法是否重写；
- protected 访问；
- 构造器可见性；
- 测试访问。

重构后应重新编译并执行覆盖测试。

## 11.18 final 方法

父类：

```java
public final void validate() {
}
```

子类不能重写：

```java
// @Override
// public void validate() {
// }
```

### 11.18.1 final 方法的价值

- 固定关键不变量；
- 防止子类破坏算法步骤；
- 保持安全检查；
- 稳定模板方法中的固定部分；
- 明确非扩展点。

### 11.18.2 final 类

```java
public final class Money {
}
```

不能被继承，因此所有实例方法都不存在外部子类重写风险。

### 11.18.3 不要无理由全部 final

若类型本来设计为扩展点，过度 `final` 会限制合理扩展。

选择应基于：

- 是否为继承设计；
- 是否有稳定契约；
- 是否需要封闭实现；
- 不变量是否允许子类参与。

## 11.19 静态方法隐藏

父类：

```java
public class Parent {

    public static void print() {
        System.out.println("Parent");
    }
}
```

子类：

```java
public class Child extends Parent {

    public static void print() {
        System.out.println("Child");
    }
}
```

这叫：

```text
静态方法隐藏
```

不是实例方法重写。

### 11.19.1 根据编译时类型或限定类名选择

```java
Parent value = new Child();

value.print();
```

调用目标按静态方法规则解析，通常是：

```text
Parent.print()
```

### 11.19.2 推荐使用类名

```java
Parent.print();
Child.print();
```

避免通过实例调用静态方法。

### 11.19.3 @Override 不允许

```java
// @Override
public static void print() {
}
```

静态方法不参与实例动态绑定。

---

## 11.20 实例方法与静态方法不能互相覆盖

父类实例方法：

```java
public void execute() {
}
```

子类不能声明同签名静态方法：

```java
// public static void execute() {
// }
```

反过来也不允许：

父类静态方法与子类同签名实例方法冲突。

原因是：

```text
实例动态分派语义
与
类级静态解析语义
不能混用同一覆盖关系
```

## 11.21 字段隐藏

字段不存在方法重写。

父类：

```java
public class Parent {

    public String name = "Parent";
}
```

子类：

```java
public class Child extends Parent {

    public String name = "Child";
}
```

子类字段隐藏父类同名字段。

### 11.21.1 根据表达式编译时类型访问

```java
Child child = new Child();
Parent parent = child;

System.out.println(child.name);  // Child
System.out.println(parent.name); // Parent
```

字段访问不进行实例方法式动态绑定。

### 11.21.2 同一个对象中存在两个字段

`Child` 对象中可以同时存在：

- `Parent.name`；
- `Child.name`。

### 11.21.3 使用 super 访问父类字段

```java
System.out.println(super.name);
```

### 11.21.4 工程建议

避免在父子类中声明同名实例字段。

字段隐藏非常容易造成：

- 阅读错误；
- 序列化混乱；
- 反射歧义；
- 调试困难；
- 状态不一致。

## 11.22 方法重写与字段隐藏对比

```text
实例方法
→ 可以重写
→ 运行时对象类型参与动态分派

字段
→ 只能隐藏
→ 表达式编译时类型决定访问哪个字段

静态方法
→ 隐藏
→ 编译期解析
```

示例：

```java
public class Parent {

    public String field = "Parent";

    public String method() {
        return "Parent";
    }
}

public class Child extends Parent {

    public String field = "Child";

    @Override
    public String method() {
        return "Child";
    }
}
```

调用：

```java
Parent value = new Child();

System.out.println(value.field);  // Parent
System.out.println(value.method()); // Child
```

## 11.23 super.method()

子类可以显式调用直接父类实现：

```java
@Override
public void execute() {
    super.execute();
    audit();
}
```

### 11.23.1 典型用途

- 在父实现基础上扩展；
- 保留父类校验；
- 调用模板步骤；
- 避免重复父类逻辑。

### 11.23.2 不是动态分派

```java
super.execute()
```

明确选择直接父类实现，不会再次根据当前对象类型回到子类重写方法。

### 11.23.3 不能跳过直接父类

不能写：

```java
// super.super.execute();
```

如果需要复用祖先逻辑，应由直接父类提供受控方法，或重新评估继承层次。

### 11.23.4 不应机械调用 super

某些父方法语义要求完全替换，而不是追加。

是否调用 `super` 应由父类文档说明。

## 11.24 模板方法中的重写

父类定义算法骨架：

```java
public abstract class Task {

    public final void run() {
        validate();
        execute();
        cleanup();
    }

    protected void validate() {
    }

    protected abstract void execute();

    protected void cleanup() {
    }
}
```

### 11.24.1 固定流程

`run()` 声明为 `final`，防止子类打乱顺序。

### 11.24.2 可重写钩子

- `validate()`；
- `execute()`；
- `cleanup()`。

### 11.24.3 父类必须文档化

应说明：

- 调用顺序；
- 是否允许调用 `super`；
- 是否可以抛异常；
- 调用次数；
- 是否在锁内调用；
- 是否在构造期间调用；
- 参数是否可变；
- 线程安全要求。

## 11.25 抽象子类重新抽象具体方法

父类有具体实现：

```java
public class Parent {

    public void execute() {
        System.out.println("default");
    }
}
```

抽象子类可以重新声明为抽象：

```java
public abstract class AbstractChild
        extends Parent {

    @Override
    public abstract void execute();
}
```

### 11.25.1 作用

强制更下层具体子类重新提供实现。

### 11.25.2 限制

父方法不能是：

```text
final
static
private
或不可继承方法
```

### 11.25.3 谨慎使用

它会取消父类默认实现，增加继承层次理解成本。

应确保该抽象层确实具有不同契约。

## 11.26 重写中的参数规则

方法重写要求参数类型匹配覆盖关系。

父类：

```java
public void process(Number value) {
}
```

子类：

```java
@Override
public void process(Number value) {
}
```

### 11.26.1 缩小参数类型不是重写

```java
public void process(Integer value) {
}
```

这是重载，不是重写。

### 11.26.2 扩大参数类型也不是重写

```java
public void process(Object value) {
}
```

同样是重载。

### 11.26.3 为什么参数不能协变

若允许子类把参数缩小为 `Integer`：

```text
父类型承诺接受任意 Number
子类却只接受 Integer
```

会破坏父类型替换能力。

Java 普通重写参数保持不变。

## 11.27 泛型方法重写

父类：

```java
public class Parent<T> {

    public T value() {
        return null;
    }
}
```

子类：

```java
public class Child
        extends Parent<String> {

    @Override
    public String value() {
        return "Java";
    }
}
```

### 11.27.1 类型实参替换后判断

`Parent<String>` 中继承到的返回类型是：

```text
String
```

子类重写合法。

### 11.27.2 原始类型会增加复杂度

使用 raw type：

```java
Parent parent = new Child();
```

会丢失泛型检查，并可能产生非受检警告。

### 11.27.3 泛型擦除

JVM 层方法描述符需要兼容擦除后的类型。

编译器可能生成桥接方法。

## 11.28 桥接方法

示例：

```java
public class Parent<T> {

    public T value() {
        return null;
    }
}

public class Child
        extends Parent<String> {

    @Override
    public String value() {
        return "Java";
    }
}
```

擦除后，父类方法近似：

```java
public Object value()
```

子类源码方法：

```java
public String value()
```

为了保持覆盖关系，编译器可能生成类似：

```java
public Object value() {
    return value();
}
```

该方法称为桥接方法。

### 11.28.1 桥接方法特征

反射中可能看到：

```java
method.isBridge()
method.isSynthetic()
```

### 11.28.2 价值

- 保持擦除后的多态；
- 兼容 JVM 方法描述符；
- 支持协变返回和泛型重写。

### 11.28.3 不应手工调用或依赖

桥接方法是编译器实现细节。

框架使用反射扫描方法时，应注意过滤或正确处理桥接方法。

## 11.29 泛型名称冲突

父类：

```java
public class Parent<T> {

    public void process(T value) {
    }
}
```

子类：

```java
public class Child
        extends Parent<String> {

    @Override
    public void process(String value) {
    }
}
```

合法。

但若子类再声明：

```java
// public void process(Object value) {
// }
```

可能与擦除后的继承方法产生名称冲突。

### 11.29.1 判断不能只看源码泛型

需要同时考虑：

- 类型参数替换；
- 方法签名；
- 子签名；
- 擦除；
- 桥接方法。

详细规则见泛型专题。

## 11.30 数组协变不是方法重写协变

Java 数组具有协变：

```java
String[] strings = new String[10];
Object[] objects = strings;
```

但写入错误类型会在运行时抛出：

```java
objects[0] = 100;
// ArrayStoreException
```

### 11.30.1 泛型通常不协变

```java
List<String>
```

不是：

```java
List<Object>
```

的子类型。

### 11.30.2 与协变返回不同

```text
协变返回
→ 重写方法返回类型可以更具体

数组协变
→ 数组子类型关系

泛型通配符
→ 使用点变型
```

三者不能混为一谈。

## 11.31 父类引用与子类对象

```java
Parent value = new Child();
```

这是向上转型。

编译器允许调用哪些成员，先看：

```text
引用的编译时类型 Parent
```

实例方法最终执行哪个重写实现，再看：

```text
对象的运行时类型 Child
```

### 11.31.1 本章边界

这里只建立：

```text
重写方法具备运行时替换能力
```

完整动态绑定过程见 `12-多态与动态绑定.md`。

### 11.31.2 子类特有成员不可直接调用

```java
// value.childOnly();
```

需要：

- 改变变量静态类型；
- 安全向下转型；
- 重新设计父类抽象。

## 11.32 构造器中的重写调用风险

父类：

```java
public class Parent {

    public Parent() {
        initialize();
    }

    protected void initialize() {
    }
}
```

子类：

```java
public class Child extends Parent {

    private String value = "ready";

    @Override
    protected void initialize() {
        System.out.println(value);
    }
}
```

创建：

```java
new Child();
```

父类构造器执行时，动态绑定可能调用 `Child.initialize()`。

但子类字段初始化尚未完成，`value` 可能是：

```text
null
```

### 11.32.1 不要在构造器中调用可重写方法

包括间接调用。

### 11.32.2 安全选择

构造过程使用：

- `private` 方法；
- `final` 方法；
- 静态纯函数；
- 构造参数；
- 构造完成后的显式初始化阶段。

## 11.33 sealed 类

sealed 类用于限制哪些类型可以直接继承它。

```java
public sealed class Shape
        permits Circle, Rectangle {
}
```

### 11.33.1 直接子类必须明确后续策略

```java
public final class Circle
        extends Shape {
}
```

```java
public sealed class Rectangle
        extends Shape
        permits Square {
}
```

```java
public non-sealed class OpenShape
        extends Shape {
}
```

### 11.33.2 三种选择

```text
final
→ 终止继承

sealed
→ 继续限制继承

non-sealed
→ 重新开放继承
```

### 11.33.3 目的

- 封闭类型层次；
- 穷尽模式匹配；
- 明确扩展边界；
- 保护业务状态模型；
- 提高编译器分析能力。

---

## 11.34 sealed 的位置约束

被允许的直接子类型必须满足模块或包位置规则。

通常：

```text
命名模块中
→ 与 sealed 父类型位于同一模块

未命名模块中
→ 与 sealed 父类型位于同一包
```

### 11.34.1 permits 可以省略

当直接子类型在同一编译单元中可被编译器推断时，可以省略显式 `permits`。

### 11.34.2 只限制直接子类

若某个直接子类声明为 `non-sealed`，它的后代可以继续开放扩展。

### 11.34.3 sealed 不自动保证行为正确

它只控制类型集合。

仍需：

- 不变量；
- 重写契约；
- 访问控制；
- 测试；
- 合理抽象。

## 11.35 record 与继承

record 隐式是 `final`，不能被普通类继承。

```java
public record Point(int x, int y) {
}
```

### 11.35.1 record 不能 extends 自定义父类

record 隐式继承：

```text
java.lang.Record
```

不能再继承其他类。

### 11.35.2 可以实现接口

```java
public record Point(int x, int y)
        implements Comparable<Point> {

    @Override
    public int compareTo(Point other) {
        return Integer.compare(x, other.x);
    }
}
```

### 11.35.3 适合值对象

record 的封闭继承边界有利于稳定值语义。

## 11.36 enum 与继承

枚举隐式继承：

```text
java.lang.Enum<E>
```

不能显式继承其他类。

### 11.36.1 可以实现接口

```java
public enum Operation
        implements Calculator {

    ADD,
    SUBTRACT
}
```

### 11.36.2 枚举不能被普通类继承

枚举类型的实例集合由枚举常量控制。

### 11.36.3 常量特定类体

枚举常量可以提供特定方法实现：

```java
public enum Operation {

    ADD {
        @Override
        int apply(int a, int b) {
            return a + b;
        }
    };

    abstract int apply(int a, int b);
}
```

这是枚举内部受控多态，不等于开放给外部普通继承。

## 11.37 里氏替换原则概览

里氏替换原则强调：

> 子类型对象应能够替代父类型对象，而不破坏程序正确性。

### 11.37.1 不只看方法签名

即使重写语法合法，行为仍可能破坏契约。

父类：

```java
public void add(Item item) {
}
```

子类重写：

```java
@Override
public void add(Item item) {
    throw new UnsupportedOperationException();
}
```

若父类契约承诺可添加，这个子类可能违反替换原则。

### 11.37.2 常见行为约束

子类不应：

- 加强输入前置条件；
- 削弱输出后置条件；
- 破坏父类不变量；
- 改变关键副作用语义；
- 抛出调用方无法预期的新失败；
- 改变线程安全承诺。

完整设计原则见 `15`。

## 11.38 脆弱基类问题

父类内部实现变化可能意外破坏子类。

### 11.38.1 自用方法问题

父类：

```java
public class CollectionLike {

    public void add(Item item) {
    }

    public void addAll(
            List<Item> items
    ) {
        for (Item item : items) {
            add(item);
        }
    }
}
```

子类重写 `add()` 进行计数。

如果子类又重写 `addAll()` 并额外计数，可能出现重复统计。

### 11.38.2 父类版本演进

父类新增一个可重写方法，可能与子类已有同名方法形成意外重写。

### 11.38.3 protected 状态耦合

子类依赖父类字段布局和调用顺序，父类很难安全重构。

### 11.38.4 结论

公共继承体系必须设计和文档化，不能只依赖“目前能运行”。

## 11.39 为继承设计父类

适合继承的父类应明确：

- 哪些方法允许重写；
- 哪些方法禁止重写；
- 可重写方法何时调用；
- 是否在构造器中调用；
- 是否在锁内调用；
- 是否允许调用 `super`；
- 调用次数；
- 参数和返回值约束；
- 异常契约；
- 状态变化顺序；
- 线程安全语义。

### 11.39.1 优先 private 字段

不直接暴露 `protected` 可变字段。

通过：

- `protected final` 查询方法；
- 受控修改方法；
- 模板钩子；
- 不可变快照；

提供扩展能力。

### 11.39.2 非扩展类禁止继承

可以使用：

```java
final
```

或者：

```java
sealed
```

明确边界。

### 11.39.3 构造器避免可重写调用

保证子类不会在半初始化状态被回调。

---

## 11.40 继承与组合的选择

继承适合：

- 稳定 `is-a` 关系；
- 子类能够替换父类；
- 父类明确为继承设计；
- 需要共享统一抽象；
- 扩展点稳定且有文档。

组合适合：

- 只是复用实现；
- 行为需要运行时替换；
- 多个能力需要组合；
- 不希望暴露父类内部状态；
- 生命周期独立；
- 继承契约不稳定。

### 11.40.1 示例

不推荐：

```java
class PropertiesConfig
        extends HashMap<String, String> {
}
```

如果配置对象不应支持任意 `Map` 行为，更适合：

```java
final class PropertiesConfig {

    private final Map<String, String> values;
}
```

完整原则见 `15`。

## 11.41 常见错误

### 11.41.1 只为复用两行代码继承

引入的父子类耦合远大于复用收益。

### 11.41.2 子类缩小参数接受范围

通过重载伪装成重写，父类型调用不会进入预期方法。

### 11.41.3 字段与方法同名隐藏混淆

调用者误以为字段也会动态绑定。

### 11.41.4 静态方法通过实例调用

容易误认为发生多态。

### 11.41.5 protected 字段公开内部状态

子类可绕过父类不变量。

### 11.41.6 构造器调用可重写方法

子类状态尚未初始化。

### 11.41.7 忘记 @Override

签名变化后悄悄变成重载或新方法。

### 11.41.8 重写扩大受检异常

破坏父类型调用方的异常契约。

### 11.41.9 sealed 当作安全校验

限制子类集合不能替代权限和输入校验。

### 11.41.10 父类方法文档未说明 super 调用要求

子类无法判断应完全替换还是追加行为。

public class SealedDemo {

            permits Success, Failure {

            implements Result {
    }

            implements Result {

public class CompositionDemo {

    static final class Config {

        private final Map<String, String>
                values;

                Map<String, String> values
        ) {
            this.values =
                    Map.copyOf(values);

                        "missing key: " + key
                );

            return value;
        }
    }

        Map<String, String> values =
                new HashMap<>();

        values.put("host", "localhost");

        Config config = new Config(values);

        System.out.println(
                config.require("host")
        );
    }
}

## 11.44 易错点

### 误区一：继承只是代码复用机制

**错误。**

它首先建立子类型和行为替换关系。

### 误区二：Java 支持多个类的直接继承

**错误。**

普通类最多直接继承一个类。

### 误区三：没有写 extends 的类没有父类

**错误。**

普通类默认直接继承 `Object`。

### 误区四：父类 private 字段不在子类对象中

**错误。**

父类定义的实例状态仍属于子类对象，只是子类不能直接访问。

### 误区五：构造器会被子类继承

**错误。**

构造器不属于类成员，也不能被重写。

### 误区六：方法名相同就是重写

**错误。**

还需参数签名、返回类型、权限、异常和可继承性满足规则。

### 误区七：不写 @Override 也不会有风险

**错误。**

拼写或参数变化可能悄悄变成新方法。

### 误区八：子类可以随意缩小重写方法权限

**错误。**

这会破坏父类调用方的访问契约。

### 误区九：返回类型宽化也属于协变返回

**错误。**

协变返回要求子类返回更具体的引用类型。

### 误区十：int 返回值可以重写成 long

**错误。**

基本类型不支持返回类型协变。

### 误区十一：子类可以抛出任意更宽受检异常

**错误。**

不能扩大父类调用方的受检异常责任。

### 误区十二：private 方法会被动态重写

**错误。**

它对子类不可继承，子类同名方法是独立声明。

### 误区十三：跨包子类声明同名包级方法就是重写

**错误。**

不可访问的父方法不参与普通重写关系。

### 误区十四：final 方法可以重写但不能调用

**错误。**

final 方法可以正常调用，但不能被重写。

### 误区十五：静态方法支持运行时多态

**错误。**

静态方法发生隐藏并在编译期解析。

### 误区十六：通过父类变量调用子类静态方法会进入子类版本

**错误。**

目标根据编译时类型解析。

### 误区十七：字段像实例方法一样动态绑定

**错误。**

字段访问由表达式编译时类型决定。

### 误区十八：子类同名字段会替换父类字段

**错误。**

两个字段可以同时存在。

### 误区十九：重写方法必须调用 super

**错误。**

是否调用取决于父类契约。

### 误区二十：super.method() 会再次调用当前子类重写方法

**错误。**

它明确选择直接父类实现。

### 误区二十一：可以使用 super.super 调用祖父类实现

**错误。**

Java 不支持这种语法。

### 误区二十二：子类可以通过缩小参数类型实现更具体重写

**错误。**

这会形成重载而不是重写。

### 误区二十三：泛型方法重写只需看源码显示类型

**错误。**

还需考虑类型替换、擦除和子签名。

### 误区二十四：桥接方法是开发者重复写出的普通方法

**错误。**

它通常由编译器生成。

### 误区二十五：反射看到 bridge 方法说明源码有两个同名实现

**错误。**

其中一个可能是编译器适配方法。

### 误区二十六：数组协变与泛型协变规则相同

**错误。**

数组协变有运行时存储检查，泛型默认不变。

### 误区二十七：父类引用只能指向父类对象

**错误。**

可以通过向上转型指向子类对象。

### 误区二十八：构造器中调用可重写方法可以帮助子类初始化

**错误。**

可能访问尚未初始化的子类状态。

### 误区二十九：sealed 类的任何后代都必须写在 permits 中

**错误。**

`permits` 只列直接子类型。

### 误区三十：non-sealed 表示不能继续继承

**错误。**

它表示重新开放继承。

### 误区三十一：sealed 自动保证所有子类行为正确

**错误。**

它只限制类型集合。

### 误区三十二：record 可以继承任意父类

**错误。**

record 隐式继承 `Record` 且是 final。

### 误区三十三：enum 不能拥有多态行为

**错误。**

枚举常量可以提供特定实现，也可以实现接口。

### 误区三十四：语法上满足 extends 就一定满足 is-a

**错误。**

还必须满足行为替换契约。

### 误区三十五：子类抛 UnsupportedOperationException 总是合法设计

**错误。**

若父类承诺支持该行为，可能违反里氏替换。

### 误区三十六：protected 字段是为子类扩展最方便的设计

**错误。**

它会暴露内部表示并削弱不变量。

### 误区三十七：父类内部实现可以随意修改，不会影响子类

**错误。**

可重写调用、自用方法和 protected 状态会形成脆弱基类。

### 误区三十八：继承层次越深，复用程度越高越好

**错误。**

深层次会增加契约、初始化和理解成本。

### 误区三十九：组合无法实现运行时多态

**错误。**

通过接口字段和委托同样可以替换实现。

### 误区四十：所有非 final 类都天然适合继承

**错误。**

能够继承不等于为继承设计。

## 11.45 工程实践建议

1. 使用继承前先确认稳定、真实的 `is-a` 关系。
2. 不仅检查语法，还检查子类能否替代父类。
3. 只为复用实现时优先使用组合和委托。
4. 所有重写与接口实现方法统一添加 `@Override`。
5. 重写方法不缩小访问权限。
6. 协变返回只用于更具体的引用类型。
7. 重写方法不扩大受检异常范围。
8. 不通过缩小参数类型伪装重写。
9. 父类字段保持 `private`，避免 `protected` 可变状态。
10. 避免父子类声明同名实例字段。
11. 静态方法通过类名调用，不通过实例调用。
12. 不在构造器、字段初始化器和实例初始化块中调用可重写方法。
13. 父类模板方法固定流程时声明为 `final`。
14. 可重写钩子保持小、明确、无隐藏副作用。
15. 父类文档说明钩子调用顺序、次数和锁状态。
16. 父类文档明确子类是否需要调用 `super`。
17. 反射框架识别并正确处理 bridge 和 synthetic 方法。
18. 泛型继承避免使用 raw type。
19. sealed 用于封闭稳定类型层次，不替代业务校验。
20. sealed 直接子类型选择 `final`、`sealed` 或 `non-sealed` 时表达明确扩展意图。
21. 值对象优先使用 final 类或 record。
22. 不开放没有明确扩展契约的公共类继承。
23. 非扩展类使用 `final`，受控扩展层次使用 `sealed`。
24. 继承层次保持浅，减少跨多层查找行为。
25. 不让子类依赖父类字段布局和内部调用细节。
26. 父类演进前检查新增方法是否与子类方法冲突。
27. 对公共继承体系执行二进制和源码兼容测试。
28. 使用单元测试验证父类契约在所有子类中成立。
29. 对模板方法测试调用顺序和异常路径。
30. 对构造期间动态调用编写回归测试或直接消除该设计。
31. 组合对象通过接口注入，避免硬编码具体协作者。
32. 代码审查重点检查：错误重载、字段隐藏、异常扩大和替换原则破坏。

## 11.47 本章总结

### 11.47.1 继承主线

```text
class Child extends Parent
→ 建立子类型关系
→ 继承可访问成员
→ 参与构造链
→ 可以重写可继承实例方法
```

### 11.47.2 重写规则

```text
方法名与参数签名匹配
+
返回类型相同或协变
+
访问权限不缩小
+
受检异常不扩大
+
父方法可继承且非 final
=
合法重写
```

### 11.47.3 三种同名机制

```text
实例方法
→ 重写
→ 运行时动态绑定

静态方法
→ 隐藏
→ 编译期解析

字段
→ 隐藏
→ 编译时类型决定
```

### 11.47.4 不可重写成员

```text
构造器
→ 不属于类成员

private 方法
→ 不被子类继承

final 方法
→ 禁止重写

static 方法
→ 只能隐藏
```

### 11.47.5 泛型与桥接

```text
泛型重写
↓
类型擦除后方法描述符可能变化
↓
编译器生成 bridge 方法
↓
保持 JVM 多态调用兼容
```

### 11.47.6 继承边界

```text
final
→ 禁止继续继承

sealed
→ 只允许指定直接子类型

non-sealed
→ 重新开放继承

record
→ 隐式 final
```

### 11.47.7 面试口述版

Java 类只支持单继承，但可以实现多个接口。继承不只是代码复用，而是建立子类型和行为替换关系。子类对象包含父类定义的实例状态，父类 `private` 字段虽然不能被子类直接访问，但仍存在于子类对象中。构造器不是类成员，因此不会被继承或重写。

方法重写要求方法签名满足覆盖关系，返回类型相同或使用协变返回，访问权限不能缩小，受检异常不能扩大，并且父方法必须可继承且不是 `final`。`private` 方法不能被重写，静态方法只会隐藏，字段也只会隐藏。实例方法调用可以动态绑定，静态方法和字段则主要根据编译时类型解析。

泛型继承经过类型擦除后，编译器可能生成桥接方法来保持多态。sealed 类通过 `final`、`sealed` 和 `non-sealed` 明确控制继承边界。工程上使用继承前必须验证真实 `is-a` 关系和里氏替换原则；如果只是复用实现，通常应优先使用组合和委托。
