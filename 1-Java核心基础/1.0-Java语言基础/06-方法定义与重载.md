# 方法定义与重载

## 3.21 方法的定义

方法的基本结构：

```
访问修饰符 其他修饰符 返回类型 方法名(参数列表) {
方法体
}
```

示例：

```java
public static int add(int a, int b) {
    return a + b;
}
```

组成部分：

- public ：访问权限
- static ：类方法
- int ：返回类型
- add ：方法名
- int a, int b ：参数列表
- return a + b ：方法体

**3.21.1 返回类型**

无返回值：

```java
public void execute() {
}
```

有返回值：

```
public String queryName() {
return "Java";
}
```

返回值必须与声明类型兼容：

```
public long count() {
return 10;
}
```

int 可以自动提升为 long 。

**3.21.2 方法不能独立存在**

Java 普通方法必须定义在：

- 类
- 接口
- 枚举
- 记录类

内部。
Java 不支持像某些语言那样定义真正的顶层函数。

## 3.22 方法签名

Java 语言中，方法签名主要由以下部分组成：

```
方法名 + 参数类型列表
```

例如：

```
void execute(int value)
void execute(String value)
```

两者签名不同。
下面两个方法不能同时存在：

```
int execute(int value)
String execute(int value)
```

因为它们只有返回值不同，方法签名相同。
核心结论：
返回类型不参与方法重载判断。

**3.22.1 参数名不参与签名**

```
void execute(int a)
void execute(int b)
```

两者签名完全相同，不能同时定义。
参数名只影响代码可读性，不参与方法识别。

**3.22.2 修饰符不参与签名**

```java
public void execute(int value)
private void execute(int value)
```

同样不能同时定义。
public 、 private 、 static 、 final 等都不用于区分重载方法。

## 3.23 方法重载

方法重载是指：
在同一个类或继承体系中，存在多个同名方法，但参数列表不同。
示例：

```java
public void execute(int value) {
}
public void execute(String value) {
}
public void execute(int value, String name) {
}
```

**3.23.1 重载成立条件**

重载要求参数列表至少有一项不同：

- 参数数量不同
- 参数类型不同
- 参数顺序不同
- 例如：

```
void execute(int value, String name)
void execute(String name, int value)
```

可以构成重载。

**3.23.2 返回类型不能区分重载**

错误：

```
int query()
String query()
```

编译器无法根据调用位置稳定确定要调用哪个方法。

**3.23.3 重载是编译期绑定**

```java
void print(int value) {
System.out.println("int");
}
void print(long value) {
System.out.println("long");
}
```

调用：

```
print(10);
```

编译器选择：

```
print(int value)
```

因为整数字面量 10 默认是 int 。

方法重载在编译期根据：

- 实参静态类型
- 方法参数列表
- 类型转换规则

进行选择。
因此重载属于静态绑定。

## 3.24 重载方法选择规则

编译器通常按“最匹配”原则选择方法。

**3.24.1 精确匹配优先**

```
void print(int value)
void print(long value)
```

调用：

```
print(10);
```

选择 int 。

**3.24.2 基本类型宽化**

```
void print(long value)
```

调用：

```
print(10);
```

int 自动提升为 long 。

**3.24.3 装箱**

```
void print(Integer value)
```

调用：

```
print(10);
```

会发生自动装箱。

**3.24.4 可变参数**

```
void print(int... values)
```

调用：

```
print(10);
```

也可以匹配。
通常优先级可以概括为：

```
精确匹配
↓
基本类型宽化
↓
自动装箱
↓
装箱后引用宽化
↓
可变参数
```

该顺序只适合作为常见案例的辅助记忆，不是完整的 Java 语言规范规则。

正式规则简化为：

1. 先寻找固定参数、严格调用上下文下的适用方法；
2. 再寻找固定参数、宽松调用上下文下的适用方法，允许装箱和拆箱；
3. 如果仍未找到，再考虑可变参数方法；
4. 在当前阶段的适用候选方法中选择最具体方法；
5. 如果不存在唯一最具体方法，产生编译期二义性错误。

遇到复杂重载时，应以编译器实际规则为准，不建议人为设计过于接近的重载。

**3.24.5 宽化优先于装箱**

```java
void print(long value) {
System.out.println("long");
}
void print(Integer value) {
System.out.println("Integer");
}
```

调用：

```
print(10);
```

通常选择：

```
long
```

因为基本类型宽化优先于自动装箱。

**3.24.6 null 产生的歧义**

```
void print(String value)
void print(Integer value)
```

调用：

```
print(null);
```

编译错误，因为 null 同时可以匹配 String 和 Integer ，且两者没有更具体的继承关系。
但如果是：

```
void print(Object value)
void print(String value)
```

调用：

```
print(null);
```

会选择 String ，因为 String 比 Object 更具体。

## 3.25 可变参数

定义：

```java
public void print(String... values) {
}
```

调用：

```
print();
print("A");
print("A", "B");
```

**3.25.1 可变参数本质是数组**

方法内部：

```java
public void print(String... values) {
    System.out.println(values.length);
}
```

values 的类型实际是：

```
String[]
```

因此也可以直接传数组：

```
String[] values = {"A", "B"};
print(values);
```

**3.25.2 可变参数必须放在最后**

正确：

```
void execute(String name, int... values)
```

错误：

```
void execute(int... values, String name)
```

一个方法最多只能有一个可变参数。

**3.25.3 数组与可变参数不能构成重载**

下面两个声明本质相同：

```
void print(String[] values)
void print(String... values)
```

不能同时存在。
因为编译后参数类型都是：

```
String[]
```

**3.25.4 可变参数与普通重载**

```
void print(String value)
void print(String... values)
```

调用：

```
print("A");
```

通常优先选择普通单参数方法。
调用：

```
print("A", "B");
```

选择可变参数方法。

**3.25.5 传入 null 的歧义**

```
print(null);
```

对于：

```
void print(String... values)
```

编译器可能将 null 解释为：

```
String[] null
```

而不是包含一个 null 元素的数组。
如果要表达一个 null 元素：

```
print((String) null);
```

如果要表达数组为 null：

```
print((String[]) null);
```

这类写法容易误解，实际 API 设计应避免。

## 3.26 递归方法

递归是方法直接或间接调用自身。
示例：

```java
public static int factorial(int n) {
    if (n <= 1) {
        return 1;
    }
    return n * factorial(n - 1);
}
```

递归必须包含：

- 终止条件
- 向终止条件逼近的过程

否则会无限调用。

**3.26.1 递归调用风险**

每次方法调用通常都会创建新的调用上下文。
递归层数过深可能导致：

```
StackOverflowError
```

例如：

```java
public static void execute() {
    execute();
}
```

**3.26.2 递归与迭代选择**

适合递归的场景：

- 树结构遍历
- 分治算法
- 深度优先搜索
- 天然递归的数据结构
- 适合迭代的场景：
- 简单线性循环
- 递归深度可能非常大
- 对栈空间敏感
- 追求可控性能

Java 不保证通用尾递归优化，因此不能假设尾递归一定不会占用调用栈。

## 3.27 方法调用的基本过程

从语言层面看：

```
int result = add(1, 2);
```

大致经历：

```
计算实参
↓
选择目标方法
↓
为形参传入实参值
↓
执行方法体
↓
返回结果
↓
继续执行调用方代码
```

本章只建立概念：

- 方法调用有独立的局部变量作用域
- 形参是方法内部变量
- 局部变量之间互不直接共享
- 调用结束后返回调用点继续执行
- 关于：
- 栈帧
- 局部变量表
- 操作数栈
- 动态链接
- 返回地址

放在 JVM 模块。

## 3.28 方法中的局部变量作用域

```java
public void execute() {
    int value = 10;
}
```

value 只在当前方法中可见。
不同方法可以声明同名局部变量：

```java
public void methodA() {
    int value = 10;
}
public void methodB() {
    int value = 20;
}
```

它们互不冲突。

**3.28.1 代码块作用域**

```java
public void execute() {
    if (condition) {
        int value = 10;
    }
    System.out.println(value); // 编译错误
}
```

变量只在声明所在代码块及其内部作用域有效。

**3.28.2 循环变量作用域**

```java
for (int i = 0; i < 10; i++) {
}
System.out.println(i); // 编译错误
```

i 只在 for 语句及循环体中有效。

## 3.29 控制流与可达性

Java 编译器会检查部分不可达代码。
例如：

```java
public int execute() {
    return 1;
    System.out.println("无法执行"); // 编译错误
}
```

return 后面的代码永远不可执行，因此编译器拒绝。
类似：

```java
throw new RuntimeException();
System.out.println("无法执行");
```

同样属于不可达代码。

**3.29.1 无限循环后的代码**

```java
while (true) {
}
System.out.println("结束"); // 编译错误
```

编译器可以确定循环永远不会退出。
但如果条件是变量：

```java
while (running) {
}
System.out.println("结束");
```

编译器通常不能确定 running 是否会改变，因此后续代码可能被认为可达。
