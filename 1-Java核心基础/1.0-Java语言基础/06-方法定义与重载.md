## 6.2 方法是什么

方法是声明在类、接口、枚举、记录类或隐式声明类中的可调用行为单元。

典型方法：

```java
public int add(int left, int right) {
    return left + right;
}
```

可以拆成：

```text
访问修饰符
→ public

返回类型
→ int

方法名
→ add

形式参数列表
→ int left, int right

方法体
→ return left + right;
```

### 6.2.1 方法的主要价值

方法用于：

- 封装可复用逻辑；
- 为行为命名；
- 隐藏实现细节；
- 建立输入和输出契约；
- 降低重复代码；
- 分解复杂流程；
- 提供多态扩展点；
- 支持测试和替换；
- 维护对象不变量。

### 6.2.2 方法不是函数对象

普通 Java 方法本身不是一个可以任意存储的对象。

下面只是方法调用：

```java
int result = calculator.add(1, 2);
```

需要把行为作为值传递时，通常使用：

- Lambda；
- 方法引用；
- 函数式接口；
- 策略对象；
- 命令对象。

### 6.2.3 方法与函数的日常称呼

工程交流中常把无状态静态方法称为“函数”。

但 Java 语言模型中，普通方法仍然是某个类型或隐式声明类的成员。

## 6.3 方法声明结构

### 6.3.1 完整结构

```java
@Deprecated
public static <T extends Comparable<T>>
T max(T first, T second)
        throws IllegalArgumentException {

    return first.compareTo(second) >= 0
            ? first
            : second;
}
```

可能包含：

```text
注解
修饰符
类型参数
返回类型
方法名
形式参数
throws 子句
方法体
```

### 6.3.2 常见修饰符

方法可能使用：

- `public`；
- `protected`；
- 包级可见；
- `private`；
- `static`；
- `abstract`；
- `final`；
- `synchronized`；
- `native`；
- `strictfp`。

不是所有组合都合法。

例如：

```java
public abstract void execute();
```

抽象方法没有方法体。

```java
public native void execute();
```

本地方法声明以分号结束，具体实现来自本地代码。

### 6.3.3 普通方法体

```java
public void execute() {
    System.out.println("execute");
}
```

方法体是代码块。

### 6.3.4 无方法体声明

```java
public abstract void execute();
```

不能写成：

```java
// public abstract void execute() {
// }
```

抽象方法与接口方法完整规则见 `13`、`14`。

## 6.4 方法名与命名规则

### 6.4.1 方法名属于标识符

合法示例：

```java
calculate()
calculateTotal()
isEnabled()
getName()
```

方法名不能：

- 使用关键字；
- 以数字开头；
- 包含非法字符；
- 与声明语法冲突。

### 6.4.2 使用动词表达行为

推荐：

```java
calculateTotal()
validateOrder()
loadUser()
sendMessage()
```

不清晰：

```java
data()
handle()
process()
doIt()
```

后者不是绝对错误，但在复杂上下文中缺少业务语义。

### 6.4.3 布尔方法命名

常见形式：

```java
isEnabled()
hasPermission()
canCancel()
shouldRetry()
containsValue()
```

名称应让条件表达式自然可读：

```java
if (order.canCancel()) {
}
```

### 6.4.4 查询与命令分离

查询方法：

```java
BigDecimal calculateTotal()
```

应尽量只返回结果。

命令方法：

```java
void cancel()
```

用于修改状态或触发行为。

如果方法既修改状态又返回复杂结果，需要清楚说明契约。

## 6.5 返回类型

### 6.5.1 返回基本类型

```java
public int size() {
    return 10;
}
```

### 6.5.2 返回引用类型

```java
public User findUser() {
    return user;
}
```

返回引用值，不会自动复制对象。

### 6.5.3 返回数组

```java
public int[] values() {
    return values;
}
```

数组是引用类型。

直接返回内部数组可能泄漏可变状态。

### 6.5.4 返回泛型类型

```java
public List<User> findUsers() {
    return users;
}
```

### 6.5.5 返回类型必须兼容

```java
public long count() {
    return 10;
}
```

`int` 常量可以按返回上下文宽化为 `long`。

错误：

```java
public int count() {
    // return 10L; // 编译错误
}
```

除非显式转换且值可接受：

```java
return (int) value;
```

但强转不应掩盖范围风险。

## 6.6 void 方法

### 6.6.1 void 表示不产生方法返回值

```java
public void execute() {
    System.out.println("execute");
}
```

`void` 不代表：

```text
返回 null
```

它表示：

```text
该方法调用表达式不产生可赋值的方法结果值
```

因此不能写：

```java
// Object result = execute(); // 编译错误
```

### 6.6.2 void 方法可以使用 return

```java
public void process(Order order) {
    if (order == null) {
        return;
    }

    execute(order);
}
```

`return;` 用于提前结束方法。

### 6.6.3 void 方法不能返回值

```java
public void execute() {
    // return 1; // 编译错误
}
```

### 6.6.4 调用 void 方法可以作为语句

```java
execute();
```

但不能把它嵌入需要值的表达式：

```java
// System.out.println(execute()); // 编译错误
```

## 6.7 return 语句

### 6.7.1 返回值

```java
public int max(int first, int second) {
    if (first >= second) {
        return first;
    }

    return second;
}
```

### 6.7.2 返回表达式先求值

```java
public int next() {
    return index++;
}
```

返回的是自增前的值，之后 `index` 更新。

这种写法语法合法，但可能降低可读性。

更清晰：

```java
int current = index;
index++;

return current;
```

### 6.7.3 return 结束当前方法

一旦执行 `return`：

- 当前方法后续语句不再执行；
- 控制权返回调用方；
- 非 `void` 方法把结果值传回调用点。

### 6.7.4 finally 可能影响返回过程

```java
public int value() {
    try {
        return 1;
    } finally {
        System.out.println("finally");
    }
}
```

`finally` 会在方法真正返回前执行。

危险：

```java
public int value() {
    try {
        return 1;
    } finally {
        return 2;
    }
}
```

最终返回 `2`，并可能吞掉异常。

工程代码禁止在 `finally` 中写 `return`。

完整异常控制流放在异常处理章节。

## 6.8 非 void 方法的返回完整性

### 6.8.1 所有正常完成路径必须返回值

正确：

```java
public int sign(int value) {
    if (value > 0) {
        return 1;
    }

    if (value < 0) {
        return -1;
    }

    return 0;
}
```

错误：

```java
public int sign(int value) {
    if (value > 0) {
        return 1;
    }

    // 编译错误：其余路径没有返回值
}
```

### 6.8.2 抛异常也是终止路径

```java
public int parse(String text) {
    if (text == null) {
        throw new IllegalArgumentException(
                "text must not be null"
        );
    }

    return Integer.parseInt(text);
}
```

异常路径不需要返回值。

### 6.8.3 无限循环可以阻止正常完成

```java
public int waitForever() {
    while (true) {
    }
}
```

语言层可能认为方法不会正常完成，因此不要求 `return`。

但这种设计通常不适合业务方法。

### 6.8.4 switch 表达式简化返回

```java
public String describe(Status status) {
    return switch (status) {
        case CREATED -> "created";
        case PAID -> "paid";
        case CANCELLED -> "cancelled";
    };
}
```

每个分支产生值，方法结构更集中。

## 6.9 形式参数与实际参数

### 6.9.1 形式参数

方法声明中的变量：

```java
public int add(int left, int right) {
    return left + right;
}
```

`left` 和 `right` 是形式参数。

### 6.9.2 实际参数

调用时传入的表达式：

```java
int result = add(10, count + 1);
```

实参是：

```text
10
count + 1
```

实参不一定是变量，也可以是：

- 字面量；
- 表达式；
- 方法调用；
- 字段访问；
- 数组元素；
- 对象创建表达式。

### 6.9.3 参数变量只在方法内部有效

```java
public void print(String message) {
    System.out.println(message);
}
```

`message` 的作用域位于方法体。

### 6.9.4 参数在方法入口已确定赋值

参数在方法开始执行时已经接收到实参值。

即使值是 `null`：

```java
print(null);
```

参数仍然是“已赋值”，只是保存空引用。

## 6.10 Java 始终按值传递

### 6.10.1 基本类型参数

```java
public static void change(int value) {
    value = 100;
}
```

调用：

```java
int number = 10;
change(number);

System.out.println(number); // 10
```

传入的是 `number` 当前基本值的副本。

### 6.10.2 引用类型参数

```java
public static void rename(User user) {
    user.setName("Java");
}
```

调用方对象可能变化，因为：

```text
调用方引用变量
↓ 复制其引用值
参数变量
↓
两个引用值访问同一个对象
```

### 6.10.3 替换参数引用不影响调用方变量

```java
public static void replace(User user) {
    user = new User("new");
}
```

调用后，调用方原引用变量不会自动改指向。

### 6.10.4 Java 没有“引用按引用传递”

Java 传递的是：

```text
基本值
或
引用值
```

两者都属于值传递。

完整示意、数组、字符串和包装类型案例见 `07-参数传递机制.md`。

## 6.11 参数修饰与注解

### 6.11.1 final 参数

```java
public void execute(final Order order) {
}
```

方法内部不能给参数重新赋值：

```java
// order = new Order(); // 编译错误
```

但可以修改对象：

```java
order.cancel();
```

`final` 限制的是参数变量，不保证对象不可变。

### 6.11.2 参数注解

```java
public void execute(
        @NotNull Order order
) {
}
```

参数注解可以供：

- 编译器；
- IDE；
- 校验框架；
- 依赖注入框架；
- 文档工具；
- 运行时反射；

使用。

具体效果取决于注解定义和工具支持。

### 6.11.3 var 不能用于普通方法参数

错误：

```java
// public void print(var value) {
// }
```

普通方法签名必须声明明确类型。

`var` 可以用于 Lambda 参数：

```java
(var value) -> value.toString()
```

完整规则见 `02-Java类型系统与变量.md`。

## 6.12 方法签名

### 6.12.1 实用理解

在普通重载分析中，可以把方法签名理解为：

```text
方法名
+
形式参数类型列表
```

例如：

```java
void print(int value)
void print(long value)
void print(String value)
```

三个方法签名不同。

### 6.12.2 参数名不属于签名

以下两个方法冲突：

```java
void print(int first) {
}

// void print(int second) {
// }
```

参数名不同不能构成重载。

### 6.12.3 返回类型不属于重载区分条件

以下代码冲突：

```java
int value() {
    return 1;
}

// long value() {
//     return 1L;
// }
```

调用：

```java
value();
```

编译器不能只根据调用点期望的返回类型稳定地区分。

### 6.12.4 throws 子句不属于签名

以下代码冲突：

```java
void execute()
        throws IOException {
}

// void execute()
//         throws SQLException {
// }
```

### 6.12.5 修饰符不属于签名

以下代码冲突：

```java
static void execute(int value) {
}

// void execute(int value) {
// }
```

`static`、访问权限和 `final` 都不能单独区分签名。

### 6.12.6 泛型方法需要考虑类型参数适配

严格的语言规范还会考虑：

- 方法类型参数；
- 类型参数之间的对应；
- 形式参数类型；
- 类型擦除后的子签名关系。

日常重载判断可以先使用：

```text
名称 + 参数类型列表
```

泛型冲突则必须进一步检查擦除。

## 6.13 方法重载

### 6.13.1 定义

同一个类中，或继承后可见的方法集合中：

```text
方法名相同
参数列表不同
```

称为重载。

```java
void print(int value) {
}

void print(long value) {
}

void print(String value) {
}
```

### 6.13.2 参数列表可以如何不同

可以改变：

- 参数数量；
- 参数类型；
- 参数类型顺序。

```java
void send(String message) {
}

void send(String message, int retryCount) {
}

void send(int retryCount, String message) {
}
```

### 6.13.3 只改变返回类型不构成重载

```java
int query() {
    return 1;
}

// String query() {
//     return "1";
// }
```

### 6.13.4 只改变参数名不构成重载

```java
void save(String username) {
}

// void save(String email) {
// }
```

### 6.13.5 重载是编译期多态

调用哪个重载，主要在编译期根据：

- 方法名；
- 实参数量；
- 实参编译时类型；
- 可用转换；
- 泛型推断；
- 最具体方法；

确定。

它不同于实例方法重写的运行时动态绑定。

## 6.14 重载解析总体流程

编译器大致需要完成：

```text
找到候选方法
↓
检查可访问性
↓
按阶段判断适用方法
↓
选择最具体方法
↓
若唯一确定
→ 调用成功

若没有适用方法
→ 编译错误

若存在多个且无法确定更具体者
→ 调用歧义
```

### 6.14.1 三个主要适用阶段

可简化理解为：

```text
第一阶段
→ 固定参数个数
→ 严格调用
→ 不依赖装箱和可变参数

第二阶段
→ 固定参数个数
→ 允许较宽松的方法调用转换
→ 包括装箱、拆箱等

第三阶段
→ 可变参数调用
```

因此常见记忆：

```text
精确匹配
优先于
基本类型宽化
优先于
装箱
优先于
可变参数
```

这只是常见结果，不是完整规范替代。

### 6.14.2 先看适用阶段，再看“最具体”

不是所有候选方法都放在一起直接比较。

如果第一阶段已经找到适用方法，后续装箱和可变参数阶段通常不会继续参与竞争。

## 6.15 精确匹配

```java
static void print(int value) {
    System.out.println("int");
}

static void print(long value) {
    System.out.println("long");
}

print(10);
```

整数字面量 `10` 默认是 `int`，因此选择：

```text
print(int)
```

### 6.15.1 变量类型决定重载候选

```java
short value = 10;

print(value);
```

如果存在：

```java
print(short)
print(int)
```

会优先选择精确的 `print(short)`。

### 6.15.2 运行时对象类型不决定普通重载

```java
Object value = "Java";

print(value);
```

如果存在：

```java
print(Object)
print(String)
```

编译器根据 `value` 的编译时类型 `Object` 选择 `print(Object)`。

运行时对象是 `String`，不会让普通重载自动改选。

## 6.16 基本类型宽化

### 6.16.1 int 可以宽化为 long

```java
static void print(long value) {
    System.out.println("long");
}

print(10);
```

选择 `print(long)`。

### 6.16.2 宽化路径存在优先距离

```java
static void print(long value) {
    System.out.println("long");
}

static void print(float value) {
    System.out.println("float");
}

print(10);
```

`int` 可以转为 `long` 或 `float`。

通常选择更具体的 `long` 版本。

### 6.16.3 不允许先宽化再装箱到任意包装类型

```java
static void print(Long value) {
}

// print(10); // 编译错误
```

`int` 不能通过：

```text
int
→ long
→ Long
```

作为普通方法调用转换链。

但可以：

```java
print(10L);
```

### 6.16.4 可以拆箱后宽化

```java
static void print(long value) {
}

Integer value = 10;
print(value);
```

可能执行：

```text
Integer
→ 拆箱 int
→ 宽化 long
```

如果 `value == null`，拆箱会抛 `NullPointerException`。

## 6.17 宽化与装箱的优先级

### 6.17.1 宽化优先于装箱

```java
static void print(long value) {
    System.out.println("long");
}

static void print(Integer value) {
    System.out.println("Integer");
}

print(10);
```

通常输出：

```text
long
```

原因：

```text
int → long
属于更早的严格调用阶段

int → Integer
需要装箱
```

### 6.17.2 装箱不一定意味着“更接近”

从业务直觉看，`Integer` 似乎比 `long` 更像 `int`。

但重载解析按语言阶段执行，而不是按人类主观距离。

### 6.17.3 显式变量改变选择

```java
Integer value = 10;
print(value);
```

会选择 `print(Integer)`。

## 6.18 装箱与可变参数的优先级

```java
static void print(Integer value) {
    System.out.println("Integer");
}

static void print(int... values) {
    System.out.println("varargs");
}

print(10);
```

通常选择：

```text
print(Integer)
```

因为固定参数装箱阶段早于可变参数阶段。

### 6.18.1 传入多个参数

```java
print(10, 20);
```

只有可变参数版本适用。

### 6.18.2 传入 int 数组

```java
int[] values = {10, 20};

print(values);
```

可变参数在固定参数形式下本质可接收数组。

## 6.19 最具体方法

### 6.19.1 引用类型示例

```java
static void print(Object value) {
    System.out.println("Object");
}

static void print(CharSequence value) {
    System.out.println("CharSequence");
}

static void print(String value) {
    System.out.println("String");
}

print("Java");
```

选择：

```text
print(String)
```

因为 `String` 版本最具体。

### 6.19.2 接口之间可能无法比较

```java
static void print(Serializable value) {
}

static void print(CharSequence value) {
}

// print("Java"); // 编译歧义
```

`String` 同时实现两个接口，但：

```text
Serializable
与
CharSequence
```

彼此没有子类型关系，编译器无法确定更具体方法。

### 6.19.3 显式转换消除歧义

```java
print((CharSequence) "Java");
```

但更应先检查 API 是否设计过度。

## 6.20 null 与重载歧义

### 6.20.1 null 可以匹配引用类型

```java
static void print(String value) {
}

static void print(Object value) {
}

print(null);
```

选择 `print(String)`，因为 `String` 比 `Object` 更具体。

### 6.20.2 无继承关系时歧义

```java
static void print(String value) {
}

static void print(StringBuilder value) {
}

// print(null); // 编译歧义
```

两者都能接收 `null`，但互不更具体。

### 6.20.3 显式转换

```java
print((String) null);
```

可指定目标重载。

### 6.20.4 API 设计风险

大量同名引用类型重载会让：

- `null` 调用歧义；
- Lambda 目标类型歧义；
- 方法引用歧义；
- 泛型推断复杂；
- 调用者难以预测。

## 6.21 可变参数

### 6.21.1 基本语法

```java
static int sum(int... values) {
    int result = 0;

    for (int value : values) {
        result += value;
    }

    return result;
}
```

调用：

```java
sum();
sum(1);
sum(1, 2, 3);
```

### 6.21.2 本质是数组参数

```java
int... values
```

在方法体内按照：

```java
int[] values
```

使用。

也可以传入数组：

```java
int[] values = {1, 2, 3};

sum(values);
```

### 6.21.3 必须位于最后

合法：

```java
void print(String prefix, Object... values) {
}
```

非法：

```java
// void print(Object... values, String suffix) {
// }
```

### 6.21.4 一个方法最多一个可变参数

```java
// void print(String... names, int... ages) {
// }
```

无法确定参数如何切分。

### 6.21.5 零个参数时得到空数组语义

```java
sum();
```

方法体中的 `values` 通常是长度为 `0` 的数组，而不是自动为 `null`。

## 6.22 可变参数的调用陷阱

### 6.22.1 null 调用

```java
static void print(String... values) {
    System.out.println(values.length);
}

print(null);
```

编译器可能把 `null` 当成整个 `String[]` 参数，并给出警告。

运行时：

```java
values.length
```

可能抛 `NullPointerException`。

### 6.22.2 显式表达调用意图

表示空数组：

```java
print();
```

或者：

```java
print(new String[0]);
```

表示一个值为 `null` 的元素：

```java
print((String) null);
```

表示数组本身为 `null`：

```java
print((String[]) null);
```

最后一种通常不应出现在业务代码。

### 6.22.3 可变参数重载容易歧义

```java
static void print(int... values) {
}

static void print(boolean... values) {
}

// print(); // 编译歧义
```

零参数同时适用于两个版本。

### 6.22.4 数组重载不能与同类型 varargs 并存

以下两个声明本质冲突：

```java
void print(String[] values) {
}

// void print(String... values) {
// }
```

`String...` 在签名层面对应数组类型。

## 6.23 泛型可变参数概览

```java
static <T> List<T> listOf(T... values) {
    return List.of(values);
}
```

泛型可变参数可能涉及：

- 非具体化类型；
- 数组协变；
- 堆污染；
- 编译警告。

### 6.23.1 @SafeVarargs

在满足实现确实安全的前提下，可以使用：

```java
@SafeVarargs
static <T> void printAll(T... values) {
}
```

`@SafeVarargs` 是程序员对编译器和调用者的安全承诺，不是自动修复。

允许位置通常包括：

- `static` 方法；
- `final` 实例方法；
- `private` 实例方法；
- 构造器。

详细规则放在泛型专题。

## 6.24 泛型方法

### 6.24.1 基本语法

```java
public static <T> T first(List<T> values) {
    return values.get(0);
}
```

类型参数声明在返回类型之前：

```text
<T>
```

### 6.24.2 调用时类型推断

```java
String value = first(
        List.of("A", "B")
);
```

编译器推断：

```text
T = String
```

### 6.24.3 显式类型实参

```java
String value =
        Utility.<String>first(values);
```

多数场景不需要显式写出。

### 6.24.4 泛型方法与泛型类独立

```java
public class Utility {

    public static <T> T identity(T value) {
        return value;
    }
}
```

类本身不是泛型类，方法仍然可以是泛型方法。

## 6.25 类型擦除与签名冲突

### 6.25.1 典型冲突

```java
void print(List<String> values) {
}

// void print(List<Integer> values) {
// }
```

两者擦除后都近似为：

```text
print(List)
```

因此不能重载。

### 6.25.2 泛型参数不同不一定能区分方法

```java
<T> void process(T value) {
}

// <R> void process(R value) {
// }
```

类型参数名称不同没有意义。

### 6.25.3 使用不同原始参数结构

可以通过不同参数数量或不同擦除后类型区分：

```java
void print(List<String> values) {
}

void print(Set<Integer> values) {
}
```

擦除后分别是：

```text
List
Set
```

### 6.25.4 不要依赖“泛型看起来不同”

判断能否重载时，需要检查：

```text
擦除后的参数类型
是否仍然不同
```

## 6.26 重载与 Lambda 歧义

### 6.26.1 两个函数式接口重载

```java
static void execute(Runnable task) {
}

static void execute(Callable<Void> task) {
}
```

调用：

```java
execute(() -> null);
```

可能选择 `Callable<Void>`。

但某些 Lambda 形态可能同时兼容多个函数式接口，造成歧义。

### 6.26.2 相同形状的自定义接口

```java
interface TextParser {
    int parse(String value);
}

interface TextLength {
    int apply(String value);
}

static void execute(TextParser parser) {
}

static void execute(TextLength function) {
}

// execute(text -> text.length()); // 歧义
```

两个目标类型具有相同参数和返回形状，但彼此无继承关系。

### 6.26.3 显式类型转换

```java
execute(
        (TextParser) text -> text.length()
);
```

可以消除歧义。

### 6.26.4 API 设计建议

不要大量重载只在函数式接口类型上不同的方法。

这种设计会让：

- Lambda；
- 方法引用；
- `null`；
- 泛型方法；

变得难以调用。

## 6.27 重载与方法引用

```java
static String convert(int value) {
    return Integer.toString(value);
}

static String convert(long value) {
    return Long.toString(value);
}
```

方法引用：

```java
IntFunction<String> first =
        Utility::convert;

LongFunction<String> second =
        Utility::convert;
```

目标函数式接口帮助编译器选择重载。

如果缺少目标类型：

```java
// var converter = Utility::convert; // 编译错误
```

方法引用本身需要目标类型。

## 6.30 方法调用求值顺序

### 6.30.1 接收者先求值

```java
receiver().execute(first(), second());
```

大致顺序：

```text
receiver()
↓
first()
↓
second()
↓
调用 execute
```

### 6.30.2 参数从左到右求值

```java
execute(first(), second(), third());
```

Java 规定实参表达式从左到右求值。

### 6.30.3 某个实参抛异常后，后续实参不执行

```java
execute(first(), fail(), third());
```

如果 `fail()` 抛异常：

- `first()` 已执行；
- `third()` 不执行；
- 方法体不进入。

### 6.30.4 不依赖实参副作用

不推荐：

```java
execute(index++, ++index);
```

即使规则确定，也难以阅读。

```java
public int value(boolean condition) {
```

## 6.32 Java 25 紧凑源文件中的方法

### 6.32.1 可以省略显式类声明

```java
void main() {
    System.out.println(greeting());
}
```

### 6.32.2 这些方法仍然属于隐式声明类

编译器会为紧凑源文件隐式声明一个类。

因此：

```text
源码看起来没有 class
不等于
方法脱离了类模型
```

这些方法仍是隐式声明类的成员。

### 6.32.3 不是全局函数

### 6.32.4 适用场景

适合：

- 入门学习；
- 小型脚本式程序；
- 快速实验；

企业工程仍通常使用：

- 显式类；
- 包；
- 模块；
- 明确访问边界。

## 6.33 递归

递归是方法直接或间接调用自身。

### 6.33.1 阶乘示例

```java
public static long factorial(int value) {
    if (value < 0) {
        throw new IllegalArgumentException(
                "value must be non-negative"
        );
    }

    if (value <= 1) {
        return 1L;
    }

    return value * factorial(value - 1);
}
```

### 6.33.2 递归必须具有基线条件

```text
递归问题
↓
不断缩小规模
↓
到达基线条件
↓
停止继续调用
```

缺少基线条件：

```java
public static void execute() {
    execute();
}
```

最终通常抛出：

```text
StackOverflowError
```

### 6.33.3 每层调用都有独立局部状态

```java
factorial(4)
```

概念过程：

```text
factorial(4)
→ 4 * factorial(3)
→ 4 * 3 * factorial(2)
→ 4 * 3 * 2 * factorial(1)
→ 24
```

每层调用拥有各自参数和局部变量语义。

## 6.34 直接递归与间接递归

### 6.34.1 直接递归

```java
void first() {
    first();
}
```

### 6.34.2 间接递归

```java
void first() {
    second();
}

void second() {
    first();
}
```

间接递归更难排查。

### 6.34.3 数据结构中的合理递归

适合：

- 树遍历；
- 目录遍历；
- 语法树；
- 分治算法；
- 回溯；
- 深度优先搜索。

但应评估：

- 最大深度；
- 输入是否受控；
- 是否可能存在环；
- 是否需要访问标记；
- 是否应改为显式栈。

## 6.35 尾递归与优化边界

### 6.35.1 尾递归形式

```java
static long factorial(
        int value,
        long accumulator
) {
    if (value <= 1) {
        return accumulator;
    }

    return factorial(
            value - 1,
            accumulator * value
    );
}
```

递归调用是当前方法的最后操作。

### 6.35.2 Java 不保证尾调用优化

即使写成尾递归，Java 规范也不保证 JVM 消除栈帧。

深度过大仍可能：

```text
StackOverflowError
```

### 6.35.3 深递归改为循环

```java
static long factorial(int value) {
    long result = 1L;

    for (int current = 2;
         current <= value;
         current++) {

        result *= current;
    }

    return result;
}
```

循环通常更适合深度可能很大的线性递归。

## 6.36 方法异常声明

### 6.36.1 throws 子句

```java
public String read(Path path)
        throws IOException {

    return Files.readString(path);
}
```

`throws` 描述方法可能向调用方传播的受检异常。

### 6.36.2 throws 不属于重载签名

不能只通过不同异常声明重载。

### 6.36.3 非受检异常可以不声明

```java
public int divide(int first, int second) {
    return first / second;
}
```

可能抛 `ArithmeticException`，但不要求写在 `throws` 中。

### 6.36.4 异常声明属于 API 契约

方法设计需要明确：

- 哪些错误由返回值表达；
- 哪些错误抛受检异常；
- 哪些错误属于调用方违反前置条件；
- 异常中是否保留原始原因；
- 是否允许重试。

完整规则见异常处理章节。

## 6.37 方法重载与异常

### 6.37.1 异常不会帮助选择重载

```java
void load(String value)
        throws IOException {
}

void load(Path value)
        throws SQLException {
}
```

选择依据是参数类型，不是异常类型。

### 6.37.2 调用方 catch 不影响重载选择

```java
try {
    load(value);
} catch (IOException exception) {
}
```

编译器不会因为存在 `catch IOException` 就优先选择某个重载。

### 6.37.3 Lambda 的 throws 可能影响目标兼容性

函数式接口方法是否允许抛受检异常，可能影响 Lambda 或方法引用能否兼容。

这属于函数式接口和重载共同作用的复杂场景，应减少同名目标类型重载。

## 6.38 方法默认参数与命名参数

### 6.38.1 Java 不支持普通默认参数语法

不能写：

```java
// void connect(
//         String host,
//         int timeout = 30
// ) {
// }
```

### 6.38.2 使用重载模拟默认值

```java
public void connect(String host) {
    connect(host, 30);
}

public void connect(
        String host,
        int timeoutSeconds
) {
}
```

### 6.38.3 参数很多时不要无限重载

```java
create(name)
create(name, age)
create(name, age, address)
create(name, age, address, enabled)
```

容易形成重载爆炸。

更适合：

- 参数对象；
- Builder；
- 静态工厂；
- 配置对象；
- 明确领域类型。

### 6.38.4 Java 不支持普通命名实参

调用：

```java
connect(
        host = "localhost",
        timeout = 30
);
```

不是 Java 普通方法调用语法。

应通过清晰类型和方法名提高可读性。

## 6.39 重载 API 的兼容性风险

### 6.39.1 添加重载可能造成源码歧义

旧代码：

```java
static void print(Object value) {
}

print(null);
```

后来添加：

```java
static void print(String value) {
}
```

重新编译时可能改选更具体的 `String` 版本。

再添加：

```java
static void print(StringBuilder value) {
}
```

旧调用：

```java
print(null);
```

可能直接变成歧义。

### 6.39.2 已编译字节码与重新编译源码

已编译调用通常记录目标方法描述符。

因此：

```text
旧二进制继续运行
与
旧源码重新编译
```

可能表现不同。

### 6.39.3 重载并非越多越友好

添加重载前要评估：

- `null`；
- Lambda；
- 方法引用；
- 泛型类型推断；
- 基本类型与包装类型；
- 可变参数；
- 源码兼容；
- API 文档复杂度。

### 6.39.4 有时应使用不同方法名

相比：

```java
load(String value)
load(Path value)
load(URL value)
```

可以考虑：

```java
loadText(String value)
loadFile(Path path)
loadRemote(URL url)
```

当语义明显不同，独立名称更清晰。

## 6.40 方法设计原则

### 6.40.1 单一职责

不推荐：

```java
validateAndSaveAndNotify(order);
```

更适合分解：

```java
validate(order);
save(order);
notifyUser(order);
```

是否拆分还要考虑事务边界和领域原子性。

### 6.40.2 参数数量

参数过多常意味着：

- 方法职责过多；
- 缺少参数对象；
- 缺少领域模型；
- 布尔开关过多；
- 调用方容易传错顺序。

### 6.40.3 避免相同类型长参数列表

```java
transfer(
        String source,
        String target,
        String operator,
        String remark
);
```

调用方很容易把顺序写错。

可以引入：

```java
TransferCommand command
```

### 6.40.4 不使用 boolean 表达多种模式

```java
execute(order, true, false);
```

不清晰。

更适合：

```java
execute(
        order,
        ExecutionMode.URGENT,
        RetryPolicy.DISABLED
);
```

### 6.40.5 返回值表达稳定语义

不要用：

```java
int result
```

同时表示：

- `0` 成功；
- `-1` 不存在；
- `-2` 无权限；
- 正数表示数量。

更适合：

- 明确结果对象；
- 枚举；
- 异常；
- `Optional`；
- 专门值类型。

### 6.40.6 副作用明确

方法名应体现：

```text
查询
还是
修改
```

例如：

```java
findUser()
activateUser()
calculateTotal()
sendMessage()
```

## 6.43 易错点

### 误区一：方法就是独立于类型的全局函数

**错误。**

普通 Java 方法属于类、接口、枚举、记录类或隐式声明类。

### 误区二：Java 25 紧凑源文件引入了真正全局函数

**错误。**

其中的方法仍属于编译器隐式声明的类。

### 误区三：void 方法返回 null

**错误。**

`void` 表示方法调用不产生返回值。

### 误区四：void 方法不能写 return

**错误。**

可以使用不带值的 `return;` 提前结束。

### 误区五：非 void 方法只要有一个 return 就能编译

**错误。**

所有可能正常完成的路径都必须返回值。

### 误区六：参数名不同就能形成重载

**错误。**

参数名不属于重载区分条件。

### 误区七：返回类型不同就能形成重载

**错误。**

返回类型不能单独区分重载。

### 误区八：throws 异常不同就能形成重载

**错误。**

`throws` 子句不属于方法签名。

### 误区九：一个 static 方法和一个实例方法即使参数相同也能并存

**错误。**

`static` 不属于签名区分条件。

### 误区十：重载根据运行时对象类型选择

**错误。**

普通重载主要根据编译时类型解析。

### 误区十一：装箱永远比基本类型宽化更优先

**错误。**

基本类型宽化通常位于更早的适用阶段。

### 误区十二：可变参数比装箱优先

**错误。**

可变参数通常是最后考虑的阶段。

### 误区十三：int 可以先宽化成 long 再自动装箱成 Long

**错误。**

普通方法调用转换不支持任意组合链。

### 误区十四：null 会自动选择任意一个引用重载

**错误。**

如果多个候选互不更具体，会产生编译歧义。

### 误区十五：可变参数不是数组

**错误。**

在方法体内可变参数按数组使用。

### 误区十六：可变参数可以出现在参数列表任意位置

**错误。**

它必须位于最后。

### 误区十七：一个方法可以有多个可变参数

**错误。**

参数边界无法确定，因此不允许。

### 误区十八：零参数调用可变参数方法时，参数数组一定是 null

**错误。**

正常零参数调用对应空数组语义。

### 误区十九：print(null) 一定表示传入一个 null 元素

**错误。**

对可变参数方法，它可能被解释为传入 `null` 数组。

### 误区二十：String[] 与 String... 可以构成重载

**错误。**

两者在方法签名层面冲突。

### 误区二十一：泛型参数不同就一定能形成重载

**错误。**

需要检查类型擦除后的签名。

### 误区二十二：List<String> 和 List<Integer> 是两个不同的运行时参数签名

**错误。**

擦除后都对应 `List`。

### 误区二十三：@SafeVarargs 会自动让实现安全

**错误。**

它只是程序员对堆污染风险的承诺。

### 误区二十四：Lambda 自身包含唯一完整类型

**错误。**

Lambda 需要目标函数式接口类型。

### 误区二十五：var 可以直接保存没有目标类型的方法引用

**错误。**

方法引用需要目标类型帮助选择方法和签名。

### 误区二十六：静态方法中存在隐式 this

**错误。**

静态方法没有当前对象接收者。

### 误区二十七：静态方法可以被实例方法正常重写

**错误。**

同名静态方法属于隐藏，不参与实例动态绑定。

### 误区二十八：Java 方法实参求值顺序未定义

**错误。**

Java 规定从左到右求值。

### 误区二十九：引用参数是按引用传递

**错误。**

传递的是引用值的副本，仍然是值传递。

### 误区三十：给参数重新赋值会改变调用方变量

**错误。**

只改变当前方法内参数变量。

### 误区三十一：递归一定比循环更优雅

**错误。**

需要考虑深度、栈空间、可读性和输入规模。

### 误区三十二：尾递归在 Java 中一定不会增长栈

**错误。**

Java 不保证尾调用优化。

### 误区三十三：throws 声明越多，API 越安全

**错误。**

异常契约应准确表达可恢复错误，而不是机械扩大声明。

### 误区三十四：Java 支持默认参数

**错误。**

通常使用重载、参数对象或 Builder 模拟。

### 误区三十五：重载越多，API 越易用

**错误。**

过多重载会造成歧义、推断复杂和兼容性问题。

### 误区三十六：添加重载只会增加能力，不会影响旧代码

**错误。**

旧源码重新编译时可能改选目标或产生歧义。

### 误区三十七：方法参数越少越好，因此应该把所有数据放进 Map

**错误。**

应使用具有明确类型和约束的参数对象，而不是失去类型安全。

### 误区三十八：一个方法只能有一个 return

**错误。**

多个清晰的卫语句返回通常是可接受的。

### 误区三十九：方法越短越好

**不准确。**

方法应围绕一个清晰职责，不能仅按行数机械拆分。

### 误区四十：方法名不重要，只要注释清楚即可

**错误。**

调用方首先看到的是方法名和签名，名称是 API 契约的重要部分。

## 6.44 工程实践建议

1. 方法名使用清晰动词或业务谓词，避免模糊的 `handle()`、`process()` 和 `doIt()`。
2. 一个方法围绕一个可解释职责组织，不按固定行数机械拆分。
3. 查询方法与修改状态的方法尽量分离。
4. 返回值、异常和副作用在方法契约中明确说明。
5. 非 `void` 方法确保所有正常路径都产生结果。
6. 不在 `finally` 中使用 `return`。
7. 参数靠近其使用语义设计，不传递无类型 `Map<String, Object>` 代替稳定模型。
8. 避免多个相同类型参数连续排列，必要时引入参数对象和值对象。
9. 不使用多个布尔参数控制方法模式。
10. 参数超过合理数量时，检查是否职责过多或缺少领域对象。
11. 不通过强制转换消除重载歧义，而不检查 API 设计。
12. 避免同时提供大量基本类型、包装类型和可变参数重载。
13. 对 `null` 具有不同语义时，不依赖重载自动选择。
14. 函数式接口参数尽量使用不同方法名，减少 Lambda 歧义。
15. 可变参数适合少量便捷参数，不适合大规模数据传输。
16. 可变参数方法内部不要假设调用方永远不会传入 `null` 数组。
17. 泛型可变参数谨慎使用，只有真正安全时才添加 `@SafeVarargs`。
18. 添加公共重载前进行源码兼容性检查。
19. 语义明显不同的操作使用不同方法名，而不是强行重载。
20. 静态方法通过类名调用，实例行为通过对象调用。
21. 方法调用实参不要混入多个自增、赋值和其他副作用。
22. 深递归前评估最大深度、环和栈空间。
23. 线性深递归优先考虑循环。
24. 树和图递归需要显式考虑环检测和深度限制。
25. Java 25 紧凑源文件用于学习和小程序，不替代大型工程类型边界。
26. 默认参数需求较少时可使用委托重载，参数组合多时使用 Builder 或参数对象。
27. 返回内部可变对象时考虑封装泄漏。
28. 方法异常声明保持准确，不把所有异常统一包装成无语义运行时异常。
29. 为重载、边界值、`null`、可变参数和异常路径编写测试。
30. API 文档说明单位、范围、空值、线程安全和副作用。

```text

```

### 6.46.5 递归

```text

```

### 6.46.6 面试口述版

Java 方法签名在普通重载分析中主要由方法名和参数类型列表组成，返回类型、参数名、访问修饰符、`static` 和 `throws` 不能单独区分重载。重载在编译期解析，主要依据实参的编译时类型，而不是运行时对象类型。

重载解析通常先考虑固定参数的严格调用，再考虑允许装箱、拆箱等转换的固定参数调用，最后考虑可变参数。因此基本类型宽化通常优先于装箱，装箱通常优先于可变参数。如果多个候选方法都适用但不存在唯一最具体方法，就会产生编译歧义，`null`、Lambda、方法引用和泛型尤其容易触发这种问题。

可变参数本质上是数组参数，必须位于参数列表最后。Java 参数传递始终是值传递：基本类型复制基本值，引用类型复制引用值。递归必须具有基线条件，并评估最大深度，因为 Java 不保证尾递归优化。Java 25 紧凑源文件虽然允许省略显式类声明并直接书写方法，但这些方法仍属于编译器隐式声明的类，不是真正的全局函数。
