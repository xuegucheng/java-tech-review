# 第7章：抽象类

## 7.1 本章定位

上一章讨论了继承、重写和多态，但普通父类并不一定适合直接创建对象，也不一定能完整描述所有子类的共同能力。
例如，不同支付方式都可以执行支付：
1 支付宝支付
2 微信支付
3 银行卡支付
4
它们具有共同的行为契约：
1 pay()
2
但不存在一个有明确业务意义的“普通支付对象”。
此时可以使用抽象类或接口表达抽象能力。
本章主要解决以下问题：

## 7.2 抽象的含义

抽象是：
从多个具体事物中提取共同特征，隐藏不必要的实现细节，只保留当前关注的核心能力。
例如，仓储系统中可能存在：
1 人工拣货
2 自动化设备拣货
3 机器人拣货
4
从具体实现来看，它们差异很大，但都可以抽象出：
1 pick()
2
调用方通常不需要知道：
使用人工还是机器人
设备如何通信
如何规划路径
如何处理具体硬件协议
调用方只关注：
1 能够执行拣货任务
2
抽象的价值是：
隐藏具体实现
提供统一调用方式
降低调用方与实现方的耦合
支持多态替换
便于扩展新实现

## 7.3 抽象类

使用 abstract 修饰的类称为抽象类：
1 public abstract class Animal {
2 }
3
抽象类可以包含：
实例字段
静态字段
构造方法
普通实例方法
抽象方法

静态方法
final 方法
代码块
内部类
抽象类并不是“只能定义抽象方法的类”。
它仍然可以拥有完整状态和实现。
### 7.3.1 抽象类不能直接实例化
1 Animal animal = new Animal();
2
如果 Animal 是抽象类，上述代码编译失败。
原因是：
抽象类代表不完整或概念性的类型，可能包含尚未实现的抽象行为，因此不能直接创建具体实例。
但是抽象类仍然可以作为引用类型：
1 Animal animal = new Dog();
2
这里：
编译时类型是 Animal
运行时对象是 Dog
抽象类仍然可以参与多态。
### 7.3.2 抽象类可以没有抽象方法
下面是合法的：
1 public abstract class BaseService {
2
3 public void execute() {
4 System.out.println("execute");
5 }
6 }
7
即使没有抽象方法，类仍然可以声明为抽象类。
常见目的：
不希望外部直接创建父类对象
只允许通过子类使用
表示该类型在概念上不完整
为子类提供公共实现
控制继承体系入口
因此：
有抽象方法的类一定是抽象类，但抽象类不一定有抽象方法。

## 7.4 抽象方法

抽象方法只声明方法契约，不提供方法体：

1 public abstract void execute();
2
完整示例：
1 public abstract class Animal {
2
3 public abstract void speak();
4 }
5
子类需要实现：
1 public class Dog extends Animal {
2
3 @Override
4 public void speak() {
5 System.out.println("Dog bark");
6 }
7 }
8
### 7.4.1 抽象方法没有方法体
正确：
1 public abstract void execute();
2
错误：
1 public abstract void execute() {
2 }
3
抽象方法声明以分号结束。
### 7.4.2 包含抽象方法的类必须是抽象类
错误：
1 public class Animal {
2
3 public abstract void speak();
4 }
5
正确：

1 public abstract class Animal {
2
3 public abstract void speak();
4 }
5
因为普通类必须是完整、可实例化的类型，不能保留未实现的方法。
### 7.4.3 普通子类必须实现全部抽象方法
父类：
1 public abstract class Animal {
2
3 public abstract void speak();
4
5 public abstract void move();
6 }
7
普通子类：
1 public class Dog extends Animal {
2
3 @Override
4 public void speak() {
5 System.out.println("Dog bark");
6 }
7
8 @Override
9 public void move() {
10 System.out.println("Dog run");
11 }
12 }
13
如果 Dog 未实现全部抽象方法：
1 public class Dog extends Animal {
2
3 @Override
4 public void speak() {
5 }
6 }
7
会编译失败。
除非 Dog 自己也声明为抽象类：
1 public abstract class Dog extends Animal {
2
3 @Override
4 public void speak() {

5 }
6 }
7
此时未完成的抽象行为继续交给更具体的子类实现。
### 7.4.4 抽象方法不能使用 private
错误：
1 private abstract void execute();
2
原因：
抽象方法要求子类重写
private 方法对子类不可见
子类无法实现不可见的方法
这两个语义互相矛盾。
### 7.4.5 抽象方法不能使用 final
错误：
1 public abstract final void execute();
2
原因：
abstract 要求子类重写
final 禁止子类重写
二者语义冲突。
### 7.4.6 抽象方法不能使用 static
普通抽象方法依赖实例多态：
1 animal.speak();
2
而静态方法属于类，不参与实例方法的动态绑定。
因此不能声明：
1 public abstract static void execute();
2
接口可以定义静态方法，但接口静态方法同样不是抽象实例方法。

## 7.5 抽象类的字段

抽象类可以拥有实例字段：
1 public abstract class Animal {

2
3 private final String name;
4
5 protected Animal(String name) {
6 this.name = name;
7 }
8
9 public String getName() {
10 return name;
11 }
12 }
13
子类对象中包含父类定义的状态：
1 public class Dog extends Animal {
2
3 public Dog(String name) {
4 super(name);
5 }
6 }
7
创建：
1 Dog dog = new Dog("旺财");
2
对象结构可以抽象为：
1 Dog 对象
2 ├── Animal 部分
3 │ └── name = "旺财"
4 └── Dog 部分
5
因此抽象类适合表示：
多个子类共享状态、公共实现和统一生命周期的父类型。

## 7.6 抽象类的构造方法

抽象类不能直接实例化，但可以有构造方法：
1 public abstract class Animal {
2
3 private final String name;
4
5 protected Animal(String name) {
6 this.name = name;
7 }
8 }
9
子类创建时调用：

1 public class Dog extends Animal {
2
3 public Dog(String name) {
4 super(name);
5 }
6 }
7
### 7.6.1 抽象类构造方法的作用
抽象类构造方法用于：
初始化父类公共字段
校验父类状态
建立父类不变量
为所有子类提供统一初始化逻辑
虽然不能执行：
1 new Animal()
2
但创建子类对象时，仍然必须先完成 Animal 部分的初始化。
### 7.6.2 构造方法可见性
抽象类构造方法通常使用：
1 protected
2
例如：
1 protected Animal(String name) {
2 }
3
表示只允许：
当前类
同包代码
子类
调用。
如果使用 private ：
1 private Animal() {
2 }
3
普通外部子类将无法调用该构造方法。
这会限制继承，有时用于：
只允许内部嵌套类继承
构建封闭继承体系

配合静态工厂控制实例创建
但常规抽象父类一般不使用 private 构造方法。

## 7.7 抽象类中的普通方法

抽象类可以同时包含抽象方法与已实现方法：
1 public abstract class ImportTask {
2
3 public final void execute() {
4 validate();
5 List<String> rows = read();
6 process(rows);
7 finish();
8 }
9
10 protected void validate() {
11 System.out.println("公共校验");
12 }
13
14 protected abstract List<String> read();
15
16 protected abstract void process(List<String> rows);
17
18 protected void finish() {
19 System.out.println("公共收尾");
20 }
21 }
22
子类只实现变化部分：
1 public class CsvImportTask extends ImportTask {
2
3 @Override
4 protected List<String> read() {
5 return List.of("A", "B");
6 }
7
8 @Override
9 protected void process(List<String> rows) {
10 System.out.println("处理 CSV");
11 }
12 }
13
这种设计体现：
1 父类固定流程骨架
2 +
3 子类实现差异步骤
4
通常称为模板方法思想。

### 7.7.1 抽象类的适合场景
抽象类适合：
多个子类有共同字段
多个子类共享大量实现
需要统一构造过程
需要 protected 扩展点
需要固定算法流程
子类之间存在稳定的类型关系
需要限制某些方法不能被重写
