# 抽象类

## 13.1 本章定位

上一章讨论了继承、重写和多态，但普通父类并不一定适合直接创建对象，也不一定能完整描述所有子类的共同能力。
例如，不同支付方式都可以执行支付：

```
支付宝支付
微信支付
银行卡支付
```

它们具有共同的行为契约：

```
pay()
```

但不存在一个有明确业务意义的“普通支付对象”。
此时可以使用抽象类或接口表达抽象能力。

本章主要解决以下问题：

- 什么是抽象类？
- 抽象方法与普通方法有什么区别？
- 抽象类能否有构造方法和实例字段？
- 抽象类为什么不能直接实例化？
- 抽象类的适用场景是什么？
- 模板方法思想是什么？

本章核心主线：

```
抽象类表达不完整的类型
↓
抽象方法声明能力，延迟到子类实现
↓
构造方法和实例字段为子类提供共享基础
↓
模板方法固定流程骨架，子类填充细节
```

本章暂不深入：
static 与类初始化：见 16-static与类初始化。
final 与常量设计：见 17-final与常量设计。
接口设计：见 14-接口设计。
抽象类与接口的比较与选择：见 15-组合与设计原则。
Lambda 与函数式接口：放在高级语言特性笔记。
Spring 依赖注入：放在 Spring 模块。

## 13.2 抽象的含义

抽象是：
从多个具体事物中提取共同特征，隐藏不必要的实现细节，只保留当前关注的核心能力。
例如，仓储系统中可能存在：

```
人工拣货
自动化设备拣货
机器人拣货
```

从具体实现来看，它们差异很大，但都可以抽象出：

```
pick()
```

调用方通常不需要知道：

- 使用人工还是机器人
- 设备如何通信
- 如何规划路径
- 如何处理具体硬件协议
- 调用方只关注：

```
能够执行拣货任务
```

抽象的价值是：

- 隐藏具体实现
- 提供统一调用方式
- 降低调用方与实现方的耦合
- 支持多态替换
- 便于扩展新实现

## 13.3 抽象类

使用 abstract 修饰的类称为抽象类：

```java
public abstract class Animal {
}
```

抽象类可以包含：

- 实例字段
- 静态字段
- 构造方法
- 普通实例方法
- 抽象方法
- 静态方法
- final 方法
- 代码块
- 内部类

抽象类并不是“只能定义抽象方法的类”。
它仍然可以拥有完整状态和实现。

**13.3.1 抽象类不能直接实例化**

```
Animal animal = new Animal();
```

如果 Animal 是抽象类，上述代码编译失败。
原因是：
抽象类代表不完整或概念性的类型，可能包含尚未实现的抽象行为，因此不能直接创建具体实例。
但是抽象类仍然可以作为引用类型：

```
Animal animal = new Dog();
```

这里：

- 编译时类型是 Animal
- 运行时对象是 Dog

抽象类仍然可以参与多态。

**13.3.2 抽象类可以没有抽象方法**

下面是合法的：

```java
public abstract class BaseService {
    public void execute() {
        System.out.println("execute");
    }
}
```

即使没有抽象方法，类仍然可以声明为抽象类。

常见目的：

- 不希望外部直接创建父类对象
- 只允许通过子类使用
- 表示该类型在概念上不完整
- 为子类提供公共实现
- 控制继承体系入口
- 因此：

有抽象方法的类一定是抽象类，但抽象类不一定有抽象方法。

## 13.4 抽象方法

抽象方法只声明方法契约，不提供方法体：

```java
public abstract void execute();
```

完整示例：

```java
public abstract class Animal {
    public abstract void speak();
}
```

子类需要实现：

```java
public class Dog extends Animal {
    @Override
    public void speak() {
        System.out.println("Dog bark");
    }
}
```

**13.4.1 抽象方法没有方法体**

正确：

```java
public abstract void execute();
```

错误：

```java
public abstract void execute() {
}
```

抽象方法声明以分号结束。

**13.4.2 包含抽象方法的类必须是抽象类**

错误：

```java
public class Animal {
    public abstract void speak();
}
```

正确：

```java
public abstract class Animal {
    public abstract void speak();
}
```

因为普通类必须是完整、可实例化的类型，不能保留未实现的方法。

**13.4.3 普通子类必须实现全部抽象方法**

父类：

```java
public abstract class Animal {
    public abstract void speak();
    public abstract void move();
}
```

普通子类：

```java
public class Dog extends Animal {
    @Override
    public void speak() {
        System.out.println("Dog bark");
    }
    @Override
    public void move() {
        System.out.println("Dog run");
    }
}
```

如果 Dog 未实现全部抽象方法：

```java
public class Dog extends Animal {
    @Override
    public void speak() {
    }
}
```

会编译失败。
除非 Dog 自己也声明为抽象类：

```java
public abstract class Dog extends Animal {
    @Override
    public void speak() {
    }
}
```

此时未完成的抽象行为继续交给更具体的子类实现。

**13.4.4 抽象方法不能使用 private**

错误：

```java
private abstract void execute();
```

原因：

- 抽象方法要求子类重写
- private 方法对子类不可见
- 子类无法实现不可见的方法

这两个语义互相矛盾。

**13.4.5 抽象方法不能使用 final**

错误：

```java
public abstract final void execute();
```

原因：

- abstract 要求子类重写
- final 禁止子类重写

二者语义冲突。

**13.4.6 抽象方法不能使用 static**

普通抽象方法依赖实例多态：

```
animal.speak();
```

而静态方法属于类，不参与实例方法的动态绑定。
因此不能声明：

```java
public abstract static void execute();
```

接口可以定义静态方法，但接口静态方法同样不是抽象实例方法。

## 13.5 抽象类的字段

抽象类可以拥有实例字段：

```java
public abstract class Animal {
    private final String name;
    protected Animal(String name) {
        this.name = name;
    }
    public String getName() {
        return name;
    }
}
```

子类对象中包含父类定义的状态：

```java
public class Dog extends Animal {
    public Dog(String name) {
        super(name);
    }
}
```

创建：

```
Dog dog = new Dog("旺财");
```

对象结构可以抽象为：

```bash
Dog 对象
├── Animal 部分
│ └── name = "旺财"
└── Dog 部分
```

因此抽象类适合表示：
多个子类共享状态、公共实现和统一生命周期的父类型。

## 13.6 抽象类的构造方法

抽象类不能直接实例化，但可以有构造方法：

```java
public abstract class Animal {
    private final String name;
    protected Animal(String name) {
        this.name = name;
    }
}
```

子类创建时调用：

```java
public class Dog extends Animal {
    public Dog(String name) {
        super(name);
    }
}
```

**13.6.1 抽象类构造方法的作用**

抽象类构造方法用于：

- 初始化父类公共字段
- 校验父类状态
- 建立父类不变量
- 为所有子类提供统一初始化逻辑
- 虽然不能执行：

```
new Animal()
```

但创建子类对象时，仍然必须先完成 Animal 部分的初始化。

**13.6.2 构造方法可见性**

抽象类构造方法通常使用：

```
protected
```

例如：

```java
protected Animal(String name) {
}
```

表示只允许：

- 当前类
- 同包代码
- 子类

调用。
如果使用 private ：

```java
private Animal() {
}
```

普通外部子类将无法调用该构造方法。

这会限制继承，有时用于：

- 只允许内部嵌套类继承
- 构建封闭继承体系
- 配合静态工厂控制实例创建

但常规抽象父类一般不使用 private 构造方法。

## 13.7 抽象类中的普通方法

抽象类可以同时包含抽象方法与已实现方法：

```java
public abstract class ImportTask {
    public final void execute() {
        validate();
        List<String> rows = read();
        process(rows);
        finish();
    }
    protected void validate() {
        System.out.println("公共校验");
    }
    protected abstract List<String> read();
    protected abstract void process(List<String> rows);
    protected void finish() {
        System.out.println("公共收尾");
    }
}
```

子类只实现变化部分：

```java
public class CsvImportTask extends ImportTask {
    @Override
    protected List<String> read() {
        return List.of("A", "B");
    }
    @Override
    protected void process(List<String> rows) {
        System.out.println("处理 CSV");
    }
}
```

这种设计体现：

```
父类固定流程骨架
+
子类实现差异步骤
```

通常称为模板方法思想。

**13.7.1 抽象类的适合场景**

抽象类适合：

- 多个子类有共同字段
- 多个子类共享大量实现
- 需要统一构造过程
- 需要 protected 扩展点
- 需要固定算法流程
- 子类之间存在稳定的类型关系
- 需要限制某些方法不能被重写

## 13.8 建议实验

实验一：抽象类不能直接实例化

```java
public abstract class Animal {
}

public class Demo {
    public static void main(String[] args) {
        // Animal animal = new Animal(); // 编译错误
        Animal animal = new Dog();
    }
}
```

观察直接创建抽象类对象的编译错误，理解抽象类只能作为引用类型。

实验二：抽象方法必须被子类实现

```java
public abstract class Animal {
    public abstract void speak();
    public abstract void move();
}

public class Dog extends Animal {
    @Override
    public void speak() { System.out.println("Dog bark"); }
    @Override
    public void move() { System.out.println("Dog run"); }
}
```

尝试只实现其中一个方法，观察编译错误；再把 `Dog` 改为 `abstract`，理解抽象方法的传递。

实验三：抽象类的构造方法

```java
public abstract class Animal {
    private final String name;
    protected Animal(String name) {
        this.name = name;
    }
    public String getName() { return name; }
}

public class Dog extends Animal {
    public Dog(String name) { super(name); }
    public static void main(String[] args) {
        Dog dog = new Dog("旺财");
        System.out.println(dog.getName());
    }
}
```

验证抽象类构造方法通过 `super` 在子类创建时被调用。

实验四：模板方法思想

```java
public abstract class ImportTask {
    public final void execute() {
        validate();
        process();
        finish();
    }
    protected void validate() { System.out.println("公共校验"); }
    protected abstract void process();
    protected void finish() { System.out.println("公共收尾"); }
}

public class CsvImportTask extends ImportTask {
    @Override
    protected void process() { System.out.println("处理 CSV"); }
    public static void main(String[] args) {
        new CsvImportTask().execute();
    }
}
```

观察流程骨架由父类固定，子类只填充差异步骤。

实验五：抽象方法的非法修饰符

```java
// private abstract void execute();      // 编译错误
// public abstract final void execute(); // 编译错误
// public abstract static void execute(); // 编译错误
```

尝试上述声明，观察编译器如何拒绝互相矛盾的修饰符组合。

## 13.10 易错点

**误区一：抽象类只能定义抽象方法**

**错误。**

抽象类可以同时包含实例字段、静态字段、构造方法、普通实例方法、抽象方法、静态方法、`final` 方法和代码块。它不是"只能定义抽象方法的类"。

**误区二：抽象类一定有抽象方法**

**错误。**

抽象类可以没有任何抽象方法，仅仅是为了阻止外部直接实例化、表示概念上不完整或为子类提供公共实现。

**误区三：抽象类不能有构造方法**

**错误。**

抽象类不能直接实例化，但仍然可以有构造方法，用于在子类对象创建时初始化父类公共字段和建立不变量。

**误区四：private 方法可以声明为 abstract**

**错误。**

`abstract` 要求子类重写，而 `private` 对子类不可见，两者语义矛盾，不能组合使用。`final` 和 `static` 同理冲突。

**误区五：子类不实现抽象方法也能编译通过**

**错误。**

普通子类必须实现父类的全部抽象方法，否则编译失败。只有把子类自己也声明为 `abstract`，未实现的抽象行为才能继续向下传递。

**误区六：抽象类的构造方法可以直接被外部调用**

**错误。**

抽象类构造方法只能通过子类构造方法的 `super(...)` 间接调用，不能直接执行 `new AbstractClass()`。

## 13.11 本章总结

```
抽象类表达不完整或概念性的类型
↓
抽象方法声明能力，延迟到子类实现
↓
有抽象方法的类必须是抽象类，但抽象类不一定有抽象方法
↓
抽象类不能直接实例化，但可以拥有构造方法和实例字段
↓
构造方法为子类提供统一初始化逻辑
↓
模板方法：父类固定流程骨架，子类填充差异步骤
```

面试口述版：

- 抽象类用于表达不完整或概念性的类型，可以包含实例字段、构造方法、普通方法和抽象方法。有抽象方法的类必须是抽象类，但抽象类不一定有抽象方法。抽象类不能直接实例化，但可以作为引用类型参与多态，且仍可拥有构造方法，用于在子类创建时初始化公共字段和建立不变量，通常使用 `protected` 可见性。普通子类必须实现父类的全部抽象方法，除非自身也声明为抽象类。抽象方法不能与 `private`、`final`、`static` 组合，因为语义互相矛盾。模板方法思想是父类用 `final` 方法固定流程骨架，将差异步骤声明为抽象方法由子类实现。抽象类适合多个子类共享字段、统一构造过程和固定算法流程的场景，与接口的比较与选择见 15-组合与设计原则。
