# 抽象类

## 7.1 本章定位

上一章讨论了继承、重写和多态，但普通父类并不一定适合直接创建对象，也不一定能完整描述所有子类的共同能力。
例如，不同支付方式都可以执行支付：

```
支付宝支付
微信支付
银行卡支付
```

它们具有共同的行为契约：

```
pay()
```

但不存在一个有明确业务意义的“普通支付对象”。
此时可以使用抽象类或接口表达抽象能力。

本章主要解决以下问题：

- 什么是抽象类？
- 抽象方法与普通方法有什么区别？
- 抽象类能否有构造方法和实例字段？
- 抽象类为什么不能直接实例化？
- 什么是接口？
- 接口能否定义字段、普通方法和静态方法？
- 接口中的字段为什么默认是常量？
- 接口默认方法解决了什么问题？
- 一个类为什么可以实现多个接口？
- 接口多继承如何处理方法冲突？
- 抽象类和接口应该如何选择？
- 继承、接口实现和组合有什么区别？
- 为什么工程设计通常强调面向接口编程？
- 什么是依赖倒置和接口隔离？
- 组合为什么通常比深层继承更灵活？

本章核心主线：

```
共同能力或契约
↓
抽象类或接口
↓
具体类提供实现
↓
调用方依赖抽象类型
↓
运行时替换具体实现
↓
组合多个独立能力
↓
降低耦合并提高扩展性
```

本章暂不深入：
static 、 final 的完整语义：放在下一章。
L bd 与函数式接口 放在高级语言特性笔记
Lambda 与函数式接口：放在高级语言特性笔记。
Spring 依赖注入：放在 Spring 模块。
设计模式的完整实现：放在系统设计或设计模式模块。
JVM 接口调用指令：放在 JVM 模块。

## 7.2 抽象的含义

抽象是：
从多个具体事物中提取共同特征，隐藏不必要的实现细节，只保留当前关注的核心能力。
例如，仓储系统中可能存在：

```
人工拣货
自动化设备拣货
机器人拣货
```

从具体实现来看，它们差异很大，但都可以抽象出：

```
pick()
```

调用方通常不需要知道：

- 使用人工还是机器人
- 设备如何通信
- 如何规划路径
- 如何处理具体硬件协议
- 调用方只关注：

```
能够执行拣货任务
```

抽象的价值是：

- 隐藏具体实现
- 提供统一调用方式
- 降低调用方与实现方的耦合
- 支持多态替换
- 便于扩展新实现

## 7.3 抽象类

使用 abstract 修饰的类称为抽象类：

```java
public abstract class Animal {
}
```

抽象类可以包含：

- 实例字段
- 静态字段
- 构造方法
- 普通实例方法
- 抽象方法
- 静态方法
- final 方法
- 代码块
- 内部类

抽象类并不是“只能定义抽象方法的类”。
它仍然可以拥有完整状态和实现。

**7.3.1 抽象类不能直接实例化**

```
Animal animal = new Animal();
```

如果 Animal 是抽象类，上述代码编译失败。
原因是：
抽象类代表不完整或概念性的类型，可能包含尚未实现的抽象行为，因此不能直接创建具体实例。
但是抽象类仍然可以作为引用类型：

```
Animal animal = new Dog();
```

这里：

- 编译时类型是 Animal
- 运行时对象是 Dog

抽象类仍然可以参与多态。

**7.3.2 抽象类可以没有抽象方法**

下面是合法的：

```java
public abstract class BaseService {
    public void execute() {
        System.out.println("execute");
    }
}
```

即使没有抽象方法，类仍然可以声明为抽象类。

常见目的：

- 不希望外部直接创建父类对象
- 只允许通过子类使用
- 表示该类型在概念上不完整
- 为子类提供公共实现
- 控制继承体系入口
- 因此：

有抽象方法的类一定是抽象类，但抽象类不一定有抽象方法。

## 7.4 抽象方法

抽象方法只声明方法契约，不提供方法体：

```java
public abstract void execute();
```

完整示例：

```java
public abstract class Animal {
    public abstract void speak();
}
```

子类需要实现：

```java
public class Dog extends Animal {
    @Override
    public void speak() {
        System.out.println("Dog bark");
    }
}
```

**7.4.1 抽象方法没有方法体**

正确：

```java
public abstract void execute();
```

错误：

```java
public abstract void execute() {
}
```

抽象方法声明以分号结束。

**7.4.2 包含抽象方法的类必须是抽象类**

错误：

```java
public class Animal {
    public abstract void speak();
}
```

正确：

```java
public abstract class Animal {
    public abstract void speak();
}
```

因为普通类必须是完整、可实例化的类型，不能保留未实现的方法。

**7.4.3 普通子类必须实现全部抽象方法**

父类：

```java
public abstract class Animal {
    public abstract void speak();
    public abstract void move();
}
```

普通子类：

```java
public class Dog extends Animal {
    @Override
    public void speak() {
        System.out.println("Dog bark");
    }
    @Override
    public void move() {
        System.out.println("Dog run");
    }
}
```

如果 Dog 未实现全部抽象方法：

```java
public class Dog extends Animal {
    @Override
    public void speak() {
    }
}
```

会编译失败。
除非 Dog 自己也声明为抽象类：

```java
public abstract class Dog extends Animal {
    @Override
    public void speak() {
    }
}
```

此时未完成的抽象行为继续交给更具体的子类实现。

**7.4.4 抽象方法不能使用 private**

错误：

```java
private abstract void execute();
```

原因：

- 抽象方法要求子类重写
- private 方法对子类不可见
- 子类无法实现不可见的方法

这两个语义互相矛盾。

**7.4.5 抽象方法不能使用 final**

错误：

```java
public abstract final void execute();
```

原因：

- abstract 要求子类重写
- final 禁止子类重写

二者语义冲突。

**7.4.6 抽象方法不能使用 static**

普通抽象方法依赖实例多态：

```
animal.speak();
```

而静态方法属于类，不参与实例方法的动态绑定。
因此不能声明：

```java
public abstract static void execute();
```

接口可以定义静态方法，但接口静态方法同样不是抽象实例方法。

## 7.5 抽象类的字段

抽象类可以拥有实例字段：

```java
public abstract class Animal {
    private final String name;
    protected Animal(String name) {
        this.name = name;
    }
    public String getName() {
        return name;
    }
}
```

子类对象中包含父类定义的状态：

```java
public class Dog extends Animal {
    public Dog(String name) {
        super(name);
    }
}
```

创建：

```
Dog dog = new Dog("旺财");
```

对象结构可以抽象为：

```bash
Dog 对象
├── Animal 部分
│ └── name = "旺财"
└── Dog 部分
```

因此抽象类适合表示：
多个子类共享状态、公共实现和统一生命周期的父类型。

## 7.6 抽象类的构造方法

抽象类不能直接实例化，但可以有构造方法：

```java
public abstract class Animal {
    private final String name;
    protected Animal(String name) {
        this.name = name;
    }
}
```

子类创建时调用：

```java
public class Dog extends Animal {
    public Dog(String name) {
        super(name);
    }
}
```

**7.6.1 抽象类构造方法的作用**

抽象类构造方法用于：

- 初始化父类公共字段
- 校验父类状态
- 建立父类不变量
- 为所有子类提供统一初始化逻辑
- 虽然不能执行：

```
new Animal()
```

但创建子类对象时，仍然必须先完成 Animal 部分的初始化。

**7.6.2 构造方法可见性**

抽象类构造方法通常使用：

```
protected
```

例如：

```java
protected Animal(String name) {
}
```

表示只允许：

- 当前类
- 同包代码
- 子类

调用。
如果使用 private ：

```java
private Animal() {
}
```

普通外部子类将无法调用该构造方法。

这会限制继承，有时用于：

- 只允许内部嵌套类继承
- 构建封闭继承体系
- 配合静态工厂控制实例创建

但常规抽象父类一般不使用 private 构造方法。

## 7.7 抽象类中的普通方法

抽象类可以同时包含抽象方法与已实现方法：

```java
public abstract class ImportTask {
    public final void execute() {
        validate();
        List<String> rows = read();
        process(rows);
        finish();
    }
    protected void validate() {
        System.out.println("公共校验");
    }
    protected abstract List<String> read();
    protected abstract void process(List<String> rows);
    protected void finish() {
        System.out.println("公共收尾");
    }
}
```

子类只实现变化部分：

```java
public class CsvImportTask extends ImportTask {
    @Override
    protected List<String> read() {
        return List.of("A", "B");
    }
    @Override
    protected void process(List<String> rows) {
        System.out.println("处理 CSV");
    }
}
```

这种设计体现：

```
父类固定流程骨架
+
子类实现差异步骤
```

通常称为模板方法思想。

**7.7.1 抽象类的适合场景**

抽象类适合：

- 多个子类有共同字段
- 多个子类共享大量实现
- 需要统一构造过程
- 需要 protected 扩展点
- 需要固定算法流程
- 子类之间存在稳定的类型关系
- 需要限制某些方法不能被重写
