# Q09. JVM 的内存区域是怎么划分的？

> JVM · P0 · 高频

**30 秒回答**：按线程私有与共享分两组：线程私有的有程序计数器、虚拟机栈、本地方法栈；线程共享的有堆、方法区（JDK 8 起实现为元空间）；此外直接内存虽不在 JVM 规范内，却会被 `OutOfMemoryError` 影响。各区域职责不同、溢出行为也不同——栈深超限抛 `StackOverflowError`，堆与元空间容量不足抛 `OutOfMemoryError`。

**深入理解**：

| 区域 | 归属 | 存什么 | 溢出行为 |
| --- | --- | --- | --- |
| 程序计数器 | 线程私有 | 当前执行字节码的行号（Native 方法时为 undefined） | 唯一不会 OOM 的区域 |
| 虚拟机栈 | 线程私有 | 栈帧（局部变量表、操作数栈、动态链接、返回地址） | 栈深超限 → `StackOverflowError` |
| 本地方法栈 | 线程私有 | Native 方法执行上下文 | HotSpot 中与虚拟机栈合并处理 |
| 堆 | 线程共享 | 几乎全部对象实例与数组，GC 主战场 | 容量不足 → `OutOfMemoryError: Java heap space` |
| 方法区 | 线程共享 | 类型信息、常量、静态变量、JIT 代码缓存（JDK 8 起实现为元空间） | `OutOfMemoryError: Metaspace` |
| 直接内存 | 线程共享（非规范区域） | NIO `DirectByteBuffer` 等堆外内存 | `OutOfMemoryError: Direct buffer memory` |

三个必须讲清的版本差异：

- **元空间替代永久代（JDK 8）**：JDK 7 及以前方法区实现为永久代（`-XX:MaxPermSize`，在堆内），类元数据与对象争空间、易 OOM、难以调优；JDK 8 起改为元空间（本地内存，`-XX:MaxMetaspaceSize`，默认几乎无上限）。好处是类元数据不再挤占堆、可按需增长；代价是**不设上限时有耗尽本机内存的风险**，生产必须显式限制。
- **字符串常量池从方法区移到堆（JDK 7）**：永久代回收效率低，`String.intern` 高频调用曾频繁引发永久代 OOM；移到堆后可正常参与 GC，也让运行时常量池的静态结构（如 Class 文件常量池）与方法区其他内容解耦。
- **`StackOverflowError` vs `OutOfMemoryError`**：前者是「栈深度超过单个线程允许的栈帧数」，是**逻辑问题**（递归失控），固定栈大小下必然复现；后者是「动态扩展/新建时拿不到内存」，是**容量问题**。HotSpot 不支持虚拟机栈动态扩展，所以实践中栈几乎只抛 `StackOverflowError`；而「无法创建新 Native 线程」（`unable to create new native thread`）是线程数/内存问题，属于 OOM 家族，不要和栈深混淆。

**为什么这样设计**：私有/共享的划分依据是「生命周期与访问方式」——随线程生死的区域（PC、栈）天然不需要同步，按线程隔离即免锁；堆作为最大且共享的区域，交给 GC 统一管理。元空间外移则是把「随类加载器增减的元数据」从对象堆中剥离，让两类内存各自按需伸缩，避免互相挤占。

**面试官可能继续追问**：
- **为什么程序计数器是唯一不会 OOM 的区域？** —— 它只是一个记录执行位置的计数器，大小固定、没有可增长的数据结构，Native 方法时值为 undefined 甚至不占空间，不存在「存不下」的可能。
- **元空间默认有上限吗？生产怎么设？** —— 默认几乎无上限（受物理内存约束），这正是线上风险：类加载器泄漏 + 动态类生成会让元空间悄悄吃光本机内存。生产应显式设 `-XX:MaxMetaspaceSize`（如 256m~512m），把它变成可控的、可预期的失败点。
- **直接内存 OOM 怎么排查？** —— 看堆外内存监控与 `DirectByteBuffer` 引用；显式设 `-XX:MaxDirectMemorySize` 把不可控变可控；常见泄漏源是 Netty 池化内存未释放、`ByteBuffer` 未走 Cleaner 清理路径。注意 dump 时堆看起来不大，容易误判。
- **JDK 9 模块化后方法区内容变了吗？** —— 规范上方法区仍是运行时数据区之一，实现仍是元空间；变化在类库组织方式（jimage/模块路径），加载来源多了模块系统，三层委派结构与「加载器+全限定名决定类身份」不变。

**实际工程场景**：容器化部署（JDK 10+ 容器感知默认开启）要用容器视角做容量规划——`-Xmx` 只是堆上限，元空间、线程栈、直接内存、JVM 自身开销都在容器 limit 内，堆设太满会把其他区域挤爆；NIO/Netty 服务必须单独监控堆外内存。

**容易答错的地方**：说「方法区就是永久代」——JDK 8 起是元空间，且永久代只是方法区的一种过时实现；说「对象存在栈上」——正常分配在堆，JIT 逃逸分析的栈上分配是优化例外（见 Q15）；说虚拟机栈会抛 OOM——HotSpot 下几乎只有 `StackOverflowError`；回答里完全不提版本。
