# 专题题库

> 按技术专题组织的面试题库：一类题一个文件，每题带重要程度标注、面试口径回答、追问与工程场景。

返回 [面试首页](../README.md) · [仓库首页](../../README.md)。

## 这一层怎么用

这个目录回答三个问题：**面试官怎么问、你应该怎么答、会被追到多深**。所有题目按技术专题组织，不按公司、不按年份——公司维度的组织在 [企业专项](../02-企业专项/README.md)，两边通过链接互通，不重复维护同一道题。

每篇专题都是可以独立用于面试复习的成品文档，结构统一：

| 区块 | 内容 | 什么时候读 |
| --- | --- | --- |
| 专题定位 | 为什么考、面试官验证什么、5 年以上要答多深 | 第一次读这篇时 |
| 高频题目导航 | 全部题目的索引表（编号 / 重要程度 / 追问深度） | 查漏、决定先复习哪题 |
| 题目正文 | 30 秒回答 → 深入理解 → 为什么这样设计 → 追问 → 工程场景 → 易错点 | 主力阅读区 |
| 本专题常见追问链 | 面试官从一个问题追到下一个问题的路径 | 理解追问逻辑 |
| 面试前速记 | 核心结论速记卡 | 面试当天早上 |

## 标签怎么用

每道题带两类标注，互相独立：

| 标签 | 含义 |
| --- | --- |
| `P0` | 复习优先级最高：高频且答不出会明显减分 |
| `P1` | 常见，需要会答、能接住一层追问 |
| `P2` | 了解即可，不必深挖 |
| `高频`/`中频`/`低频` | 公开面经里出现的相对印象，**不是精确统计，也不代表任何公司的官方标准** |
| `重点`/`了解` | 重要程度与追问入口的辅助判断 |

P0/P1/P2 是本仓库的复习优先级划分，不是面试出现频率的统计结果；频率标签同样只是相对印象。用它们分配复习时间，不要用它们预测题目。

## 每道题长什么样

固定从「能复述」走到「能深聊」：

```text
### Q01：问题？ `P0` `高频`

30 秒回答        —— 面试里最先说出口的那句，必须能脱离上下文单独成立
深入理解         —— 原理、关键流程、底层机制
为什么这样设计   —— 复杂题保留，回答「为什么不选另一种方案」
面试官可能继续追问 —— 2～4 个有深度的追问，各带明确答案
实际工程场景     —— 什么时候用、为什么这样选、限制和风险
容易答错的地方   —— 典型误区、版本差异、适用边界
```

简单题不机械套满六个区块（如「SQL 有哪几类」只有回答和少量展开），复杂题（AQS、MVCC、三级缓存）才展开完整链路——题库是复习工具，不是百科全书。

## 和知识层的关系

本库给的是**面试口径的答案**，不是机制解释的权威来源。仓库已有技术笔记的分类，题目底部的「权威内容」行指回知识层：

| 分类 | 权威文章在哪 |
| --- | --- |
| Java基础 | [01-Java核心](../../01-Java核心/README.md) |
| 集合框架 | [02-集合框架](../../02-集合框架/README.md) |
| Java多线程 | [03-并发编程](../../03-并发编程/README.md) |
| JVM | [04-JVM](../../04-JVM/README.md) |
| 数据库基础、SQL、Redis、Spring、MyBatis、计算机网络、操作系统、分布式、消息队列 | 对应模块尚未建设，题目内标注可参考的官方文档与经典书目 |

写新题时守住这条边界：**仓库已有权威文章的分类，只写面试口径的压缩答案并链接过去，不要把知识层的机制解释再抄一遍。** 知识层尚未建设的分类，回答可以完整，但要标明权威页暂缺，避免读者误以为本库就是该主题的权威来源。

## 怎么加一道新题

1. **找分类文件。** 没有合适分类就新建一个，用单一概念的短名（`SQL` 而不是 `SQL 与查询优化`），一个文件只装一类题。
2. **追加到文件末尾**，编号接续，不要插在中间打乱既有编号。
3. **标 P0/P1/P2 与频率**，P 档不要留空。
4. **写 30 秒回答与深入理解**；核心题补「为什么这样设计」与追问，工程相关题补工程场景与易错点。
5. **回链知识层**（见上节）；知识层没有的主题注明可参考的官方文档。
6. **更新本页的分类表**（题量、覆盖描述）。
