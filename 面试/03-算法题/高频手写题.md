## 题一：LRU 缓存

**要求**：`get` 和 `put` 都是 O(1)，容量满时淘汰最久未使用的。

```java
import java.util.HashMap;
import java.util.Map;

public class LruCache<K, V> {

    private static final class Node<K, V> {
        K key;
        V value;
        Node<K, V> prev;
        Node<K, V> next;

        Node(K key, V value) {
            this.key = key;
            this.value = value;
        }
    }

    private final int capacity;
    private final Map<K, Node<K, V>> map = new HashMap<>();
    private final Node<K, V> head = new Node<>(null, null);   // 哨兵：最近使用端
    private final Node<K, V> tail = new Node<>(null, null);   // 哨兵：最久未使用端

    public LruCache(int capacity) {
        if (capacity <= 0) {
            throw new IllegalArgumentException("capacity must be positive, got " + capacity);
        }
        this.capacity = capacity;
        this.head.next = this.tail;
        this.tail.prev = this.head;
    }

    public V get(K key) {
        Node<K, V> node = map.get(key);
        if (node == null) {
            return null;
        }
        moveToHead(node);
        return node.value;
    }

    public void put(K key, V value) {
        Node<K, V> node = map.get(key);
        if (node != null) {
            node.value = value;          // 注意：只更新值，不要新建节点
            moveToHead(node);
            return;
        }
        node = new Node<>(key, value);
        map.put(key, node);
        addToHead(node);
        if (map.size() > capacity) {
            Node<K, V> removed = removeTail();
            map.remove(removed.key);     // 必须从 map 里同步删除，否则内存泄漏
        }
    }

    private void addToHead(Node<K, V> node) {
        node.prev = head;
        node.next = head.next;
        head.next.prev = node;
        head.next = node;
    }

    private void removeNode(Node<K, V> node) {
        node.prev.next = node.next;
        node.next.prev = node.prev;
    }

    private void moveToHead(Node<K, V> node) {
        removeNode(node);
        addToHead(node);
    }

    private Node<K, V> removeTail() {
        Node<K, V> removed = tail.prev;
        removeNode(removed);
        return removed;
    }
}
```

### 判分点

| 检查项 | 写错会怎样 |
| --- | --- |
| 两个哨兵节点 | 没有哨兵就要处理「链表为空」「只有一个节点」等分支，容易出 bug |
| `put` 命中已有 key 时只更新值 | 新建节点会导致链表和 map 不一致 |
| 淘汰时 `map.remove(removed.key)` | 内存泄漏，且 get 到已淘汰的节点 |
| `capacity <= 0` 校验 | 面试官常问「容量为 0 会怎样」——不校验会立即淘汰刚放进去的元素 |
| 新增后判断 `size > capacity` | 判断时机错了会多淘汰一个 |

### 可能的追问

- **「怎么加过期时间？」** 在 `Node` 里加 `expireAt` 字段，`get` 时判断，过期则删除并按未命中处理。惰性删除足够应付大多数场景；要求精确清理则需要时间轮或最小堆。
- **「线程安全怎么做？」** 最简单是给 `get`/`put` 加 `synchronized`（但会退化为串行）。更好的做法是分段锁，或直接用 `ConcurrentHashMap` + 跳表（ConcurrentSkipListMap 思路）。面试时说明取舍即可。
- **「和 LinkedHashMap 的关系？」** 见 [LinkedHashMap 与 LRU 缓存](../../02-集合框架/02-深度解析/LinkedHashMap与LRU缓存.md)——`LinkedHashMap` 的 access-order 模式加 `removeEldestEntry` 就能实现，但面试要求手写时通常不允许直接用。

## 题二：双重检查单例

```java
public final class Singleton {

    private static volatile Singleton instance;

    private Singleton() {
        // 防反射破坏（严格场景再加），正常写可以留空
    }

    public static Singleton getInstance() {
        if (instance == null) {                  // 第一次检查：避免每次进入同步块
            synchronized (Singleton.class) {
                if (instance == null) {          // 第二次检查：避免重复创建
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```

### 判分点

| 检查项 | 写错会怎样 |
| --- | --- |
| `volatile` 关键字 | 可能拿到**未初始化完成**的对象，见下面解释 |
| 两处 `null` 检查 | 只写一处：要么每次都加锁，要么并发下创建多个实例 |
| 构造器 `private` | 外部可直接 new，单例失效 |
| 类声明 `final` | 可被继承后绕过（次要加分项） |

**为什么必须 `volatile`**：`instance = new Singleton()` 在字节码层面是三步——①分配内存、②初始化对象、③把引用赋给 `instance`。②和③之间**可能被重排序**。若重排成 ①③②，另一个线程在第一次检查时会看到 `instance != null`，直接返回一个字段全是默认值的半成品对象。

**其他写法对比**：

| 写法 | 优点 | 缺点 |
| --- | --- | --- |
| 饿汉式 | 简单、线程安全 | 类加载即创建，无法延迟 |
| 双重检查 | 延迟加载 + 并发安全 | 代码略复杂，必须写对 `volatile` |
| 静态内部类 | 简洁、延迟加载、线程安全 | 无法接收构造参数 |
| 枚举 | 最安全，天然防反射与序列化 | 不能延迟加载 |

面试时**主动说出「静态内部类和枚举写法更简洁」是加分项**，但要能解释为什么双重检查仍然被广泛考察——因为它同时考了 `volatile` 的语义。

## 题三：生产者消费者

### 推荐写法：BlockingQueue

```java
import java.util.concurrent.ArrayBlockingQueue;
import java.util.concurrent.BlockingQueue;

public class ProducerConsumerWithQueue {

    private static final int CAPACITY = 5;
    private static final int POISON = -1;              // 结束信号

    public static void main(String[] args) throws InterruptedException {
        BlockingQueue<Integer> queue = new ArrayBlockingQueue<>(CAPACITY);

        Thread producer = new Thread(() -> {
            try {
                for (int i = 1; i <= 20; i++) {
                    queue.put(i);                      // 队列满时自动阻塞
                    System.out.println("produced: " + i);
                }
                queue.put(POISON);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();     // 恢复中断标志，不要吞掉
            }
        }, "producer");

        Thread consumer = new Thread(() -> {
            try {
                while (true) {
                    int value = queue.take();           // 队列空时自动阻塞
                    if (value == POISON) {
                        break;
                    }
                    System.out.println("consumed: " + value);
                }
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }, "consumer");

        producer.start();
        consumer.start();
        producer.join();
        consumer.join();
    }
}
```

### 手写版：wait / notifyAll

```java
public class BoundedBuffer<T> {

    private final Object[] items;
    private int count;
    private int putIndex;
    private int takeIndex;

    public BoundedBuffer(int capacity) {
        this.items = new Object[capacity];
    }

    public synchronized void put(T item) throws InterruptedException {
        while (count == items.length) {          // 必须用 while，不能用 if
            wait();
        }
        items[putIndex] = item;
        putIndex = (putIndex + 1) % items.length;
        count++;
        notifyAll();                             // 唤醒所有等待者，不能只 notify
    }

    @SuppressWarnings("unchecked")
    public synchronized T take() throws InterruptedException {
        while (count == 0) {
            wait();
        }
        T item = (T) items[takeIndex];
        items[takeIndex] = null;                 // 帮助 GC，避免对象滞留
        takeIndex = (takeIndex + 1) % items.length;
        count--;
        notifyAll();
        return item;
    }
}
```

### 判分点

| 检查项 | 写错会怎样 |
| --- | --- |
| `while` 而不是 `if` 包 `wait()` | 被虚假唤醒后条件不成立却继续执行，导致越界或取出 null |
| `notifyAll()` 而不是 `notify()` | 只唤醒一个可能唤醒的是同类线程，导致另一方永久等待 |
| `wait()` 在 `synchronized` 内 | 否则抛 `IllegalMonitorStateException` |
| 中断后恢复标志 | 吞掉中断会让上层无法感知取消 |
| 取出后置 `null` | 长生命周期缓冲区会持有无用引用 |

### 追问：「为什么用 while 不用 if？」

因为 `wait()` 存在**虚假唤醒**（spurious wakeup）——没有收到通知也可能返回。即使没有虚假唤醒，被 `notify` 唤醒时条件也可能已经被其他线程改变。所以醒来后**必须重新检查条件**。

## 题四：令牌桶限流器

```java
public class TokenBucketRateLimiter {

    private final double capacity;                  // 桶容量（允许的突发量）
    private final double refillPerNano;             // 每纳秒补充的令牌数
    private double tokens;
    private long lastRefillNanos;

    public TokenBucketRateLimiter(double capacity, double tokensPerSecond) {
        if (capacity <= 0 || tokensPerSecond <= 0) {
            throw new IllegalArgumentException("capacity and rate must be positive");
        }
        this.capacity = capacity;
        this.refillPerNano = tokensPerSecond / 1_000_000_000.0;
        this.tokens = capacity;
        this.lastRefillNanos = System.nanoTime();
    }

    public synchronized boolean tryAcquire() {
        refill();
        if (tokens >= 1.0) {
            tokens -= 1.0;
            return true;
        }
        return false;
    }

    private void refill() {
        long now = System.nanoTime();
        double elapsed = now - lastRefillNanos;
        if (elapsed <= 0) {
            return;                                  // 时钟回拨或同一纳秒，不补
        }
        tokens = Math.min(capacity, tokens + elapsed * refillPerNano);
        lastRefillNanos = now;
    }
}
```

### 判分点

| 检查项 | 写错会怎样 |
| --- | --- |
| 惰性补充（用到时才算） | 起后台线程定时补充，浪费线程且精度差 |
| `Math.min(capacity, ...)` | 不限上界会累积出远超容量的令牌，失去限流意义 |
| 用 `System.nanoTime()` | `currentTimeMillis` 受系统时钟调整影响，`nanoTime` 单调 |
| `elapsed <= 0` 兜底 | 时钟异常时可能算出负补充 |
| 令牌用 `double` | 用 `int` 会导致低速限流时永远补不满 1 个令牌 |

### 追问：「和漏桶、滑动窗口的区别？」

| 算法 | 特点 | 适用 |
| --- | --- | --- |
| 令牌桶 | 允许一定突发（桶里攒的令牌） | 大多数业务限流 |
| 漏桶 | 恒定速率流出，不允许突发 | 保护脆弱的下游 |
| 固定窗口 | 实现最简单 | 精度要求不高的场景 |
| 滑动窗口 | 平滑，避免窗口边界突刺 | 精度要求高的场景 |

## 题五：手写快排

```java
public final class QuickSort {

    private QuickSort() {
    }

    public static void sort(int[] nums) {
        if (nums == null || nums.length < 2) {
            return;
        }
        quickSort(nums, 0, nums.length - 1);
    }

    private static void quickSort(int[] nums, int left, int right) {
        if (left >= right) {
            return;
        }
        int pivotIndex = partition(nums, left, right);
        quickSort(nums, left, pivotIndex - 1);
        quickSort(nums, pivotIndex + 1, right);
    }

    private static int partition(int[] nums, int left, int right) {
        int randomIndex = left + ThreadLocalRandom.current().nextInt(right - left + 1);
        swap(nums, randomIndex, right);           // 随机化基准，避免有序输入退化
        int pivot = nums[right];
        int store = left;
        for (int i = left; i < right; i++) {
            if (nums[i] < pivot) {
                swap(nums, i, store);
                store++;
            }
        }
        swap(nums, store, right);
        return store;
    }

    private static void swap(int[] nums, int i, int j) {
        int tmp = nums[i];
        nums[i] = nums[j];
        nums[j] = tmp;
    }
}
```

### 判分点

| 检查项 | 写错会怎样 |
| --- | --- |
| 递归边界 `left >= right` | 写成 `left > right` 在单元素时会多做一次无效分区（不错但多余）；写成 `left == right` 则可能栈溢出 |
| 随机化基准 | 固定取末尾，遇到已排序数组退化为 O(n²) |
| `store` 指针语义 | 它是「小于 pivot 区域的下一写入位」，理解错了分区就错 |
| 最坏复杂度 | 要能说出「平均 O(n log n)，最坏 O(n²)，空间 O(log n) 栈深度」 |

### 追问：「归并排序和快排怎么选？」

| 维度 | 快排 | 归并 |
| --- | --- | --- |
| 平均时间 | O(n log n) | O(n log n) |
| 最坏时间 | O(n²) | O(n log n) |
| 空间 | O(log n) | O(n) |
| 稳定性 | 不稳定 | 稳定 |
| 适用 | 内存排序、数组 | 链表排序、要求稳定、外部排序 |

## 通用检查清单

手写题写完，**主动说一句「我检查一下边界」**，然后真的过一遍这几项：

- 输入为空、长度为 0 或 1；
- 容量为 0 或负数（涉及容量设计的题）；
- 并发场景下的可见性与原子性；
- 异常路径下的资源释放与状态恢复；
- 会不会有整数溢出（比较、累加、时间差）；
- 有没有可能死循环或无限递归。
