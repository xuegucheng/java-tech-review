# 栈队列与堆

> **一句话定位**：栈和队列本身不难，难的是**识别出「什么时候该用单调栈」「什么时候该用堆」**。识别对了，代码都是十几行。

返回 [算法题首页](README.md) · [面试首页](../README.md)。

## 识别信号

| 题面信号 | 该想的套路 | 为什么 |
| --- | --- | --- |
| 括号匹配、嵌套结构、撤销 | 栈 | 后进先出天然对应嵌套 |
| 「下一个更大的元素」「左边第一个比它小的」 | 单调栈 | 用栈维护还没找到答案的元素 |
| 滑动窗口的最值 | 单调队列 | 队列维持候选集合，队首即当前窗口最值 |
| TopK、第 K 大、前 K 高频 | 堆 | 只需维护 k 个元素，O(n log k) |
| 数据流的中位数 | 双堆 | 一半大顶堆、一半小顶堆 |
| 需要 O(1) 获取极值 | 辅助栈 / 辅助结构 | 用空间换时间 |

## 核心模板

### 模板一：单调栈（求「下一个更大」）

```java
Deque<Integer> stack = new ArrayDeque<>();   // 存下标，栈内值单调递减
for (int i = 0; i < n; i++) {
    while (!stack.isEmpty() && 当前值 > 栈顶对应值) {
        int idx = stack.pop();               // 栈顶元素在这一刻找到了答案
        记录答案(idx, i);
    }
    stack.push(i);                           // 当前元素入栈，等待它自己的答案
}
```

**核心直觉**：栈里存的是「还没找到右边更大元素」的下标，而且它们的值从栈底到栈顶递减。**新元素进来时，所有比它小的栈顶元素都找到了答案，可以弹出。**

### 模板二：小顶堆求 TopK

```java
PriorityQueue<Integer> heap = new PriorityQueue<>();   // 默认小顶堆
for (int num : nums) {
    heap.offer(num);
    if (heap.size() > k) {
        heap.poll();                     // 弹出最小的，堆里始终是最大的 k 个
    }
}
```

**为什么求「最大的 k 个」要用手小顶堆**：堆顶是这 k 个里最小的，新元素只要比堆顶大就替换掉堆顶。**用大顶堆会需要 O(n log n) 全排序**，而小顶堆只需要 O(n log k)。

## 典型题

### 题一：有效的括号

**题干**：判断括号字符串是否合法。

```java
public boolean isValid(String s) {
    Deque<Character> stack = new ArrayDeque<>();
    for (char c : s.toCharArray()) {
        // 遇到左括号，压入对应的右括号
        if (c == '(') {
            stack.push(')');
        } else if (c == '[') {
            stack.push(']');
        } else if (c == '{') {
            stack.push('}');
        } else {
            // 遇到右括号：栈空或栈顶不匹配都非法
            if (stack.isEmpty() || stack.pop() != c) {
                return false;
            }
        }
    }
    return stack.isEmpty();          // 全部匹配完才合法
}
```

- **时间 O(n)，空间 O(n)。**
- **技巧**：压入的是**期望的右括号**而非左括号本身。这样匹配时只需一次比较，省掉了映射表。
- **易错点一**：`stack.pop() != c` 中间不能漏掉 `stack.isEmpty()` 判断，否则 `")"` 这种输入会抛异常。
- **易错点二**：最后返回 `stack.isEmpty()` 而不是 `true`。`"(("` 会走到最后但栈非空。

### 题二：每日温度（单调栈）

**题干**：对每天，求还要等多少天才会出现更高温度，没有则填 0。

```java
public int[] dailyTemperatures(int[] temperatures) {
    int n = temperatures.length;
    int[] res = new int[n];
    Deque<Integer> stack = new ArrayDeque<>();      // 存下标，对应温度单调递减
    for (int i = 0; i < n; i++) {
        while (!stack.isEmpty() && temperatures[i] > temperatures[stack.peek()]) {
            int prevIndex = stack.pop();
            res[prevIndex] = i - prevIndex;         // 答案就是下标差
        }
        stack.push(i);
    }
    return res;
}
```

- **时间 O(n)（每个下标入栈出栈各一次），空间 O(n)。**
- **为什么是 O(n) 而不是 O(n²)**：虽然有嵌套 `while`，但每个元素最多入栈一次、出栈一次，总操作数是 2n。
- **易错点**：栈里存**下标**而不是值。存值的话无法计算「等了多少天」，也无法判断元素是否还在窗口内。
- **面试变体**：「下一个更大元素 II」是循环数组 → 遍历两倍长度，下标取模。

### 题三：最小栈（辅助栈设计）

**题干**：实现一个栈，支持 `push`、`pop`、`top`、`getMin`，全部 O(1)。

```java
class MinStack {
    private final Deque<Integer> data = new ArrayDeque<>();
    private final Deque<Integer> minStack = new ArrayDeque<>();

    public void push(int val) {
        data.push(val);
        // 注意用 <=，相等时也要入栈，否则 pop 时会误弹出
        if (minStack.isEmpty() || val <= minStack.peek()) {
            minStack.push(val);
        }
    }

    public void pop() {
        int val = data.pop();
        if (val == minStack.peek()) {
            minStack.pop();
        }
    }

    public int top() {
        return data.peek();
    }

    public int getMin() {
        return minStack.peek();
    }
}
```

- **所有操作 O(1)，空间 O(n)。**
- **设计要点**：`minStack` 和 `data` **同步增删**，所以 `minStack` 的栈顶永远是当前 `data` 的最小值。
- **易错点一**：`push` 时必须用 `<=` 而不是 `<`。如果相等时不入栈，那么 `push(5), push(5), pop()` 之后，`minStack` 会少了元素，`getMin` 结果错乱。
- **易错点二**：不要在 `pop` 里用 `==` 比较两个 `Integer` 对象（超过 127 时缓存失效会误判）。这里 `data.pop()` 赋值给 `int` 后已拆箱，比较的是值，是安全的——**但如果写成 `Integer val = data.pop()` 就会变成引用比较**。

### 题四：滑动窗口最大值（单调队列）

**题干**：返回每个长度为 k 的窗口中的最大值。

```java
public int[] maxSlidingWindow(int[] nums, int k) {
    int n = nums.length;
    int[] res = new int[n - k + 1];
    Deque<Integer> deque = new ArrayDeque<>();      // 存下标，对应值单调递减
    for (int i = 0; i < n; i++) {
        // ① 维护单调性：比当前值小的都不可能再成为最大值
        while (!deque.isEmpty() && nums[deque.peekLast()] <= nums[i]) {
            deque.pollLast();
        }
        deque.offerLast(i);
        // ② 移除已经滑出窗口的队首
        if (deque.peekFirst() <= i - k) {
            deque.pollFirst();
        }
        // ③ 窗口形成后记录答案
        if (i >= k - 1) {
            res[i - k + 1] = nums[deque.peekFirst()];
        }
    }
    return res;
}
```

- **时间 O(n)，空间 O(k)。**
- **三个动作的顺序**：先维护单调性 → 再加入当前元素 → 再移除过期元素 → 最后取答案。顺序错了会漏掉或误取。
- **易错点**：`nums[deque.peekLast()] <= nums[i]` 用 `<=` 保证队列里不会留下等值的旧元素，减少无效比较；用 `<` 也能得到正确答案，但队列会稍长。
- **为什么不能用优先队列**：堆无法 O(1) 地删除已滑出窗口的元素，会变成 O(n log n) 且带延迟删除逻辑。单调队列是更优解。

### 题五：数组中的第 K 个最大元素

**题干**：求无序数组中第 k 大的元素。

**解法一：小顶堆（更通用）**

```java
public int findKthLargestByHeap(int[] nums, int k) {
    PriorityQueue<Integer> heap = new PriorityQueue<>();    // 小顶堆
    for (int num : nums) {
        heap.offer(num);
        if (heap.size() > k) {
            heap.poll();
        }
    }
    return heap.peek();          // 堆顶就是第 k 大
}
```

- **时间 O(n log k)，空间 O(k)。**
- **适用场景**：数据量大到无法全部载入内存（流式数据），这种方式只需保存 k 个元素。

**解法二：快速选择（平均更快）**

```java
public int findKthLargest(int[] nums, int k) {
    int target = nums.length - k;          // 第 k 大 = 升序排列后的第 n-k 个
    int left = 0, right = nums.length - 1;
    while (left <= right) {
        int pivotIndex = partition(nums, left, right);
        if (pivotIndex == target) {
            return nums[pivotIndex];
        } else if (pivotIndex < target) {
            left = pivotIndex + 1;
        } else {
            right = pivotIndex - 1;
        }
    }
    return -1;
}

private int partition(int[] nums, int left, int right) {
    int pivot = nums[right];
    int store = left;
    for (int i = left; i < right; i++) {
        if (nums[i] < pivot) {
            int tmp = nums[i];
            nums[i] = nums[store];
            nums[store] = tmp;
            store++;
        }
    }
    int tmp = nums[store];
    nums[store] = nums[right];
    nums[right] = tmp;
    return store;
}
```

- **平均时间 O(n)，最坏 O(n²)；空间 O(1)。**
- **最坏情况**：数组已经有序且每次都取末尾元素做基准，每次只能排除一个元素。**生产代码应随机选择基准**（交换 `nums[right]` 与随机位置的元素）。
- **面试建议**：先说堆的 O(n log k) 解法（稳妥、可解释、能应对追问「数据量很大怎么办」），再提快速选择作为优化。**直接上快选但写错 partition，损失更大。**

### 题六：前 K 个高频元素

```java
public int[] topKFrequent(int[] nums, int k) {
    Map<Integer, Integer> freq = new HashMap<>();
    for (int num : nums) {
        freq.merge(num, 1, Integer::sum);       // 比 containsKey 判断更简洁
    }
    PriorityQueue<int[]> heap = new PriorityQueue<>(Comparator.comparingInt(a -> a[1]));
    for (Map.Entry<Integer, Integer> entry : freq.entrySet()) {
        heap.offer(new int[]{entry.getKey(), entry.getValue()});
        if (heap.size() > k) {
            heap.poll();
        }
    }
    int[] res = new int[k];
    for (int i = 0; i < k; i++) {
        res[i] = heap.poll()[0];
    }
    return res;
}
```

- **时间 O(n log k)，空间 O(n)。**
- **为什么用 `int[]` 而不是 `Map.Entry`**：`PriorityQueue` 用数组配合比较器最直观，也方便调整比较字段。
- **易错点**：`Comparator.comparingInt(a -> a[1])` 是**小顶堆**（按频次升序），这样才能用 `poll` 弹出频次最低的。写成 `reversed()` 就变成大顶堆，逻辑全反。

## 易错点汇总

| 易错点 | 典型表现 | 预防 |
| --- | --- | --- |
| 栈里存值而非下标 | 无法计算距离/判断过期 | 需要位置信息时一律存下标 |
| 单调栈方向写反 | 求错「更大」还是「更小」 | 先写一句「栈内值单调递 X」再动笔 |
| 最小栈相等判断写 `<` | pop 后最小值丢失 | 相等也要入栈，用 `<=` |
| 滑动窗口三步骤乱序 | 结果偏移一位 | 单调 → 入队 → 过期 → 取值，按顺序写 |
| TopK 用大顶堆 | 复杂度升到 O(n log n) | 求最大 k 个用小顶堆 |
| 快选基准固定 | 有序输入退化成 O(n²) | 随机选基准 |
| `Integer` 用 `==` 比较 | 大数误判 | 先拆箱成 `int` 再比 |
