# 算法题

> 算法面试考的不是「你见过多少题」，而是**能不能在有限时间里，把一类问题识别出来并写对**。
> 所以这里按题型组织，不按题号组织——题号是别人的顺序，题型才是你自己的武器。

## 怎么用这个模块

| 你的状态 | 建议做法 |
| --- | --- |

## 题型地图：看到什么信号，用什么套路

这张表是模块的核心。**面试时真正要做的判断，是从题面里读出信号，而不是回忆题号。**

| 题型 | 识别信号 | 核心套路 | 典型复杂度 |
| --- | --- | --- | --- |
| [数组与双指针](数组与双指针.md) | 有序数组、求和、去重、原地修改 | 对撞指针、快慢指针、原地交换 | O(n) / O(n log n) |
| [链表](链表.md) | 反转、找环、找倒数第 k 个、合并 | 虚拟头节点、快慢指针、指针反转 | O(n) |
| [二叉树](二叉树.md) | 遍历、深度、路径、祖先、BST | 递归三要素、层序 BFS、BST 中序有序 | O(n) |
| [动态规划](动态规划.md) | 求最值、方案数、能不能、区间 | 定义状态、转移方程、初始化、遍历顺序 | O(n²) 常见 |
| [回溯与图搜索](回溯与图搜索.md) | 全排列、组合、子集、网格连通、依赖 | 决策树 + 撤销选择、DFS/BFS、拓扑排序 | 指数级 / O(mn) |
| [栈队列与堆](栈队列与堆.md) | 括号、下一个更大、TopK、中位数 | 单调栈、单调队列、优先队列 | O(n) / O(n log k) |
| [高频手写题](高频手写题.md) | 缓存、限流、生产者消费者、排序 | 组合数据结构、模板化实现 | 视题而定 |

### 三条通用识别原则

1. **看到「有序」先想二分和双指针**，不要直接暴力。
2. **看到「最值 / 方案数 / 可行性」想动态规划**，先想状态怎么定义。
3. **看到「所有方案 / 所有组合」想回溯**，先画决策树。

## 推荐顺序

按「先建立模板，再练组合」的顺序走，比按题号刷效率高得多：

```text
数组与双指针  →  链表  →  二叉树  →  栈队列与堆
     ↓                                    ↓
  回溯与图搜索  ←  动态规划  ←  高频手写题
```

| 阶段 | 题型 | 目标 | 建议题量 |
| --- | --- | --- | --- |
| 1 | 数组与双指针 | 写出不看模板也能写的对撞/快慢指针 | 8～10 |
| 2 | 链表 | 反转、找环、合并三类闭眼能写 | 6～8 |
| 3 | 二叉树 | 递归三要素形成肌肉记忆，层序 BFS 熟练 | 8～10 |
| 4 | 栈队列与堆 | 能识别「下一个更大」和 TopK 场景 | 5～6 |
| 5 | 动态规划 | 能自己推出转移方程，而不是套模板 | 10～12 |
| 6 | 回溯与图搜索 | 决策树能画清，剪枝知道加在哪 | 8～10 |
| 7 | 高频手写题 | LRU、单例、生产者消费者能一次写对 | 5～6 |

## 面试编码的六条实用建议

这些不是技术点，但直接影响结果：

1. **先问清约束再动手。** 数据范围、是否允许改原数组、有没有重复元素、要不要返回下标——问清楚比分错方向重要。
2. **先说暴力解再优化。** 「暴力 O(n²)，优化方向是用哈希降到 O(n)，我开始写优化的」——这句话能让面试官知道你有思路，即使后面写崩了也不至于全丢。
3. **边写边说。** 沉默写代码是最容易被误判的场景。写下 `// 这里用双指针收缩窗口` 比什么都不说好。
4. **写完主动检查边界。** 空输入、单元素、全相同、整数溢出、链表只有两个节点——主动说「我检查一下边界」并真的看一遍。
5. **标注复杂度，并说明依据。** 「时间 O(n)，每个元素最多被访问两次；空间 O(1)，只用了常数个变量」。
6. **不会就诚实说。** 「这题我想到的思路是 X，但复杂度不达标，暂时没想到更优的」——比硬憋着写错强。

## 代码说明

- 本模块代码统一使用 **Java 21** 语法风格，但只用到 JDK 8 就有的语言特性，便于在任何版本下运行。
- 每个解法都标注**时间复杂度、空间复杂度**和**易错点**。
- 代码为完整方法实现，可直接复制到 IDE 中运行；不依赖任何第三方库。
- 涉及数据结构定义的题目（如链表节点、树节点），会一并给出节点类定义。
- 这些是**题解片段**，不是仓库级可运行示例，因此不进入 `04-示例代码/`；需要完整可运行验证的手写题见 [高频手写题](高频手写题.md)。
