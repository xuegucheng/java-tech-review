## 岗位技术域拆解

AI 软件工程岗（工程方向）通常不是算法研究员岗，核心是**把模型变成稳定运行的服务**。结合公开岗位画像，考察面大致分五块：

| 技术域 | 相对权重 | 典型内容 |
| --- | --- | --- |
| 编程语言与计算机基础 | 高 | Python / C++ 语言细节、数据结构、操作系统、网络 |
| AI 框架与模型服务 | 高 | 训练/推理框架、模型部署、服务化、性能优化 |
| 数据工程 | 中高 | 大数据处理链路、数据清洗、特征工程、ETL |
| 工程与云原生 | 中 | 容器、K8s、CI/CD、可观测性、MLOps |
| 项目与协作 | 高 | 模型上线全链路的问题定位与取舍 |

> 说明：如果你的目标是 Java 后端转 AI 工程岗，本仓库的 Java 后端主线（[专题题库](../01-专题题库/README.md)）仍然覆盖「编程语言与计算机基础」「工程与云原生」两大块的底座；AI 框架与数据工程需要按目标部门 JD 额外补。牛客等平台上的 C++ 基础、AI 算法、大模型基础、测试理论等题库属于相邻方向，本仓库不机械纳入 Java 后端主线，仅通过本页做方向索引。

## 追问链示例

### 从模型服务追到工程闭环（模拟推演）

```text
面试官：你们模型服务怎么部署的？
你（L1）：打包成镜像，K8s 部署，前面挂负载均衡。
面试官：QPS 涨上来之后，哪里先出问题？
你（L2）：先看单副本的 GPU/CPU 利用率与批大小；
        推理是计算密集，副本数受加速卡总量限制，扩容不是无限的。
面试官：那延迟还是压不下来怎么办？
你（L3）：上动态批处理（dynamic batching）把多个请求合并推理，
        用排队时间换吞吐；同时区分在线/离线流量，离线走批量任务。
面试官：模型要更新怎么办？
你（L4）：影子发布 + AB：新版本先接少量流量对比指标，
        指标劣化自动切回；模型文件和代码分离，回滚只换模型不换服务。
```

**这条链在考什么**：AI 工程岗和普通后端岗的追问路径高度相似——都会从「怎么部署」追到「扩容约束」再追到「发布与回滚」。差别只在被追问的对象是模型而不是数据库。答到 L4 的关键是把后端服务的治理经验迁移到模型服务上。

权威内容：[分布式 Q08](../01-专题题库/分布式.md) · [04-场景设计题](../04-场景设计题/README.md)

## 高频失分点

| 失分点 | 表现 | 怎么改 |
| --- | --- | --- |
| 只懂算法不懂工程 | 模型指标背得熟，问部署/监控就卡 | 补「模型上线之后」的半程：服务化、灰度、回滚、监控 |
| 把 AI 岗当研究员准备 | 全程论文公式，没有工程取舍 | 工程岗考的是「稳定跑起来、可观测、可回滚」 |
| 数据环节空白 | 只关心模型不关心数据质量 | 数据发现、处理、防再发的闭环必须能讲 |
| 不懂装懂 | 对大模型前沿强行回答 | 直接说「这块我了解概念，深度不够」，讲你会的相邻部分 |
| 量级意识缺失 | 讲方案不带数据规模 | 每个方案配一组数字：数据量、QPS、副本数 |

## 一句话准备建议

AI 软件工程岗的面试主线是**「模型怎么稳定地跑在生产环境」**。Java 后端练出来的工程能力（服务治理、排查方法论、容量意识）大部分可以直接迁移；需要额外补的是 AI 框架与数据工程两块——按目标部门 JD 决定补多深，不要按全网题库平均补。
