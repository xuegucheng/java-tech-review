## 追问链示例

### 例一：算法题不会只让你写出来

```text
面试官：写一个 LRU 缓存，get 和 put 都是 O(1)。
你：（写完双向链表 + HashMap）
面试官：为什么要用双向链表，单链表不行吗？
你：删除节点需要拿到前驱，单链表删除是 O(n)，双向链表 O(1)。
面试官：那 HashMap 里存的是什么？
你：存 key 到链表节点的映射，这样能 O(1) 定位到节点再调整顺序。
面试官：现在加个需求——每个 key 带过期时间，get 时发现过期要当作不存在。
        你怎么改？
你：把过期时间存在节点里，get 时先判断，过期就按淘汰处理；
        另外用一个惰性删除策略避免额外线程扫描。
面试官：如果要求过期时间一到就立即清理呢？
你：那就需要时间轮或者最小堆来驱动定时清理，
        但会引入额外线程和锁竞争，一般业务里惰性删除够用。
```

**这道题在考什么**：字节的算法题几乎一定会加变体。**把模板题背下来只是入场券，能跟着需求改设计才是得分点。**

权威内容：[LinkedHashMap 与 LRU 缓存](../../02-集合框架/02-深度解析/LinkedHashMap与LRU缓存.md) · [高频手写题](../03-算法题/高频手写题.md)

### 例二：并发从概念追到线上

```text
面试官：volatile 保证了什么？
你（L1）：可见性和有序性，不保证原子性。
面试官：可见性是怎么实现的？
你（L2）：写 volatile 变量会插内存屏障，把工作内存刷到主内存，
        读的时候会从主内存重新加载。
面试官：那它和 synchronized 的可见性有什么区别？
你（L3）：synchronized 是「释放锁时的写回 + 获取锁时的失效」，
        顺带保证原子性；volatile 只是单个变量的读写语义，
        不互斥，多个线程同时写不会有锁的开销也没有锁的保护。
面试官：i++ 用 volatile 修饰为什么还是不安全？
你（L4）：i++ 是读-改-写三步，volatile 只保证每一步看到的都是最新值，
        不保证三步整体原子，两个线程可能都读到 5 然后都写 6。
面试官：那你会怎么解决？
你（L5）：换成 AtomicInteger，或者用锁。不过如果只是计数统计，
        高并发下 LongAdder 的分段累加性能更好。
```

**这道题在考什么**：从「是什么」一路追到「怎么选」。字节的追问节奏很快，每层只给你一两句话的机会。

权威内容：[volatile 原理与使用边界](../../03-并发编程/02-深度解析/volatile原理与使用边界.md) · [CAS 与原子类](../../03-并发编程/02-深度解析/CAS与原子类.md)

### 例三：一道题同时考编码和边界

```text
面试官：给一个无序数组和目标值，找出两个数相加等于目标，返回下标。
        五分钟，开始。
你：（写双重循环）
面试官：时间复杂度？能优化吗？
你：O(n²)。可以一次遍历加哈希表记录已访问值，降到 O(n)。
面试官：那如果要求不许用哈希表呢？
你：先排序再用对撞双指针，O(n log n)，但会丢失原始下标，
        需要额外记录原位置。
面试官：时间复杂度一样的情况下，你会选哪个？
你：看约束——数组是否允许改动、是否需要返回原下标、
        内存是否紧张。需要返回原下标且不想改数组就用哈希表。
```

**这道题在考什么**：限时 + 追问 + 取舍，是字节最常见的组合。**先给能跑的版本，再说优化**，比一上来卡在最优解更安全。

权威内容：[数组与双指针](../03-算法题/数组与双指针.md)

## 高频失分点

| 失分点 | 表现 | 怎么改 |
| --- | --- | --- |
| 算法超时 | 想最优解想太久，时间到了没写出来 | 先写暴力解拿到 baseline，再口头讲优化方向 |
| 代码有边界 bug | 空数组、单节点、整数溢出 | 写完主动说一句「我检查一下边界」，并真的检查 |
| 只写不说 | 全程沉默敲代码 | 边写边讲思路，面试官会更宽容 |
| 项目讲不清 | 简历上写了但不记得细节 | 简历只写能讲 15 分钟的东西 |
| 复杂度说不准 | 「大概是 O(n) 吧」 | 养成写一行就标一次复杂度的习惯 |

## 一句话准备建议

字节的通过线很大程度由算法决定。**刷题的目标不是「见过」，而是「冷启动 5 分钟内能写出无 bug 的版本」**——包括边界检查、复杂度口述和快速给出变体方案。
