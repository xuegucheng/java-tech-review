## 追问链示例

### 例一：TCP 追问链

```text
面试官：为什么三次握手，两次不行？
你（L1）：因为要确认双方的收发能力都正常。
面试官：具体是谁的能力？
你（L2）：第一次确认客户端发送能力，第二次确认服务端收发能力，
        第三次确认客户端接收能力。两次的话，服务端无法确认客户端
        能收到自己的包。
面试官：那只从可靠性角度说不够。如果我第一次握手的请求延迟很久才到，
        服务端建了连接，客户端却不认，会怎样？
你（L3）：这就是历史连接问题。服务端为这个迟到的请求建立了连接，
        但客户端认为自己没发起过，不会用它，服务端资源就白白占着。
        三次握手让服务端在收到第三次确认前不认为连接可用，
        可以避免为失效请求分配资源。
面试官：那把三次改成四次会不会更安全？
你（L4）：不会，三次已经能同时确认双方的收发能力，
        再加一次只是重复确认，增加一次 RTT 没有收益。
```

**这道题在考什么**：L2 是背来的答案，L3 才体现你真的想过「如果不这样做会发生什么」。

权威内容：TCP 协议细节当前尚未在仓库建设，可参考 RFC 9293 与《TCP/IP 详解》。

### 例二：从线程池追到队列类型

```text
面试官：线程池的队列你用的哪种？
你（L1）：LinkedBlockingQueue。
面试官：它默认容量是多少？
你（L2）：默认是 Integer.MAX_VALUE，相当于无界。
面试官：无界会有什么问题？
你（L3）：maximumPoolSize 实际永远不会生效，因为队列不满就不会创建
        非核心线程；任务一直堆在队列里，内存和延迟都会失控。
面试官：那你怎么改的？
你（L4）：换成有界队列并指定容量，配合监控队列水位；
        同时明确拒绝策略——核心业务用 CallerRunsPolicy 做背压，
        非核心用 DiscardPolicy 并打点。
面试官：CallerRuns 有什么副作用？
你（L5）：会让提交任务的线程自己执行，可能阻塞上游。
        如果用在下游调用链上，会把堵塞传导上去，必须配合超时。
```

**这道题在考什么**：从参数一路追到「副作用」。**能说出方案的负面效果，比只说好处更能体现工程判断。**

权威内容：[ThreadPoolExecutor 线程池](../../03-并发编程/02-深度解析/ThreadPoolExecutor线程池.md)

### 例三：从 GC 追到原理

```text
面试官：Java 有哪些引用类型？
你（L1）：强、软、弱、虚。
面试官：软引用和弱引用在回收时机上有什么区别？
你（L2）：软引用在内存不足时才回收，弱引用下次 GC 就回收。
面试官：那弱引用适合做什么？
你（L3）：适合做「生命周期不影响对象存活」的关联数据，
        比如给对象挂附加信息，或者 ThreadLocalMap 的 key。
面试官：虚引用呢？
你（L4）：虚引用拿不到对象，主要用于在对象被回收时收到通知，
        所以必须配合 ReferenceQueue 用。
面试官：为什么 ThreadLocalMap 的 key 用弱引用，value 却用强引用？
你（L5）：key 用弱引用是为了让 ThreadLocal 对象本身能被回收，
        避免 key 永远存活；value 是强引用是因为 Entry 持有它，
        如果 value 也用弱引用，正常使用时就可能被回收掉。
        代价是 key 被回收后 value 会滞留，才需要主动 remove。
```

**这道题在考什么**：从 API 列表追到「为什么这样设计」。最后一层的答案，是把四个引用类型串成一个设计决策。

权威内容：[ThreadLocal 原理与内存泄漏](../../03-并发编程/02-深度解析/ThreadLocal原理与内存泄漏.md)

## 高频失分点

| 失分点 | 表现 | 怎么改 |
| --- | --- | --- |
| 网络只会背结论 | 答「三次握手防止资源浪费」但说不出浪费在哪 | 每个结论准备一个「不这样做会发生的具体故障」 |
| 操作系统空白 | 被问 IO 模型直接卡住 | 至少补 select/poll/epoll、用户态内核态、虚拟内存 |
| 业务场景无法代入 | 讲技术方案不结合场景 | 提前熟悉社交/游戏/支付的基本架构特征 |
| 引用类型只背定义 | 说不出使用场景 | 记住「软引用做缓存、弱引用做关联、虚引用做通知」 |
| 回答过于简短 | 一句话结束，面试官要反复追问 | 主动补一句「这里的关键是……」把话题延展开 |

## 一句话准备建议

腾讯的面试像一张**覆盖面很宽的网**，单点不要求极深，但漏洞很容易被看到。复习时先保证「每一块都能答到 L2」，再挑两块（通常是并发和网络）做到 L4。
