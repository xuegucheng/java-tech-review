## 岗位技术域梳理

华为通用软件岗（Java 后端方向）的公开岗位画像通常覆盖：编程语言基础、数据结构与算法、操作系统与计算机网络、数据库、后端框架、工程实践。结合公开讨论，考察重心可归纳为：

| 技术域 | 相对权重 | 说明 |
| --- | --- | --- |
| Java 基础与集合 | 高 | 语言语义、相等性、泛型、集合底层，追问到设计动机 |
| 并发编程 | 高 | JMM、锁、线程池、并发容器，重视工程使用场景 |
| 计算机网络与操作系统 | 高 | 通用软件岗的传统强项，TCP/IP、进程线程、内存管理问得细 |
| 数据库 | 中高 | 索引、事务、SQL，结合业务场景 |
| JVM | 中 | 内存模型、GC 思路、结合线上现象 |
| 框架（Spring / MyBatis） | 中 | 原理级问题 + 项目中的使用 |
| 项目与工程能力 | 高 | 二面核心，重视问题定位过程与协作 |
| 算法与手写代码 | 中高 | 常见数据结构操作、排序、简单场景题，限时现场写 |

**准备策略**：通用软件岗的特点是**底盘要全**——网络与操作系统在这里不是加分项而是常规考点；同时把「项目里排查过什么问题」按证据链准备（现象 → 定位手段 → 根因 → 修复 → 验证），这类回答在主管面尤其吃香。

## 追问链示例

### 从一道基础题追到工程判断（模拟推演）

```text
面试官：HashMap 为什么线程不安全？
你（L1）：并发 put 会丢数据，JDK 7 扩容还可能成环。
面试官：丢数据具体丢在哪一步？
你（L2）：桶定位和链表写入没有同步，两个线程同时写同一个空桶会互相覆盖；
        size 的 ++ 也不是原子操作，计数会偏小。
面试官：那你们并发场景用什么？为什么不用 Hashtable？
你（L3）：ConcurrentHashMap。Hashtable 是全表一把锁，并发度只有 1；
        CHM 是空桶 CAS、非空桶锁头节点，锁粒度到单个桶。
面试官：CHM 的 get 为什么可以不加锁？
你（L4）：节点 value 是 volatile、next 是 final 的，配合 happens-before，
        读到的状态一定来自某个已完成写入的线程，不会读到中间态。
```

**这条链在考什么**：从「会不会背」到「懂不懂并发安全的实现手段」，再到「选型依据」。通用软件岗的基础面很爱这条路径，答到 L4 需要真正理解 JMM 与 CAS，入口见 [Java多线程](../01-专题题库/Java多线程.md)。

权威内容：[ConcurrentHashMap 并发容器](../../03-并发编程/02-深度解析/ConcurrentHashMap并发容器.md) · [集合框架 Q06](../01-专题题库/集合框架.md)

## 高频失分点

| 失分点 | 表现 | 怎么改 |
| --- | --- | --- |
| 网络/操作系统空白 | 被问 TCP 或 IO 模型直接卡住 | 通用软件岗底盘，至少保证 L2：结论 + 一个「不这样做会怎样」 |
| 只答结论不答依据 | 排查题只会说「看日志」 | 每步说清「看到什么 → 所以下一步做什么」 |
| 项目讲成需求文档 | 只讲做了什么功能 | 每个技术点准备「问题 → 方案 → 取舍 → 结果」四段 |
| 手写代码不出声 | 沉默写题 | 边说思路边写，写完主动检查边界 |
| 把模拟题当真题背 | 面试遇到变体不会 | 练习题只用来自测方向，答案要理解不要背诵 |

## 一句话准备建议

华为通用软件岗的面试像**宽底盘 + 深追问**：网络、操作系统、数据库、并发每块都要能答到机制层，再挑一两块（通常是并发或数据库）答到能讲工程取舍。练习题只是自检工具，真正的标准答案永远在 [专题题库](../01-专题题库/README.md)。
