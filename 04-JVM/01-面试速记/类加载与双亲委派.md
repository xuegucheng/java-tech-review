# 类加载与双亲委派

> **P0 · Java 21 / JVMS 21 · 面试速记**
>
> 生命周期部分由 [类文件与类加载生命周期](../02-深度解析/类文件与类加载生命周期.md) 唯一维护；双亲委派与类型身份仍是后续 Owner。

## 一句话结论

先分清 Loading、Linking 和 Initialization：JVM 从普通类/接口的二进制表示创建运行时类型；Linking 包含验证、准备和解析；Initialization 才执行类级初始化逻辑。解析时机可以延迟，`Class<?>` 是 Java API 镜像，不是 Class File。

## 30 秒回答

> `.java` 经 `javac` 编译为 Class File 二进制表示。普通 class/interface 的 Loading 由 JVM 与 ClassLoader 协作完成；Linking 包含 Verification、Preparation、Resolution。准备通常先为静态字段设置默认值，但带 `ConstantValue` 的静态字段在 Initialization 中、`<clinit>` 前赋值。Resolution 可以 eager 或 lazy，不保证所有符号引用都在初始化前一次完成。Initialization 执行 `<clinit>`，与实例初始化方法 `<init>` 不同。数组类由 JVM 创建，没有外部 Class File。

## 展开顺序

1. **Class File** 是类型的二进制表示，包含结构、符号引用和 JVM 指令；不等于 Java API 的 `Class<?>`。
2. **Loading** 建立 VM 运行时类型。二进制表示可由文件、归档、网络或运行时生成来源提供；数组类走 JVM 创建路径。
3. **Linking** 检查输入约束、建立静态字段状态，并解析运行时符号关系。
4. **Initialization** 执行类型初始化方法；Java 语言级触发条件和源码顺序回到 Java Core Owner。
5. **ClassLoader 委派与类身份** 是下一段机制，本入口暂不定义完整策略。

## 快速纠错

- 类已 Loading，不代表 `static` 块已经执行。
- `Preparation` 不执行普通静态字段初始化表达式；`ConstantValue` 有单独规范时机。
- Resolution 可以延迟到符号引用使用时，也可能在类型初始化后继续。
- `ClassLoader.loadClass(String)` 默认不初始化；`Class.forName(String)` 会请求初始化。
- 同名运行时类型还涉及 defining loader；细节进入下一篇 P0 Owner。
