# 方法重载与调用解析

> **P1 · JDK 8+ · 5 分钟复习**

## 面试结论

Java 的普通重载在编译期完成。编译器先按调用点的编译时类型收集可见候选，再依次尝试固定参数的严格调用、固定参数的宽松调用，最后才尝试可变参数；同一阶段仍有多个候选时选择最具体的方法。运行时对象只影响被选中实例方法的重写分派，不会重新做一次重载匹配。

## 30 秒回答

> 方法重载主要由方法名和形参类型序列区分，返回类型、参数名、`throws` 和 `static` 不能单独形成重载。调用解析优先恒等和基本类型宽化，其次装箱/拆箱等宽松转换，最后才是可变参数；`null` 能匹配任意引用类型，所以两个互不相关的引用重载可能产生歧义。若父类引用指向子类对象，先按父类的可见候选选择重载，再对选中的可重写实例签名做动态分派。

## 追问链

### 1. 什么是方法签名？

面试中的实用说法是“方法名 + 形参类型序列”。参数名、返回类型和 `throws` 不用于单独区分重载；泛型还要检查擦除后的签名是否冲突。

### 2. 为什么不能只改返回类型重载？

调用可能完全不使用返回值，编译器无法依据目标类型稳定地区分两个同名同参方法。

### 3. `int`、`long`、`Integer`、`int...` 谁优先？

对 `1`，先命中 `int` 的严格恒等匹配；对 `short`，通常在严格阶段宽化到 `int`；只有固定参数阶段没有适用候选时才进入装箱或可变参数阶段。

### 4. `null` 为什么会歧义？

`null` 可转换到任意引用类型。`String` 与 `Object` 有明确的更具体关系，选 `String`；`String` 与 `Integer` 互不更具体，调用失败。

### 5. 重载和重写如何同时发生？

```java
Parent value = new Child();
value.handle("x");
```

先按 `Parent` 能看到的参数列表选择重载，再由运行时 `Child` 对该签名的重写实现接管。`Child` 新增的同名重载不会在运行时被发现。

### 6. 泛型能否用来区分重载？

不能依赖 `List<String>` 与 `List<Integer>` 区分，因为擦除后都是 `List`。泛型方法还可能与普通 `Object` 参数发生擦除后的名称冲突。

### 7. 可变参数有什么成本？

它是数组调用语法，最后才参与解析，可能产生临时数组；对公共 API 要避免装箱重载、引用重载和 `Object...` 组合成难以预测的调用面。

## 易错点

| 错误说法 | 修正 |
| --- | --- |
| 重载按运行时参数类型选择 | 普通重载按编译时类型解析 |
| 返回类型可以区分重载 | 返回类型不能单独区分 |
| 装箱总是优先于宽化 | 固定参数严格阶段先尝试宽化 |
| 可变参数最方便所以优先 | 可变参数是最后阶段 |
| `null` 总能选一个引用重载 | 互不相关的引用类型会歧义 |
