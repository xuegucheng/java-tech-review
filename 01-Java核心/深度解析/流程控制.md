# Java 流程控制

> **本章定位：控制流收口页。** 只保留条件、`switch`、循环、跳转、可达性和现代模式匹配中最容易影响正确性与审查的规则。表达式类型和运算符见 [运算符与表达式陷阱.md](运算符与表达式陷阱.md)，异常资源清理见对应专题。

## 5.1 控制流的审查顺序

```text
条件是否真的为 boolean
↓
分支是否互斥且覆盖边界
↓
循环是否有明确进展和终止条件
↓
break/continue/return 是否让路径可读
↓
finally 是否改变了原本的返回或异常
```

Java 没有把非零整数自动当作真值：`if (count)` 不能编译，必须显式写比较。

## 5.2 `if` 与卫语句

```java
if (request == null) return;
if (!request.isValid()) return;

process(request);
```

卫语句把异常路径提前结束，减少层层嵌套。条件应表达业务谓词，避免在 `if` 中塞入难以测试的 I/O 或多重状态修改。

`else-if` 按源码顺序匹配，第一个为真的分支执行；边界值要明确放在更具体的条件前面。

## 5.3 传统 `switch`：穿透是语义，不是 bug 修复

```java
switch (status) {
    case NEW:
    case RETRY:
        enqueue();
        break;
    case DONE:
        archive();
        break;
    default:
        reject();
}
```

冒号标签若没有 `break`、`return`、`throw` 或其他控制转移，会继续执行下一个 case。刻意合并标签可以利用穿透，但复杂共享逻辑应改用方法或新式 `switch`。

## 5.4 `switch` 表达式与 `yield`

```java
String label = switch (status) {
    case NEW, RETRY -> "pending";
    case DONE -> "closed";
    default -> "unknown";
};
```

箭头标签不会自动穿透；表达式必须产生值。一个 case 需要多条语句时使用 `yield`：

```java
String label = switch (status) {
    case NEW -> {
        audit(status);
        yield "pending";
    }
    default -> "unknown";
};
```

## 5.5 穷尽性、`default` 与 Java 21 模式

枚举 `switch` 表达式可以列出所有枚举常量而不写 `default`，新增枚举值时让编译器暴露需要更新的地方。对开放类型或未来值，`default` 可能更合适。

Java 21 的模式 `switch` 还涉及类型覆盖、支配关系、`null` 标签和 sealed 类型穷尽性：

```java
String describe(Object value) {
    return switch (value) {
        case null -> "null";
        case String text when !text.isBlank() -> "text";
        case String text -> "blank";
        default -> "other";
    };
}
```

更具体的模式必须放在更宽泛的模式前，否则会被支配；`null` 要按需求显式处理。完整模式匹配演进放在版本专题，控制流页只保留穷尽性和顺序边界。

## 5.6 循环：先写不变量与进展

```java
int index = 0;
while (index < values.length) {
    consume(values[index]);
    index++;
}
```

选择循环时看语义：

| 形式 | 适合 |
| --- | --- |
| `for` | 计数器、索引和明确更新 |
| 增强 `for` | 只读遍历元素 |
| `while` | 终止条件由外部状态或读取结果决定 |
| `do-while` | 至少执行一次的交互/重试 |

循环必须有可证明的进展；`while (true)` 只有在内部有明确 `break`、阻塞或返回协议时才可接受。

## 5.7 遍历修改与快照边界

直接在增强 `for` 中结构性修改集合通常会触发 `ConcurrentModificationException` 或产生未定义的业务结果：

```java
for (String item : items) {
    if (expired(item)) items.remove(item); // ❌
}
```

根据意图选择 `Iterator.remove()`、`removeIf`、新集合或并发集合。这里不展开集合实现；集合语义见 `02-集合框架`。

## 5.8 `break`、`continue`、标签与 `return`

- `break` 结束最近的循环或 `switch`；
- `continue` 跳到下一次循环；
- 标签可以跳出嵌套循环，但通常应优先提取方法；
- `return` 结束当前方法，不等于结束调用链中的所有方法。

```java
outer:
for (Item item : items) {
    for (Rule rule : rules) {
        if (rule.matches(item)) {
            handle(item);
            continue outer;
        }
    }
}
```

标签不是错误，但当循环承担多个职责时，提取 `findMatchingRule` 等方法通常更易测试。

## 5.9 可达性与 `finally`

编译器会拒绝明显不可达语句，例如 `return` 后同一块中的普通语句。`finally` 通常总会执行，但以下写法会覆盖原返回值或吞掉异常：

```java
int read() {
    try {
        return 1;
    } finally {
        // return 2; // ❌ 会覆盖 try 的返回
    }
}
```

资源关闭优先使用 try-with-resources；不要用 `finally` 中的 `return` 改写控制流。

## 5.10 高频陷阱清单

| 误区 | 正确判断 |
| --- | --- |
| `if (1)` 合法 | 条件必须是 boolean |
| `switch` case 自动互斥 | 冒号 case 可能穿透，箭头 case 不自动穿透 |
| `switch` 表达式可缺少结果 | 每条正常路径都要产生值或抛异常 |
| 枚举永远必须写 default | 需要编译器检查新增枚举值时可省略 |
| `for-each` 中 remove 安全 | 结构性修改需要 iterator/removeIf 等明确协议 |
| `while(true)` 永远错误 | 关键是是否有清晰的阻塞/跳出协议 |
| `continue` 结束整个循环 | 只进入下一次当前循环 |
| finally 只负责清理不影响结果 | finally 中 return/throw 会改变原路径 |
