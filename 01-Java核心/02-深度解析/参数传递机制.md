# Java 参数传递机制

> **本章定位：参数语义权威页。** 只保留“值传递、引用值副本、对象可变状态、参数重绑”四个核心问题，并用数组、字符串、包装类型和可变参数验证它们。不可变对象、深浅复制和防御性复制的完整设计见 [对象创建与不可变设计.md](对象创建与不可变设计.md)。

## 7.1 唯一总原则

> **Java 只有值传递。**

所谓引用类型参数，是把“引用值”复制给形参，不是把调用方变量本身交给方法：

```text
调用方变量 ──引用值 A──> 对象
                         ↑
形参变量   ──复制引用值 A─┘
```

因此要分开问两件事：

1. 方法是否通过副本找到同一个对象，并修改了对象状态？
2. 方法是否只是让形参改为指向另一个对象？

前者对调用方可见，后者不可见。

## 7.2 基本类型：复制基本值

```java
static void change(int value) {
    value = 99;
}

int original = 1;
change(original);
// original 仍为 1
```

`value` 保存的是 `1` 的副本。形参重新赋值不会回写调用方的局部变量。

## 7.3 引用类型：复制引用值

```java
static void mutate(StringBuilder builder) {
    builder.append("!");
}

static void rebind(StringBuilder builder) {
    builder = new StringBuilder("new");
}

StringBuilder text = new StringBuilder("old");
mutate(text); // text 看到 old!
rebind(text); // text 仍指向 old!
```

图示见 [Java值传递.svg](../03-图示/参数传递/Java值传递.svg)。

```text
mutate：形参副本与实参变量指向同一对象 → 改对象状态可见
rebind：只修改形参副本保存的引用值     → 调用方变量不变
```

这不是“Java 有时引用传递”，而是引用值本身恰好指向可变对象。

## 7.4 为什么普通方法不能交换两个变量

```java
static void swap(StringBuilder left, StringBuilder right) {
    StringBuilder temp = left;
    left = right;
    right = temp;
}

StringBuilder a = new StringBuilder("A");
StringBuilder b = new StringBuilder("B");
swap(a, b);
// a 仍是 A，b 仍是 B
```

方法只能交换自己的两个参数变量。若要让调用方观察到“交换”，应返回一个结果对象、修改一个可见容器，或由调用方显式接收两个新值；不要把这种做法称为改变实参引用。

## 7.5 数组、可变参数与别名

数组变量保存引用值，所以数组元素修改可见：

```java
static void mark(int[] values) {
    values[0] = 7;
}

int[] values = {1, 2};
mark(values);
// values[0] == 7
```

可变参数只是数组参数的调用语法：

```java
static void setFirst(int... values) {
    if (values.length > 0) values[0] = 7;
}

int[] input = {1, 2};
setFirst(input); // 允许直接传入数组，input 被修改
```

如果多个变量或参数持有同一个数组/集合引用，就产生别名。参数传递本身没有复制对象；是否需要快照是 API 设计问题。

## 7.6 `String`、包装类型与 `final`

`String` 看起来“传进去不能改”，不是因为参数传递规则特殊，而是 `String` 不提供原地修改操作：

```java
static void replace(String value) {
    value = value + "!"; // 创建新 String，只重绑形参
}
```

包装类型也按值传递引用值；`Integer` 等常见包装对象不可变，所以不能通过对象状态修改表现出变化：

```java
static void increase(Integer value) {
    value = value + 1; // 拆箱、计算、装箱，再重绑形参
}
```

`final` 参数只禁止形参变量再次赋值，不会冻结对象：

```java
static void append(final StringBuilder builder) {
    builder.append("!"); // 合法：改对象
    // builder = new StringBuilder(); // ❌ 形参不能重绑
}
```

不可变性由对象的实现和暴露的修改入口决定，不由参数上的 `final` 决定。

## 7.7 返回内部对象与复制边界

参数传递页只给出判断框架：

| API 边界 | 直接共享的后果 | 需要考虑的策略 |
| --- | --- | --- |
| 接收调用方集合 | 方法可意外修改调用方状态 | 文档约束、快照或不可变副本 |
| 保存调用方集合 | 调用方后续修改会改变对象内部状态 | 构造器防御性复制 |
| 返回内部集合 | 调用方可绕过不变量修改内部状态 | 不可变视图或快照 |
| 嵌套可变对象 | 只复制外层仍共享子对象 | 明确定义复制深度 |

不要在这里重复“深复制算法”或 `List.copyOf` 的全部差异；完整 owner 是 [对象创建与不可变设计](对象创建与不可变设计.md)。本页只负责说明：**传参不会自动复制对象，复制必须由 API 语义明确选择。**

## 7.8 输入参数的工程契约

写方法前先声明所有权：

```text
只读借用：调用期间读取，不保存、不修改
可变借用：允许修改，文档写清副作用
快照接收：方法内部保存独立状态
转移/所有权：生命周期由方法接管
```

Java 没有借用检查器替你执行这些规则，因此要靠类型选择、不可变接口、复制和文档共同建立契约。

推荐：

- 只读消费优先暴露 `List` 等最小接口，并明确是否会保存；
- 跨线程或跨生命周期保存时，不要默认相信调用方不会继续修改；
- 大对象复制可能昂贵，先明确一致性要求再决定快照时机；
- 不要通过“返回一个可变内部对象让调用方修改”隐式暴露领域状态。

## 7.9 递归和异步边界

递归调用仍然遵循同一参数规则：每层栈帧都有自己的形参变量，但这些形参可能指向同一堆对象。异步提交后，任务可能在调用方修改参数之后才执行；此时直接捕获可变对象会产生时间上的别名问题。

```text
同步调用：共享对象的修改顺序通常紧邻可见
异步调用：共享对象还叠加执行时序、可见性和生命周期问题
```

并发可见性、线程安全和消息传递交给未来并发模块；本页只指出参数副本不会自动变成线程安全快照。

## 7.10 面试快速回答

> Java 只有值传递。基本类型复制基本值；引用类型复制引用值，所以形参和实参变量可能指向同一个对象。通过形参修改该对象的可变状态，调用方可以看到；让形参重新指向新对象，调用方变量不会改变。数组和可变参数也遵循这个规则。`String` 和包装类型表现得像值类型，主要是因为对象不可变。参数上的 `final` 只限制形参重绑，不保证对象不可变。是否需要深浅复制或防御性复制属于对象 API 的所有权设计，不是 Java 参数传递的隐藏规则。
