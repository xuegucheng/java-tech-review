# 类型设计：不变量、接口与组合

> **P1 · JDK 8+；record/sealed 单独标版本 · 5 分钟复习**

## 面试结论

好的类型不是字段加 Getter/Setter，而是让对象从创建开始就合法，并通过最小公开协议维护不变量。继承表达稳定的 is-a 契约；组合和委托更适合替换行为、隔离变化和测试。

## 设计判断

```text
先找变化轴与不变量
        ↓
能否用稳定能力接口表达？
        ↓
优先组合/委托隔离实现变化
        ↓
只有子类型真正满足父类型契约时才继承
```

接口解决“调用方需要什么能力”；抽象类可以共享状态、骨架流程和受保护扩展点；二者都不应成为把所有业务塞进父类的理由。

## 追问链

1. 为什么优先组合？依赖方向更明确，替换和测试成本更低，避免脆弱基类。
2. Getter/Setter 都是 `public` 是否封装？不一定；如果外部可以绕过校验任意改状态，表示仍然泄漏。
3. 什么时候抽象类比接口合适？需要共享不变量、状态或不可绕过的模板流程时。
4. SOLID 如何落地？把它当作发现变化、控制依赖和缩小职责的检查表，不要当成模式清单。

## 工程坑

- 先设计十层继承树，再寻找业务问题，通常会过度抽象。
- 过大的接口让实现类被迫依赖无关方法。
- 构造器、反序列化、ORM 映射和依赖注入都可能绕过正常创建路径，必须重新确认对象不变量。
- 不能把仓库中的技术案例自动改写成个人生产事故或个人项目经历。
